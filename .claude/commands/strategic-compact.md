# /strategic-compact

複雑タスクのコンテキスト圧縮・効率化コマンド

## 使用場面
- 長時間にわたるセッション実行で、プロンプトキャッシュが枯渇しているとき
- 複数のエージェント・並行タスク実行時に、トークン効率を上げたい
- 前のセッションからの引き継ぎで、会話履歴が膨大なとき
- 複数の独立した作業を1つのセッションで行う場合

## 実行方法
チャットに `/strategic-compact` と入力して実行

## 効果
1. **会話履歴の圧縮**
   - 古い会話を要約・統合
   - 不要なやりとりを削除
   - コンテキスト長を50-70%削減

2. **セッション分割の提案**
   - 大規模タスクを複数セッションに分割
   - セッション間の依存関係を明示
   - 最適な並列実行構成を提案

3. **キャッシュ戦略の再設計**
   - Prompt caching TTL を超えないように調整
   - 再利用率の高いコンテキスト（CLAUDE.md, docs/等）を優先
   - セッション内でのキャッシュ命中率を予測

## hojo-hq での活用例

### 過去の事例
- **カチトーク続新セッション**: 49B cache_read tokens（異常な高コスト）
  - 原因: 複数 Routine + 複雑な議事が単一セッションに蓄積
  - 対策: `/strategic-compact` で会話を圧縮、または新セッション分割

- **複数エージェント・ワークフロー実行**:
  - glow-ma システム更新（複数部門が同じスプレッドシート編集）
  - 各部門を別セッション化し、定期的に同期

### 推奨パターン

**パターン1: 月次結算セッション**
```
スタッフ会議（議事記録3ヶ月分） → /strategic-compact 圧縮
→ 新セッションで Q4 計画立案 → cache 効率 70%削減
```

**パターン2: 複数ルーチン + エージェント実行**
```
定期クロール (毎日) + 検証チェック (週1) + SNS投稿案出 (週3) 
→ /strategic-compact で3つを分離セッション化
→ 各セッション月額コスト 50% 削減
```

**パターン3: 既存セッションの引き継ぎ**
```
❶営業管理システム（4ヶ月累積会話100K tokens）
→ /strategic-compact で「決定済み事項」に圧縮
→ 新しい Routine 実行時の cache_read 削減
```

## 推奨実行頻度
- **月1回**: 月初（新月度セッションスタート時）
- **セッション引き継ぎ時**: 既存セッションの会話が累積 50K tokens 以上
- **大規模実行前**: 複数エージェント並行実行時（コスト計画立案）
- **コスト異常時**: 月額費用が前月比 +20% 以上のとき

## 実装ガイドライン

### コンテキスト圧縮のルール
1. **保持対象（必須）**:
   - CLAUDE.md（プロジェクト憲法）
   - 決裁・最終判断（小柳さん指示）
   - 実装済み・リリース済みの内容

2. **削除可能（非保持）**:
   - 却下された提案
   - プロセス中の試行錯誤
   - 旧バージョンの議事（新版がある場合）

3. **圧縮推奨（要約化）**:
   - 複数の似たやりとり → 1つの結論にまとめる
   - 長い背景説明 → 「✓ 2026-08-17 決定済み」に短縮
   - 実装過程の詳細 → 最終的な決定と理由だけ残す

### セッション分割のガイドライン
```
❌ 避けるべき：1つのセッションで複数部門の異なるテーマを扱う
  例: glow-ma システム + note 記事作成 + SNS 企画立案

✓ 推奨：部門別またはテーマ別に分離
  例: ❶ 営業管理システム（専用セッション）
      ❷ note編集部（専用セッション）
      ❸ SNS部（専用セッション）
      + 月1回同期ミーティング
```

## 注意点
- セッション分割時は、引き継ぎドキュメント（docs/議事）を必ず作成
- 圧縮後、新セッションで意思決定が変わらないか確認
- キャッシュ TTL (1時間) を考慮した実行スケジュール設計
