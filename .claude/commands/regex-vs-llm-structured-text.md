# /regex-vs-llm-structured-text

単純作業を AI から外して トークン節約するコマンド

## 使用場面
- 正規表現でパターンマッチング・抽出ができるタスク
- CSV/JSON の単純変換・フォーマット調整
- ファイル名の一括変更・リネーム
- テキストの機械的な削除・置換・フィルタリング
- ログ解析・データクリーニング

## 実行方法
チャットに `/regex-vs-llm-structured-text` と入力して実行

## 原則
**AI を使う必要がない単純作業は、bash/Python スクリプトで処理**

| タスク | 方法 | 理由 | 節約量 |
|---|---|---|---|
| CSV の特定列を抽出 | `awk`, `cut` | 決定的、高速、トークン0 | 5-10K tokens |
| JSON パース・フィルタ | `jq` | 標準ツール、1行で完結 | 10-20K tokens |
| 正規表現マッチ・置換 | `sed`, `grep`, Python `re` | パターン明確、LLM不要 | 5-10K tokens |
| ファイル一括処理 | bash loop + `find` | 機械的 | 3-5K tokens |
| テキスト整形（markdown → HTML等） | pandoc, sed | ツール存在 | 10-20K tokens |

## 実装ガイドライン

### ステップ1: タスク分析

**このチェックリストで判断**:
- [ ] **パターンが固定か？** YES → Bash/正規表現 / NO → AI 相談
- [ ] **入出力フォーマットが明確か？** YES → Bash / NO → AI 相談
- [ ] **既存ツール（awk, sed, jq等）で実装できるか？** YES → ツール使用 / NO → AI 相談
- [ ] **判断ロジックが必要か？** YES → AI 相談 / NO → Bash

### ステップ2: ツール選択

```bash
# テキスト1行単位の処理
grep, sed, awk

# CSV/TSV 処理

# 複雑ファイル操作

# 複合処理（パイプ）
tool1 | tool2 | tool3
```

### ステップ3: AI 活用（ツール選択後）

AI が手伝うべき場面：
1. **ツール実行が複雑** → スクリプト設計の相談
2. **パターンが複数** → 複数パターンの正規表現設計
3. **エラーハンドリング** → 例外ケースへの対応
4. **パフォーマンス** → 大規模ファイルの高速化

## hojo-hq での リアルタイム実装例

### 例: 制度DB の自動フィルタリング（実運用）

**タスク**: 毎日のクロール結果から「沖縄県」 + 「受付中」のみ抽出

```bash
#!/bin/bash
# tools/filter_okinawa.sh
# AI 不要（決定的な処理）

input_csv=$1

# 単純な正規表現フィルタ
awk -F',' '
  NR==1 { print; next }  # ヘッダは保持
  $3 == "沖縄県" && $5 ~ /受付中/ { print }
' "$input_csv" > okinawa_active.csv

echo "✓ フィルタ完了: $(wc -l < okinawa_active.csv) 件"
```

**トークン消費**: 0（Claude AI 不使用）  
**実行時間**: < 0.1秒

## 推奨実行頻度
- **タスク計画時**: 新しい自動化を設計する前に必ず実行
- **スクリプト レビュー時**: AI が出力したコードで、単純作業をしていないか確認
- **月次最適化**: 実装済みスクリプトで「ここは Bash に変更できる」部分を発見

## チェックリスト（AI 依頼前）

```
□ このタスクは「判断」が必要か？
  YES → AI に相談
  NO → Bash/ツールで実装

□ 入力・出力フォーマットは固定か？
  YES → Bash/ツール
  NO → AI に相談

□ 既存ツールで 80% 実装できるか？
  YES → まずツール実装 → AI は 20% の複雑部分だけ
  NO → AI 設計から

□ このスクリプトは月 1回 以上実行されるか？
  YES → コード化すべき（トークン節約のため）
  NO → 1回限りなら AI に任せても OK
```

## 注意点
- 正規表現の複雑さ（5 段階超）は AI に相談
- セキュリティ（SQL injection 等）が絡む場合は AI 設計必須
- パフォーマンスが重要（100万行ファイル等）なら事前相談
- チーム内で再利用するスクリプトは、ドキュメント + コメント必須
