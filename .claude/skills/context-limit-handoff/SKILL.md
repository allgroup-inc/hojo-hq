# コンテキスト上限への対応(会話を失っても作業を失わない)

「コンテキストウィンドウがいっぱいです」という警告が出たら、まずこのスキルの
手順に従う。合言葉: **会話は記憶、作業の現在地は外部に持たせる**
(`resilient-agent-design`の③状態を外部へ保存する、と同じ考え方)。

## 警告が出たときの判断フロー

1. **今進めている作業がgit(コミット/PR)に残っているか確認する**
   - 残っていれば: 会話が消えても作業は失われない。次のステップへ
   - 残っていなければ: まずコミット/PR化するか、少なくとも今の状態(何をやっていて
     次に何をすべきか)をどこかのファイル(docs/等)にメモしてから次のステップへ
2. **選択肢を選ぶ**
   - **何もせず自動コンパクトに任せる**(推奨・デフォルト): 古い部分が要約され、
     直近の文脈と作業状態は残る。git上の作業は無関係に安全
   - **巻き戻し**: 直近のやり取りを破棄して過去の時点へ戻る。**未コミットの
     指示・確認事項はここで失われる**ため、①を必ず先に済ませてから使う
   - **新しいセッションを開始する**: 会話の記憶は完全にリセットされるが、
     gitに残っている作業(コミット・PR・ドキュメント)は影響を受けない。
     新セッションに「前回どこまでやったか」を一言伝えれば続きから再開できる

## 判断の目安

| 状況 | 推奨アクション |
|---|---|
| 作業はgitにコミット済み、会話が長いだけ | 何もしない(自動コンパクトに任せる) |
| 未コミットの確認待ち事項がある | 先にコミット/メモしてから何もしない、または巻き戻し |
| セッションが不安定・応答が悪い | git状態を確認 → 新しいセッションを開始 |
| 「巻き戻し」を使うか迷う | 基本的に使わない。gitに残っていれば新セッションの方が安全 |

## なぜ「巻き戻し」を基本使わないのか

巻き戻しは会話内の情報だけを対象にした操作で、**その時点までの意思決定の
経緯(なぜその実装にしたか、何を却下したか)が失われる**。git上のコミット・
PR説明文・docsに残しておけば、会話をどう扱っても実質的な作業(コード・
ドキュメント・意思決定の記録)は失われない。判断に迷ったら、まず
「今の状態はgitに残っているか」を自問する。
