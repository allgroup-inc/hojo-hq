# user-research-hojo スキル — テストケース

## テストケース概要

※ このファイルの点数・日付・ペルソナの値はすべて仮定の入力と期待値であり、実績ではない。

このファイルは、user-research-hojo スキルの「ペルソナ鮮度」「リサーチサイクル」「施策～検証の連続性」を検証するテストケース集です。

点数はすべて SKILL.md「検査結果の判定」の【スコア計算】で数える（ペルソナ鮮度スコア = 8 項目の合計・満点 80 点。各項目 グリーン +10 / イエロー 0（項目 8 のみ）/ レッド -5）。テストケース 1〜5 は 1 項目ずつの判定、テストケース 6 は合計点を確かめる。

## テストケース 1: ペルソナ更新日検査

**目的**: ペルソナの最終更新日が 30 日以内に保たれているか確認

### テスト 1-1: ペルソナが最新に保たれている

```
入力:
  ペルソナ最終更新日: 2026-10-05（本日）
  現在日: 2026-10-05

期待値:
  ✅ グリーン（OK）「項目 1: グリーン = +10 点」

実施方法:
  ├─ ペルソナ定義の文書から最終更新日を抽出（置き場所は運用で決める）
  └─ 更新日から経過日数を計算（30 日以内 → OK / 以上 → NG）
```

### テスト 1-2: ペルソナが 30 日以上未更新

```
入力:
  ペルソナ最終更新日: 2026-08-20
  現在日: 2026-10-05

期待値:
  ❌ レッド（要更新）「項目 1: レッド = -5 点」「経過日数: 46 日」

実施方法:
  ├─ 経過日数 = 現在日 - 最終更新日
  └─ 46 日 > 30 日 → 「更新期限切れ」フラグを立てる
     └─ 対応: 月次ペルソナ更新（段階 9）を即座に実施
```

### テスト 1-3: ペルソナ複数セグメントで鮮度がバラバラ

```
入力:
  セグメント A 最終更新日: 2026-10-02（3 日前）→ グリーン
  セグメント B 最終更新日: 2026-09-10（25 日前）→ グリーン
  セグメント C 最終更新日: 2026-08-20（46 日前）→ レッド

期待値:
  ❌ レッド（項目 1: レッド = -5 点。いちばん古いセグメントで判定する）
  「セグメント C が 46 日未更新。他セグメントより優先度高」

実施方法:
  ├─ 各セグメントの更新日を個別に確認
  ├─ 30 日以上のセグメントが 1 つでもあれば → 項目 1 はレッド（グリーン / レッドの 2 値）
  └─ 対応: セグメント C のペルソナを再更新（理由: 新規顧客属性が未反映）
```

## テストケース 2: 施策～検証の連続性検査

**目的**: 実装された施策に対して、KPI 測定と検証記録が残されているか確認

### テスト 2-1: 施策が実装され、検証記録も完全

```
入力:
  施策: 「診断結果に成功事例を埋め込む」
  実装日: D（日付は相対表記。D = 実装日）
  検証期限: D + 31 日
  検証記録: 
    ├─ D + 7 日: 33%（初回測定）
    ├─ D + 14 日: 36%
    └─ D + 31 日: 42% → ✅ KPI 達成（目標 40% 以上）

期待値:
  ✅ グリーン（OK）「項目 2: グリーン = +10 点」「KPI 達成」

実施方法:
  ├─ 施策の記録から「実装日」「検証期限」を抽出
  ├─ 検証期限までの「KPI 測定記録」が週次で存在するか確認
  ├─ 検証期限の日に「最終値」が記録されているか確認
  └─ 最終値が KPI を達成しているか確認
```

### テスト 2-2: 施策が実装されたが、検証期限を過ぎても測定なし

```
入力:
  施策: 「LINE 登録ボタンテキスト変更」
  実装日: 2026-10-10
  検証期限: 2026-11-10（期限を過ぎた）
  現在日: 2026-12-05
  検証記録: 空（記録がない）

期待値:
  ❌ レッド（検証忘れ）「項目 2: レッド = -5 点」「経過日数: 25 日（検証期限超過）」

実施方法:
  ├─ 「検証期限」と「現在日」を比較（現在日 > 検証期限 か？）
  ├─ 検証記録の存在確認（施策名と開始日で探す）
  └─ 記録がない → 「検証期限超過のまま未検証」フラグを立てる
     └─ 対応: 即座に検証を実施（段階 8）
```

### テスト 2-3: 施策が実装されて 1 ヶ月、検証期限は決まっているが期限までのコースは不明

```
入力:
  施策: 「PDF ダウンロード機能」
  実装日: 2026-09-15
  検証期限: 2026-10-15
  現在日: 2026-10-20（検証期限を 5 日過ぎた）
  検証記録: 部分的（実装直後に 1 回だけ測定）
    └─ 2026-09-20: 15 DL（初期値のみ）
  最終値: なし（期限後も測定されず）

期待値:
  ❌ レッド（継続測定なし）「項目 2: レッド = -5 点」「検証期限までの週次測定: 1 回だけ」

実施方法:
  ├─ 検証期限までに「週次の KPI 更新」が存在するか確認
  ├─ 検証期限の直前に「最終値」が記録されているか確認
  └─ 記録が途中で途絶えている → 「継続測定の停止」を検出
     └─ 対応: 検証をやり直す（段階 8）、または検証期限を延長
```

## テストケース 3: 現場の違和感報告 → リサーチ発動の追跡

**目的**: 現場から出た「違和感」が、その後のリサーチ実施につながったか確認

### テスト 3-1: 違和感報告から 5 日以内にリサーチが開始された

```
入力:
  違和感報告: 2026-10-01「飲食店経営者も新規登録が増えている」
  リサーチ開始: 2026-10-03（2 日後）「新規セグメント調査」

期待値:
  ✅ グリーン（OK）「項目 3: グリーン = +10 点」「報告～開始: 2 日」

実施方法:
  ├─ 「違和感報告ファイル」から日付を抽出（例: `違和感_20261001_飲食店層.md`）
  ├─ リサーチ開始メモを検索（例: `リサーチ_20261003_新規セグメント.md`）
  └─ 開始日 - 報告日 ≤ 5 日 → グリーン
```

### テスト 3-2: 違和感報告があるが、その後のリサーチ開始記録がない

```
入力:
  違和感報告: 2026-09-10「高齢経営者は、診断結果を紙に印刷して見たいらしい」
  現在日: 2026-10-05（25 日経過）
  リサーチ開始: なし

期待値:
  ❌ レッド（リサーチ未発動）「項目 3: レッド = -5 点」「経過: 25 日」

実施方法:
  ├─ リポジトリ内を検索（例: `違和感_20260910` に対応する `リサーチ_*`）
  ├─ マッチするリサーチファイルが存在しないか確認
  └─ なし → 「違和感報告が停滞」アラートを発出
     └─ 対応: 3 名体制で「このリサーチは必要か」を判定し、対応を決定
```

### テスト 3-3: リサーチは開始されたが、「完了と実装」への転換がない

```
入力:
  違和感報告: 2026-09-15「セグメント B に飲食店の経営者が増え、申請ニーズが新しい」
  リサーチ開始: 2026-09-18「飲食店向けペルソナ調査」
  リサーチ完了: 2026-09-28（「ジャーニーマップ草案」を作成）
  施策化の期限: 2026-10-03（完了から 5 日）
  現在日: 2026-10-10
  施策の決定・実装: なし（期限から 7 日経過）

期待値:
  ❌ レッド（項目 6: レッド = -5 点。対策案に「施策の決定と実装期限」が無い）「リサーチ～施策化: 7 日遅延」

実施方法:
  ├─ リサーチ完了日を確認（例: `リサーチ_20260928_完了.md` の存在）
  ├─ 完了から施策実装（段階 7）までの日数を計算
  ├─ 完了から 5 日以上経過して施策が実装されていない → 警告
  └─ 対応: 即座に「施策実装の三名体制議論」を開始（段階 7）
```

## テストケース 4: ペルソナ更新と新規セグメント追加の検査

**目的**: 新規セグメントが見つかったときに、ペルソナ定義に追加されているか確認

### テスト 4-1: 新規セグメント（飲食店層）が出現し、ペルソナ定義に追加された

```
入力:
  過去 30 日の新規ユーザーの業種:
    ├─ 建設業: 45%
    ├─ 製造業: 35%
    └─ 飲食店（新しく増えた層）: 20%
  
  ペルソナ定義（セグメント A〜C は SKILL.md 段階 5 と同じ）:
    └─ セグメント B の業種に「飲食店」を追加（2026-10-05。SKILL.md 段階 9 の更新テンプレートの例）

期待値:
  ✅ グリーン（OK）「項目 5: グリーン = +10 点」「新しい層の検出から追加まで: 期間内」

実施方法:
  ├─ ペルソナ定義の文書から「セグメント B に飲食店を追加した日」を抽出
  ├─ 月次ペルソナ更新（段階 9）の実施記録（例: `ペルソナ更新_20261005.md`）で追加日を確認
  ├─ 新規ユーザー属性の変化を検出した日 ≤ ペルソナ追加日 ≤ その月の月末
  └─ 上記が成立 → グリーン
```

### テスト 4-2: 新規セグメントが検出されたが、ペルソナ追加が遅延

```
入力:
  新しい層（飲食店）の検出: 2026-09-20
  月次ペルソナ更新実施記録: 2026-09-30「セグメント B に飲食店層を追加」
  現在（2026-10-05）も、飲食店層向けのジャーニーマップ・施策がない

期待値:
  ⚠️ 項目 5: グリーン = +10 点（追加は済み）／ 項目 6: レッド = -5 点（施策化が遅延）
  「ペルソナ追加: OK / 施策化: NG」

実施方法:
  ├─ セグメント B の飲食店層のペルソナ定義（属性・ニーズ・決定トリガー）が存在するか確認
  ├─ 飲食店層向けの施策（段階 7 の「施策実装タイムライン」）が記録されているか確認
  └─ 施策記録がない → 「ペルソナ追加後、施策化へ進んでいない」を検出
     └─ 対応: 3 名体制での「飲食店層向け施策検討」を即座に開始
```

## テストケース 5: フィードバックループの発動と完了追跡

**目的**: KPI 未達成時に「ループ発動 → 再リサーチ → 新施策実装」が実行されているか確認

### テスト 5-1: ループが正常に発動・進行している

```
入力:
  施策: 「LINE 登録後の初回メッセージ改善」
  第 1 ループ期間: D ~ D + 30 日（日付は相対表記。D = 第 1 ループの開始日）
  第 1 ループ結果: ❌ KPI 未達成（CV 数 5 件 < 目標 20 件）
  
  ループ発動記録: D + 30 日「フィードバックループ開始」
    ├─ 段階 1: 再ヒアリング（D + 31 日）→ 「最初のメッセージが長くて読まない」という声確認
    ├─ 段階 2: ジャーニーマップ更新（D + 35 日）
    ├─ 段階 4: ユーザーテスト再実施（D + 37 日）
    └─ 段階 7: 新施策「締切の近い制度だけを短く先に届ける」の実装決定（D + 40 日）
  
  第 2 ループ期間: D + 51 日 ~ D + 82 日（進行中）

期待値:
  ✅ グリーン（正常）「項目 7: グリーン = +10 点」「ループ 1 → ループ 2 への移行が確認できた」

実施方法:
  ├─ フィードバックループの記録（施策名と開始日で探す）を確認
  ├─ 第 1 ループが KPI 未達成で終了し、「発動」記録があるか確認
  ├─ 段階 1～10 のいずれかが進行中（または完了）記録があるか確認
  ├─ 第 2 ループが新施策を持って開始されているか確認
  └─ 上記が全て確認できたら → グリーン（ループが正常に回っている）
```

### テスト 5-2: ループが発動されたが、段階が途中で停止している

```
入力:
  施策: 「補助金検索 UI 改善」
  第 1 ループ期間: D ~ D + 29 日（日付は相対表記。D = 第 1 ループの開始日）
  第 1 ループ結果: ❌ KPI 未達成

  ループ発動: D + 29 日
    ├─ 段階 1: 再ヒアリング（D + 31 日 実施）→ 完了
    ├─ 段階 2: ジャーニーマップ更新（実施なし）← ⚠️ 停止
    └─ 段階 3～10: 未開始

  現在日: D + 36 日（5 日停止）

期待値:
  ❌ レッド（ループが停止）「項目 7: レッド = -5 点」「ループ進行: 段階 1 で停止」

実施方法:
  ├─ ループ記録の「最後の実施日」を確認
  ├─ 現在日 - 最後の実施日を計算
  ├─ 3 日以上停止している → 「ループが停滞」フラグを立てる
  └─ 対応: ループの「次の段階」を確認し、責任者に期限を再設定させる
```

## テスト実行スケジュール

| 実行タイミング | テストケース | 実施者 | 備考 |
|---|---|---|---|
| **月次（毎月末）** | 1・4・6（ローカル検証） | 統括 + 部門長 | 月末ペルソナ更新時に同時実施 |
| **施策実装時** | 2-1・2-2 | 施策責任者 | 施策記録テンプレートで手動確認 |
| **施策検証期限時** | 2-3 | 検証責任者 | 検証レポートで手動確認 |
| **現場から違和感報告あり** | 3 全般 | リサーチ担当 | 報告受け取り時に即座に追跡開始 |
| **KPI 未達成時** | 5 全般 | フィードバックループ責任者 | ループ発動と段階進行を記録 |
| **ペルソナ鮮度アラート時** | 1・6 全般 | 統括 | 期限切迫時に通知発出 |

## テスト記録テンプレート

テスト実行時に、以下の記録を残す（置き場所は運用で決める）：

```markdown
# user-research-hojo テスト実行記録 — YYYY-MM-DD

**実行者**: 統括 + 各部門長
```
