# Humanizer(AIっぽさを消す仕上げチェック)

このリポジトリの対外文面(SNS投稿・LINE配信・サイトコピー・お知らせ)を書き終えた/
直し終えた最後に必ず通す仕上げスキル。CLAUDE.md(または相当する憲法ファイル)の
トーン指定を実現するための最終チェックとして使う。専門的な話を、読み手が
「自分ごと」として読める、あたたかく自然な日本語に仕上げる。

> ALLGROUP共通スキル(hojo-hqを本店として複数リポジトリで共有)。特定事業名を
> 主語にせず「このリポジトリ」で書くこと。

**直接依存**: shiryo-sakusei, educational-content-design, note編集部(content)

- 戻り値の構造変更

**本番前テスト**: 下流スキル(特にshiryo-sakusei)を実際に実行して、異なる結果が出ないことを確認必須。

## AIっぽさのサイン(見つけたら直す)

- 定型の書き出し: 「〜って知っていましたか?」「実は、」「今回は〜についてご紹介します」
- 定型の締め: 「ぜひチェックしてみてください!」「お気軽にご相談ください!」を毎回同じ形で使う
- 箇条書きの多用・見出しの機械的な三段構成(結論→理由→まとめ)をSNS投稿にまで持ち込む
- 絵文字・「!」の過剰な連打、意味のない強調(**太字**の多用)
- 「〜と言えるでしょう」「〜かもしれません」など、断定を避ける曖昧な語尾の連発
- ダッシュ(—)や「まさに」「そんな」といった、話し言葉では使わない書き言葉的な接続
- 情報を全部盛り込もうとして一文が長くなる、または逆に短文を機械的に並べる

## 5ステップ手順

### Step 1: テキスト分析（AI生成感の検知）

**目的**: テキスト全体から「AI生成のサイン」を見つけ出す

**検証メソッド**:
1. 声に出して読む（読みにくい・不自然な箇所を探す）
2. 上記「AIっぽさのサイン」リストと照らし合わせる
3. 問題の種類をメモする（定型フレーズ / 語尾の曖昧性 / 一文が長い など）

**OK判定**: AI生成特有の定型感が感じられない、読んで自然に入ってくる

### Step 2: 文体統一（敬語・口調のバランス）

**目的**: 敬語レベル・話し口調の一貫性を確保し、ブレを除く

**検証メソッド**:
1. テキスト内で敬語のレベルが混在していないか確認（例：「です・ます」と「だ」の混在）
2. カジュアル（SNS）か丁寧（公式サイト）か、想定読者に合わせたトーンを統一
3. 段落ごとに文体が一貫しているか確認

**OK判定**: 全文を通じて敬語レベル・文体が統一されている

### Step 3: 句読点・改行の最適化

**目的**: 文の流れ・リズムを整え、読みやすさを向上させる

**検証メソッド**:
1. 一文の長さが極端でないか確認（目安：40字～60字程度）
2. 句点(。)の位置で自然に一呼吸置けるか確認
3. 段落の区切りが論理的か確認（関連する内容ごとに1段落）
4. 改行が多すぎて「スマホ対応」という名目の見出し乱立になっていないか確認

**OK判定**: テンポよく、かつ意味の区切りが明確に読める

### Step 4: 表現の洗練・具体化

**目的**: 定型フレーズを置き換え、固有性・説得力を高める

**検証メソッド**:
1. 「〜と言えるでしょう」「〜かもしれません」など曖昧な語尾を確認し、根拠があれば断定に
2. 「ぜひチェック」「お気軽に」など汎用フレーズを、コンテキストに合わせた具体的な表現に置き換え
3. 絵文字・太字・感嘆符が本当に必要か確認（目安：1件当たり1個まで）
4. 体言止め・問いかけなど、語尾のバリエーションを混ぜているか確認

**OK判定**: 文体が生き生きしている、「人の声」が聞こえる

### Step 5: 出力確認（自然さの最終確認）

**目的**: 全体として「人が書いた」自然な文になっているか、最終判定を行う

**検証メソッド**:
1. **事実情報の正確性**: 締切・金額・要件など数値・ルール表現が元テキストと一致しているか確認
2. **CV導線の保全**: CV(コンバージョン導線)が曖昧になっていないか、定義済みの中間リンク経由か確認
3. **トーン一貫性**: 想定読者(経営者/生活者)に「自分ごと」として届いているか、もう一度読み返す
4. **代替表現の自然さ**: 置き換えた表現が文脈に合っているか、作為的でないか最終確認

**OK判定**: 「この情報、誰かが実際に教えてくれているような」感覚で読める

## 旧チェック手順(互換性のため参照)

以下は上記5ステップの簡潔版。既存ワークフローで参照されている場合の後方互換性のため記載:

1. 声に出して読んで、不自然に感じる箇所(人が実際にはこう言わない、という箇所)を探す
2. 上記の定型フレーズ・締めが使われていないか確認し、使われていたら具体的な言い回しに置き換える
3. 一文の長さ・語尾にばらつきを持たせる(全部「です・ます」で終わらせない、体言止めや問いかけを混ぜる)
4. 絵文字・強調は本当に必要な1箇所だけに絞る
5. **締切・金額・要件など事実情報は書き換えの過程で変えない**(このリポジトリに
   正確性チェック系・締切表現ルール系のスキルがあれば、それらと矛盾していないか
   最後に必ず確認する)

## やってはいけないこと

- 自然さを優先して、このリポジトリの数値・ルール表現を崩す(「要確認」表示を外す、など)
- 事実確認済みの数値・表現を、語感を良くするために変更する
- CV導線を曖昧にしない: このリポジトリで定められたCV(コンバージョン導線)を崩さない
  (例: 登録リンクの直貼り禁止・計測用の中間リンク経由が定められていれば、それに従う)

## 検証失敗時（よくある問題と対処）

### 問題1: テキストがまだAI生成っぽく感じる

**症状**: 5ステップを通したのに、どこか定型的・機械的に聞こえる

**原因候補**:
- 定型フレーズの置き換えが不完全（「申請することをお勧めします」など、別の定型フレーズに置き換えただけ）
- 語尾が単調（「〜です」「〜ます」が連続している）
- 具体性が足りない（「自社に合った」など、抽象的な修飾語が残っている）

**対処方法**:
1. Step 1 に戻り、「AIっぽさのサイン」をもう一度細かくチェック
2. 定型フレーズ→具体的表現の置き換えを、段落ごとに再確認
3. 語尾を意図的に変える（「〜ます」→「〜んです」→「〜ですよ」など、バリエーションを持たせる）
4. 数字・固有名詞・具体例を足し、より「実感」のある文に
5. 誰かに「この文、人が書いてるっぽく聞こえる？」と読んでもらう

### 問題2: 過度に親近感を出してしまった（カジュアルすぎる）

**症状**: 公式サイトやLINE公式の文章なのに、友達トークのようになっている

**原因候補**:
- Step 2 で敬語レベルを「カジュアル」に統一しすぎた
- 絵文字や「ですよ」「んです」の多用
- 文法的に崩れている（ひらがなが多い、助詞が曖昧、など）

**対処方法**:
1. Step 2 に戻り、想定読者・使用場面を再確認（例：LINE公式は「親しみやすい丁寧」が目安）
2. 敬語レベルの基準を決め直す（「です・ます」をベースに、適切な箇所で「ですよ」を混ぜる、など）
3. 絵文字の数を数える（1段落1個以下が目安）
4. 「親近感」と「信頼感」のバランスを意識
5. 公式文面として読んだときの「品位」を再確認

### 問題3: 意味が歪んでしまった（本来の情報が変わった）

**症状**: 人間らしく書き直したら、元の意図が変わってしまった

**原因候補**:
- Step 4 で具体的表現に置き換える際、ニュアンスをズラしてしまった
- 曖昧さを「避ける」ために、逆に誤った断定をしてしまった
- 制度の説明が、置き換え過程で簡潔になりすぎて誤解を招いている

**対処方法**:
1. Step 5 に戻り、「事実情報の正確性」を元のテキストと逐一突き合わせる
2. 置き換えた表現が元の意味を保持しているか、第三者に読んでもらう
3. **原文を読まずに、書き直したテキストだけで内容が正確に伝わるか確認**
4. 不安な箇所は「要確認」に戻すか、原文へのリンクを併記する
5. 正確さが優先される情報（締切・金額・資格要件）は、一文ごとに原文を照合
