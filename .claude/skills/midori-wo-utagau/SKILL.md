# 緑を疑う — 動いているつもりで動いていないものを見つける

## これは何か

実際に起きた事故から作った**点検の型**です。どれも共通点が1つあります。

> **緑だった。エラーも出ていなかった。でも、何も起きていなかった。**

毎朝の催促が2か月ぶん1件も届いていなかった。移設したはずの資料が公開のまま残っていた。
検査を足したのに1行も拾えていなかった。相手はとっくに返事をしていた。
どれも**誰も嘘をついていない**のに、現実とずれていました。

人間もモデルも、**「異常が見えないこと」を「正常」と読み替えます**。
その読み替えだけを、ここで止めます。

## 使いどころ

- 定期ジョブ・自動化を作る/直す/レビューするとき
- 検査・バリデーション・ガードを足すとき
- 「設定したのに反映されない」「通知が来ない」「残っているはずがないのに残っている」の調査
- **完了を報告するとき**(いちばん事故る)
- 他チーム・他チャットへ依頼や回答を渡すとき、秘密を受け渡すとき

---

## 1. 黙って通るものを疑う

**「見えない」は「無い」ではありません。**

- **知らないことを、許可と読み替えない。** 値が返ってこなかった = わからない、であって「やってよい」ではない。
  可否を問い合わせて返事が無いなら、**やらない**側に倒す
- **エラーを空の値に変換しない。** `except: return []` は、失敗を「0件」に化けさせます。
  **別の型で落とす**(例外・専用のエラー値)。0件と失敗が同じ見た目になった瞬間、以後ずっと区別できません
- **沈黙を緑にしない。** 0件は結論ではなく、**疑うきっかけ**です。
  「0件でした」と報告する前に、**0件になる経路を1つ以上実際に通して**から言う
- **部分的な取得で、全体の不在を結論しない。** 一覧を取る呼び方と、中身まで取る呼び方は別物です。
  「コメントが見当たらない」は「返事が無い」ではなく「**その呼び方では見えない**」かもしれません

> 実例: 課題の本文だけ返る読み方で取得し、コメントが見えないことから「返事が無い」と判断して催促を送った。
> 相手は**丸一日前に答えて実装まで終えて**いた。同じ日に、別件でも同じことをしていた。

**言い換えの型**: 「〜が無い」と書きたくなったら、「**〜では見えない**」に書き換えて、
見える呼び方を1つ試してから結論する。

## 2. 検査が効いているかを疑う

**足した検査の多くは、最初は効いていません。**

- **検査を書いたら、わざと壊して落ちることを確かめる。**
  通ることの確認は、検査が空振りでも通ります。**落ちることの確認だけが、効いている証拠**です
- **期待値を実装で作らない。** 実装から期待値を生成すると、両方同時にずれて、誰も気づけません
- **文章で守るルールは、いつか誰かが破る。** 規約・手引き・コメントは守られません。
  守りたいなら**検査で落とす**
- **「いつも通る道」しか通っていない経路は、未検証と同じ。**
  条件分岐・失敗時の処理・空のときの処理は、**毎回素通りしていても緑**です。
  通っていない分岐の一覧を持ち、**通っていないことを毎回表に出す**
- **検査を足したら、まず実物にかけて件数を書く。**
  きっかけが1件でも、実物では桁が違うことがあります。**体験の数ではなく、実測の数で判断する**

> 実例: 「同じ依頼が2度来た」という1件から検査を書いたら、実物では**6件**あった。
> 別の日、公開してはいけない資料5件から走査を始めたら、**68か所**で見つかった。
> 「1件だけだから仕組みは大げさ」と判断していたら、残りは見つからなかった。

> 実例: 検査そのものを正規表現で書いたら、**対象を1つも拾えず丸ごと空振り**していた。
> 自己点検が捕まえた。構造のあるもの(YAML・JSON・HTML)を正規表現で読むと、まず間違える。

## 3. 報告と文書が嘘をつくのを疑う

**書いた時点では本当でも、黙って嘘になります。**

- **完了報告に実測を添える。** 件数・終了コード・ログの1行・指紋。
  **実測なき完了報告は無効**とみなす
- **実測を貼ったら、「いつの・どの版か」の印を添える。**
  貼ったあとに中身を直すと、**書いた本人も気づかないまま嘘になります**
- **できないことを、できるように見せない。** 受け取るが守れない項目、押せるが何も起きないボタン、
  「対応予定」とだけ書かれた欄。**作った側は分かっていても、使う側には区別がつきません**
- **置き場所と、届け方は別。** 「保存しました」は保存の話で、**相手が読めるかの話ではありません**。
  報告には**どこに置いたか**と**どうやって読めるか**を両方書く

> 実例: 「非公開側に置きました」と何度も報告していたが、相手の画面からは**そのリポジトリが開けなかった**。
> 置き場所としては正しく、しかし**1つも読まれていなかった**。

**報告の型**:

```
やったこと: <何を>
実測:       <件数 / exit code / ログの1行>
置いた場所: <どこに>
読み方:     <相手がどうすれば読めるか>
できていないこと: <隠さずに1行>
```

## 4. 人の手数が残っていないかを疑う

**手数が残っている工程は、そこで止まります。相手が怠けているのではありません。**

- **配る手順を書いたら、空のディレクトリで一度そのとおりにやる。**
  書いた本人の環境には、手順に書き忘れた物がすでに置いてあります
- **覚えておく運用にしない。** 「コミット前に必ず〜する」は守られません。機械に止めさせる
- **手数を減らしたら、「片付ける手数」も一緒に減らす。**
  依頼を出しやすくしても、完了を記録する手数が残っていれば、そこが新しい詰まりになります
- **秘密の受け渡しは、人の手数を1回にする。値を運ばせない。**
  貼る→設定する→試す→結果を報告する、と手数が残ると、渡しても止まります。
  **1回入れたら、あとは機械が試して結果まで出す**形にする
- **秘密は、ログに出ない渡し方だけを使う。**
  実行するコマンドの文字列に直接埋め込むと、展開後の文字列が渡り、**ログに値そのものが出ます**。
  環境変数など、伏せられる経路で渡す

> 実例: 「値を渡すだけ」が9日間止まった。渡す相手が忙しかったからではなく、
> 渡したあとに**4手**残っていたから。しかも実行環境が使い捨てで、入れても次に消えた。

## 5. 相手待ちを疑う

**「相手待ち」と書いてあるものの何割かは、相手に届いていません。**

- **相手が読める場所に出ていない依頼は、「待ち」ではありません。** 待っても永久に返事は来ません
- 依頼には**出した場所**を必ず持たせ、**場所の無い「待ち」を検査で落とす**
- 催促する前に、**もう返事が来ていないか**を確かめる。
  確かめずに催促すると、答えてくれた相手に失礼になります
- 催促は**短く、聞くことを1つに**。長い依頼は読まれません

> 実例: 「相手待ち」8件のうち**6件**が、相手の読める場所に出ていなかった。
> 同じ日、こちらが長文で出した回答には1件も返事が来ず、再送されてきた。

## 点検のやり方(短い版)

何かを「できています」と言う前に、この5つを順に当てる:

1. **緑の理由を言えるか。** 「エラーが出ていない」以外の根拠があるか
2. **落ちることを見たか。** わざと壊して、検査・通知・ガードが実際に落ちるのを見たか
3. **実測を貼れるか。** 件数・終了コード・ログの1行
4. **相手は読めるか。** 置いた場所ではなく、**相手の手元から読めるか**
5. **残った手数は何手か。** 1手でなければ、そこで止まると考える

どれか1つでも「たぶん」が混じったら、**そこがまだ動いていない**と考えて確かめる。

## よくある「静かな失敗」の原因(当てはめる先)

点検の型だけでは手が止まるので、**実際に多い原因**を挙げます。
上の5つを当てるとき、ここから探すと早いです。

**失敗が「0件」に化ける**
- 広い `try/except` や `except: pass`、`|| true`、`continue-on-error`、`set -e` の無いシェル
- 権限不足(403)を握りつぶして空を返す。**権限は足りた日にしか試されない**
- 一覧だけ取る呼び方を使い、中身まで取る呼び方と取り違えている
- ページングの1ページ目しか見ていない

**入力が死んでいるのに正常終了**
- 認証・トークンの失効、ラベル名や項目名の変更、問い合わせ範囲の条件ずれ
- **対象件数をログに出していない**ので、0件なのか取れていないのか区別できない

**判定が常に同じ側に倒れている**
- 日付の起算・閾値の単位や符号の間違いで、条件が永久に成立しない
- タイムゾーン(UTC/現地)のずれ。日付をまたぐ処理は毎日1回ずれる
- 「既存があれば作らない」の判定が常に真になり、何も作られない

**出口が塞がっている**
- 通知・課題の作成に要る権限が無い
- 送り先が変わっている、宛先が空のまま
- **作られてはいるが、誰も見ていない場所に出ている**

**どれを疑うか迷ったら**: まず**対象件数をログに出す**。
0件なのか取れていないのかが分かれば、残りの切り分けはすぐ進みます。

## この型を使うときの注意

- **全部に当てるとコストが見合いません。** 不可逆なもの(公開・削除・外部送信・本番設定)と、
  **誰も見ていないまま動き続けるもの**(定期ジョブ・自動化)に絞ると効きます
- **赤にしすぎない。** 「まだ条件が揃っていない」ことまで赤にすると、
  **赤が当たり前になって誰も見なくなります**。条件待ちは「見送り」で緑のまま、
  本当の異常だけを赤にする
