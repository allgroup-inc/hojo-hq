# Figma でデザイン（UI/UX）— hojo-hq 専用版

## 使うべきタイミング

🟠 **新規 LP を作りたい**
  └─ ミカタの診断ツール、もらいわすれ堂のランディングページ

🟠 **診断結果や LINE で見せる画面を改善したい**
  └─ ミカタの診断結果画面（Web）、もらいわすれ堂の LINE リッチメニュー（`site/fukugiiro/assets/line-richmenu.png`）

🟠 **既存 LP が『使いづらい』と言われた**
  └─ LINE 部・提携部に届いた声や問い合わせの『違和感』を形にする

🟠 **プレゼン資料をスライド化したい**
  └─ スライドのレイアウト・図解をビジュアル化

## Stage 1: ワイヤーフレーム（情報の配置）

Figma を開く前に、『誰に何を伝えるのか』を紙で整理する。

### **テンプレート（ミカタ LP の例）**

```
対象ペルソナ: 沖縄の 50 代経営者（補助金初心者）
目的: 「診断ツールまで進ませる」
離脱ポイント: 「何をすればいいか分からない」

ワイヤーフレーム:

┌─────────────────────────────┐
│ ヘッダー                     │
├─────────────────────────────┤
│                             │
│ [ビジュアル大きく]          │
│ 「こんな企業が対象」         │
│ + イメージ画像              │
│                             │
├─────────────────────────────┤
│ セクション 1: なぜ補助金？   │
│ • テキスト + アイコン 3 個   │
├─────────────────────────────┤
│ セクション 2: あなたは対象？ │
│ 📊 診断ボタン（大きく）     │
│ 「30 秒で分かります」       │
├─────────────────────────────┤
│ セクション 3: 診断後は？     │
│ • 士業紹介                  │
│ • 締切アラート              │
│ • よくある質問              │
├─────────────────────────────┤
│ CTA: LINE 登録              │
│ 「無料で受け取る」          │
└─────────────────────────────┘

配置の原則:
  • 「何を訴えたいのか」を一番上に（大きく、シンプルに）
  • セクションごとに『問い → 答え』の構造
  • ボタンは右側（スマホだと下）に
  • 色は最小限（ネイビー + オレンジだけ）
```

## Stage 2: Figma での実装（コンポーネント化）

### **準備**

1. **プロジェクト作成**: 事業ごとにチームプロジェクトを分けて作成（名前は運用で決める。ミカタともらいわすれ堂を同じファイルに混ぜない）
2. **フレーム設定**:
   ```
   Desktop (1440px 幅)
   Tablet (768px 幅)
   Mobile (375px 幅)
   ```
3. **コンポーネントライブラリ**:
   ```
   buttons/ (CTA・サブ・テキストリンク)
   typography/ (見出し・本文・注釈)
   cards/ (情報カード・リスト項目)
   colors/ （ブランドカラー）
   ```

### **ルール**

✅ **毎回ここを確認**:
```
□ ブランドカラー（design-system-hojo）が正しいか
  └─ ミカタ = ネイビー #00335C + オレンジ #F88800
  
□ フォント（Noto Sans JP）が適用されているか
  └─ 見出し: 24px bold
  └─ 本文: 16px regular
  └─ 注釈: 12px regular
  
□ 余白がテンプレ感を出していないか
  └─ 全セクション同じ余白 NG
  └─ セクションごとに微調整 OK
  
□ このボタンは『何を促したい』のか言えるか
  └─ CTA（LINE 登録）= オレンジ、大きく
  └─ サブボタン（詳しく見る）= グレー、小さく
```

## Stage 3: 現場の『違和感』をデザインに落とし込む

### **例：診断結果画面を見直すときの観点（想定の練習問題）**

> これは練習用の**仮定の画面**で、今の `site/index.html` の診断結果画面のことではない。
> 今の結果画面には、結果のすぐ後に LINE 登録の案内（`result-line-cta`）がすでにある。
> 実際に直すときは、まず今の画面を開いて確かめてから Before を書く（想像で Before を書かない）。

現場の声（LINE 部・提携部に届いた声の想定。実際に使うときは聞き取りの記録に置き換える）:
```
「診断で『対象かも』と出たのに、次に何をすればいいか分からなかった」
「締切と金額がどこに書いてあるのか、スマホだと探しにくい」
```

デザイン改善（仮定の画面で考える練習）:
```
❌ Before（仮定）: もし結果画面が次のようだったら
  • 制度名が並ぶだけで、締切・上限額が本文に埋もれている
  • 次の一歩（LINE 登録）の案内が、結果から離れた場所にしかない
  → 「自分は何をすればいいか」が分からず、そのまま閉じてしまう

✅ After（考え方）:
  • 制度ごとに「締切・上限額・原文リンク」を 1 枚のカードにまとめる
  • 不明な項目は「要確認」と表示し、断定しない（hojo-accuracy-check）
  • 結果の直後に「締切の約1か月前からお知らせを受け取る（LINE）」案内を置く
    （今のページの `result-line-cta` と同じ考え方）
  • 文字サイズ・タッチターゲットは Stage 5 の基準（16px 推奨・44px 以上）
  → 結果を見た流れのまま、次の一歩（LINE 登録）に進める
```

user-research-hojo の「例 1」「離脱ポイント分析」と同じ場面。聞き取り → デザインの順で使う。

## Stage 4: カラー・配置・アニメーション（テンプレ感を消す）

### **NG パターン**

❌ 全ページ同じテンプレ:
```
┌─────────────────┐
│ ヘッダー         │
├─────────────────┤
│ [画像]          │
│ テキスト         │
│ ボタン          │
├─────────────────┤
│ [画像]          │
│ テキスト         │
│ ボタン          │
└─────────────────┘
← 単調、見た人が「どこが重要なのか」分からない
```

### **OK パターン（ミカタ LP の例）**

✅ セクションごとに強調を変える:
```
■ Hero セクション（一番重要）
  色が濃い（ネイビー背景）
  テキスト: 大きく（48px）
  ビジュアル: 占有率 60%

■ 説明セクション（次に重要）
  色が薄い（白 + アイコン 3 つ）
  テキスト: 中程度（20px）
  アイコン：色付き（オレンジ）

■ 診断セクション（アクション）
  背景: 薄いオレンジ
  ボタン: オレンジ（強調）
  テキスト: 「30 秒で分かります」

■ よくある質問（補足）
  背景: 白
  テキスト: 小さい（14px）
  色: グレー

← 『何が重要か』を色と大きさで表現
```

## Stage 5: モバイル最適化

### **チェックリスト**

```
□ 縦 375px で読めるか
  └─ 文字が 14px 以下は読みづらい（16px 推奨）

□ タッチターゲットが 44px 以上か
  └─ ボタン・リンクは最小 44×44px

□ 横スクロールが発生していないか
  └─ 画像・テーブルが 375px を超えていないか確認

□ 色だけで情報を伝えていないか
  └─ 「赤いボタン = エラー」だけでなく、テキストも付ける
  └─ 色覚障害への対応

□ 1 画面に情報が詰まりすぎていないか
  └─ セクションごとに余白で区切る
```

## Stage 6: プロトタイプ・ユーザーテスト

### **簡易テスト（3 人 × 5 分）**

```
対象: 実際の利用者（ミカタなら県内の経営者、もらいわすれ堂なら県民の方）

手順:
  1. Figma デザインを見せる（説明なし）
  2. 「このページで、何ができると思いますか？」と聞く
  3. 「どこをクリックしますか？」と聞く
  4. 違和感があれば、それを記録

テスト結果の例:
  フィードバック: 「診断ボタンが見つからない」
  改善: オレンジのボタンをさらに大きく、上に配置
```

---

## Stage 7: デザインの完成チェック

```
□ ブランドガイドに従っているか
  ├─ 色: design-system-hojo で指定された色か
  ├─ フォント: Noto Sans JP か
  └─ トーン: ペルソナに合った親しみやすさか

□ 情報が正確か（shiryo-sakusei の確認）
  └─ 締切・金額に出典 URL が付いているか
  └─ 不明な情報は「要確認」と書いているか

□ 個人情報が入っていないか
  └─ 顧客氏名・連絡先は入っていないか

□ アクセシビリティ
  └─ 色覚障害者でも分かるか（色以外に情報を付ける）
  └─ キーボード操作で全機能にアクセスできるか（Web の場合）

□ パフォーマンス
  └─ 画像サイズは圧縮済みか（hojo-lighthouse-triage で確認）
```
