# Figma でデザイン（UI/UX）— hojo-hq 専用版

## 使うべきタイミング

🟠 **新規 LP を作りたい**
  └─ ミカタの診断ツール、もらいわすれ堂のランディングページ

🟠 **アプリ UI を改善したい**
  └─ KAKEHASHI の営業マン向けアプリ画面

🟠 **既存 LP が『使いづらい』と言われた**
  └─ 営業やカスタマーサポートからの『違和感』を形にする

🟠 **プレゼン資料をスライド化したい**
  └─ スライドのレイアウト・図解をビジュアル化

## Stage 1: ワイヤーフレーム（情報の配置）

Figma を開く前に、『誰に何を伝えるのか』を紙で整理する。

### **テンプレート（ミカタ LP の例）**

```
対象ペルソナ: 沖縄の 50 代経営者（補助金初心者）
目的: 「診断ツールまで進ませる」
離脱ポイント: 「何をすればいいか分からない」

ワイヤーフレーム:

┌─────────────────────────────┐
│ ヘッダー                     │
├─────────────────────────────┤
│                             │
│ [ビジュアル大きく]          │
│ 「こんな企業が対象」         │
│ + イメージ画像              │
│                             │
├─────────────────────────────┤
│ セクション 1: なぜ補助金？   │
│ • テキスト + アイコン 3 個   │
├─────────────────────────────┤
│ セクション 2: あなたは対象？ │
│ 📊 診断ボタン（大きく）     │
│ 「60 秒で分かります」       │
├─────────────────────────────┤
│ セクション 3: 診断後は？     │
│ • 士業紹介                  │
│ • 締切アラート              │
│ • よくある質問              │
├─────────────────────────────┤
│ CTA: LINE 登録              │
│ 「無料で受け取る」          │
└─────────────────────────────┘

配置の原則:
  • 「何を訴えたいのか」を一番上に（大きく、シンプルに）
  • セクションごとに『問い → 答え』の構造
  • ボタンは右側（スマホだと下）に
  • 色は最小限（ネイビー + オレンジだけ）
```

## Stage 2: Figma での実装（コンポーネント化）

### **準備**

1. **プロジェクト作成**: `hojo-hq-デザイン` というチームプロジェクトで作成
2. **フレーム設定**:
   ```
   Desktop (1440px 幅)
   Tablet (768px 幅)
   Mobile (375px 幅)
   ```
3. **コンポーネントライブラリ**:
   ```
   buttons/ (CTA・サブ・テキストリンク)
   typography/ (見出し・本文・注釈)
   cards/ (情報カード・リスト項目)
   colors/ （ブランドカラー）
   ```

### **ルール**

✅ **毎回ここを確認**:
```
□ ブランドカラー（design-system-hojo）が正しいか
  └─ ミカタ = ネイビー #00335C + オレンジ #F88800
  
□ フォント（Noto Sans JP）が適用されているか
  └─ 見出し: 24px bold
  └─ 本文: 16px regular
  └─ 注釈: 12px regular
  
□ 余白がテンプレ感を出していないか
  └─ 全セクション同じ余白 NG
  └─ セクションごとに微調整 OK
  
□ このボタンは『何を促したい』のか言えるか
  └─ CTA（LINE 登録）= オレンジ、大きく
  └─ サブボタン（詳しく見る）= グレー、小さく
```

## Stage 3: 営業からの『違和感』をデザインに落とし込む

### **例：KAKEHASHI アプリの改善**

営業フィードバック:
```
「アプリは使えるが、経営者に見せるのが恥ずかしい」
理由: 「デスク向けで、対面で見せにくい」
```

デザイン改善:
```
❌ Before（デスク最適化）:
  • 画面幅: 1200px
  • 文字サイズ: 12px
  • ボタン: 20px
  → 対面で見せると、字が小さすぎて読めない

✅ After（対面プレゼン最適化）:
  • 画面幅: 375px（スマホサイズ）
  • 文字サイズ: 16px（読みやすい）
  • ボタン: 48px（触りやすい）
  • タッチターゲット: 最小 44px（Apple ガイドライン）
  → 経営者が自分でスワイプできる、親友感
```

## Stage 4: カラー・配置・アニメーション（テンプレ感を消す）

### **NG パターン**

❌ 全ページ同じテンプレ:
```
┌─────────────────┐
│ ヘッダー         │
├─────────────────┤
│ [画像]          │
│ テキスト         │
│ ボタン          │
├─────────────────┤
│ [画像]          │
│ テキスト         │
│ ボタン          │
└─────────────────┘
← 単調、見た人が「どこが重要なのか」分からない
```

### **OK パターン（ミカタ LP の例）**

✅ セクションごとに強調を変える:
```
■ Hero セクション（一番重要）
  色が濃い（ネイビー背景）
  テキスト: 大きく（48px）
  ビジュアル: 占有率 60%

■ 説明セクション（次に重要）
  色が薄い（白 + アイコン 3 つ）
  テキスト: 中程度（20px）
  アイコン：色付き（オレンジ）

■ 診断セクション（アクション）
  背景: 薄いオレンジ
  ボタン: オレンジ（強調）
  テキスト: 「60 秒で分かります」

■ よくある質問（補足）
  背景: 白
  テキスト: 小さい（14px）
  色: グレー

← 『何が重要か』を色と大きさで表現
```

## Stage 5: モバイル最適化

### **チェックリスト**

```
□ 縦 375px で読めるか
  └─ 文字が 14px 以下は読みづらい（16px 推奨）

□ タッチターゲットが 44px 以上か
  └─ ボタン・リンクは最小 44×44px

□ 横スクロールが発生していないか
  └─ 画像・テーブルが 375px を超えていないか確認

□ 色だけで情報を伝えていないか
  └─ 「赤いボタン = エラー」だけでなく、テキストも付ける
  └─ 色覚障害への対応

□ 1 画面に情報が詰まりすぎていないか
  └─ セクションごとに余白で区切る
```

## Stage 6: プロトタイプ・ユーザーテスト

### **簡易テスト（3 人 × 5 分）**

```
対象: 実際の顧客（ミカタなら経営者、KAKEHASHI なら営業マン）

手順:
  1. Figma デザインを見せる（説明なし）
  2. 「このサイト・アプリで、何ができると思いますか？」と聞く
  3. 「どこをクリックしますか？」と聞く
  4. 違和感があれば、それを記録

テスト結果の例:
  フィードバック: 「診断ボタンが見つからない」
  改善: オレンジのボタンをさらに大きく、上に配置
```

## Stage 7: デザインの完成チェック

```
□ ブランドガイドに従っているか
  ├─ 色: design-system-hojo で指定された色か
  ├─ フォント: Noto Sans JP か
  └─ トーン: ペルソナに合った親しみやすさか

□ 情報が正確か（shiryo-sakusei の確認）
  └─ 締切・金額に出典 URL が付いているか
  └─ 不明な情報は「要確認」と書いているか

□ 個人情報が入っていないか
  └─ 顧客氏名・連絡先は入っていないか

□ アクセシビリティ
  └─ 色覚障害者でも分かるか（色以外に情報を付ける）
  └─ キーボード操作で全機能にアクセスできるか（Web の場合）

□ パフォーマンス
  └─ 画像サイズは圧縮済みか（lighthouse-triage で確認）
```
