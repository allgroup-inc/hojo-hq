# KGI→KSF→KPI→Actionの逆算チェーン

目標が「宣言」で終わらず、実際に達成される確率を上げるための考え方。
最終ゴール(KGI)から逆算して、成功のカギ(KSF)・測る数値(KPI)・具体的行動(Action)
まで一本の線でつなぐ。どこか1つでも欠けると、目標は「言っただけ」になる。

## 4つの用語

| 用語 | 定義 | 問い |
|---|---|---|
| **KGI**(重要目標達成指標) | 最終的に達成したいゴール(結果) | どこを目指すのか? |
| **KSF**(重要成功要因) | KGIを達成するために特に重要となる要因 | 達成するために何が重要か? |
| **KPI**(重要業績評価指標) | KSFの達成度を測り、KGIに近づいているかを数値で把握する指標 | 進捗を何で測るのか? |
| **Action**(具体的行動) | KPIを改善するために取るべき具体的な行動・施策 | 具体的に何をするのか? |

## 逆算の流れ

```
KGI(最終ゴール、例: 年間売上1億円)
  ↓ 「これを達成するために特に重要なことは何か」
KSF(成功のカギ、例: 新規顧客の獲得力を高める)
  ↓ 「その達成度をどう数値で測るか」
KPI(進捗指標、例: 商談件数42件/月・成約率20%・平均単価100万円)
  ↓ 「その数値を改善するために何をするか」
Action(具体的行動、例: 新規架電・セミナー集客・提案力強化)
```

## 必ずやること: 数式で辻褄を確認する

KPIを並べただけで満足しない。**KPIを掛け合わせるとKGIの数字に戻るか**を検算する。

例: 商談件数42件/月 × 成約率20% × 平均単価100万円 × 12ヶ月 = 1億円(KGI)

辻褄が合わなければ、どこかのKPIの見積もりが甘いか、KSFの選定自体が間違っている。
「KPIは決めたが、それを全部達成してもKGIに届かない」という状態を防ぐための最重要ステップ。

このリポジトリの例: CLAUDE.mdの「KGI / KPI」節(LINE登録1,000社 → チャネル別内訳 →
月次マイルストーン → 支持KPI)は、この逆算チェーンを実際に適用した形。新しく目標を
立てる/見直すときは、まずそこを読んで同じ粒度感を掴む。

## 使うタイミング

- **新規設計**: 新しいプロジェクト・事業・機能の目標を立てるとき。KGIだけ決めて満足せず、
  KSF→KPI→Actionまで一気通貫で作る
- **既存の点検**: 「目標は掲げているが進んでいる実感がない」ときに、どの段が抜けているか
  診断する。よくある欠落パターン:
  - KGIはあるがKSF/KPIが無い → 何をすればいいか誰も分からない
  - KPIはあるがKGIと数式的につながっていない → 全部達成してもゴールに届かない
  - Actionはあるが対応するKPIが無い → 忙しいだけで進捗が測れない
  - KPIを達成しているのにKGIに近づいていない → KSFの選定自体が的外れ

## 8ステップの設定・見直し手順

### 初期設定フェーズ（初回実施）

**Step 1: KGIの設定と妥当性検査**
- KGIを1つに絞る(複数あると優先順位が曖昧になる。複数事業がある場合は事業ごとに1つ)
- 形式: 「数値・期限・具体的結果」の3点が揃っているか確認
- 例: ✓「沖縄企業LINE登録1,000社（12ヶ月）」/ ✗「会員を増やす」
- 記録場所: CLAUDE.md の「KGI / KPI」節など、対外文書に明記

**Step 2: KSF（重要成功要因）の抽出**
- KGIを達成するために「特に重要な要因」を2〜3個に絞る
- 逆問い: 「これが無かったら KGI は達成できないか？」で検証
- 例：沖縄企業のミカタの場合：
  - KSF①: LINE登録チャネルの確保（既存顧客基盤・SNS・紹介等）
  - KSF②: 出口（士業送客・GLOW接続）への相談転換

**Step 3: KPI（進捗指標）の決定と数式設定**
- 各KSFに対応するKPIを、測定可能な数値で設定
- **KPI は「数式で組み立てられる」形に揃える** 
- 形式: KPI = 「何をカウントするか」+ 「達成基準の値」+ 「計測期間」
- 例:
  - LINE登録数: 月20社/週（KGI 1,000社 ÷ 12ヶ月 ÷ 4.3週）
  - チャネル別内訳: 既存顧客300社 + SNS300社 + 紹介200社 + その他200社
  - 出口転換: 相談・面談月10件（LINE5件 + 提携5件）

**Step 4: 数式検算（必須・最重要）**
- KPIを掛け合わせて/積み上げて、KGIの数字に一致するか確認
- 失敗パターン: 「KPI達成しているのに KGI に近づかない」
- 例: 月20社 × 12ヶ月 = 240社 → KGI 1,000社に届かない ⇒ 数式見直し
- **数式が合わなければ、KSF選定か KPI値を修正** して2〜3に戻る
- 検算シート（Excel等）を作成し、毎月の実績を入れたときに計算が自動で更新されることを確認

**Step 5: アクション（行動施策）の具体化**
- 各KPIを改善するために「誰が・いつ・何をするか」を記載
- 曖昧な言葉（「頑張る」「強化する」）を避け、実行可能な粒度で記述
- 例: ✓「毎週火曜のSNS投稿で新制度3件掲載」 / ✗「SNS発信を強化」

### 運用フェーズ（初期設定後）

**Step 6: マイルストーン（中間目標）の設置**
- 3ヶ月・6ヶ月・9ヶ月・12ヶ月時点での目標値を設定
- 形式: 各チャネルの登録数（月別累積）と出口転換の月ペース
- 例（沖縄企業のミカタ）:
  - 3ヶ月: 100社 / 6ヶ月: 300社 / 9ヶ月: 600社 / 12ヶ月: 1,000社
- **記録場所**: CLAUDE.md や計測ダッシュボードに明記
- **見直し期限**: マイルストーン日付が過去になったら自動で再議論

**Step 7: 月次見直し（定期実施）**
- 実績値を検算シートに入力
- KPI達成度をチェック: 「計画値 vs 実績値」の乖離を分析
- **KGI進捗 vs KPI達成の対照**: 「KPI達成しているのに KGI が進まない」場合は KSF が的外れ
- 例:
  - LINE登録は月20社達成 ⇒ ✓KPI達成
  - ただし出口転換が月5件（目標10件） ⇒ 「KPI達成しても KGI に貢献しない」
  - **根本原因**: KSF「出口転換率」の見積もりが甘い ⇒ KSF妥当性診断へ
- 三名体制(スイシン・ウタガイ・ベッカイ)で議論し、改善案を決定

**Step 8: KSF妥当性診断（月次見直しの一部）**
- 「KPI達成してもKGIに近づかない」ケースを検出
- 診断フロー:
  1. 計算式で「KPI達成値を入れるとKGIがいくつになるか」を逆算
  2. 実際の KGI 進捗と比較
  3. 乖離が大きい場合: **KSF の前提が間違っている** と判定
- 改善案: KSF を見直すか、KPI値の根拠（競争力、市場規模等）を再検証
- 見直し期限（最長6ヶ月）を設定し、期限切れは自動で再議論

## 失敗パターン（検出・回避法）

検出可能な失敗パターンを5つ挙げます。いずれも月次見直しで機械的に検査できます。

| 失敗パターン | 症状 | 検出方法 | 回避法 |
|---|---|---|---|
| **①KSF見誤り** | KPI達成しているのに KGI に近づかない | 計算式で KPI値→KGI進捗 を逆算し、実績と対照 | Step 8: KSF妥当性診断で月次検証。3役で根本原因を議論 |
| **②マイルストーン見直し遅延** | 「12ヶ月1,000社」目標だったが、6ヶ月後に古い数字で判定 | マイルストーン日付が本日より過去か確認。過去なら自動で再議論フラグ | 見直し期限を CLAUDE.md や計測ダッシュボードに**明示**。期限切れは自動チェック対象に |
| **③数式不一致** | KPI A×B×C を掛け合わせても KGI に一致しない。達成判定が月によって変わる | 検算シート(Excel等)を毎月実行。KPI実績値を入れて自動計算し、KGI予測値を確認 | Step 4 で「数式が立つ」まで繰り返し。KPI の根拠(顧客数・成約率・単価等)を明記 |
| **④チャネル別KPI報告漏れ** | 全体「月10件」目標だが、LINE部5件の内訳が報告されない。誰が何をしているか不透明 | 月次レポで「LINE部 vs 提携部」の分解を必須項目化。どちらかが報告無い = NG | 各チャネルの **責任部門を明確化**。週次レポで内訳を別欄に（例: docs/統合週次レポ.md §チャネル別進捗）|
| **⑤見直し期限切れ** | 「2026年7月に KPI を決めたが、2026年9月にも同じ値で動いている」 →市場変化・競争激化に追従できない | CLAUDE.md 等で **見直し期限（最長6ヶ月）を明記**。毎月末に自動チェックし、期限切れ案件を一覧化 | 決定文書に `見直し期限: 2026-11-06` と記載。期限切れ時は自動で三名体制議論を開始 |

## ローカル検証テスト

月次見直しの前に、以下の検査を実施（データ鮮度チェック・数式妥当性等）。

### 検算テスト（毎月実施）

```python
# テスト例: 沖縄企業のミカタ KGI/KPI
KGI_monthly = 1000 / 12  # 月当たり目標 ~83社/月

# チャネル別内訳の検算
channel_targets = {
    "existing": 300,     # 既存顧客基盤
    "sns": 300,          # Instagram→サイト→LINE
    "referral": 200,     # 士業・商工会・金融機関
    "organic": 200       # 検索・その他
}
kpi_total = sum(channel_targets.values())  # 1000 == KGI?
assert kpi_total == 1000, f"チャネル内訳の合算が KGI と一致: {kpi_total} != 1000"

# 出口転換の検算
exit_line = 5    # LINE部月当たり
exit_partner = 5  # 提携部月当たり
exit_total = exit_line + exit_partner  # 10 == KPI?
assert exit_total == 10, f"出口転換内訳が KPI と一致: {exit_total} != 10"

# 月別マイルストーン検査
milestones = {
    3: 100,
    6: 300,
    9: 600,
    12: 1000
}
for month, target in milestones.items():
    expected = KGI_monthly * month
    assert target >= expected * 0.9, f"月{month}: 目標{target} は月当たり{expected}より現実的か"
```

### マイルストーン日付検査

```python
from datetime import datetime, timedelta

# マイルストーン設定例
milestones_with_dates = {
    "3ヶ月": {"date": "2026-12-XX", "target": 100},
    "6ヶ月": {"date": "2027-03-XX", "target": 300},
    "9ヶ月": {"date": "2027-06-XX", "target": 600},
    "12ヶ月": {"date": "2027-09-XX", "target": 1000},
}

today = datetime.now()
for label, data in milestones_with_dates.items():
    m_date = datetime.fromisoformat(data["date"])
    is_past = m_date < today
    
    if is_past:
        print(f"⚠️  {label} ({data['date']}) は本日より過去。再議論が必要")
    else:
        days_remaining = (m_date - today).days
        print(f"✓ {label}: 残り{days_remaining}日（目標{data['target']}）")
```

### KSF妥当性テスト

```python
# KPI達成が KGI進捗に反映されているか確認
def validate_ksf():
    """
    「KPI達成してもKGIに近づかない」を検出
    → KSF選定が的外れ、または KPI値の根拠が甘い
    """
    
    # 実績例: 当月
    actual_line_registrations = 22  # 月20社目標 → 達成
    actual_exit_conversions = 4     # 月10件目標 → 未達
    
    # KPI達成判定
    kpi_registrations_ok = actual_line_registrations >= 20
    kpi_exit_ok = actual_exit_conversions >= 10
    
    # KGI進捗への寄与（12ヶ月累積で1000社・月10件相談に向かうか）
    cumulative_12m = actual_line_registrations * 12  # 264社
    kgi_on_track = cumulative_12m >= 1000
    
    # 失敗パターン: ①KPI達成しているのに②KGIに進まない
    if kpi_registrations_ok and not kgi_on_track:
        print("⚠️  失敗パターン①: LINE登録は達成しているが、KGI(1000社)に届かない")
        print("→ KSF見誤り: LINE登録数以外の要因（チャネル多様性・質）が不足している")
        print("→ 改善: 既存顧客・SNS・紹介の内訳を再分析")
        return False
    
    # 失敗パターン②: 出口転換が進まない
    if not kpi_exit_ok:
        print("⚠️  失敗パターン②: 出口転換（相談月10件）が進まない")
        print("→ KSF見誤り: 「LINE登録数」だけでなく「登録者の質（事業規模・融資ニーズ）」が重要")
        print("→ 改善: 診断ツール・AI スクリーニング・リード配信の見直し")
        return False
    
    print("✓ KSF妥当性: KPI達成が KGI進捗に反映されている")
    return True
```

## 気をつけること

- KSF・KPIを一度決めたら固定せず、実績に応じて見直す(このリポジトリに三名体制
  レビューの仕組みがあれば、そこで定期的に検証する)
- 「頑張る」「強化する」のような曖昧な言葉をActionに残さない。誰が読んでも同じ行動を
  取れる粒度まで具体化する
- KGIを短期間で達成不能な水準に設定しない。逆算した結果、Actionの量が現実的な体制
  (人数・時間)を超えるなら、KGI自体か期間を見直す
- **最終根拠は数式**。KPI値を決めるときは「なぜこの数字か」の根拠（市場規模、競争力、
  過去実績）を明記。根拠無い数値は後で「達成不可能」と判定されやすい
