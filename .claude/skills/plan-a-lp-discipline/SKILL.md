# Plan A LP の規律(2026-10-02 制定)

Plan A は実績ゼロから第1期を集める段階にある。だから信用の芯は「派手な成果」ではなく
「正直さと費用の全開示」。このスキルは、その芯を文面・資料・計測の全部で崩さないためのもの。
根拠と経緯: `docs/Plan A LP_構成設計書v2_20261001.md`(付録A・B)/ `docs/議事/議事_20261001_Plan A LP構成v2.md`

## 1. 書く前に読む(3分)
- `docs/Plan A LP_構成設計書v2_20261001.md` §0〜§5(構成・コピー・計測)と 付録B-7(v1の主張→推奨表現の対応表)
- `docs/Plan A LP_公開前チェックリストv2_20261002.md`(未確定項目の現在地)
- 実装: `site/go/plan-a/index.html`(A案)/ `site/go/plan-a/sns/index.html`(B案)/ `site/go/plan-a/scripts.js`

## 2. 事実と表現のルール(理由つき)
| ルール | 理由 |
|---|---|
| 数字は出所URLと「◯年◯月時点」を付けたものだけ書く。無いなら書かない | 景表法の不実証広告規制(15日以内に根拠提出)。1つ崩れると全部疑われる |
| 架空の人物・体験談・事例は「イメージです」と添えても載せない | 消費者庁の考え方では体験談の演出は不当表示。写真の演出とは別物 |
| 「売上◯倍」「97%があなたの利益」など成果・利益の約束を書かない | 根拠が無く、利益は送料・関税で変わる。脚注「売上や受注を保証するものではありません」を必ず置く |
| 取引保護は「Alibaba.comの取引保護サービス(Trade Assurance)に対応」。「認定」「GLOWが保証」とは書かない | 認定制度ではなく、買い手を守る決済サービス。手数料は支払額の4%・上限100米ドル(b2b-manual.alibaba.co.jp/ta-09) |
| 「あなたのバーチャルブース/ストア」と書かない。「GLOWの店に、あなたの商品を掲載」 | Alibaba.comの規約上、他社商品は会員(GLOW)名義で、生産者の販売許諾書が要る |
| 「Alibaba.com公式パートナー」「沖縄県支援事業」は契約・採択通知が無い限り書かない | 商標・公的事業名の誤認 |
| 県・JETROの無料支援を悪く言わない。「相談で終わらず、代わりにやる」で差を出す | 県との関係と守り部の方針。補助金はむしろPlan Aの味方にする |
| 「できないこと」(植物検疫に通らない生鮮・輸出規制品・成果の約束)を必ず1段置く | 過大約束の防止。正直さ自体が差別化 |
| 未確定の数字・条件は `<span class="todo">【要決裁】</span>` `【要確認】` で見える形で残す。消して埋めない | 公開前に grep で0件にする運用。黙って仮の数字を入れると後で誰も気づけない |

## 3. 導線と計測のルール
- CTAはLINE1本。資料・説明会はLINEの中で渡す。メール・電話フォームは小柳さん決裁と議事が無い限り置かない(CV単一ルール)
- LINEへのリンクは `/go/plan-a-line/` 経由(lin.ee 直貼り禁止)。イベントは `plan_a_line_redirect`(channel=plan-a-line)で、既定の `line_redirect` を使わない。使うとミカタのLINE登録1,000社(KGI)に混ざる
- ページ内イベントは `plan_a_view`(variant=a|b)と `plan_a_cta_click`(position=hero|final|sticky)だけ。クリックと完了(相談・契約)を同じ名前で数えない
- 個人情報はイベントに乗せない

## 4. 文体
- 中学生が読める日本語。専門語(RFQ・ゴールドサプライヤー・インコタームズ)は訳す
- 1文1義、「必ず」「絶対」「No.1」なし。humanizer を最後に通す
- 見出しは願望と事実から入り、「1万円」「Plan A」で始めない(相手はまだ手段を知らない段階)

## 5. 公開までの手順(順番を守る)
1. 文面を書く/直す → `python3 scripts/shipping_gate.py --check-group lp` を通す(HTML末尾のコメントに `## 出荷ゲート` の記録を更新)
2. `grep -c "要決裁\|要確認\|要作成" site/go/plan-a/index.html site/go/plan-a/sns/index.html` が 0 0 になるまで、チェックリストv2 §2 の根拠集めと決裁を回す
3. 守り部・検証部が付録A/Bの出所URLを実機で開いて照合(この環境では直接取得できない前提で作ったため)
4. noindex を外す → `.github/workflows/update.yml` の除外2行(`go/plan-a`, `go/plan-a-line`)を外す → Lighthouse実測 → 小柳さんの公開判定
5. 公開後は `docs/Plan A_運用台帳_20261002.xlsx` の週次KPIに実数だけを記録(推測値禁止)

## 6. 変えてよいもの・だめなもの
- 変えてよい: 見出しの言い回し、段の順番(生産者10人のテスト結果で)、FAQの中身、写真
- 議事と決裁が要る: 費用条件、保証、募集数、CV導線の追加、イベント名、公開範囲
