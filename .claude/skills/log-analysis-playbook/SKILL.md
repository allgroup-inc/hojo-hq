# ログ分析プレイブック（事業非依存の標準型）

出典: あいおい生命CC事業（callcenter-hq）で2026-07〜08に実証。
通話ログ19,527件・録音21本から月次サイクル一式を構築した際の「考え方」を汎用化した。
**他のログシステムへ連動するには: このスキルをコピー → §Dの対応表を自事業の言葉で埋める → ツールを対応させる。**

## A. 分析の考え方（8つの型）

1. **取込の関門**: 生データはまずバリデータを通す（列構成・既知カテゴリ・未知値率で fail-fast）。
   「黙って誤集計」が最大の敵。フォーマット変化で止まるのは正しい挙動。
2. **定義は推測せず確認**: ステータス・フラグの意味は現場/オーナーに確認してから集計する。
   （実例: 「現アナ」をアポと誤解釈→提出数字の訂正になった。確認1つで防げた）
   確定した定義は「オーナー確認済み・日付つき」でスキル/定義書に記録し、二度と迷わない。
3. **ファネル分解**: 活動→接触→合意→履行→成果 の段に分け、各段を**率＋実数＋分母**で表す。
   分母違いの率を同じ名前で並べない（同一語3分母は誤読のもと）。母数30未満は自動で参考値フラグ。
4. **個人×行動の帰属**: 記録（メモ・履歴）から個人単位の行動を復元する。ただし
   **記録規律の個人差＝計器の歪み**を必ず併記する（記録が多い人が「悪い」に見える逆転に注意）。
5. **無駄の金額化**: 成果ゼロが確定している宛先への活動（欠番・拒否済み等）を単価×件数で金額にする。
   仮定単価は前提として明示し「機会費用でありキャッシュ削減ではない」と必ず注記。交渉材料に最も効く。
6. **収穫逓減と打ち切りルール**: 試行回数別の成果累積を出し、「N回で◯%出尽くす」から
   打ち切り・休眠・復活条件を決める（実例: アポの98.7%は6回以内→6回ルール。外部研究とも一致）。
7. **状態遷移と再訪スコア**: 顧客ごとの状態履歴（不通→会話→保留→成果/離脱）を復元し、
   「どの断りなら追ってよいか」を反転率で類型別にスコア化する。追う/条件付き/休眠の3分類。
8. **前月比の作法**: 定点指標を固定し、データ品質欄（記録率・不明率・表記ゆれ件数）を併記。
   数値の変化が「行動の変化」か「記録・定義の変化」かを常に区別する。

## B. 教育の考え方（積み上げ型）

1. **レポート構成は必ずこの順**: ①全体傾向 → ②個人ごと（一覧表→個人カード）→
   ③まとめ（良い人の共通要素→全員に配る知識・アクション）→ ④お客様が動いた言葉（実録・匿名）。
2. **文体はダメ出し禁止**: ×「記載率が低い」→ ○「◯◯の型を真似ると伸びる」。
   弱点は必ず**学び先（その指標がチームで最も良い人）とセット**で書く。
   全指標が良い人には「型を言語化して配る側」という次の役割を渡す（No.1は参考、No.2が教科書）。
3. **教材は実例から作る**: 成功した実際の言葉・記録を匿名化して類型にする（創作しない）。
   転換の共通構造を抽出する（実例: 否定しない→知識を1つ→選択の自由を返す）。
4. **個人主軸の画面**: 本人の今期数字＋過去推移＋TOPとの距離バー＋「どうすれば近づけるか」の
   具体アクション。全体（ALL）と個人は別画面。従業員配布版では他者比較を外す。
5. **賞賛の仕組み**: 成果にならなくても顧客に感謝された接触を「成果」として掲載する
   （ありがとうピックアップ）。従業員の誇りと経営の確信の両方に効く。
6. **効果検証とセット**: 教育施策は必ず「翌期のどの行動指標で確認するか」を決めてから配る。
   AIの分類は人間判定との一致率80%を超えるまで「仮判定」表示（評価に単独使用しない）。

## C. 顧客分析の考え方

1. **属性×成果クロス**: 年代・性別・チャネル・既存関係の有無ごとの成果率で「狙うべき相手」を特定。
   相関であって因果ではないと明記し、翌期に再現するか検証する。
2. **断り/離脱の類型化**: 断り文句を類型辞書にし、類型ごとに対応（標準の返し・追跡可否）を決める。
3. **守りの予兆辞書**: 強い離脱（拒否・ブロック・苦情）に至った顧客の直前記録から予兆表現を逆引きし、
   リスク倍率つきで「次の接触を止める」判断材料にする。禁止台帳＋誤接触ゼロ照合を毎期自動で回す。
4. **再訪資産**: 断られても感謝で終わった接触・時期が悪かっただけの接触を名簿化し、
   再訪の名分（記念日・更新月など）とセットで温存する。断り＝失敗ではなく資産。

## D. 他システムへの連動手順（このスキルをコピーした先で埋める）

### 1) 概念の対応表を埋める（これが移植の核。30分で書ける）

| 汎用概念 | CC事業での実体 | ←自事業では何か |
|---|---|---|
| 活動イベント | 架電1回（メモ1行） | 例: 商談/来店対応/配信1通 |
| 接触（キャッチ） | 通電・本人会話 | 例: ブース着席/既読・返信 |
| 合意（中間成果） | アポ（面談了承） | 例: 見積依頼/診断予約 |
| 履行→最終成果 | 訪問→申込 | 例: 来店→成約 |
| 断り/離脱 | NG・着信拒否 | 例: 断り・ブロック・退店 |
| 個人の帰属 | メモ行末の架電者名 | 例: 担当者ID・投稿者 |
| 品質メモ指標 | 候補日/時間帯/既加入の記載率 | 例: 次回約束/予算/家族構成の記録率 |
| 打ち切り閾値 | 6回ルール | 実測の累積カーブから自事業値を出す |

### 2) ツールの役割対応（callcenter-hq/tools/ が参照実装）

validate_input（関門）→ ingest（正規化・匿名化抽出）→ operator_analysis＋scorecard（個人）→
customer_analysis（顧客属性）→ transition/recall（遷移・再訪）→ guard_audit（守り・台帳）→
cost_analysis（無駄の金額化）→ build_dashboard（経営版/従業員版の2系統）。
列名・カテゴリ辞書を自事業に差し替えるのが移植作業の実体。

### 3) 安全の型は必ず一緒に移植する（削らない）

- 個人情報の原本は git 管理外の隔離フォルダのみ・コミット前PIIガード・外部送信ゼロ（分析はローカル）
- 出力の匿名化 2層（外部提出用=匿名ID／内部育成用=実名可はアクセス制御された環境のみ）
- 誇張禁止（率は実数+分母）・機械分類は仮判定表示・「遅延は許す、虚偽は許さない」

### 4) 立ち上げの順番（実証済みの最短ルート）

初月: 関門→取込→ファネル→個人一覧（ここまでで提出物になる）
→ 2ヶ月目: 前月比＋教育資料＋守りの台帳 → 3ヶ月目: 打ち切りルール・A/B等の施策検証。
最初から全部を作らない。「届いたら2営業日で返す」リズムの確立を最優先する。
