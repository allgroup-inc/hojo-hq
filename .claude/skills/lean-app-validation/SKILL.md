# 小さく検証してから作る(1%戦略・レビュー起点・作る前にマーケ)

新しいアプリ・ツール・デジタル商品を作るとき、思いつきで作り始めると大抵中途半端に終わる。
**「新しいアイデアを発明する」のではなく「既に需要がある場所の、わずかなシェアを取りに行く」**
という考え方で、作る前に検証する。

## 核心の考え方

1. **新しいアイデアはいらない**: 巨大市場×1%を狙う×小さく勝つ。伸びている市場・企業を
   見つけ、そのごく一部のシェアを取りにいく方が、ゼロから市場を作るより成功確率が高い
2. **競合が多い=需要がある証拠**: 「似たアプリがあるからやめる」ではなく「似たアプリが
   ある=需要が確実にある市場」と捉える。App Store/類似サービスの検索で確認する
3. **価値は誰の悩みを解決するかだ**: アイデアそのものより、既存の不満(悩み)ベースで
   開発する方が当たる確率が高い
4. **すべてをやろうとしない**: 見つけた不満のうち、最も多い1つだけに絞って徹底的に
   改善する。全部解決しようとすると、どれも中途半端になる

## 手順

### 1. アイデアを探す(発明しない、見つける)
- SNS(TikTok/Instagram/X)でトレンド・話題をチェック(このリポジトリに`last30days`
  スキルがあれば、そちらでより体系的にできる)
- 伸びている巨大市場・企業を見つける(派手な市場は競争が激しいが、地味な市場
  (税金・法務・行政等の実務系)は競争が少なく需要が大きいことがある)

### 2. 需要を検証する(作る前に確認する)
- 見つけたトレンド・領域で、類似サービス/アプリが既に存在するか検索する
- 存在する = 需要が確実にある市場(むしろ好材料)
- 存在しない = 慎重に。本当に需要があるか、単に誰もやっていないだけかを見極める

### 3. 不満(レビュー)から改善点を見つける
- 既存サービスのレビュー、特に**低評価レビュー**を読む(改善のヒントが集まっている)
- 見るべき観点: 何に困っているか / 欲しい機能は何か / 使い方が分かりにくい箇所はどこか
- レビューサイト・コミュニティ(Discord等)・SNSの声・問い合わせ内容も同様に集める
- 集めた不満をAI(Claude)に読ませ、改善アイデアに変換する。このとき事実(実際の
  レビュー内容)を誇張・捏造しない(このリポジトリに正確性チェック系スキルがあれば、
  その考え方をここにも適用する)

### 4. 作る前にマーケする(価値提案を先に決める)
- 作り始める前に「3秒で伝わる価値」を1文で決める
- 可能であれば、Coming Soon的な告知(価値提案+待機リスト)で先に反応を見て、
  「売れると確信してから作る」を徹底する。作ってから売るのは順序が逆
- このリポジトリに`copywriting`スキルがあれば、価値提案の言語化に使う

### 5. 小さく作って高速で回す
- MVPは最小限の機能で素早く作る(バックエンドを除けば数時間〜数日が目安)
- 完璧を目指さず、まず世に出す。データとフィードバックが次の改善を作る
- 集客は無料チャネル優先(SNS投稿・コミュニティでの価値提供・SEO等)から始め、
  UGC(ユーザー生成コンテンツ)で勝ちパターンを見つけてから、広告費を使う判断をする。
  勝った素材だけを広告化し、ROAS(広告費用対効果)が良い間だけ予算を拡大する
- サイクル: アイデア→開発→集客→改善、を高速で回し続けることが継続的成長の鍵

## 気をつけること

- 「あれもこれも作りたくなる病」に注意する。新しいアイデアに次々飛びつくより、
  1つに集中して伸ばす方が成果が出る(複数同時着手して全部中途半端、という失敗パターン
  が典型)
- レビュー・不満を集める際、実在しない声を作らない。集めた事実だけを根拠にする
- 「作ってから売る」ための遠回りをしない。先に需要の手応えを得てから作り込む
