# リスクモデルの品質ゲート(正確性最優先・断定しない)

早期解約リスクの数字は、現場の保全判断と営業の評価に直結する。当たらないモデルや過信を招く表示は、
CLAUDE.md 憲法の「正確性最優先」「断定しない」に反する事故になる。数字を出す前に必ずこのゲートを通す。

## 絶対ルール

1. **バックテストのゲート**: 学習したモデルは、過去データのバックテスト(AUC・上位リフト・予測/実績の較正)で妥当性を確認してから使う。**AUCが0.5付近なら"当たっていない"→本番投入しない**。当たらないまま一覧・カルテ・保全指示に流さない。
2. **断定しない表示**: 表示するリスク%は `score.display_pct` で `[0.1, 99.0]` にクランプし、**100%・0%という"確定"表現を出さない**(モデル内部の生の値は保持する)。
3. **少件数は参考**: 母数が `MIN_RELIABLE_N` 未満の要因・集計・効果測定は「参考(母数不足)」と明示する。3件で「高リスク断定」しない。
4. **学習と採点の集合を混ぜない**: 学習(fit)は**成熟した実績のみ**(6ヶ月以上経過 or 6ヶ月以内解約が確定)。まだ6ヶ月経っていない継続中を「解約しなかった」に数えない。採点(score)の対象は**継続中・6ヶ月未満**(これから手を打てる先)。
5. **業務値の閾値は勝手に変えない**: リスク帯(`BAND_HIGH_MULT` 等)・スムージング・放置日数などの業務パラメータは小柳さんの決裁事項。テストを通すためだけに定数を書き換えない(合わないのはデータ側=テスト・母集団を疑う)。

## チェック手順(数字を出す・モデルを更新する前に)

1. 学習に使う集合が `is_resolved`(成熟実績)のみになっているか確認する。未成熟が母数に混じっていないか。
2. モデルを更新したら、まず `backtest` を回して AUC・上位リフト・予測/実績の乖離を見る。AUC≈0.5なら本番に出さず、要因・データ量・掛け合わせを見直す。
3. 表示%が `display_pct` を通っているか(100/0が出ていないか)確認する。カルテ・一覧・カードの全出力で。
4. 母数の少ない要因・営業マン別・効果測定に「参考」表示が付いているか確認する。
5. 閾値・定数を変える必要が出たら、その是非を三名体制(`hojo-triangle-review`)で議事化し、小柳さんの決裁に上げる。勝手に変えない。

## やってはいけないこと

- バックテスト未通過(または AUC≈0.5)のモデルを一覧・カルテ・保全指示に流す。
- リスク%を「100%解約する」等の断定形で見せる。
- 少件数の解約率を根拠のように断定表示する(特に営業マン別)。
- テストを緑にするために業務パラメータ(帯・スムージング等)を無断で書き換える。
