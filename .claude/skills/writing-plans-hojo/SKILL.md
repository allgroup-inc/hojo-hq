# 構成設計・ナラティブ（プレゼン資料）— hojo-hq 専用版

## 原則：「誰が何を決めるのか」から逆算

資料を作る前に、以下 3 つを確認する：

```
1. 「読む人は誰か」
   例: 小柳さん（決裁者）、嶺井さん（営業責任者）、経営者（見込み客）

2. 「その人は何を決めるのか」
   例: 「この提携に乗るか」「今月の広告予算をどう配分するか」

3. 「決断に必要な情報は何か」
   例: 「根拠となる数値」「成功事例」「リスク」
```

これが決まると、構成が自動的に決まる。

---

## 構成タイプ別テンプレート

### **Type A: 決裁資料（小柳さん向け）**

読む人: 決定者（小柳さん）  
決定事項: 「採用 / 不採用 / 保留」

**構成（1 ページ A4 を推奨）**:

```
┌──────────────────────────┐
│ タイトル                  │
│ （決めてほしいこと 1 文） │
└──────────────────────────┘
        ↓
┌──────────────────────────┐
│【決めてほしいこと】       │
│ □ A 案（推奨）           │
│ □ B 案                  │
│ □ C 案                  │
│ □ その他                │
└──────────────────────────┘
        ↓
┌──────────────────────────┐
│【根拠（3 つまで）】       │
│ ✅ 成功事例 / データ       │
│ ✅ コスト・スケジュール    │
│ ✅ リスク・対策           │
└──────────────────────────┘
        ↓
┌──────────────────────────┐
│【次のアクション】         │
│ • 誰が（小柳さん）        │
│ • いつまでに（明日）      │
│ • 何を（決定）           │
└──────────────────────────┘
```

**実例: ミカタ 新機能追加の決裁**

```
【決めてほしいこと】
□ AI 質問機能を追加する（推奨）
□ 次月延期

【根拠】
✅ ユーザーから「診断後の相談先が分からない」との声（5 件/月）
✅ 実装: 2 週間、追加コスト月 5 万円
✅ リスク: AI の誤った回答 → mamori が事前チェック

【決定後】
• 小柳さんが月末までに決定
• 決定後、実装部門へ連携
```

### **Type B: 営業提案資料（見込み客向け）**

読む人: 見込み客（経営者・士業など）  
決定事項: 「提携に乗るか / 契約するか」

**構成**:

```
表紙
  ↓
01. 「こんな課題、ありませんか？」
    └─ 相手の痛点を、相手の言葉で表現
    
02. 「私たちができること」
    └─ 解決策（1-2 つに絞る）
    
03. 「実績・事例」
    └─ 『同じような企業』の成功例（写真・数値）
    
04. 「料金・条件」
    └─ 透明性が信頼につながる
    
05. 「次のステップ」
    └─ 「デモを見ますか」「相談日を決めますか」
```

**実例: ミカタ の士業向け提案資料**

```
表紙: 「沖縄企業のミカタ — 顧問先の補助金情報を自動配信」

01. 課題
    「顧問先が補助金の締切を見落とし、受給機会を失っている」

02. 解決策
    「補助金情報を毎日自動配信 + LINE で締切アラート」
    「貴事務所は『申請サポート』に集中できる」

03. 実績
    「月 252 件の補助金を追跡」
    「導入事務所の紹介件数が平均 3 件/月 増加」

04. 料金
    「初期費用: 0 円」
    「月額: 定額 2 万円（初年度は 1 万円）」

05. 次
    「来月 1 日から試してみませんか」
```

---

### **Type C: 説明資料（顧客向け LP・note など）**

読む人: 一般ユーザー（経営者・県民など）  
決定事項: 「使ってみるか」「登録するか」

**構成**:

```
ビジュアル大きく（何ができるのか一目で）
  ↓
「こんな悩みありますか？」（相手の言葉で）
  ↓
「3 ステップで解決」（シンプルに）
  ↓
「実は簡単」（事例・写真）
  ↓
「今すぐやってみる」（ボタン）
```

**実例: もらいわすれ堂 の LP**

```
Hero: 「あなたが受け取れる給付金を、自動で探す」
      [イメージ画像: 家族が happy]

問題: 「給付金って、複雑で分かりません」
     「もらい忘れている制度、たくさんあります」

解決: 「3 ステップで分かる」
     ① 診断（1 分）
     ② 該当制度を確認
     ③ 受け取り手続き

事例: 「〇〇さんは月 3 万円の給付金を新たに受け取れました」

CTA: 「診断してみる」[LINE で始める]
```

## 構成のチェック（毎回ここを通す）

```
□ 読み手が「何を決めるのか」が 1 文で書いてあるか
  └─ 書いてなければ、資料の目的が曖昧

□ 根拠が「3 つ以下」に絞られているか
  └─ 4 つ以上あると、読み手が迷う

□ 『次のアクション』が『誰が・いつ・何を』で書いてあるか
  └─ 「ご検討ください」「お気軽にお問い合わせ」は NG

□ ページ数は適切か
  └─ 決裁資料: 1 ページ
  └─ 営業提案: 5-8 ページ
  └─ 説明資料（Web）: 1 スクロール = 1 セクション

□ 数値に「出典」が付いているか（shiryo-sakusei）
  └─ 「月 252 件」← 「制度 DB から集計」と書く
```

## ナラティブの工夫（「テンプレ感」を消す）

### **NG パターン**

❌ 「当社は〇〇を提供しています」  
   → 読む人は「でお前の何なんだ」と思う

❌ 「貴社のビジネスを加速させます」  
   → 根拠がない、信じられない

### **OK パターン**

✅ 「あなたの顧問先が、補助金の締切を見落としたことはありませんか」  
   → 相手の痛点から入る、共感

✅ 「導入した 5 事務所の紹介件数が平均 3 件 / 月 増えました」  
   → 数値 + 成功事例で信じられる
