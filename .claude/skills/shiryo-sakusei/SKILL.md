# 資料作成(shiryo-sakusei)

資料は「頼んだ人の記憶」ではなく「読む相手の判断」のために作る。同じ人が同じ内容を
頼んでも、日によって配色・断定表現・構成がブレると、読み手は毎回読み方から学び直す
ことになる。このスキルは、その揺れを止めるための固定の手順。コードは書かない。
実際のファイル生成は既存の形式別スキル(`pptx` `docx` `pdf` `xlsx` `docs`)に任せ、
ここでは「何を・誰に・どの型で・どのゲートを通して」を決める。

## Step 1 — 目的確認とペルソナ決定

### 目的
資料の「読み手」と「読み手が下す判断」を明らかにする。これが決まると、盛る情報の量・トーン・構成が自動的に決まる。

### 実行方法
分からないときだけ、1問にまとめて聞く: **「誰が読んで、何を決める資料ですか?」**

例:
- 嶺井さんが紹介先に渡す提案書 → 読み手=経営者、判断=提携するかどうか
- 小柳さんが採否を決める稟議資料 → 読み手=決裁者、判断=投資・実行・延期の3択
- 士業に提携を打診する提案書 → 読み手=事務所長、判断=手数料・仕組みに納得できるか

会話に既に答えがあるなら聞かずに進む。

### 検証メソッド
- [ ] 読み手が1人(またはグループ)と決まっている
- [ ] その読み手が「何を決める」のかが明確

## Step 2 — 形式選択

### 目的
用途に応じて、最適なファイル形式を選ぶ。形式を決めると、呼ぶスキルと制約が決まる。

### 実行方法
読み手の「その場での編集有無」で判定:

| 用途 | 形式 | 呼ぶスキル | 迷ったときの判断 |
|---|---|---|---|
| 説明・提案・説得(対面や画面共有で見せる) | PowerPoint | `pptx` | プレゼンか、紙で渡すか → スライドなら pptx |
| 報告・稟議・議事・手順(読んで残す) | Word | `docx` | 読み手がコメント・編集したいか → したいなら docx |
| 配布・印刷・添付(改変されず届ける) | PDF | `pdf` | 先方が編集しないなら PDF、元は docx/pptx で OK |
| 数値・一覧・比較(並べ替えて使う) | Excel | `xlsx` | グラフ・ピボット作成が要るか → 要るなら xlsx |
| 共同編集・コメントで育てる下書き | Google Docs | `docs` | ドラフト段階で複数人が触るか → 触るなら docs |

判定フロー:
1. 読み手がその場で編集・並べ替えたいか → YES なら Word/Excel
2. 見せるだけ・改変されたくないか → YES なら PDF/スライド
3. リアルタイム共編集が要るか → YES なら Google Docs

### 検証メソッド
- [ ] 形式が決まっている
- [ ] その形式が読み手の行動に合致している

## Step 3 — ブランド・スタイル適用

### 目的
資料が属する事業のブランドガイドに準拠し、色・フォント・トーンを統一する。異なるブランドの混在は避ける。

### 実行方法
まず事業を特定し、対応するガイドを適用:

| 事業 | ブランド | 配色 | フォント | トーン | ガイド |
|---|---|---|---|---|---|
| 沖縄企業のミカタ(GLOW) | ミカタ | ネイビー#00335C × オレンジ#F88800 | Meiryo(Web: Noto Sans JP) | 専門用語をやさしく翻訳 | CLAUDE.md |
| もらいわすれ堂(フクギイロ) | もらいわすれ堂 | 朱#B9502F × 黄#F2B705、背景#FFFBF4、本文#1F2A2E | 丸ゴシック系 | やさしい日本語・断定しない | docs/もらいわすれ堂_ブランドガイドv1.md |
| 家計のポっ(社内ツール) | 家計のポっ | 黄#F9C93F × 墨#221D11 | — | 社内向け・簡潔 | — |

ない場合の手順:
1. そのリポジトリの CLAUDE.md またはブランドガイド を読む
2. なければ 「配色の指定はありますか」と確認し、勝手に決めない

**絶対ルール**: 別事業の色・名称・ロゴを同じ資料に混ぜない。

### 検証メソッド
- [ ] 事業が特定されている
- [ ] ブランドガイドを読んでいる
- [ ] 指定された配色コード(RGB/#値)を使っている
- [ ] フォント家族が統一されている
- [ ] トーンが事業のものに合致している(例: やさしい日本語、専門用語の翻訳等)

## Step 4 — 品質ゲート実行

### 目的
資料を対外に出す前に、正確性・個人情報・文面・見た目を機械および人間の目で検査し、ルール違反を防ぐ。

### 実行方法
4つのゲートを **この順で** 通す。対外文面(顧客・提携先・県向け)の場合、さらに `shipping_gate.py` で機械検査を実行:

**ゲート 1 — 正確性 (accuracy-check)**
- 締切・金額・要件は原文URLを併記 → 不明なら「要確認」と明記し断定しない(絶対ルール1)
- 数値(件数・達成率・予算)には出典を添える(週次レポ・台帳・原文URL)
- 3つ以上の異なる日付・数値が出てきたら、ダブルチェック(決裁者にも見せる前に)

**ゲート 2 — 個人情報 (PII)**
- 顧客の氏名・連絡先・会社名・個別の相談内容は載せない
- 件数・割合に丸める → 「13社」ではなく「10社以上」「3割超」に
- 載せる必要があるときは資料を **公開リポジトリに置かず受け渡しのみ** にする
- 社員名も不要なら省く(「ツナグさんが対応」→「LINE部が対応」)

**ゲート 3 — 文面 (humanizer)**
- 対外向けの文章(顧客・提携先・県向け)は `humanizer` スキルで仕上げる
- 定型の書き出し・結び・過剰な強調・単調な語尾を除く
- 「〜です。〜です。〜です。」の繰り返しを避ける
- 「ぜひ〜をお願いします」などの定型句を自然な言い方に置き換える

**ゲート 4 — 見た目 (taste)**
- `taste-skill` の考え方で、AIが作りがちなテンプレ感を避ける
- 全部同じ余白・意味のないアイコン・3列カード乱発を避ける
- 1枚1メッセージ、余白で読ませる、強調は最小限に

**ゲート 5 — 対外文面の shipping_gate 検査(自動化)**
- 対外文面を作ったら、以下の禁止表現を **機械が検査** する:
  - 「締切7日前」「7日前に通知」→ NG(CLAUDE.md: 7日前では準備が間に合わない。「約1か月前から」と統一)
  - 「必ずもらえる」「確実に受給」「誰でも申請できます」→ NG(断定表現・絶対ルール1違反)
  - `https://lin.ee/` 直貼り → NG(go-link-discipline: `/go/<チャネル>/` を経由すること)
  - 承継・M&Aへの直接訴求(「後継者のお悩み」「M&A相談」)→ NG(カモフラージュ設計違反)
- 出荷ゲート記録(以下の Markdown)を自動で生成・追記:
  ```
  ## 出荷ゲート
  - gates: accuracy-check, deadline-alert, humanizer
  - checked: 2026-09-30
  - by: scripts/generate_sns.py
  ```

### 検証メソッド
- [ ] accuracy-check: 数値に出典が付いている / 不明なら「要確認」と書いてある
- [ ] PII: 氏名・連絡先・会社名が特定の個人に該当しない
- [ ] humanizer: スキル呼び出し済み / 定型句が削除されている
- [ ] taste: 余白が意図的 / アイコンは意味を持つ
- [ ] shipping_gate: 対外文面なら禁止表現がない / 記録が記載されている

## Step 5 — 出力先と配信フロー確認

### 目的
資料をどこに置き、誰に・どのように渡すかを決める。公開リポジトリと非公開・個別配信の区別を明確にする。

### 実行方法

**出力先の選択**:
1. **公開リポジトリ(hojo-hq等)に置く** → 個人情報・営業数値・顧客接点情報を含まないもののみ
   - 例: 公開LP、掲載制度リスト、ブランドガイド
   - 機密区分は各リポジトリの CLAUDE.md に従う(hojo-hq は PUBLIC)

2. **個別配信のみ(リポジトリに残さない)** → `SendUserFile` を使用
   - 例: 営業数値入りの週次レポ、顧客名入り提案書、金融機関への提携書
   - 受け渡し後、ローカル削除または指定フォルダのみ保管

**配信フロー**:
- 対外文面(SNS・LINE・メール・PDF添付)なら、`shipping_gate.py` を通す
  ```bash
  python scripts/shipping_gate.py --check-group sns   # SNS投稿用
  python scripts/shipping_gate.py --check-group line  # LINE配信用
  python scripts/shipping_gate.py --check-all        # 全チェック
  ```
- NG が出たら、禁止表現を修正してから再度検査

**ファイル名の統一**:
```
<事業>_<内容>_<YYYY-MM-DD>.<拡張子>
```
例:
- `ミカタ_週次レポート_2026-09-21.pptx`
- `もらいわすれ堂_診断結果_2026-09-20.pdf`
- `決裁キュー_2026-09-21.docx`

### 検証メソッド
- [ ] 公開・個別配信の判定が明確
- [ ] 対外文面の場合、shipping_gate を実行している
- [ ] ファイル名が統一形式に従っている

## 実装例

### 例1: SNS投稿をミカタで生成・配信する

**Step 1**: 読み手 = Instagram フォロワー(経営者)、判断 = LINE登録するか

**Step 2**: 形式 = MarkdownファイルをSNS向けに(Instagram キャプション) → スキル呼び出しなし、テキスト生成

**Step 3**: ブランド = ミカタ(ネイビー#00335C × オレンジ#F88800)。ハッシュタグもミカタ規定に従う

**Step 4**: 品質ゲート実行
```python
# 疑似コード: SNS投稿の品質検査フロー
from scripts.shipping_gate import render_stamp, verify

content = """
# 新しい補助金制度が公開されました

沖縄県の企業向け経営サポート補助金。
締切の約1か月前からLINEでお知らせします。

制度詳細: [原文URL]

## 出荷ゲート
{stamp}
""".format(
    stamp=render_stamp(
        by="scripts/generate_sns.py",
        checked="2026-09-30"  # 本日
    )
)

ok, problems, warnings = verify(content, label="posts/launch/補助金.md")
if not ok:
    for p in problems:
        print(f"[NG] {p}")  # 出荷停止
else:
    print("[OK] 禁止表現なし。配信可")
```

**Step 5**: 出力先・配信フロー
- ファイル: `posts/launch/210_新補助金_2026-09-30.md`
- 検査: `python scripts/shipping_gate.py --check-group sns`
- 配信先: Instagram, X (自動投稿ジョブで配信)

## 検証失敗時

### 禁止表現が検知された

**症状**: `shipping_gate.py` が「禁止表現『締切7日前』」を報告

**原因**: CLAUDE.md では「締切7日前は誤り」と明記。7日前では書類・gBizID準備が間に合わない

**修正方法**:
1. 「締切7日前」→ 「締切の約1か月前から」に変更
2. 「7日前に通知」→ 「約1か月前からお知らせ」に変更
3. 再検査: `python scripts/shipping_gate.py posts/line/msg.md`

**参考**: CLAUDE.md 「アラートは締切3層ルール」セクション

### lin.ee 直貼りが検知された

**症状**: `shipping_gate.py` が「禁止表現『https://lin.ee/』」を報告

**原因**: go-link-discipline により、LINE登録には `/go/` パターンを経由する(計測と保守性)

**修正方法**:
1. `https://lin.ee/xxxx` → `/go/line/` に変更
2. `/go/` リンク先は、実装システムで自動的に LINEへ転送
3. 参考: scripts/shipping_gate.py の FORBIDDEN パターン

### PII (個人情報)が残っている

**症状**: 資料に顧客名「○○株式会社」「田中太郎さん」が記載されている

**修正方法**:
1. 個別情報 → 数値・割合に丸める
   - 「田中太郎さんが登録」→ 「新規登録1社」
   - 「○○株式会社」→ 「金融機関向け」(業種単位)
2. 公開リポジトリに置かない → 個別配信のみ
3. Step 4 の PII ゲート を再実行

### ブランド色・フォントが違う

**症状**: ミカタの資料なのに、もらいわすれ堂の黄色が混ざっている

**修正方法**:
1. CLAUDE.md で正しいブランド配色を確認:
   - ミカタ: ネイビー#00335C × オレンジ#F88800
   - もらいわすれ堂: 朱#B9502F × 黄#F2B705
2. 配色パレットを修正(PowerPoint/Wordのテーマカラー)
3. フォントも確認(ミカタ=Meiryo、もらいわすれ堂=丸ゴシック)
4. [オプション] デザイナーに確認

### 禁止表現の誤検知

**症状**: 「要件は必ず原文でご確認ください」が「断定表現『必ず』」として検知された

**原因**: shipping_gate.py のフィルターが過敏(false positive)

**修正方法**: 
1. 検査対象文を確認: 「必ず〜確認」は注意書きで OK → パターン改善待ち
2. 一時的に `--check` を `--check-all` から除外
3. 2026-11-06までに patterns.py を見直す(CLAUDE.md: 「見直し期限」)

## 本番前テスト

対外文面を出す前に、以下の 8 項目を最低限チェック。自動テストも用意:

### テスト 1 — 禁止表現の regex テスト

```python
import re

FORBIDDEN_PATTERNS = [
    r"締切\s*[の]?\s*7\s*日前",
    r"7\s*日前\s*(?:に|から)?\s*(?:お知らせ|通知|アラート)",
    r"必ず\s*(?:もらえ|受け取れ|通り|採択)",
    r"確実に\s*(?:もらえ|受給|採択)",
    r"誰でも\s*(?:もらえ|受け取れ|申請できま)",
    r"https?://lin\.ee/",
]

content = "締切7日前にお知らせします"
for pat in FORBIDDEN_PATTERNS:
    if re.search(pat, content):
        print(f"[NG] 禁止表現マッチ: {pat}")
```

手動チェック項目:
- [ ] 「締切7日前」「7日前に通知」が含まれていない
- [ ] 「必ず」「確実に」「誰でも」による断定がない
- [ ] lin.ee 直貼りが無い(全て /go/ パターン)

### テスト 2 — PII (個人情報) 検知テスト

```python
import re

PII_PATTERNS = [
    r"\d{3}-?\d{4}-?\d{4}",  # 電話番号
    r"[\w\.-]+@[\w\.-]+\.\w+",  # メールアドレス
    r"\d{11}",  # マイナンバー(11桁)
    r"(?:[ァ-ヴー]|[a-zA-Z]){2,}(?:[太郎|花子|田中|山田|佐藤])",  # 人名パターン
]

content = """
新規登録: 田中太郎さん (会社: ABC株式会社)
メール: tanaka@abc.co.jp
"""

for name, pat in [("メール", PII_PATTERNS[1])]:
    if re.search(pat, content):
        print(f"[NG] PII 検知: {name}")
```

手動チェック項目:
- [ ] 顧客の氏名・会社名が特定個人に該当しない

- [ ] 「新規登録3社」(数値)など、件数は丸められている

```python
import os

def validate_output(filepath):
    """生成ファイルの形式と内容をチェック"""
    errors = []
    
    # ファイル名チェック
    basename = os.path.basename(filepath)
    if not re.match(r"[^_]+_[^_]+_\d{4}-\d{2}-\d{2}\.\w+$", basename):
        errors.append(f"ファイル名が形式違反: {basename} (期待: 事業_内容_YYYY-MM-DD.拡張子)")
    
    # ファイルサイズチェック
    size_mb = os.path.getsize(filepath) / (1024 * 1024)
    if size_mb > 50:
        errors.append(f"ファイルサイズが大きすぎる: {size_mb:.1f} MB (推奨: 50MB以下)")
    
    # PowerPoint の場合、ページ数確認
    if filepath.endswith(".pptx"):

    return errors
```
