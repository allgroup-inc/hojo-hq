# 教育コンテンツ設計（hojo-hq 専用版）

## 使うべきタイミング

新人営業を 3 ヶ月で現場レベルに引き上げたい、
または既存営業のスキルばらつきを減らしたい場面で使う。
「AI が作ったみたいな汎用教材」ではなく、
自社の実績・失敗・成功パターンを教材に組み込む。

### 違和感シーン（なぜ既存教材が機能しないのか）

❌ **Before（一般的な営業研修）:**
```
note 記事: 「営業成功の 5 つのステップ」
  1. ヒアリング
  2. ニーズ分析
  3. 提案
  4. 異議処理
  5. クロージング

問題:
  • 「ヒアリング」は何を聞くのか具体的でない
  • 「提案」のフレーズ例がない（実例なし）
  • 「異議処理」の失敗事例がない
  → 新人営業が「わかった気」になるだけで、実際の客先で使えない
  → 3 週間後には全部忘れている

YouTube「営業のコツ 10 分版」
  話者がスーツ姿でスタジオに座り、一般的な話をしている
  → 実例が自社のものではない（他社事例、または架空）
  → 学習者が「これは自分の案件に当てはまるのか」と迷う
  → クリック: 2-3 件（チームの 12 人中）
```

✅ **After（自社実例ベース）:**
```
note 記事: 「『月の支払が心配』と言う顧客に、なぜ『3ヶ月回収』で納得するのか」
  導入: 9 月の営業記録から「月支払が懸念」の顧客 8 件のうち、
        成約が 4 件・失注が 4 件（50% 成約率）

  成功例（実例 1: 9/15 小林さん訪問、45 分、成約）
    営業 B の回答: 「その時点で月々払った分はすぐに返ってきます。
                  つまり 3ヶ月あれば、現在の月支払から回収できる…」
    [実録音声 2:30-3:15 を YouTube に埋め込み]
    
    成功ポイント: 「回収スパン」を明示（定量）+ 「その後 9ヶ月無料」で納得

  失敗例（実例 2: 9/22 佐藤さん訪問、30 分、失注）
    営業 A の返答: 「補償内容が充実しています」
    [実録音声 1:45-2:00 を YouTube に埋め込み]
    
    失敗ポイント: 「補償内容」で止まり、費用対効果を言っていない
                 顧客は「支払が 4,000 円増える」という負の実感だけ残った

  学習チェック:
    Q. あなたが同じ顧客に遭遇したら、何と答えますか?
    → A さんのフレーズ「補償内容が…」か、B さんのフレーズ「3ヶ月回収…」か、
       それとも別の答えか?
    
  実績:
    この記事を見た営業の、1 ヶ月後の「月支払懸念」顧客での成約率:
    71% → 82% 向上

結果:
  • クリック: 48 件（チームの 12 人全員 × 4 回平均視聴）
  • 実際の営業で「3ヶ月回収」フレーズが使われるようになった
  • 新人営業 2 人が 1 週間で「月支払懸念」パターンをマスター
```

## Stage 1: 学習目標の定義（「何ができるようになるのか」を明確に）

### 目標設定のテンプレート（SMART 目標）

```
❌ NG（曖昧）:
  「営業スキルを上げる」
  「提案力を強化する」

✅ OK（SMART）:
  「『月の支払が心配』という顧客の懸念に対して、
   『3ヶ月回収』フレーズを使い、成約率を現在の 50% から
   75% 以上に向上させることができる」

分解:
  S: Specific（具体的）
    → 「月支払懸念」という特定のシーンに限定
  
  M: Measurable（測定可能）
    → 「成約率」という数値で測定（50% → 75%）
  
  A: Achievable（達成可能）
    → 既存の成功事例（営業 B: 4/4 成約）から実現性確認
  
  R: Relevant（関連性）
    → チームの失注理由 TOP3 に「支払への懸念」が 2 位（全失注の 38%）
       → このパターンを解決すれば、月 2-3 件の失注が減る
  
  T: Time-bound（期限付き）
    → 「3 ヶ月以内にマスター」
       （新人営業の定着期間）
```

### 対象別の学習目標

```
セッション A: 新人営業（入社 1-3 ヶ月）
  目標: 「基本フロー（ヒアリング → 提案 → クロージング）を
        実際の顧客で使い、月 3 件の契約を成約できる」
  
  内容:
    • ヒアリングシート の記入例 3 件（成功・失敗・回復）
    • 提案フレーズ（5 パターン × 実録音声）
    • よくある異議への返答 5 パターン
    • 成約までの典型的な通話時間・回数（平均 2 回 / 45 分）

セッション B: 中堅営業（入社 1-2 年）
  目標: 「既存顧客への追加提案（クロスセル）で、
        月 2 件の追加契約を獲得できる」
  
  内容:
    • 既存顧客の分類（単純補償 / 医療重視 / コスト最適化）
    • 各分類別のクロスセル提案フレーズ
    • 断られた後の「2 回目接触」の成功パターン 3 件

セッション C: マネージャー（営業管理責任者）
  目標: 「部下の失注理由を分析し、月 1 回の勉強会で
        チーム全体の成約率を 3% 向上させる」
  
  内容:
    • 月次の失注分析フロー（音声記録 → パターン分類）
    • 部下別の成長ポイント（誰が何を改善すべきか）
    • 反復教材の作成・更新ルール
```

## Stage 2: 素材収集と分類（実例を「型」にする）

### 素材のソース（何から教材を作るのか）

```
ソース 1: 営業の通話記録（最高）
  ├─ Zoom Phone の自動録音
  ├─ 実例を逐語録で確保
  ├─ 感情分析で「成功/失敗」を自動判定
  ├─ 音声をそのまま YouTube に埋め込み（生の説得力）
  └─ 法的確認: mamori.md が必須（顧客同意・個人情報マスク）

ソース 2: 営業マンのテキスト記録（中程度）
  ├─ 顧客訪問後のメモ「懸念は何か」「何で納得したか」
  ├─ Slack の営業チャネルでの「成功共有」
  ├─ 週次レポの「失注理由」
  └─ 問題: 「記憶に基づく」ため、実際と異なることがある
         → 音声記録と照合する（マルチAI連携で検証）

ソース 3: 営業テンプレート・提案資料（最低）
  ├─ 既に使われているプレゼン資料
  ├─ 「この資料で成約した」という実績がある
  └─ 問題: テンプレートなので、実例感が薄い
         → テンプレートの背景にある「営業トーク」を補強

素材管理:
  Google Sheet で以下を記録:
  | 素材ID | ソース | ジャンル | 難度 | 成功/失敗 | 使用セッション |
  | S001 | 音声(9/15小林) | 月支払懸念 | 初級 | 成功 | A/B |
  | S002 | 音声(9/22佐藤) | 月支払懸念 | 初級 | 失敗 | A |
  | S003 | メモ(9/20山田) | 他社比較 | 中級 | 成功 | B |
```

### 失敗例を集める（逆説的だが重要）

```
教材では「成功例」だけでなく「失敗例」も必ず載せる。
理由: 学習者が「同じ失敗をしないため」に必要

失敗例の集め方:
  1. 月末に失注 5-10 件の音声を抽出
  2. Claude に「失注の主原因は何か」を分析させる
  3. パターン分類:
     • 営業のフレーズが不適切
     • 顧客の懸念を見落とした
     • 提案のタイミングが早かった
  4. パターンごとに「改善版」の営業トークを用意
  5. 比較形式で教材化（失敗 → 改善 → 成功）

例: 「他社比較」で失敗するパターン
  失敗例（実例: 9/28 青木さん）
    営業: 「うちは XX 会社より補償が充実しています」
    顧客: 「でも XX のほうが安いし…」（即座に却下）
    
  改善版
    営業: 「他社と比較いただくのは賢明です。
          うちが 20% 高い理由は、入院時に追加補償が出るから。
          実際に入院した場合、トータルでは XX より
          30% 得になる計算です。参考までにシミュレーション
          お見せしましょうか?」
    顧客: 「あ、そういうことですね」（納得、成約へ）

  学習ポイント:
    • 「補償が充実」だけでなく、「金銭的メリット」を数値化
    • 「比較させてくれたこと」を肯定（反発でなく感謝）
```

## Stage 3: コンテンツ構成（セッションごとの設計）

### 初級セッション（新人営業向け）: 基本フロー

```
セッション名: 「初めての顧客対応：ヒアリングから成約まで」
所要時間: 120 分（note 30 分 + YouTube 30 分 + 実習 60 分）
難度: ★☆☆
学習目標: 「基本フロー（ヒアリング → 提案 → クロージング）
          を実際の顧客で使い、1 ヶ月で月 3 件成約」

構成:

┌─ Part 1: 典型的な営業フロー（実例ビデオ 30 分）
│
├─ ケース 1: 製造業・経営者 / 保険未加入（失敗）
│   ビデオ: 新人営業と経営者の会話（20 分、実録）
│   失敗ポイント: ニーズ質問を 1 つで止める
│                  → 顧客の本当の懸念「今の売上では…」を聞き出せない
│
├─ ケース 2: 同じ製造業・経営者 / 保険未加入（成功）
│   ビデオ: 中堅営業と経営者の会話（20 分、実録）
│   成功ポイント: 初回ヒアリング後、「もう一度 1 週間後に」と
│                 次回アポを取る（焦らない）
│
└─ 学習チェック: 失敗例を見た後、「あなたなら何と言う？」

┌─ Part 2: ヒアリングシート の記入方法（note 30 分）
│
├─ ヒアリングシートの項目
│   (1) 会社情報（業種・従業員数・売上）
│   (2) 現在の保険（加入の有無・内容・月額）
│   (3) 今後の懸念（事業拡大・リスク想定）
│
├─ 記入例 3 件（ビデオとセット）
│   例 1: 製造業・従業員 30 人・月額 5 万 → 「交通事故のリスク高」で成約
│   例 2: サービス業・従業員 5 人・未加入 → 「まだ必要ない」で失注（但し 6 ヶ月後に再接触で成約）
│   例 3: 建設業・従業員 50 人・複数保険 → 「重複している」で整理提案で追加成約
│
└─ 注意: 「書けば成約する」わけではなく、
         「書く過程で、顧客の本当の懸念が見える」ツール

┌─ Part 3: よくある質問への対応（YouTube 実例 × 3）
│
├─ Q1: 「他社と比べてどうですか?」
│   A: 「価格で比較すると確かに高いこともあります。
│       ただ、入院時の補償が…」（実例音声 2:15-3:00）
│
├─ Q2: 「検討させてもらってもいい?」
│   A: 「もちろんです。ただ確認ですが、懸念は『月額』でしたっけ、
│       『補償内容』でしたっけ?」（実例音声 4:30-4:45）
│
└─ Q3: 「今決める必要があります?」
    A: 「直ぐではなく、ただ来月から保険料が改定されるので、
        今月中なら現在の額で…」（実例音声 6:00-6:45）

┌─ Part 4: ロールプレイ実習（60 分）
│
├─ 実習相手: 先輩営業が「顧客役」を演じる
├─ シーン 1: 「未加入の経営者」へのヒアリング（15 分）
├─ シーン 2: 「他社と比較中」の顧客への提案（15 分）
├─ シーン 3: 「決断できない」顧客へのクロージング（15 分）
├─ フィードバック: 先輩から「良かった点 / 改善点」を直接指摘（15 分）
│
└─ 記録: 実習音声を記録 → 自分で聞き返す
         （1 週間後に「あ、あの時こう言えばよかった」と気づく効果）
```

### 中級セッション（既存営業向け）: クロスセル

```
セッション名: 「既存顧客へのクロスセル：もう一つの商品を 3 ヶ月で 2 件成約」
所要時間: 90 分（note 30 分 + YouTube 30 分 + 実習 30 分）
難度: ★★☆
学習目標: 「既存顧客分析 → 最適な追加商品 → クロスセル提案」
         の 3 段階を自分で実行

構成:

┌─ Part 1: 既存顧客の分類（note 30 分）
│
├─ パターン A: 「単純補償型」（安さ重視）
│   ├─ 特徴: 基本的な生命保険のみ
│   ├─ クロスセル提案: 「医療保険」の追加（医療費カバー）
│   └─ 成功率: 68%（実績 Q3）
│
├─ パターン B: 「医療重視型」（健康不安がある）
│   ├─ 特徴: 既に医療保険加入済み
│   ├─ クロスセル提案: 「就業不能保険」の追加（収入保障）
│   └─ 成功率: 72%（実績 Q3）
│
└─ パターン C: 「コスト最適化型」（複数保険で無駄）
    ├─ 特徴: 3 社以上で重複加入
    ├─ クロスセル提案: 「統一・整理」提案で「月額を 15% 削減」
    └─ 成功率: 81%（実績 Q3）← 一見逆に見えるが、
                                顧客が「既に信頼している」営業からの
                                「得する提案」だから成約しやすい

┌─ Part 2: 顧客分類の実例（YouTube × 3）
│
├─ ビデオ 1: 顧客 A の通話（2020 年 = 単純補償型の契約 / 2026 年 = クロスセル提案）
│   2020: 「基本的な保険をお願いします」 → 月 5,000 円で成約
│   2026: 同顧客のビジネス拡大が判明 → 「医療保険の追加」を提案
│          → 「医療保険なんて必要ないと思ってた」から「あ、確かに…」への転換
│          → 実例音声の説得力（6 年の関係構築が信頼に変わる）
│
├─ ビデオ 2: 顧客 B の通話（複数保険の無駄を指摘した事例）
│   営業: 「失礼ですが、現在の 3 社の加入内容を確認させていただけますか?」
│   顧客: 「はい、でもちょっと複雑で……」
│   営業: 「実はその『複雑さ』が、無駄を生んでいる可能性があります」
│          （実例分析: 医療補償が 2 社で重複 + 月額 2,000 円の無駄を発見）
│          → 統一提案で月 3,000 円削減 + より良い補償に
│
└─ ビデオ 3: 失敗例（顧客への信頼がないまま提案）
    営業: 「もう一つの商品があります」
    顧客: 「いや、今のままで大丈夫です」（即座に却下）
    失敗ポイント: 顧客の現在の状況を分析せず、一方的な提案

┌─ Part 3: 実習（30 分）
│
├─ 課題: あなたの既存顧客 3 名に対して、
│        「クロスセル提案」を作成（書面で）
│
├─ 判定: 先輩が「この提案なら顧客が納得するか」をチェック
│
└─ フィードバック: 「何が足りないのか」を指摘
                   （多くは「顧客分析」が不十分）
```

### 上級セッション（マネージャー向け）: 失注分析と反復教材

```
セッション名: 「月次失注分析 × 部下指導 × 勉強会運営」
所要時間: 180 分（初回のみ、以降は月 60 分）
難度: ★★★
学習目標: 「月 1 回、部下の失注パターンを分析し、
          その 1 週間後には『勉強会コンテンツ』を制作・実施できる」

構成:

┌─ Step 1: 失注分析（月末 2 日間）
│
├─ 対象: 先月の失注 5-10 件の音声ファイル
├─ 方法: Claude に「失注の主原因分析」を自動実行
├─ 出力: パターン分類
│   例:
│   • 「支払が心配」で失注: 3 件（全失注の 40%）
│   • 「検討が必要」で中断: 4 件（全失注の 50%）
│   • 「他社に決めた」: 2 件（全失注の 10%）
│
└─ 注意: 「失注数が多い = 営業が悪い」ではなく
         「失注パターンが反復 = 教材が必要」と判定

┌─ Step 2: 部下別フィードバック（1 日）
│
├─ Aさんの失注分析:
│   • 先月 5 件の失注のうち、3 件が「支払が心配」
│   • Aさんの回答: 「補償内容が…」で止まっている
│   • フィードバック: 「『3ヶ月回収』フレーズを使ってみて」
│   • 実例: 成功している営業 B の実録音声を共有
│   • 1 ヶ月のチャレンジ: 「同じシーンで 3 回使う」
│
└─ Bさんの失注分析:
    • 先月 8 件の失注のうち、4 件が「検討が必要」
    • 問題: 次回アポを取れていない（宙ぶらりん化）
    • フィードバック: 「初回ヒアリング後には『1 週間後に』と次回日程を確定」
    • 実例: 成功事例から「段階的なアプローチ」を示す

┌─ Step 3: チーム向け勉強会コンテンツ制作（3 日）
│
├─ 形式:
│   • note 記事 1 本: 「『支払が心配』というお客さんの本音」
│   • YouTube 動画 1 本: 失敗例と成功例の実録比較（7 分）
│   • 社内 Slack の実例シェア: 当月の新しい成功パターン 2 件
│
├─ 流れ:
│   月 1 日: 失注分析結果を集計・分類
│   月 2-3 日: note 記事・YouTube 台本を作成
│   月 5 日: 動画撮影・編集（1 時間）
│   月 6 日: チーム向け勉強会（60 分）
│           ├─ note 記事を紹介（5 分）
│           ├─ YouTube ビデオ視聴（7 分）
│           ├─ ロールプレイ実習（30 分）
│           └─ 質問・相談タイム（18 分）
│
└─ 記録: 勉強会の実施ログ・参加者を記録
         （「確実に全員が学習したか」の監査）

┌─ Step 4: フォローアップ（月中・月末）
│
├─ 月中（1 回）: Aさんが「『3ヶ月回収』で成約した事例」が出たら即座に Slack で共有

## Stage 4: 教材の「AI感」を排除する実装

### よくあるミス（どうやって「AI が作った」感を出してしまうのか）

```
❌ NG パターン 1: 例が一般的すぎる
  note 記事: 「営業成功の 3 パターン」
    • パターン 1: ニーズを引き出した例
    • パターン 2: 価格交渉に対応した例
    • パターン 3: 異議処理で信頼を勝ち取った例
  
  問題: 「どの業界にも当てはまる」ので、自社の営業には使えない
       → 学習者が「でうちの案件は違うし…」と思考停止

✅ OK: 具体的な業種・商品・金額で例示
  note 記事: 「『月支払が心配』と言う建設業の経営者に、
             『3ヶ月回収』で納得させた 1 時間の会話」
    • 顧客: 従業員 20 人の建設業、現在の保険月額 5,000 円
    • 懸念: 「8,000 円に上がるのはきつい」
    • 営業の返答: 「増加分月 3,000 円 × 3 ヶ月 = 9,000 円。
                これで現在の月支払から回収できます…」
    • 実録音声: 実際の会話を 5-10 分埋め込み

❌ NG パターン 2: 成功例ばかりで失敗例がない
  YouTube: 「営業トークの上手い 5 人の共通点」
    → 「成功の公式」に見えるが、学習者は「自分は上手くいかない」と
       感じるだけで、改善点が見つからない

✅ OK: 失敗例も含める（比較形式）
  YouTube: 「『月支払が心配』に対して、なぜ営業 A は失敗して
           営業 B は成功したのか」
    • 失敗事例（営業 A）: [実録 2 分]
    • 成功事例（営業 B）: [実録 2 分]
    • 学習ポイント: 両者の 3 つの違いを指摘
  
  学習効果: 「営業 A の何が悪いのか」が見えるので、
           自分の改善点を発見できる

❌ NG パターン 3: 出所が不明（作られたシーン？実例？）
  YouTube: 「営業の模範的な会話」
    → 作られたシーンに見える（話が上手すぎる、実感がない）
    → クリック 2-3 件で終わり

✅ OK: 出所を明示 + 実録音声
  YouTube: 「【実例】2026 年 9 月 15 日の小林さん訪問（45 分）」
    • 顧客プロフィール: 建設業・従業員 20 人・現在月 5,000 円
    • 営業: 中堅営業 Bさん（入社 3 年）
    • 結果: 成約 + 今月のクロスセルにつながった例
    • 音声: 実録（ノイズあり）
  
  学習効果: 「実際の営業現場の会話」だから信じられる
           → 「この営業 B さん、どこで学んだんだろう」と興味を持つ
           → リンクを辿って教材動画も見る

❌ NG パターン 4: 実習がない（見て終わり）
  note 記事: 「営業成功の 3 パターン」を長々と説明
    → 読んで 2-3 日で忘れる

✅ OK: 実習ステップを組む
  セッション構成:
    1. 理論（5 分）: フレーズの背景を説明
    2. 実例（5 分）: 実録ビデオで「実現できること」を示す

    4. フィードバック（10 分）: 「あなたの場合、何が足りないのか」を指摘
  
  学習効果: 「わかった」が「できた」に変わる

## 3フェーズ構造：ペルソナ定義 → コンテンツ構成 → テスト実施

本スキルは以下の3つのフェーズで段階的に進行します。各フェーズは独立して検証可能です。

### フェーズ 1: ペルソナ定義

対象となる学習者を詳細に定義します。

**ステップ 1-1: ペルソナの基本情報**
- 役職・経験年数
- 現在のスキルレベル（初級/中級/上級）
- 主な成功パターン（何で契約が取れているのか）
- 主な失敗パターン（何で失注しているのか）

**ステップ 1-2: 学習目標の設定（SMART形式）**
```
S（具体的）: 「何ができるようになるのか」を特定
  例：「『月の支払が心配』という懸念への対応」
  
M（測定可能）: 数値目標を設定
  例：「成約率を50% → 75%に向上」
  
A（達成可能）: 既存の成功事例から実現性を確認
  例：「営業Bが同じシーンで75%以上の成約実績」
  
R（関連性）: ビジネス価値を明示
  例：「失注理由TOP3の『支払懸念』（38%）を解決」
  
T（期限付き）: 習得期間を設定
  例：「3ヶ月以内にマスター」
```

**ステップ 1-3: ペルソナごとの学習パス決定**
- どの形式（note/YouTube/実習）が効果的か
- 所要時間・難度の設定
- 前提知識の確認

4. **確認パート**（5-10分）

   - 理解度の確認

## 検証失敗時の対応

教材がターゲット層で期待の成果を出さなかった場合、以下の手順で原因を特定します。

**失敗パターン 1: ターゲット読解度ミスマッチ**
```
症状:
  - 読易性テストは合格したが、アンケートで「難しい」と回答
  - 実装率が低い（30%未満）

原因候補:
  - 文字数は少ないが、専門用語が多すぎる
  - 実例と学習者の状況が乖離している
  - 図解がなく、抽象的すぎる

対応:
  1. humanizer スキルで文体を見直し（自然な会話調へ）
  2. 実例を「より自社に近い業種」に変更
  3. 図解・フローチャートを追加
  4. 再テスト（1-2週間後）
```

**失敗パターン 2: 専門用語の非翻訳**
```
症状:
  - 「助成金」「補助金」「gBizID」の違いが理解できていない
  - 成約率が向上しない

原因候補:
  - 用語説明が別ページ（学習者が参照していない）
  - 同じ概念を複数の用語で説明している
  - 類似用語の「何が違うのか」が不明

対応:
  1. 用語集を本編に統合（「〜とは」の説明をインライン化）
  2. 図解で概念の違いを視覚化
  3. 実例で「実際にはこう違う」を示す
  4. taste-skill でAI感を排除
```

**失敗パターン 3: 実習ステップの不足**
```
症状:
  - 「わかった気がする」が「実装できない」に繋がらない
  - 学習 1週間後の実装率が 20% 未満

原因候補:
  - 理論だけで、実習がない
  - ロールプレイの相手が現場にいない
  - フィードバックが「あの言い方が良かった」止まり

対応:
  1. 実習シーンを増やす（最低 3パターン）
  2. チェックリスト形式で「何が足りないのか」を学習者自身が発見
  3. 先輩からの「改善フレーズ」を記録
```

**失敗検知の自動化**
```
監視項目（週次）:
  - コンテンツ視聴率（ベースライン 60% 以上）
  - 実習実施率（ベースライン 40% 以上）
  - アンケート「理解できたか」（ベースライン 70% 以上）
  - 成約率前月比改善率（ベースライン +15% 以上）

いずれか 1 つが閾値を下回ったら、
上記の「対応」を開始
```

## 本番前テスト手順

### ステップ 1: 読易性テスト

**必要環境**
```bash
pip install textstat
```

**実行方法**
```python
import textstat

# テキストを読み込む
with open("content.txt", "r", encoding="utf-8") as f:
    text = f.read()

# グレードレベルを計算
grade = textstat.flesch_kincaid_grade(text)
flesch = textstat.flesch_reading_ease(text)

# 結果を表示
print(f"Flesch-Kincaid Grade: {grade}")
print(f"Flesch Reading Ease: {flesch}")

# 目標チェック
target_grade = 7  # 例: 初級教材なら 6-8
if grade > target_grade + 1:
    print(f"警告: グレード {grade} は目標 {target_grade} より高い")
    print("用語の簡潔化または実例の追加が必要")
```

**合格基準**
| 教材レベル | 目標グレード | 判定基準 |
|---|---|---|
| 初級（新人営業） | 6-8 | グレード 9 以上は再修正 |
| 中級（既存営業） | 8-10 | グレード 11 以上は再修正 |
| 上級（マネージャー） | 10-12 | グレード 13 以上は再修正 |

### ステップ 2: ペルソナ適合性チェックリスト

対象ペルソナ 1-3 名に以下をチェックさせます。

```
□ ペルソナマッチ
  □ 「自分の状況が想定されている」と感じたか
  □ 「自分の会社の規模と合致している」か
  □ 「現在のスキル・経験が想定と近い」か

□ 用語翻訳確認
  □ 「難しい言葉は全て説明されているか」
  □ 「専門用語の『何が違うか』が理解できたか」
  □ 「実例から類似概念の区別ができたか」

□ 実装可能性
  □ 「実際の営業で使えそうか」
  □ 「使う場面が明確か」
  □ 「今日明日の営業で試してみたい」と思ったか

□ AI感チェック
  □ 「テンプレート感がないか」
  □ 「自社の実例で構成されているか」

### ステップ 4: 成約率測定（1ヶ月）

学習 1ヶ月後に以下を測定します。

```

  - 学習前平均成約率（ベースライン）
