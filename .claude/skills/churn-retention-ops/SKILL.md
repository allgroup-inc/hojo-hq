# 保全運用の規律(先回りで手厚く・人を責めない)

顧客カルテ・要フォロー・保全アクション・効果測定は、「高リスク先へ先回りで手厚い保全をあて、
早期解約を減らし継続率を上げる」ための道具。使い方を誤ると、現場疲弊・営業への不当評価・
過大な効果誤認を生む。運用と文面を設計・レビューするときはこの規律に従う。

## 絶対ルール

1. **保全連絡は締切アラートと別系統**: 顧客への保全フォローは、制度の締切アラート(SNS投稿=残り30日以上/7〜29日=LINE個別/7日未満=次回予告 の3層ルール)とは**別の連絡系統**。混同しない。締切文面の規律は `hojo-deadline-alert` の領分。
2. **放置検知は"様子見放置"を拾うためのもの**: 高リスク×直近接触なし(既定14日)は「先回りすべき先」を出す気づき。閾値は小柳さんの決裁事項で、通知過多で現場が麻痺しないよう実運用で調整する。日数はデータ・現場感覚で見直す前提。
3. **営業マン別スコアを人を責める道具にしない**: 営業担当別の解約傾向は**教育・初期フォローの型の改善**のために使う。人事評価・叱責への誤用は禁止(監査コウヘイさんが監視)。少件数の担当は「参考」表示にし、断定しない。
4. **効果測定は正直に**: 保全接触あり/なしの解約率比較は、(a)母数が `MIN_RELIABLE_N` 未満なら「参考(母数不足)」と明示、(b)**解約後の接触を"保全あり"に数えない**(免疫時間バイアスで保全を過大評価しない)。0%/100%を成果として断定しない。
5. **未紐付を隠さない**: 顧客ID欠損で束ねられなかった申込み・接触は件数を明示する(黙って母集団から消さない)。

## チェック手順(運用・文面・レビュー時)

1. その連絡が「保全フォロー」か「制度の締切告知」かを区別する。締切系なら `hojo-deadline-alert` の3層ルールへ。
2. 要フォロー(放置検知)の閾値・件数が現場の処理能力に見合うか確認する。多すぎるなら閾値・トリアージを調整して小柳さんへ。
3. 営業マン別の数字を出す文面は、目的が「教育・改善」に限定され、少件数に「参考」が付いているか確認する。責める表現になっていないか。
4. 効果測定の数字は、母数不足の明示・免疫時間の除外・断定回避ができているか確認する(モデル側の規律は `churn-model-quality-gate`)。
5. 顧客個人情報を含むカルテ・一覧・コンソールの出力は `private/` 限定か(`churn-pii-guard` を併用)。
6. 保全アクションの型・閾値・公開範囲など意思決定を伴う変更は、三名体制(`hojo-triangle-review`)で議事化して決裁に上げる。

## やってはいけないこと

- 保全フォローを締切アラートと混同した文面・配信にする。
- 営業マン別スコアを人事評価・叱責の材料に使う/使える形で見せる。
- 母数の少ない効果測定・解約率を「保全が効いた/この担当は悪い」と断定する。
- 解約後の接触を保全実績に数えて効果を水増しする。
- 未紐付(顧客ID欠損)を明示せず母集団から静かに落とす。
