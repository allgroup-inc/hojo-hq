## 2. 本体・関連文書のどちらにも拾われていなかった小粒ギャップ

### 2.1 提携実績トラッキング台帳の欠落

本体のKPIオーナー表は「紹介(士業)100社」「紹介(商工会・金融)100社」を musubu の
担当としているが、独立監査で確認した限り、実際に何件紹介し何件成約したかを
記録するファイルが存在しなかった(月次パートナーレポートは紹介文の生成のみで、
実績を追う仕組みではない)。`data/note_kpi.json` と同じ「手入力・null許容・
推測値禁止」の設計で `data/partner_referrals.json` を新設した。

### 2.2 企業のミカタ自身の収集ソースに定期監査がない

フクギイロ側は `fukugiiro-audit.yml` が週次で収集対象ドメインのrobots.txt変更を
自動検知するが、企業のミカタ自身の収集対象(`scripts/fetch_local.py` が使う
沖縄県・沖縄県産業振興公社・那覇市の3ドメイン。`docs/守り部審査記録.md` で
条件付き承認済み・本番で実際にクロール中)には、2026-07-22等の一回限りの
手動レビューしかなく、承認後にサイト側の方針が変わっても検知できない状態だった。

フクギイロ側の `scripts/audit_sources_fukugiiro.py`(robots.txtのみ取得・
連絡先付きUA・1.5秒間隔というマモリさん承認済みの安全なロジック)をそのまま
流用し、`scripts/audit_sources_mikata.py` + `.github/workflows/mikata-audit.yml`
として新設した。**新しいドメインへの収集拡大ではなく、既に承認・稼働中のドメインの
robots.txt変更を検知するだけ**であり、収集可否の最終判断は従来どおり
`docs/守り部審査記録.md` に委ねる(このスクリプト自体は機械による事実確認のみ)。

### 2.3 CLAUDE.mdの技術構成記述が実態と乖離

CLAUDE.mdは「収集: GitHub Actions cron(1日2回 06:00/18:00 JST)」と記載していたが、
`update.yml` の実際のcronは1日4回(03:00/09:00/15:00/21:00 JST)。ドキュメントと
実装が一致していないと、この後の三名体制の議論そのものが誤った前提の上に
乗ってしまうため、実態に合わせて訂正した。

### 2.4 site/staff/reply.html のXSS懸念を検証・解消

`docs/議事_20260731_直近決定の三名検証.md` のウタガイ発言で「staff/reply.htmlも
subsidies.jsonをinnerHTML展開しており、XSS類の懸念が未検証のまま残る」と
指摘されていた。今回、対象ファイルを実際に読み込んで確認した結果、
**該当箇所は`innerHTML`ではなく`.value`(textarea)・`.textContent`のみを
使用しており、HTMLとして解釈される経路は存在しないことを確認した**
(グレップで`innerHTML`の使用箇所ゼロを確認)。この議事の懸念は実装未確認ゆえの
保留であったため、本追補をもって**解消(✅化)**する。コード修正は不要だった。
