# 議事 2026-09-18: 架電リストの業態優先(ホテル・小売)とランク初期値ルール

- 発端: 小柳さん指示「沖縄県でM&Aにつながりやすい業態がホテル関係・小売り関係。リストを作ってシステムにランクを付けて投入できるか」→「どんどん進めてください」「本島のみで」
- 決裁: 小柳さん(2026-09-18 チャット)
- 議事必須の理由: **スコアリングの重み付け変更**(業種上位リストへのホテル・宿泊・観光の追加)と**ランク初期値ルールの新設**(閾値・ルールの変更=不可逆類型②)

## 新設・変更したルール

1. **スコアリング業種上位(high)に「ホテル」「宿泊」「観光」を追加**(scoring.js DEFAULT_CONFIG.industryTiers.high。小売は従来から登録済み)
2. **開拓架電リストのランク初期値**(リスト作成時に機械的に付与):
   | ランク | 基準 |
   |---|---|
   | A | 客室100室以上、または複数施設を運営する地場運営会社 |
   | B | 客室30〜99室 |
   | C | 客室30室未満、または規模情報が確認できない |
3. **流入ルート「④開拓架電」を新設**(手紙DM経由と区別して集計・出し分けするため。週間ファネルの新規獲得数①〜③には算入されない=手紙成果の水増しを防ぐ)
4. リストの対象は**地場資本・独立系を優先**し、全国大手チェーン直営・外資系運営は除外(M&A対象になりにくいため)
5. リストのデータ源は**公的オープンデータ・公式サイト等の規約上問題ない公開情報のみ**(絶対ルール2)。電話番号は確認できたもののみ記載し推測しない(絶対ルール1)
6. 企業リスト実体(CSV)は公開リポジトリに置かず、スプレッドシートへ直接投入する(機密区分ルール)

## 三名体制

### スイシン(推進)
- 連続架電モードはランクA→D順に回るため、初期ランクを付けて投入するだけでホテル・小売の優先架電が実現する(新規開発ほぼ不要)
- 業種上位への追加により、後日 recalculateAllScores を実行してもホテル系の評価が下がらない(初期ランクと再計算の整合)
- 流入ルートを分けることで「開拓架電からの成約率」を手紙・紹介と別で測れるようになる

### ウタガイ(懐疑) ※反対理由の記録
- **「M&Aにつながりやすい業態」の根拠が経験則**であり、沖縄での成約実績データに基づいていない。→ 承知の上で小柳さん(保険営業20年・現場感)の判断として採用。6ヶ月後の見直しで架電結果(断り理由・アポ率)と突き合わせて検証する
- **客室数によるランクはM&Aニーズの代理指標として粗い**(小規模でも後継者不在なら有望)。→ 初期値にすぎず、架電・面談の反応で総合スコアが更新される設計。初期値の粗さは運用で補正される
- **既存の建設リストが後回しになる懸念**: ホテルをA/Bで入れると建設のC/D企業より先に回る。→ 意図した優先順位変更であり、建設リストが消えるわけではない(キューに残る)
- **ランク再計算(recalculateAllScores)を実行すると手動ランクが上書きされる**。→ 既知の仕様。業種上位への追加で再計算後もホテルはB前後を維持するが、Aは維持されない場合がある。再計算は現状手動実行のみなので実害は限定的。実行前に本議事を確認すること

### ベッカイ(別解)
- 業態でなく「後継者不在が確認できた企業」だけに絞る案。→ 情報の取得コストが高く件数が集まらない。まず業態で母集団を作り、架電ヒアリングで後継者状況を埋める現行方式が先(不採用)
- リスト作成を❷セッション(市場調査担当)へ連携メモで依頼する案。→ 体制上は❷の領域だが、小柳さん直接指示・投入(システム側)と一体の作業のため❶で実施し、本議事で経緯を残す(今回は❶実施、恒常化する場合は❷と分担を再整理)

### 結論(裁定)
- 採否: **採用**(小柳さん決裁 2026-09-18)
- 理由: 既存のランク・スコアリング・連続架電モードの仕組みに乗るだけで優先順位を変えられ、可逆性が高い(ランクは上書き自由・ルート別集計で効果検証可能)
- 見直し期限: 2027-03-18(ホテル・小売への架電結果=アポ率・断り理由の分布を見て、業態優先の是非とランク基準を再議論)
