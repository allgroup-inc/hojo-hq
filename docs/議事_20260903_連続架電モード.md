# 議事 2026-09-03: 連続架電モードと次回アクション自動設定ルール(glow-ma v1.7.0)

- 発端: 小柳さん要望「この架電システムをより効率よく開拓が出来るようにバージョンアップさせたい」
- 決裁: 小柳さん(2026-09-03 チャットで実装プロンプトを提示し「進めて」)
- 議事必須の理由: **次回アクションの自動設定ルールの新設**(閾値・ルールの変更=不可逆類型②)

## 新設したルール(callMode.js の CALL_RULES に集約・変更時は本議事を更新)

| 架電結果 | 記録種別 | 次回アクションの自動設定 |
|---|---|---|
| 不在だった | 電話 | **3営業日後**に「再架電」 |
| 話せた(継続) | 電話 | 架電者が選んだ日付(初期値: 7日後) |
| アポ獲得 | アポ獲得 | 面談日(必須入力) |
| 断り「時期が合わない」 | 見送り | **6ヶ月後**に「再掘り起こし」 |
| 断り(それ以外の理由) | 見送り | 設定しない(予定を消す) |
| 番号違い・不通 | 電話 | 設定しない(メモに「リスト要修正」) |

架電リストの規則: ランクA→D → 期限超過の古い順 → 未着手 → 将来予定。除外=連絡不要/電話番号なし/**本日接触済み**(同日の重複架電防止)。

## 三名体制

### スイシン(推進)
- 「かける→記録→次を決める」が結果ボタン1つに畳まれ、1時間あたりの架電件数と記録率が上がる
- 不在の追いかけ(3営業日後)と「時期が合わない」の6ヶ月リサイクルが自動化され、見込みの取りこぼしが構造的に消える
- 断り理由が選択式で貯まる(業態別の断られ方の分析=教材化の材料)

### ウタガイ(懐疑) ※反対理由の記録
- **自動設定が本人の判断を奪う**: 不在でも「もうかけるべきでない」ケースがある。→ 結果ボタンは強制ではなくスキップ可。自動設定後も詳細画面からいつでも予定を変更・削除できる(上書き自由)
- **6ヶ月後リストの膨張**: 「時期が合わない」を多用すると半年後の掘り起こしが山になる。→ 見直し期限で件数を点検し、必要なら理由の細分化やランク連動の間隔に改める
- **見送りの上書き**: 断り(その他等)で次回予定を空にする際、既存の予定を消してしまう。→ 意図した仕様(断られた企業に古い予定が残る方が誤架電を招く)だが、ガイドに明記
- **祝日非対応**: 3営業日は土日のみ考慮で祝日は含まない。→ 実害は「祝日に予定が乗る」程度でポップアップ運用で吸収可。祝日対応は必要になってから

### ベッカイ(別解)
- 自動発信・オートコール型(CTI主導)にする案。→ BlueBean側の機能に依存し、現場は1人運用でリスト消化が先。tel:リンク発信+結果記録の効率化が先で、CTI連動強化は次段階(不採用・保留)
- 結果を後でまとめて記録する「一括記録」案。→ 記録の先送りは漏れの温床。1件ずつ即記録が本システムの思想(不採用)

### 結論(裁定)
- 採否: **採用**(v1.7.0として実装・全496テスト成功)
- 理由: 開拓の律速は架電の回転数と記録の徹底であり、両方を同時に解決する。ルールは定数化されており運用調整が容易
- 見直し期限: 2027-03-03(6ヶ月後リストの件数・不在再架電の実効性・断り理由の分布を見て再議論)
