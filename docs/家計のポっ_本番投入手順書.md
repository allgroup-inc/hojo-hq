# 家計のポっ 本番投入手順書(小柳さん向け・初回のみ・約30分)

2026-08-14作成。apo-kanri/README.md の手順1〜8を、初めてでも迷わないよう1クリック単位で書いたもの。
つまずいたらこのファイル名とどの手順番号で止まったかをチャットに貼れば、すぐ続きを案内できます。

## 事前に用意するもの

- パソコン(スマホだけでは初回設定は不可。運用はスマホでOK)
- Googleアカウント(スプレッドシートの持ち主になるアカウント。以後「管理アカウント」)
- スタッフ全員のGoogleアカウントのメールアドレス(Gmailアドレス)
- Slackの管理権限(通知チャンネルにWebhookを追加できること)
- このリポジトリのコード
  - **注意: 家計のポっのコードはブランチ `claude/sales-appointment-management-app-5fuo4y` にあります**
  - mainにマージ済みならmainでOK。未マージなら
    `git fetch origin claude/sales-appointment-management-app-5fuo4y && git checkout claude/sales-appointment-management-app-5fuo4y`

## 手順1: スプレッドシートを作る(3分)

1. 管理アカウントで https://sheets.new を開く
2. 左上のファイル名を「**アポ管理台帳**」に変更
3. 右上「共有」→ **アポ管理のスタッフだけ**を「編集者」で追加
   (glow-maのM&A台帳とは別ファイル・別共有。M&A側のメンバー設定を流用しない)

## 手順2: Apps Scriptプロジェクトを開く(1分)

1. そのスプレッドシートで「拡張機能」→「Apps Script」
2. 左上のプロジェクト名を「家計のポっ」に変更

## 手順3: コードを反映する(10分)

**方法A: clasp(コマンドが使える場合・推奨)**

1. ターミナルで `npm install -g @google/clasp`(未導入時のみ)
2. `clasp login` → ブラウザで管理アカウントを選んで許可
3. Apps Scriptエディタ左の歯車「プロジェクトの設定」→「スクリプトID」をコピー
4. リポジトリで `apo-kanri/.clasp.json.example` を `apo-kanri/.clasp.json` にコピーし、
   `YOUR_APPS_SCRIPT_ID_HERE` を今コピーしたIDに書き換える(このファイルはコミットしない)
5. `cd apo-kanri && clasp push`(「Manifest file has been updated」と聞かれたら y)
6. Apps Scriptエディタを再読み込みし、ファイル一覧に schema / apoCore / ApoRunner 等が並べば成功

**方法B: 手貼り(コマンドを使いたくない場合)**

1. Apps Scriptエディタの歯車「プロジェクトの設定」→「『appsscript.json』マニフェストファイルをエディタで表示する」にチェック
2. エディタで appsscript.json を開き、リポジトリの `apo-kanri/src/appsscript.json` の中身で丸ごと置き換え
3. 「ファイル+」→「スクリプト」で以下の8ファイルを1つずつ作り、同名ファイルの中身を丸ごと貼り付け
   (エディタ上では拡張子が .gs になるがそのままでよい):
   schema / apoAccess / apoCore / apoNotify / apoPage / resilience / SheetSetup / ApoRunner
4. 保存(Ctrl+S / Cmd+S)

## 手順4: シートのタブを自動作成する(2分)

1. Apps Scriptエディタ上部の関数選択プルダウンで **ensureApoTabs** を選び「実行」
2. 初回は権限確認が出る: 「権限を確認」→ 管理アカウントを選択 →
   「詳細」→「家計のポっ(安全ではないページ)に移動」→「許可」
   (自作スクリプトに必ず出る警告で、異常ではない)
3. スプレッドシートに「スタッフ」「アポ予定」「変更履歴」「設定」の4タブができていれば成功

## 手順5: スタッフを登録する(5分)

「スタッフ」タブに全員分を1行ずつ入力:

| 列 | 入れるもの |
|---|---|
| 氏名 | 画面に表示される名前(例: 比嘉太郎) |
| Slack User ID | Slackで本人のプロフィール→「…」→「メンバーIDをコピー」(**Uで始まる文字列**。メールアドレスではない) |
| 有効 | チェックを入れる(外すとアクセス不可になる=退職時はここを外す) |
| メールアドレス | 本人の**Googleアカウントのメール**(これがログイン照合に使われる) |
| 役割 | アポ入れ / 営業 / 両方(プルダウン) |

## 手順6: Slack通知をつなぐ(5分)

1. https://api.slack.com/apps →「Create New App」→「From scratch」
   → 名前「家計のポっ」・ワークスペース選択
2. 左メニュー「Incoming Webhooks」→ オンにする →「Add New Webhook to Workspace」
   → 通知を流すチャンネル(例: #アポ連携)を選択 → 発行された **Webhook URL をコピー**
3. Apps Scriptエディタの歯車「プロジェクトの設定」→ 下の「スクリプト プロパティ」
   →「スクリプト プロパティを追加」→ プロパティ名 `SLACK_WEBHOOK_URL`・値に今のURL → 保存
   (URLをコードやチャットに貼らないこと。漏れたら誰でもそのチャンネルに投稿できてしまう)

## 手順7: Webアプリとして公開する(3分)

1. Apps Scriptエディタ右上「デプロイ」→「新しいデプロイ」
2. 歯車で種類「**ウェブアプリ**」を選択
3. 説明「家計のポっ v1」/ 実行ユーザー「**ウェブアプリケーションにアクセスしているユーザー**」
   / アクセスできるユーザー「**Googleアカウントを持つ全員**」
   ⚠️ 実行ユーザーを「自分」にしないこと。個人Gmail運用ではアクセスした人のメールが
   取得できず、小柳さん以外の全員がログインできなくなります(2026-08-17レビューで検出・修正済み)
4. 「デプロイ」→ 表示された **ウェブアプリのURL** をコピー
   (「全員」でもスタッフタブに登録したメール以外はアクセス拒否画面になるので安心。
   各スタッフの初回アクセス時のみ権限承認が1度出る: 「詳細」→「移動」→「許可」)

## 手順8: スタッフに配って動作確認(5分)

1. URLをスタッフに共有。スマホで開いたら共有メニューから「**ホーム画面に追加**」を案内
2. 動作確認(自分のスマホで):
   - 「+新規アポ」からテストアポを1件登録 → Slackに📅通知が届く
   - カードをタップ→「確定」 → 🔁変更通知が届く
   - 「キャンセル(自社都合)」にする → ❌通知+🧭代打候補が届く
   - テストが済んだら変更履歴タブに操作が記録されていることを確認
3. 周知: 「シートは直接編集しない・操作はぜんぶ画面から」「正式表記は家計のポっ(小さい『っ』)」

## うまくいかないとき

- **画面が「アクセス権がありません」**: スタッフタブのメールがその人のGoogleアカウントと一致していない/「有効」チェック漏れ
- **Slackに何も届かない**: スクリプトプロパティ名が `SLACK_WEBHOOK_URL` と完全一致か確認(未設定だと通知だけスキップされ、保存は正常に動く)
- **メンションが飛ばない**: Slack User IDがメールになっている(Uで始まるIDに直す)
