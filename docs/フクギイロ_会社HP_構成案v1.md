## 1. 現行ホームページから学ぶこと(構成分析)

現行LP(もらいわすれ堂)の「安心の積み上げ」構造は会社HPにもそのまま効く:

| 現行LPの要素 | 効いている理由 | 会社HPへの流用 |
|---|---|---|
| 世界観フィルム(夜→朝の沖縄の物語) | 感情の入口。ただし重い(画像多) | ❌ 会社HPには不採用(軽さ優先)。写真1枚のヒーローで代替 |
| ヒーロー直下の microtrust(無料・匿名・登録不要) | CTAの不安をその場で消す | ⭕ 会社版に翻訳(「見積無料・売り込み電話なし」等、文言は決裁) |
| 創業の物語(なぜ始めたか+フクギ=防風林) | 会社の「顔」が見える。誠実さの背骨 | ⭕ **そのまま会社HPの主役に昇格**(現行LPでは1セクション) |
| 実績カウンター(検証済み制度数・照合率) | 数字は正直に。無いものは出さない | ⭕ seido.json連動の数字を流用+受託実績は「まもなく公開」方式 |
| 「情報サイトではありません」3ステップ | 何をしてくれるかが具体的 | ⭕ 各事業カードに「できること3つ」形式で継承 |
| 正確性へのお約束 | 断定しない誠実さの明文化 | ⭕ 会社版「お約束」に拡張(誇張しない・守秘を守る・断定しない) |
| FAQ+JSON-LD | 不安の先回り+SEO | ⭕ 会社版FAQ(「なぜB2Cは無料?」= 法人事業の収益で運営、は現行FAQと整合) |
| スティッキーCTA | 迷子防止 | △ 会社HPはCV圧を下げる(問い合わせは静かに)。導入見送り、効果測定後に再検討 |
| フッター(運営会社・保護方針・訂正窓口) | コンプライアンスの顔 | ⭕ 継承 |

## 2. ページ構成案(1ページ+既存下層への接続)

```

[1] ヒーロー
    ・一言: 「沖縄の家計と商いを守る、防風林でありたい。」(案・要磨き)
    ・サブ: フクギ=防風林の一文
    ・分岐ボタン2つ: 「県民の方へ(もらいわすれ堂)」/「事業者の方へ(制作・コンサル)」
[2] 理念(防風林の物語)
    ・現行LP story セクションの会社部分を昇格・再編集
    ・「フクギは、沖縄の集落を台風から守ってきた防風林の木…」(現行文を流用)
[3] 事業紹介(カード3枚。各カード=何をする/誰のため/できること3つ/リンク)
    ①もらいわすれ堂: 県民向け・無料/匿名 → site/fukugiiro/ へ
    ②webデザイン制作: 事業者向け・担当遥さん。「このサイト自体が制作例です」の一文
    ③システム経営コンサル: 事業者向け・担当小柳さん。ログ解析×教育で経営数字を動かす

    ・誇張しない(実績は事実のみ・無いものは「まもなく公開」)
    ・断定しない(不明は不明と言う)
    ・お客様の情報を守る(守秘・掲載は許可制)
[5] 実績
    ・もらいわすれ堂: 検証済み制度数・照合率(seido.json連動の既存実装を流用)
    ・制作/コンサル: 掲載許可の取れたものだけ。無い間は「まもなく公開」(現行カウンターと同じ正直方式)
[6] 会社概要(表)
    ・社名/設立(2026-07-24登記)/代表/所在地/事業内容(3事業)
    ・※代表名・所在地の公開範囲は決裁事項
[7] FAQ(3〜4問+JSON-LD FAQPage)
    ・「もらいわすれ堂はなぜ無料?」→ 法人向け事業の収益で運営(現行FAQと同一回答で整合)
    ・「小さな会社に頼んで大丈夫?」→ お約束(§4)への誘導
    ・「申請代行はする?」→ しない(現行と同一)
[8] お問い合わせ
    ・手段は決裁待ち(フォームは守り部審査が要るため、初版はメールまたはLINE案内を想定)
    ・県民の問い合わせが混ざらないよう「給付金のご相談はもらいわすれ堂へ」の振り分け1行
[9] フッター
    ・社名・タグライン・個人情報保護方針・訂正窓口・もらいわすれ堂へのリンク
    ・JSON-LD: Organization(3事業をdescriptionに反映。現行LPのOrganizationと整合させ重複させない)
```

## 3. 技術方針(現行と同じ・変える理由がない)

- 静的HTML+素のCSS/JS・依存ゼロ、GitHub Pages同乗。CSSカスタムプロパティでトークン化し**デザインイメージ確定後に色・フォントを一括差し替え**
- 性能予算: 初期表示150KB以下(会社HPはフィルム演出なしなので余裕)/ LCP 2.5秒 / 画像WebP+lazy
- a11y: 18px・行間1.8・コントラスト4.5:1・タップ44px(現行LP水準)
- 配置パス案: `site/fukugiiro-inc/`(もらいわすれ堂 `site/fukugiiro/` の下に置くとブランド混同するため兄弟パスにする)← 実装時に最終確認
- もらいわすれ堂LP側は不可侵(リンクはフッターの「運営: 株式会社フクギイロ」を会社HPへ張り替える1箇所のみ・実装時に決裁)

## 5. 三名体制議事(hojo-triangle-review)

## 論点: 会社HP構成案v1(現行ホームページ参考・3事業構成)の採否

### スイシン(推進)
- 現行LPで実証済みの「安心の積み上げ」構造(物語→お約束→正直な実績→FAQ)を会社HPに移植する構成。ゼロ発明がなく、実装も既存資産(トークン・seido.json連動・FAQ JSON-LD)の流用で速い
- 防風林の物語はもらいわすれ堂LPでは1セクションだが、会社HPでは主役に昇格でき、3事業を1本の理念で束ねられる

### ウタガイ(懐疑)  ← 空欄不可
- **配色の混同リスク**: 会社HPをもらいわすれ堂と同じ朱系にすると「会社=もらいわすれ堂」に見え、B2B2事業が霞む。逆に完全別色だとフッターの行き来で別会社感が出る。→ 仮置きは朱系としつつ、**デザインイメージ選定時の判断事項として明示**(§4)
- **実績空白のまま公開するリスク**: 制作・コンサル実績が「まもなく公開」だけだとB2Bの説得力が弱い。→ もらいわすれ堂の検証済み数字(実在の稼働実績)を会社実績として先に立てる構成で緩和。受注実績の掲載許可取りは人間タスク
- **代表名・所在地の公開**: 登記情報とはいえWeb掲載は問い合わせ・営業電話の窓口が個人に直撃する。公開範囲は決裁事項として構成に明記済み
- **スティッキーCTAの流用は逆効果**: B2Bの問い合わせは検討期間が長く、追いかけ型CTAは安っぽさ(=安心の毀損)につながる。→ 不採用を明記(§1)

### ベッカイ(別解)
- 1ページに3事業を詰めず、**事業別に下層ページを持つ**構成もある。→ 初版は1ページで公開し、問い合わせ・流入データを見て下層化を判断(過剰設計の回避)
- ヒーローの分岐を「県民/事業者」でなく「困りごとで選ぶ」(給付金をもらい忘れたくない/HPを作りたい/経営数字を良くしたい)にする別解。→ **一部採用**: 分岐ボタンは県民/事業者の2つを維持しつつ、事業カード3枚の見出しを困りごと起点の文言にする(例:「HPを作りたい」→webデザイン制作)

### 結論(部門長の裁定)
- 採否: **採用**(v1として確定。デザインイメージ確定後に§4を更新)
- 理由: ウタガイの4点はすべて構成内で対処済み(配色は判断事項化・実績は正直方式+既存数字・公開範囲は決裁化・追いかけCTA不採用)。ベッカイの下層ページは初版見送りで合意、困りごと起点の見出しは採用
- 見直し期限: 2026-11-11(公開後の問い合わせ実績で下層化・ブランド分離を再議論)
