# 議事: 公開成果物の設定ファイルを固定値に限定し、公開前に検査する

## なぜ(背景)

このリポジトリは公開されており、Pages の成果物もすべて公開される。
成果物の生成処理で設定値を埋め込む方式は、設定値が公開物に入る余地を残す。
公開物には固定値だけを置き、その内容を公開前に検査する方針とする。

## 前提

- 追跡中の設定ファイルは、固定の空設定である。
- 公開デプロイのジョブには、秘密の値を渡さない。
- サイトの通常の表示、データ更新(1日4回)、Pages の配信処理は変えない。

## 代替案

1. 設定値を暗号化して公開する: 復号の鍵が公開側に残るため採らない。
2. 設定値の埋め込みを残す: 公開物に値が入る余地が残るため採らない。
3. 埋め込みを廃止し、公開前に固定ファイルを検査する(採用)。
4. 送信機能を認証付きの方式に置き換える: 別工程として検討する(本議事の対象外)。

## 三名体制の議論

- **スイシン(推進)**: 埋め込みを止めれば、公開物に値が入る余地がなくなる。検査は既存の公開前検査と同じ位置に置くため、既存の配信処理を変えずに追加できる。
- **ウタガイ(懐疑・反対理由。必須)**: 固定ファイルの一致検査は、想定した形の混入しか検出できない。検査が失敗すると定期更新の公開がすべて止まり、データ鮮度の基準(24時間)を守れなくなる。また、この変更の効果は main に反映された後に初めて出る。
- **ベッカイ(別解・前提を疑う)**: 値の一致を見る方式も考えられるが、公開デプロイの工程に値を渡すことになるため採らない。外部サービスの URL の検出は誤検知の可能性があるため、最初は警告のみとする。

## 裁定

- 設定値を埋め込む手順を削除する。固定ファイルは変更しない(削除すると読み込みが失敗するため)。
- 公開前に、固定ファイルのハッシュを検査する。不一致または欠落なら公開を止める。
- 外部サービスの URL と、非空の設定値は警告のみとする。誤検知の確認後に、止める対象へ広げるかを判断する。
- 検査は公開物のアップロードの前に置く。公開デプロイの工程に秘密の値を渡さない。
- 効果の確認は main への反映後に行う。

## 実施記録

- 作業: 専用ブランチ `s3/ledger-injection-stop`(origin/main 基準)で実装。
- 検証(ローカル): 検査スクリプトの自己テストが成功。固定値との一致・不一致、警告の検出を確認。関連する単体テストと、既存の定期更新の静的テストが成功。
- 未実施: commit、push、main への反映、ワークフローの手動実行。

## 見直し条件

- 固定ファイルの内容を変えるときは、検査の期待値と本議事を同時に更新する。
- 警告の対象を広げるときは、誤検知の確認結果を記録する。
- 送信機能の方式を変えるときは、本議事を見直す。
