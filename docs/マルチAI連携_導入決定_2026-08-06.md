決裁: **小柳さん承認済み**(2026-08-06「進めて下さい。承認が必要なものは承認します」)
関連: docs/マルチAI連携セットアップガイド.md / scripts/verify_sources.py / .github/workflows/verify-sources.yml

## 論点: 原文照合パイプラインに Gemini による独立ダブルチェックを追加するか

### スイシン(推進)
- 検証部の毎日照合(5件サンプリング)は現在 Claude(Haiku)単独判定。別会社・別系統の Gemini を並走させれば誤りの相関が切れ、**絶対ルール1(正確性最優先)を仕組みで強化**できる
- 「どちらか一方が矛盾を検知したら NG」という保守的マージなので、見逃し(偽陰性)方向のリスクが確実に減る。締切・金額の誤掲載は事業の信頼を直撃するため、検知感度を上げる価値は大きい
- 実装は既存スクリプトへの関数追加のみ。GEMINI_API_KEY 未設定なら従来動作のままで、**後方互換・段階導入が可能**。無料枠から開始できコスト初期投資ゼロ
- 実行手順: ①コード変更(本日実施)②GitHub Secrets に GEMINI_API_KEY 登録(Google AI Studio で取得)③翌日の定時実行から自動でダブルチェック開始

### ウタガイ(懐疑)  ← 空欄不可
- **偽陽性ノイズの懸念**: 2つのAIで判定すれば NG になる確率は単純に上がる。表記ゆれを Gemini が「矛盾」と誤判定すれば Issue が増え、検証部が「またAIの誤検知か」と Issue を流し読みするようになる方が危険(オオカミ少年化)。導入後2週間は NG の内訳(真の不一致か誤検知か)を必ず人が確認すべき
- **外部ベンダー依存の増加**: Google のAPI仕様変更・料金改定・レート制限変更が照合パイプラインの新たな障害点になる。API障害時に照合全体を止めない設計(スキップ扱い)は必須条件
- **コストの青天井リスク**: 無料枠は変更され得る。現在は1日最大5件×1回で軽微だが、「効果があったから全件に拡大」した瞬間に費用構造が変わる。拡大判断は必ず費用見積りとセットで小柳さん決裁に戻すこと
- **APIキー管理面の攻撃面拡大**: Secrets が1つ増える。キーのスコープ・利用量アラート設定を怠ると不正利用に気づけない
- **本質的な疑問**: 照合NGの主因がAIの判定精度なのか、そもそも出典ページのHTML取得失敗・リンク切れなのか、データがない。判定AIを増やす前に NG 原因の内訳を取るべきではないか

### ベッカイ(別解)
- **別解1: Claude 単独のままサンプル数を5→15件に増やす**。ダブルチェックより「照合回数を増やす」方が検知総量は増えるのでは。→ ただし同一モデルでは同じ誤り方をするため、系統誤りは何件増やしても検知できない。目的が「系統誤りの検知」なら別系統モデルが必要
- **別解2: AIを増やさず機械照合の適用範囲を広げる**。県・公社ページも構造化抽出して厳密比較すれば AI 判定自体が不要になる。→ 自治体ページはHTML構造がバラバラで機械抽出の保守コストが高い。中期課題としては有効
- **前提への疑問**: 事業のボトルネックは今「データ正確性」ではなく「LINE登録→出口転換(真のKPI 月10件)」ではないか。ここに工数を使うより転換施策に使うべきでは。→ 本件は実装工数が小さく(1日)、正確性は信頼の土台のため両立可能と判断するが、**これ以上のマルチAI拡張は転換KPIへの寄与を説明できない限り優先しない**

### 結論(部門長の裁定)
- 採否: **採用**(小柳さん決裁済み)
- 理由: 実装コストが小さく後方互換で、正確性最優先(絶対ルール1)を仕組みで強化できる。ウタガイの懸念には次の運用条件で対応する:
  1. **導入後2週間は NG の内訳(真の不一致/誤検知)を検証部が毎回確認**し、誤検知が過半なら判定プロンプトを調整または一旦停止
  2. Gemini API 障害は NG にせずスキップ扱い(実装済み)。照合の可用性を外部ベンダーに依存させない
  3. **適用拡大(全件照合・SNS文面チェック等)は費用見積りとセットで小柳さん決裁に戻す**。無断拡大禁止
  4. Google AI Studio 側で利用量アラートを設定する
  5. ベッカイの指摘を受け、verify_report に NG 原因の内訳が蓄積されるため、2週間後のレビューで「機械照合拡大(別解2)」との比較も行う
- 見直し期限: **2026-11-06**(3ヶ月。効果測定の結果、検知精度向上が確認できなければ縮小・撤回を含め再議論)
