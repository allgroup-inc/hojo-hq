## 2. 商品と自動化マップ

| 商品 | 種別 | 生成 | 頻度 | 人間の作業 |
|---|---|---|---|---|
| 週刊 沖縄補助金 定点観測 | 無料(集客) | note-draft.yml → generate_note.py | 毎週月曜09:35 | 一読→貼り付け→公開記録追記 |
| AI編集長週報(週報+消えたもの図鑑+AI三人会議) | メンバー限定 | note-members.yml → generate_members_weekly.py | 毎週月曜09:50 | 一読→メンバー限定記事に貼り付け |
| 月刊 沖縄補助金白書 | メンバー限定(月次目玉) | monthly-report.yml → generate_monthly_report.py | 毎月1日09:40 | 一読→貼り付け |
| 単発記事(在庫化) | 有料 | 下書きは posts/note/tanpatsu/(初期2本は執筆済み。以降は月1本ずつ追加) | 月1 | 一読・微修正→価格設定→公開 |
| パートナー版白書 | note外(B2B) | monthly-report.yml | 毎月1日 | ムスブ経由で配布 |

**人間の定常作業は週15分**(月曜に無料+メンバー記事の承認貼り付け、X告知1本、noteの数字をKPI台帳へ入力)。

## 3. データ台帳(自動生成が読むファイル)

| ファイル | 中身 | 更新者 |
|---|---|---|
| data/note_kpi.json | フォロワー・会員数・月売上(noteの管理画面の実数のみ) | 人間(週1)。未入力は週報に「集計中」表示・推測値は出さない |
| data/sankai_topics.json | AI三人会議のお題キュー(初期5本入り) | 人間が随時追加(メンバーからの相談を転記。個別の法律・税務判断が要るお題は入れない) |
| data/gone_archive.json | 締切到来で消えた制度の累積(図鑑の収蔵品) | generate_note.py が自動追記 |

## 4. 公開ロードマップ(決裁済みの実行順)

1. **M1**: note開設 → 週刊vol.1公開 → 単発③(消えていく制度・780円)公開 → 単発①(AI社員17人・1,980円)公開
2. **M2-3**: フォロワーの初速を見て**メンバーシップ開設(980円)**。AI編集長週報の配信開始(下書きは開設前から自動で貯まる)
3. **M4以降**: 単発を月1本追加(次候補: 反対する係/B2B話材集)。白書はメンバー特典に統合
4. 価格・構成の変更は本ドキュメントを更新し、小柳さんの包括承認の範囲を超えるもの(値上げ・新提携)は都度決裁

## 5. 三名体制の短評(運営規程2・L2対応)

- **スイシン**: 供給(執筆)が完全自動化されたため、成否の変数は集客のみに絞られた。週15分の運用で月10万円ラインは費用対効果が明確
- **ウタガイ(反対理由の記録)**: ①集客(フォロワー月230人純増)が最大の未検証仮定であり、供給自動化は集客を1ミリも保証しない。X運用が止まればこの計画は静かに死ぬ ②KPIが手入力依存のため、入力が止まると週報の「集計中」が常態化し、有料連載としての信頼が下がる ③三人会議は生成品質の当たり外れがあり、検査不合格の週は「持ち越し」表示になる——連続すると連載の体裁が痩せる
- **ベッカイ**: 集客の別解として、単発①の実録ジャンルはnote内SEO・X拡散と相性が良く、「連載を育てる」より「単発を跳ねさせて会員に流す」を主戦略に置く方が初速が出る。よって公開順は連載充実より単発①③を先行させる(→ロードマップに反映済み)
- **裁定**: 採用。ウタガイ①はX告知を週次定常作業に明記+M3レビューでフォロワー実数を判定条件にする。②はKPI未入力2週連続でLINEリマインド(週報が「集計中」を表示し続けることで自然に検知される)。③は持ち越し設計(捏造して埋めない)を仕様として維持
