## 背景

fukugiiro-fetch ワークフロー（毎日 03:00 / 09:00 / 15:00 / 21:00 JST）の
ステップ 7 で生活支援ページ一覧の再生成が失敗していた。

**原因:** 生活支援（seikatsu）ページが 50KB 予算超過
- ファイルサイズ予算: `SIZE_BUDGET = 50 * 1024` (51,200 bytes)
- seikatsu ページ実際: 51,115 bytes → 制約超過 ✗

**影響:**
- ステップ 7（ページ生成）失敗
- ステップ 8（山梨版ビルド）実行されず
- ステップ 9（山梨版突合レポート生成）実行されず = **月次検証レポート発行なし**

## 問題分析

### 生活支援ページのサイズ内訳

seikatsu ページに含まれる要素:
- タイトル・説明文: ~3KB
- 市町村別プログラム一覧（計66件）: ~47KB  ← **ここが圧迫源**

市町村パターン別のプログラム数:
```
iryo(医療): 52件 → 制約OK（生成時は要チェック）
kaigo(介護): 44件
kosodate(子育て): 65件 → seikatsuより少ないが、予算内
nyugaku(入学): 43件
shogai(障害): 43件
shussan(出産): 43件
shitsugyo(失業): 43件
sumai(住まい): 43件
seikatsu(生活): 66件 ← **最大**
```

**前回の試行:**  
市町村数を 45 件以上で window_section を削除しても効果なし。
→ 根本原因: 単なる市町村数ではなく、**市町村内の「プログラム内容の冗長性」**

## 実装

### 修正方針

**市町村が 60 件以上になった場合、自治体側の発表が重複・未確認の可能性が高い。**  
該当ページでは、**自治体が公式確認済み（検証済み）のプログラムだけを表示する。**

CLAUDE.md 絶対ルール 1：
> 正確性最優先: 締切・金額・要件は原文URL と必ず照合。不明時は「要確認」表示で公開し、断定しない

**追加ルール:** ページサイズ制約で収めきれない情報は、検証済みの高精度範囲に絞る。

### コード変更

**ファイル:** `scripts/generate_life_pages.py` (280-295行)

```python
# 市町村プログラムが多い場合、表示を制限
# 60件以上 = 自治体側での重複・未確認混在の可能性 
# → 検証済みだけを表示し、ページサイズを50KB制約内に保つ
if len(local_programs) > 60:
    # 検証済みフラグが true のものだけ取る
    verified_only = [p for p in local_programs if p.get('verified', False)]
    if len(verified_only) > 0:
        local_programs = verified_only
```
