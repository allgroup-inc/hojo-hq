## 1. 何をつくるか(今までにない内容)

**日本のどのメディアもやっていない「補助金データジャーナリズム」を、noteで週刊連載する。**

当サイトは沖縄で唯一、国API+県・市町村サイトを毎日巡回してAIで構造化した「生きた制度DB」を持つ。
このDBの**週次差分**そのものが、他の誰にも書けない一次情報コンテンツになる。

### 連載名: 週刊「沖縄補助金 定点観測」(AI編集部が毎週自動執筆)

| コーナー | 内容 | なぜ今までにないか |
|---|---|---|
| 今週の数字 | 掲載制度数・新着数・消滅数・締切接近数 | 制度の「増減」を定点観測する媒体は存在しない |
| 新着ピックアップ | 今週DBに現れた制度(締切30日以上のみ・最大5件) | 公式発表より早く「まとめて」届く |
| 今週消えた補助金 | 締切到来・公募終了でDBから消えた制度の記録 | 「消えた制度」を弔う媒体はない。もらい損ねの実感=登録動機 |
| 公募上限額 合計(参考値) | 掲載中・上限1億円以下・公表分の合計 | 議事_総額ポテンシャル表示のルールを完全準拠 |
| AI編集後記 | Claude(AI編集長)による短評。事実は本文の数字のみ参照 | 「AIが毎週書いている」こと自体を透明に見せるメタ性 |

### note を選ぶ理由(Instagram・LINEとの役割分担)
- Instagram=フロー(発見)、LINE=クローズド(転換)に対し、**note=ストック(検索・引用・信頼)**。
- 「沖縄 補助金」系の検索・SNSシェアで長期に効く資産になり、士業・金融機関への提携営業時の「実績見本」にもなる。
- 経営者・士業読者が多いプラットフォームで、B2Bの信頼形成に向く。

## 2. 自動化の範囲(重要な前提)

**生成は全自動・公開はワンアクション(コピペ)。**

noteには記事投稿の公式APIが存在しない。非公式APIやブラウザ自動操作での自動投稿は
note利用規約に抵触するおそれがあり、絶対ルール2(守り部の事前承認なしにクロール/自動操作をしない)により**採用しない**。

```
毎日06:00/09:00… データ更新(既存 update.yml)
        ↓
毎週月曜 09:35 JST  note-draft.yml が起動
        ↓
scripts/generate_note.py が前週スナップショットと差分を取り
posts/note/YYYY-MM-DD_volN.md を全自動生成(AI編集後記はClaude API)
        ↓
LINEでたかしくん・小柳さんへ「下書きできました」通知
        ↓
人間が内容を一読 → noteにコピペして公開(週5分)
```

人間の作業は**週1回・約5分**。事実確認は不要(締切・金額・URLはDB=原文照合済みの値をそのまま転記)だが、
公開前の一読は三名体制ルール5(定型業務も週次抜き取り点検)の実施を兼ねる。

## 3. 憲法(CLAUDE.md)準拠の設計

| ルール | 本設計での担保 |
|---|---|
| 正確性最優先 | 数字はすべて data/subsidies.json(原文照合済み)から機械転記。上限額 0/未公表は「要確認」表示。AI編集後記は新しい事実・数字の生成を禁止し、禁止語(必ず/絶対/誰でも)検査に落ちたら定型文へフォールバック |
| 締切3層ルール | 記事で制度名を出して紹介するのは**残り30日以上のみ**。30日未満は件数のみ+「LINEアラート(締切の約1か月前から)」への誘導。消滅コーナーは過去の事実の記録であり勧誘ではない |
| 法務(守り部) | noteへの自動投稿は行わない(上記)。掲載内容は自社DBの転記のみで他媒体の転載なし |
| CV単一 | 記事内CTAはLINE登録(サイト経由)のみ。UTM: utm_source=note&utm_medium=article&utm_campaign=teiten |
| 最終決裁 | note開設・公開開始は小柳さん決裁後。それまではリポジトリ内に下書きが貯まるだけで外部公開されない |

## 4. 三名体制の論点(スイシン/ウタガイ/ベッカイ)

### スイシン(推進)
- 差分データは毎週自動で湧く「無限のネタ」。工数ほぼゼロで検索流入KPI(200社)に効く新チャネルが立つ。
- 「AIが毎週書く定点観測」はそれ自体がニュースバリューを持ち、士業・金融機関への提携営業の名刺になる。
- 実装は既存資産(subsidies.json・LINE通知・Actions)の組み合わせのみで、新規固定費0円。

### ウタガイ(懐疑・反対理由の記録)
1. **noteに投稿APIがない以上「自動化」は看板倒れ**。コピペ担当が止まれば連載が止まる。Instagramが「FB開設以来投稿0本」だった前例があり、人間ボトルネックの再発リスクが高い。
2. **AI生成文と明かすことは信頼の毀損リスク**にもなり得る。補助金情報は正確性が命であり、「AIが書いた」と聞いて不安に思う経営者層は一定数いる。
3. 検索流入KPIへの寄与は不確実。noteのSEOは自社ドメインに寄与せず、**育てた資産がnote社のドメインに残る**(プラットフォーム依存)。
4. 週次差分が少ない週(新着0・消滅0)は記事が痩せ、連載の体裁が崩れる。

### ベッカイ(別解・前提を疑う)
- 「自動投稿できないなら自動化ではない」という前提を疑う。ボトルネックは執筆(週2〜3時間)であり、そこが0になれば**コピペ5分は許容誤差**。承認ゲート(social-post.ymlと同じ思想)として機能する分むしろ健全。
- 信頼リスクへの別解: 「AIが書き、人間(たかしくん)が読んでから出す」体制を記事フッターに明記する。隠すのではなく**検品体制ごと開示**すれば透明性は信頼に転じる。
- プラットフォーム依存への別解: 記事は必ずサイト誘導CTAを含み、**同じMarkdownをサイト側にも掲載できる形式**で生成する(将来 site/column/ へ流用可能)。noteは入口であり資産の正本はリポジトリに残る。
- ネタ枯れ週への別解: 差分ゼロでも「今週の数字」「総額参考値」「締切接近ゾーン」は毎週必ず動く。差分ゼロ自体を「今週は静かな週でした」と定点観測として書けばよい。

### 部門長の裁定
- 採否: **採用(条件付き)** — 実装を完了し、公開開始のみ小柳さん決裁にかける
- 理由: スイシンの費用対効果(固定費0・工数週5分)は明白。ウタガイ懸念1(人間ボトルネック)は、LINE通知+週5分のワンアクション化+週次レポでの掲載状況監視(アカリさん)で最小化する。懸念2はベッカイの「検品体制ごと開示」を採り、全記事フッターに「AI自動生成+人間確認」を明記。懸念3はベッカイの「正本はリポジトリ」方式で緩和。
- ウタガイ懸念1が現実化した場合(4週連続で下書き未公開)は、アカリさんが週次レポでボトルネック報告し継続可否を再議論する
- 見直し期限: **2027-01-31**(6ヶ月。note経由の流入・LINE登録寄与をUTMで計測し、寄与ゼロなら撤退)

## 5.5 公開時の記録ルール(運営規程2のL2対応・2026-08-01追加)

公開・配信物には3役短評の記録が省略不可(三名体制運営規程2)。noteへの公開1回ごとに次を行う:

1. 公開したら、該当の `posts/note/*.md` の**先頭に次の3行+公開URLを追記してコミット**する(たかしくん)

```
<!-- published: https://note.com/…(公開URL) 2026-08-03
スイシン: 内容確認済み・数字はDB転記のとおり
ウタガイ: 締切・金額・URLを◯件抜き取り照合、問題なし(あれば記載)
ベッカイ: 構成・表現の改善案があれば1行(なければ「なし」) -->
```

2. この追記が**4週連続でない場合**(=下書きが公開されていない)、アカリさんが週次レポでボトルネック報告し継続可否を再議論する(裁定条件の実装)
