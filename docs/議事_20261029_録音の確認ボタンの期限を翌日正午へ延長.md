# 議事 2026-10-29 録音の確認ボタンの期限を翌日正午へ延長

- 起案: ❶システム関係全般(本セッション)
- 決裁: 小柳さん(2026-10-29「翌日の正午まで延ばしてください」)
- 区分: ②閾値・ルールの変更

## 背景
- 録音を要約すると、担当者のLINEに確認ボタン(会社の選択→内容の確定)が届く。これまでは**2時間**押されないと自動で取り消していた。
- 10/27〜10/28、福田さんの録音が3回取り消された(10/27 18:23・19:07、10/28 19:41)。夕方に届く・外回り中で、2時間では押せなかった。
- 原因はもう1つあった。福田さんは会社名を文字で返していたが、仕組みがボタンしか受け付けていなかった(10/28 に文字入力を受け付けるよう修正済み。docs/議事_20261026_録音ファイルの受付と要約の関係メモ追記.md の追記その3)。

## 論点: 確認を待つ期限をどこまで延ばすか

### スイシン(推進)
- 期限を「確認を送った日(日本時間)の翌日の正午」にする。夕方に届いても翌朝に押せる。
- 担当者が文字で返事をしたら、その時点から数え直す(既存の仕組み)。

### ウタガイ(懐疑)
- **確認待ちが長く残ると、その担当者の次の録音が止まる。** 確認待ちは担当者ごとに1件ずつにしたため、押されない1件が翌日の正午まで後ろを止める。
  → 止まるのは同じ担当者の録音だけで、録音は消えずに順番を待つ。文字で返事できるようにしたので、押せないまま止まる場面は減る。様子を見て、詰まるようなら「新しい録音が届いたら古い確認を後回しにする」等を検討する。
- **翌日になると、何の話だったか担当者が忘れている。** 内容の確認が甘くなり、誤った会社に記録されるおそれがある。
  → 確認画面に会社名・種別・要約・次回アクションを出しており、確定前に読める。誤りは台帳で訂正できる。
- **期限が延びたぶん、取り消しに気づくのも遅れる。**
  → 取り消しても録音は残り、管理者が送り直せる(既存)。

### ベッカイ(別解)
- 期限を設けず、押されるまで待つ案。次の録音が止まり続けるため採らない。
- 取り消す前にLINEで催促を1回送る案。通知が増えるため、今回は見送る(詰まりが続けば再検討)。

### 結論(裁定)
- 採否: 採用(小柳さん決裁。実装: glow-ma/src/voiceFileIntake.js の confirmDeadlineMs、テストは tests/glow_ma_voice_file_intake.test.mjs)
- 見直し期限: 2027-04-29(取り消し件数・確認までの時間・詰まりの有無を見て再評価)

## 追記(2026-10-30): 取り消しを点検で見えるようにした
- 10/30 正午の期限を過ぎた後、福田さんの録音2件が確認されたのか取り消されたのかを、点検(glow-ma-gcp-api)で確かめられなかった。取り消しの記録を `Logger.log` に出しており、Cloud Logging に残らないため。
