# 家計のポっ リハーサル台本(2026-08-19)

本番投入の前に、**アポが入った瞬間に登録し、全員が同じ画面を見ながら回す**流れを実機で確かめるための台本。
Google設定もSlack設定も不要。お試し版のURLを配れば、その場で全員が同時に触れる。

## 使うもの

**お試し版**: <https://claude.ai/code/artifact/b0bb8475-6f90-4585-95d9-f2ddae6c56f8>

- 画面もサーバ処理も**本物と同じコード**が動く(ダブルブッキング検知・遅れ通知の相手・代打候補・
  変更差分は本番と同一の処理)
- 疑似にしているのは2つだけ: **保存されない**(再読込で最初に戻る)/ **実際のSlackには送らない**
  (画面下の黒いバーに「こう飛びます」と出る)
- 画面上部で**操作する人を切り替えられる**(アポ花子/営業一郎/営業二郎/営業三郎)。
  アポ入れ係の見え方と営業の見え方を行き来できる

**架空のアポが約45件、5営業日分入った状態で始まる**(2026-08-22 に厚くした)。
全員が同じ初期状態から始められる。

うまくいっている状態だけ見ても、設計の穴は出ない。**わざと困った状態を混ぜてある**。

| 混ぜてあるもの | どこ |
|---|---|
| 時間が重なっているアポ | 営業二郎の2営業日後 |
| 差し戻しが続いて午前が抜けた日 | 営業三郎の本日 |
| 1人だけ終日空きの日 | 営業四郎の3営業日後 |
| 行き先が空のアポ / 担当営業が空のアポ | 翌営業日 |
| 架電禁止(対象外)の相手 | 営業三郎の3営業日後 |

ステータス9種すべてが1件以上入っている。90分以上の空きも自然に残してある。

## 進め方(50〜60分・全員がスマホで開く)

司会は小柳さん。**各場面で「思っていた動きと違う」と感じたらその場で言ってもらう**。
その一言が改善点になる。以下の台本を上から順に。

### 場面1: アポが取れた(5分)

1. 全員、画面上部の「操作する人」を **アポ花子** にする
2. アポ花子役が「＋新規アポ」→ 明日ではなく**今日の空いている時間**で1件登録
   (顧客名は架空で。例: 「リハーサル商事 新垣様」)
3. **担当営業は選ばないと保存できない**。誰かを選んで保存
4. 全員が画面下の黒いバーを開いて、飛んだ通知を見る

**確かめること**
- 登録に何秒かかったか(遅ければ入力項目が多すぎる)
- 通知の文面で、担当営業が「自分に来た仕事だ」と分かるか
- 一覧に出た行を見て、どこへ行くか一目で分かるか

### 場面2: 続けて何件も入れる(5分)★ここが一番大事

**アポ入れ担当が、連続で10件入れてください。** 1日100件を想定した設計なので、
ここで詰まるなら投入前に直す価値があります。

1. 「＋新規アポ」→ 入力 →**「保存して続けて登録」**を押す
2. 日付・担当営業・アポ入れ担当・形式が残ったまま、顧客名だけ空になり
   カーソルが顧客名に入ることを確認
3. **そのまま10件**入れてみる。途中で止まったらその場で言ってください

**機械で測った実測値(2026-08-22)**

| | 1件あたり |
|---|---|
| タップ・選択 | **2.3回**(時刻・保存ボタン・ほか) |
| 文字入力 | **12文字**(顧客名+場所) |

予定がゼロの日で10件入れて、10件とも保存されました。
**この数字より現場が遅いと感じたら、原因はタップ数ではなく別の所にあります。**
その「別の所」を教えてください。

**確かめること**
- 10件入れ終わるまでに何分かかったか
- 引き継いでほしい項目が他にないか(いまは日付・担当営業・アポ入れ担当・形式)
- **重なりの警告が出たとき、気づけたか**(下記)

### 場面3: 同じ営業に時間が重なった(3分)


1. すでに登録済みのアポと**同じ営業・同じ時間帯**で、わざと新規登録してみる
2. 警告が出ることを確認。**そのままもう一度押すと登録できる**ことも確認
3. 「保存して続けて登録」で連続入力している最中にも、同じことをやってみる

**確かめること**: 警告の文で「何とぶつかっているか」が分かるか。止められると困る場面はないか

> **2026-08-22 に実測で見つけて直した2件**
> ・警告文の顧客名が「田中様様」になっていた(通知側は8/19に直したが、警告文に残っていた)
> ・連続登録中なのに「もう一度**保存して通知**を押してください」と出ていた。
>   押していたのは「保存して続けて登録」なので、手が止まる。押したボタンを名指しするようにした。
>   あわせて、警告が画面外に出ていて気づけない問題も直した(自動で画面内へスクロール)

### 場面4: 前が長引いて遅れそう(5分)

1. 操作する人を **営業一郎** に切り替える
2. 自分の最初のアポをタップ →「遅れそう」→ **+30分**
3. 通知を全員で見る

**確かめること**
- 遅れる人として**正しい名前**が出ているか
- 影響するアポの一覧に、**そのアポ自身**と後続が出ているか
- 「時刻は自動で変わらない」ことに違和感がないか(お客様への連絡は人がやる前提)

### 場面5: 訪問に至らず差し戻し、代打を探す(7分)

1. 営業一郎のアポをタップ →「差し戻し(顧客都合)」
2. 通知に**代打候補**が出る。空いている営業と、その前後の訪問先が並ぶ
3. 地図リンクを実際にタップして開いてみる

4. もう1件を「差し戻し(**自社都合**)」にして、一覧の見え方の違いを見る

**確かめること**
- この情報で「誰に頼むか」を判断できるか。足りない情報は何か
- 代打を頼む連絡は誰がやるか(いまは人がやる設計)。ここを自動にしたいか
- **顧客都合と自社都合を押し分けられるか**。自社都合は「他のお客様に使えたはずの
  訪問枠を捨てた」損失なので分けている。※この数字は**人事評価には使わない**

### 場面6: 訪問して結果を入れる(5分)

1. アポをタップ →「訪問済」、別のアポは「申込」

   ※「訪問済」「申込」は本来**対面営業マン物件管理システム側で押す**もの。
   そちらとの連携が通るまでの暫定でここに置いている(連携後はこの2つのボタンは消え、
   表示だけになる)
2. 「分析」タブを開いて、埋まり状況と転換ファネルを見る

**確かめること**
- 結果の入力を、その日のうちに押す習慣がつきそうか(押されないと数字が死ぬ)
- 分析の数字が、判断に使える形になっているか

### 場面7: 「手当てが要るもの」を見る(5分)

画面を開いた一番上にある枠。**探さなくても、手当てが要るものが出ている**状態にした。

1. いま何件出ているか、全員で見る
2. 1行タップすると、そのアポが直接開くことを確認
3. 場面6で結果を入れずに残したアポが、しばらくすると「結果待ち」に出てくることを確認
   (訪問の終了から90分過ぎたものが対象)

**確かめること**
- ここに出ているものを、朝いちで上から片付ける運用が回りそうか
- **出すぎていないか**(多すぎると読み飛ばされて、埋もれているのと同じになる)
- 逆に「これも出してほしい」ものはあるか

### 場面8: 空いている枠を見る(3分)

本日ビューの一番下。明日から7日分の、90分以上まとまった空きが営業ごとに出る。

**確かめること**: アポを入れるときに、ここを見て決められるか。90分という区切りは妥当か

### 場面9: 全体を一目で見る(5分)

上の「全体」タブ。**朝礼・夕礼でこの1画面を見ながら話せるか**を確かめる場面。

1. 上の帯を見る。誰がいつ動くか、どこが空いているか、いまの時刻(縦の赤い線)
2. 帯をタップするとそのアポが開くことを確認
3. 下の表を見る。**「結果待ち」の列**が、その日の記録が追いついているかの目印

**確かめること**
- 朝礼でこれを見せながら段取りを決められるか
- 夕礼で「結果待ち」がゼロになるまで押す、という運用が回りそうか
- スマホだと横スクロールが要る。事務所のPCで見る前提でよいか

### 場面10: 全員で今日を眺める(5分)

1. 操作する人を切り替えながら、「自分のアポ」と担当者チップで絞り込む
2. 「週」タブも開く

**確かめること**: 朝礼でこの画面を見ながら段取りを決められるか。足りないビューはないか

## 記録の仕方

出た意見は**その場でメモするだけ**でよい。整理はこちらでやる。

| 場面 | 誰が | 何が起きた/困った | 期待していた動き |
|---|---|---|---|
| | | | |

チャットに貼ってもらえれば、**直せるものと直さないものに仕分けして、直せるものから直す**。

## 2026-08-21の変更(共通語彙への移行)

軸の裁定を受けて、ステータスの言葉を5システム共通のものに揃えた。
**前に触った人は言葉が変わって見える**ので、リハーサル前に一読を。

| 前 | 今 |
|---|---|
| 予定 / 再調整中 | スケジュール調整中 |
| 確定 | アポ確定 |
| 実施済 | 訪問済(❸が持つ・暫定でここでも押せる) |
| 申込み | 申込(❹が持つ・暫定でここでも押せる) |
| キャンセル(顧客都合/自社都合) | 差し戻し + 理由(顧客都合/自社都合) |

**枠の扱いが1つ変わった**: 旧「再調整中」は枠が空く扱いだったが、
「スケジュール調整中」は**枠を押さえたまま**になる(調整の途中で他アポに枠を取られると
調整が破綻するため)。本当に流れたら**差し戻し**にして空ける。

## このリハーサルで先に見つかったこと(2026-08-19・修正済み)

台本を作る過程で私が一通り通したところ、3件の不具合が出た。いずれも修正済み。

1. **顧客名が「田中様様」になっていた** — 現場は「サンプル商店 田中様」と敬称込みで入力するのに、
   通知側でも「様」を足していた。通知では敬称を足さない形に変更
2. **アポ入れ係が登録すると、担当営業に自分(アポ入れ係)が入っていた** — 営業でない人が
   登録したときは未選択にし、選ばないと保存できないようにした(通知先が決まらないため)
3. **地図リンクが記法のまま見えていた** — 実際のSlackではリンクとして表示されるので、
   デモの通知パネルでも同じ見え方になるよう修正

**実際に触ると、テストでは出ない問題が出る**という良い例だった。リハーサル本番でも同じことが起きるはず。
