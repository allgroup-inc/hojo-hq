# 受託時情報管理規程(共通)draft v1

**ドラフト(小柳さん決裁前・数値は全て仮)**
**本書は守り部が起案するドラフトであり、施行前に守り部審査→弁護士確認を必須とする。確認前の本規程を根拠に受注しない。**

適用範囲: フクギイロが受託する全商品(SNS運用代行・LINE構築パック・補助金ウォッチPro・有料診断・催事ログ解析ほか)で、顧客のSNSアカウント・LINE公式アカウント・データ(顧客情報・成績情報等)を預かる業務。
契約主体: **フクギイロ経由の法人契約のみ(個人契約は行わない)**。
Grp資産を用いる受託は 2026-07-31 嶺井さん・遥さん了承済み(覚書等の書面化は税理士・弁護士確認の流れで別途)を前提とする。

## 1. アクセス管理
1. 顧客アカウント(FB/IG/LINE等)は**顧客名義を原則**とし、当方は運用に必要な最小権限のみ付与を受ける(管理者権限の譲渡は受けない)
2. 認証情報(トークン・パスワード)は共有パスワードマネージャーまたはSecrets(GitHub Actions等)でのみ保管。平文でのチャット・メール・スプレッドシート記載を禁止
3. アクセス権者は案件ごとに台帳(顧客名/対象アカウント/権限範囲/付与日/権者)で管理し、四半期ごとに棚卸しする
4. 二要素認証を当方側アカウントに必須とする。顧客側にも推奨し、導入手順を提供する
5. 検証・開発では実データを使わず、仮名化(HMAC仮名化トークナイザ等)またはダミーデータを用いる

## 2. 担当者の退職・離任時
1. 退職・離任の決定後**5営業日以内**(仮)に、当該者の全顧客アカウント権限・パスワードマネージャー・Secretsアクセスを失効させる
2. 当該者が単独で保持していた認証情報(トークン等)は失効・再発行し、顧客に権限変更を通知する
3. 台帳に失効日と実施者を記録する。秘密保持義務は退職後も存続する旨を雇用・業務委託契約に定める

## 3. 解約・契約終了時のデータ返却/削除
1. 解約日から**14日以内**(仮)に、預かりデータを顧客指定形式で返却し、当方保有分(バックアップ含む)を削除する
2. 削除完了後、削除した対象と日付を記した**削除報告**を顧客に交付する
3. 法令上保存義務のあるもの(請求関係書類等)は除外し、除外範囲を契約書に明記する
4. 顧客アカウントの権限は解約日をもって返却(自己解除)し、顧客に確認を依頼する
5. 台帳・仮名化トークンの対応表も同期限で削除対象に含める

## 4. 事故時(漏えい・誤投稿・不正アクセス等)の報告
1. 検知後**24時間以内**(仮)に第一報を顧客へ行う(判明している範囲でよい。全容判明を待たない)
2. 同時に守り部へ報告し、二次被害防止措置(権限停止・トークン失効・投稿削除)を最優先で実施する
3. 個人情報漏えい等、個人情報保護法上の報告対象に該当しうる場合は、**個人情報保護委員会への報告・本人通知の要否を弁護士に即時確認**する(該当判断を自社で断定しない)
4. 事故は全件ニドナシ機構へ回付し、再発防止策の記録・真因分析・監視を行う
5. 顧客への続報は5営業日以内(仮)に原因・影響範囲・再発防止策を書面で提出する

## 5. 受注前チェック(各商品共通の開始条件)
- [ ] 本規程の施行(守り部審査+弁護士確認完了)
- [ ] 顧客とのNDA・業務委託契約(責任範囲・賠償上限・免責を弁護士確認済み雛形で)
- [ ] 預かるデータ項目の棚卸しと個人情報該当性の判定(守り部)
- [ ] 高感度データ(成績・健康・金融等)を含む案件は外部セキュリティ/個人情報専門家の確認(催事ログ解析等)

## 6. 三名体制議事(本規程ドラフトの妥当性)

### スイシン(推進)
- ★1★2の開始条件(増設プラン・ガバナンス3項)を1本の共通規程で満たせる。既存資産(HMAC仮名化・コード隔離ランブック・ニドナシ機構)を組み込んでおり、ゼロから作るより実効性が高い

### ウタガイ(懐疑)
- 日数・期限(5営業日/14日/24時間)は全て仮置きで、法的要求水準(個人情報保護法の報告期限等)との整合を確認していない。**弁護士確認前に「規程がある」と称して受注するのが最大のリスク**であり、ドラフトの存在がかえって着手を早める危険がある
- 賠償上限・保険(サイバー保険等)の手当てが未検討。規程はあっても事故時の資力の裏付けがない
- 運用負荷(台帳・四半期棚卸し)が小規模チームで回るかは未検証で、形骸化すれば無いより悪い

### ベッカイ(別解)
- 自前規程でなく、**プライバシーマーク/ISMSの簡易版チェックリストや業界標準雛形をベースに弁護士へ持ち込む**方が、確認コストが下がり抜け漏れも減る可能性がある
- 事故報告はニドナシ機構回付だけでなく、決裁キューへの自動起票(小柳さん可視化)まで含める案

### 結論(提案・小柳さん上申)
- 採否: **提案・上申** — 本ドラフトを守り部審査→弁護士確認に回すことを提案する。ベッカイの「標準雛形との突き合わせ」を弁護士確認の依頼事項に含め、ウタガイの指摘通り**確認完了までは本規程を開始条件を満たしたものとして扱わない**
- 理由: 規程の中身よりも「確認前に受注しない」統制の方が重要であり、ドラフト先行はその統制と両立する範囲でのみ有効なため
