# 議事: 併給(ダブり)チェックの常設態勢(2026-08-25)

- 分類: 議事必須類型①(小柳さん指示事項)+②(掲載ルールの追加)
- 発端: **2026-08-25 小柳さん指示**「一つの制度を申請した場合、もう一つ申請している制度が
  ダブりでは適用されない可能性があるものは、常に確認する態勢をお願いします」

## 現状把握
- スキーマには combine(exclusive/adjust/stackable+注意文)が既にあり、申請シート
  (kit)と診断結果(shindan)は3色ラベルで表示済み。ただしデータの充足が57/225件(25%)で、
  「シードを書いた人が気づいた場合だけ付く」属人的な状態だった。

## 三名体制の議論
- **スイシン**: リスクグループ(医療費助成・給食費×就学援助・補聴器×補装具費・介護慰労金×
  介護保険・出産応援の重複受給・住居確保×生活保護・職業訓練給付の併給・児童扶養手当×年金・
  減免の重複適用 等)をキーワードルール化し、fetch時に自動付与すれば、新規追加分にも常に付く。
- **ウタガイ(反対理由)**: ①機械の一括文面は個別制度の実際の併給ルールと食い違う恐れがある。
  断定調は絶対に不可。②「注意が付いていない=併用できる」という誤読を生む恐れがある。
  ③グループ外の見落とし(キーワードに掛からない併給関係)は残る — この仕組みで「完了」と
  言ってはならない。
- **ベッカイ**: 全制度に一律の汎用注意を出す案(最も安全)もあるが、全件に同じ文言が並ぶと
  警告が風景化して読まれなくなる。個別ルール+シート既存の「窓口でご確認ください」動線の
  二段構えが妥当。

## 裁定(実装)
1. `scripts/fg_combine.py` 新設: 12のリスクグループをキーワード定義し、combine未設定の
   該当制度に**非断定の注意文**(「〜場合があります」+「窓口でご確認ください(要確認)」)を
   fetch時に自動付与。**シード側の個別combineが常に優先**(ウタガイ①を採用: 個別調査済みの
   記述を機械文で潰さない)。
2. `validate_fukugiiro.py` に付け漏れ警告(リスクグループ該当なのにcombineなし)を追加。
   自動付与の配線が外れたら毎回の検証で検知される(安全網)。
3. 文面は全て「場合があります」調で、断定・網羅の主張はしない(ウタガイ②対応: 注意が無い
   制度についても、シート側の常設文言「金額・締切・対象は窓口でご確認ください」が引き続き働く)。
4. 拡充ループ(週2 Routine)は従来どおり新規シードのcombineマッピングを手順に含み、
   ルールに掛からない個別の併給関係はサイクルごとに調査・追記する(ウタガイ③対応:
   本仕組みは「底上げ」であり網羅の保証ではない、と本議事に明記)。
- 効果: 再構築後、併給注意つき制度が **57件 → 141件(63%)** に増える見込み。
- 見直し期限: 2027-02-25(6ヶ月)。文面が実際の制度と食い違う報告が出たら即時修正。

## 運用メモ
- グループ追加は fg_combine.py の RULES に1行足すだけ。文面は必ず非断定で。
- 個別制度で正確な併給関係が判明したら、シード側に combine を書く(機械文より優先される)。
