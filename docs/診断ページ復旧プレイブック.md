# 診断ページ復旧プレイブック

**目的**: 診断ページが「データ読み込み失敗」を表示した場合の完全な復旧手順。自動化の失敗時にも対応できるよう設計済み。

**最終更新**: 2026-10-31  
**責任者**: 技術チーム  
**見直し期限**: 2027-04-30  

---

## 🔍 Step 0: 診断（What went wrong?）

### 0-1. ページの動作確認
```bash
# 本番ページにアクセス確認
curl -s https://moradou.jp/shindan/ | head -50 | grep -i "error\|loading\|failed"
```

### 0-2. ブランチの状態確認
```bash
cd /path/to/hojo-hq
git fetch origin main
BRANCH=$(git rev-parse --abbrev-ref HEAD)
COMMITS_BEHIND=$(git rev-list --count HEAD..origin/main)
echo "Branch: $BRANCH"
echo "Commits behind main: $COMMITS_BEHIND"
```

### 0-3. 生成ファイルの確認
```bash
ls -lh site/fukugiiro/shindan/index.html
file site/fukugiiro/shindan/index.html
wc -c site/fukugiiro/shindan/index.html
```

**診断結果フロー:**
```
COMMITS_BEHIND > 3?
  ├─ YES → Step 1: ブランチ同期
  └─ NO → 生成ファイルが欠けてる?
      ├─ YES → Step 2: ファイル復旧
      └─ NO → Step 3: デバッグ
```

## ✅ Step 1: ブランチ同期（Branch is behind main）

**症状**: ブランチが main から 3 コミット以上遅れている

**原因**: 
- ワークフロー failure（Slackに通知済みまたはGitHubイシュー自動作成済み）
- 手動操作でコンフリクト解決中に取り残された

### 1-1. 自動ワークフロー実行（推奨）
```bash
# GitHub CLIで自動実行（最安全）
gh workflow run daily-sync-branches.yml

# または手動トリガー: GitHub Actions 画面から
# https://github.com/allgroup-inc/hojo-hq/actions/workflows/daily-sync-branches.yml
```

**待機**: 3〜5分で完了。完了後は Step 3 へ進む

### 1-2. 手動同期（ワークフロー失敗時）
```bash
# ローカルで手動実行
git fetch origin main
git checkout -B $(git rev-parse --abbrev-ref HEAD) origin/main

# 検証
ls -lh site/fukugiiro/shindan/index.html

# プッシュ
git push -u origin $(git rev-parse --abbrev-ref HEAD)
```

## 📁 Step 2: ファイル復旧（Files missing）

**症状**: `site/fukugiiro/shindan/index.html` などが存在しない

**原因**:
- ブランチが main から乖離し、生成ファイルが古い
- merge/rebase 中に誤削除された

### 2-1. Main から復旧
```bash
git fetch origin main

# 最新の診断ページを直接取得
git checkout origin/main -- site/fukugiiro/shindan/index.html
git checkout origin/main -- site/fukugiiro/index.html
git checkout origin/main -- site/fukugiiro/area site/fukugiiro/kit site/fukugiiro/life

# 確認
ls -lh site/fukugiiro/shindan/index.html

# コミット
git add site/fukugiiro/
git commit -m "復旧: 診断ページファイルを main から復元"
git push -u origin $(git rev-parse --abbrev-ref HEAD)
```

### 2-2. ファイルが Main にもない場合
```bash
# 最新の fukugiiro-fetch.yml ワークフローを確認
# リポジトリ: allgroup-inc/moradou
# ワークフロー実行: https://github.com/allgroup-inc/moradou/actions/workflows/fukugiiro-fetch.yml

# moradou repo で最新のビルドを確認
cd /path/to/moradou  # または clone して確認
git log --oneline site/fukugiiro/shindan/index.html | head -5

# 最新版をこのリポジトリへコピー
cp -v /path/to/moradou/site/fukugiiro/shindan/index.html ./site/fukugiiro/shindan/
git add site/fukugiiro/shindan/index.html
git commit -m "復旧: 診断ページファイルを moradou から取得"
git push -u origin $(git rev-parse --abbrev-ref HEAD)
```

## 🐛 Step 3: ワークフロー診断（Workflow itself failed）

**症状**: 自動同期ワークフロー自体が失敗している（GitHub Actions ログで確認可能）

### 3-1. ワークフロー実行ログ確認
```bash
# GitHub UIで確認
# https://github.com/allgroup-inc/hojo-hq/actions/workflows/daily-sync-branches.yml

# または gh CLI
gh run list --workflow=daily-sync-branches.yml --limit=5
gh run view <RUN_ID>  # ログを表示
```

### 3-2. よくあるエラーと対応

| エラー | 原因 | 対応 |
|-------|------|------|
| `fatal: bad revision 'HEAD..origin/main'` | リポジトリが正しく初期化されていない | `git fetch --all` |
| `merge conflict` | ワークフロー中の `-X theirs` が効かない | Step 2 の手動復旧を実行 |
| `validation FAILED` | 生成ファイルが実際に欠けている | moradou repo の最新ビルド確認 |
| `curl: (7) Failed to connect` | Slack webhook URL が無効 | GitHub Issues が自動作成済み（無視可） |

### 3-3. ワークフロー再実行
```bash
# 失敗した実行を再実行
gh run rerun <RUN_ID>

# または最新の成功実行から手動トリガー
gh workflow run daily-sync-branches.yml --ref=claude/okinawa-disposable-income-plan-axxs6v
```

## 📊 Step 4: 検証（Verify fix）

すべての復旧後、以下で検証:

```bash
# 1. ファイル存在確認
echo "=== Files check ===" && \
for f in site/fukugiiro/index.html site/fukugiiro/shindan/index.html; do 
  [ -f "$f" ] && echo "✅ $f ($(wc -c < $f) bytes)" || echo "❌ $f missing"
done

# 2. ブランチ同期確認
echo "" && echo "=== Branch status ===" && \
git fetch origin main && \
BEHIND=$(git rev-list --count HEAD..origin/main) && \
echo "Commits behind main: $BEHIND" && \
[ "$BEHIND" -eq 0 ] && echo "✅ Synced" || echo "⚠️  Still $BEHIND behind"

# 3. ワークフロー次回実行時刻
echo "" && echo "=== Next workflow run ===" && \
python3 -c "from datetime import datetime, timedelta; now=datetime.utcnow(); next6=(now.replace(hour=6, minute=0, second=0, microsecond=0) if now.hour < 6 else (now + timedelta(days=1)).replace(hour=6, minute=0, second=0, microsecond=0)); next12=(now.replace(hour=12, minute=0, second=0, microsecond=0) if now.hour < 12 else (now + timedelta(days=1)).replace(hour=12, minute=0, second=0, microsecond=0)); print(f'Next sync runs at: {min(next6, next12).strftime(\"%Y-%m-%d %H:%M UTC\")}')"
```
