# apo-kanri v1.1: 埋まり状況・転換率ビュー 設計書(+GPS案の裁定)

作成: 2026-08-14 / 小柳さんの追加要望(同日チャット)を受けた増分設計

## 要望(小柳さん原文の要旨)

1. 今日のアポの埋まり状況が全体で確認できるもの
2. アポの生産性: アポ→訪問の転換率、訪問→申込みの申込率
3. GPS+Googleマップ連動で、アポが切れた(空いた)ときの最適な訪問メンバーを算出して行かせる

## 三名体制レビュー(2026-08-14)

### スイシン(推進)
- ①②は既存の「アポ予定」データ(ステータス・所要分・担当営業)だけで計算でき、
  追加入力ゼロで価値が出る。画面に「分析」タブを足すだけ
- ③は移動ロスの削減に直結し、営業効率の発想として筋が良い

### ウタガイ(懐疑)  ← 空欄不可
- ③のGPS常時取得は**従業員の位置情報=要配慮に近い個人データ**。取得目的・保存期間・
  本人同意・労務上の扱い(監視と受け取られるリスク)の整理なしに実装してはならない。
  守り部審査と小柳さんの正式決裁が先(PII非取得原則 2026-08-12 決裁とも整合させる必要)
- ②の転換率を**営業マン別**に出すと、人事評価への誤用リスク(v1設計のNon-goals
  「数値の人事評価利用はしない」と衝突)。まずはチーム全体の数字に限定すべき
- ②は稼働直後はデータが少なく、少件数の%は誤解を招く(9件中6件=67%は「参考値」)。
  母数を常に併記し、少件数時は参考表示にする(churn品質ゲートと同じ規律)
- ①の「埋まり率」も個人の稼働率と読めるため、評価利用しない前提の明記が必要

### ベッカイ(別解)
- ③はGPSがなくても大半の価値が出る: **アポには「場所」が既に入っている**。空きが出たら
  「前後のアポの場所が近い営業」を候補として提示し、場所をGoogleマップのリンクで開く方式なら、
  位置情報を一切取得せず「近い人に行ってもらう」判断を支援できる。まずこれで十分では
- 埋まり状況は本日だけでなく週ビューにも薄く出せるが、YAGNIで本日のみから始める

### 結論(部門長の裁定)
- **①採用(即実装)**: 「分析」タブに本日の埋まり状況(営業別の予約済み時間バー+全体サマリー)。
  画面に「※評価目的では使わない」注記
- **②採用(即実装・チーム全体のみ)**: 過去30日のファネル(結果が出たアポ→訪問実施→申込み)。
  母数を常に併記し、母数10件未満は「参考値」表示。**営業マン別の転換率は見送り**
  (必要になったら評価利用禁止の運用ルールとセットで再上申)
- **③保留・上申**: GPS取得は守り部審査+小柳さん正式決裁まで実装しない。
  代替のGPSレス版(アポの場所データからの近接候補提示+Googleマップリンク)を
  推奨案として決裁キューに登録
- 見直し期限: 2027-02-14(v1本体と同じ)

## 実装内容(v1.1)

### 埋まり状況(apoCore.buildFillStats)
- 対象: 指定日の 予定/確定/実施済/申込み(キャンセル系・再調整中は空き扱い)
- 営業ごとに 予約済み分数・件数・埋まり率(営業時間窓 9:00〜18:00 = 540分に対する割合、上限100%)
- アポゼロの営業も0%で表示(全員の稼働が一目で見える)+全体合計

### 転換ファネル(apoCore.buildConversionStats)
- 集計対象: 「結果が出たアポ」= 実施済+申込み+キャンセル2種(予定・確定・再調整中は未確定のため除外)
- 訪問実施率 = (実施済+申込み)÷ 結果が出たアポ
- 申込み率 = 申込み ÷(実施済+申込み)
- 期間: 過去30日(日付基準)。母数0は「—」表示・母数10未満は「参考値」注記

### 画面
- ヘッダーの切替を 本日/週/分析 の3タブに拡張
- 分析タブ: 本日の埋まり状況(横バー)+過去30日ファネル(件数併記)+評価利用しない注記
- サーバ関数 getStats() を追加(getBoardと同じ多層防御の認証)
