# 結果マガ完全自動売上拡大システム設計書

**作成日**: 2026-09-30  
**目標**: 月10万円の利益収入を年末までに実現  
**方針**: 究極の完全自動化 + 外部ツール連携による継続的改善

---

## 1. 事業モデル

### 1.1 3本柱の売上構造
- **無料ログ (L-series)**: 週1本公開、X告知で流入獲得
- **有料研究レポート**: 月3〜4本の候補から最適な題材を自動選定・生成
- **段階型販売**: 無料→有料への段階的な購買喚起

### 1.2 収入源
- note マガジン会員 (月額定期購読)
- 単発有料記事 (980円〜3,000円)
- 外部ツール連携による データ分析・最適化の自動フィードバック

### 1.3 顧客セグメンテーション
| セグメント | 特徴 | 購買確度 | 施策 |
|---|---|---|---|
| 高エンゲージメント | 毎週開く、メモ取る、スキ連続 | 30% | 即・有料記事・割引クーポン |
| 積極閲覧者 | 毎週開く、時々スキ | 15% | 無料→定期購読・段階的提案 |
| 発見者 | 月1〜2回開く、新規検索流入 | 10% | 基礎記事・教育的内容 |
| LINE登録者のみ | LINE通知で接触、サイト訪問無し | 3% | 定期的なセグメント再分類 |

## 2. データパイプライン

### 2.1 データ収集元
- **note API**: 記事ビュー数、スキ数、購入数、購入者プロフィール
- **Google Analytics 4**: ページビュー、セッション、ユーザー行動フロー
- **LINE Message API**: 登録者数、セグメント別の開封率、リンククリック率
- **X API**: ツイート インプレッション、リツイート、フォロワー増加

### 2.2 分析ロジック
各週、Claude APIが以下を自動実行:
1. **購買予測スコアリング**: ユーザーの過去行動パターンから購買確度を算出
2. **セグメント判定**: 各ユーザーを4つのセグメントに分類
3. **コンテンツ最適化**: 前週のエンゲージメント・売上から今週の題材・価格を決定
4. **A/Bテスト設計**: 文面・配信時刻・CTA配置の組み合わせを自動提案

## 3. コンテンツ生成

### 3.1 有料記事の自動候補化
毎週の無料ログ (L-series) から、Claude が以下の条件で有料化候補を3〜4本抽出:
- 反応が大きかった題材
- ユーザーからの質問・リアクションが多かった内容
- 他媒体との差別化が可能な深掘り視点

### 3.2 記事生成フロー
1. **素材抽出**: 無料ログの「学び」セクションをClaude が要約
2. **拡張執筆**: 3周推敲
   - 1周目: AI っぽさを削る
   - 2周目: タイトル・冒頭100字だけ批評
   - 3周目: 誇大表現・無根拠数字をチェック
3. **ガード検査**: 禁止語・数字の原文照合・長さ検証
4. **自然性確保**: 人間の思考プロセス・迷い・試行錯誤を意図的に混ぜ込み、AI感を排除

### 3.3 記事メタデータ (自動生成)
- タイトル (30字以内)
- リード文 (80〜100字)
- 目次 (3〜5項目)
- 価格帯決定ロジック (前週売上・セグメント構成から自動算出)

## 4. 販売戦略

### 4.1 段階的な購買喚起
```
無料ログ開封
  ↓
(1日目) 無料内容で基礎理解
  ↓
(2〜3日目) 関連有料記事のセグメント別プッシュ
            - 高エンゲージ層: 即・有料リンク
            - 積極閲覧層: 「詳しくはこちら」の軽め提案
            - 発見者層: 「この話題を深く理解する記事」と教育的トーン
  ↓
(4〜7日目) 週次メールまたは LINE で「見逃し向け紹介」
```

### 4.2 定価設定の自動調整
- **基準価格**: 1,000円 (季刊の主力記事)
- **割増要因** (価格 UP):
  - 前週の同テーマ有料記事が月5人以上購入 → +500円
  - セグメント別購買スコア平均が60点以上 → +300円
- **割引要因** (価格 DOWN):
  - 新規テーマまたは反応が予測困難 → -300円
  - 需要期(年末・決算期など)の低セグメント層向け → 特別割引680円

### 4.3 マガジン会員化への誘導
- 単発有料記事を3本購入したユーザーへ: 「月額980円で全記事読み放題」プロモ
- LINE登録者限定の早期割引 (通常1,500円 → 1,000円)

## 5. 外部ツール連携

### 5.1 自動データ分析 (Google Sheets + Claude API)
**週次定期タスク** (毎週月曜朝):
1. GA4 から過去7日間のセッション・PV・CTR を自動抽出
2. note API から記事別売上・購入者属性を自動抽出
3. LINE API から開封率・クリック率を自動抽出
4. Claude API に「先週の成果を基に、来週の施策案を3案提示」と指示
5. 施策案を Google Sheets の「週次分析シート」に記録

### 5.2 Power Automate との連携
- note で新規購入者が発生 → 自動で LINE に「ご購入ありがとうございました」通知
- セグメント別のタイミング別配信自動化
  - 高エンゲージメント層: 毎週木曜朝7時に新記事案内
  - 積極閲覧層: 毎週日曜夜10時に月間人気記事まとめ
  - 発見者層: 月2回の基礎解説記事

### 5.3 X × note 連携の最適化
- X 投稿の「いいね」「リツイート」を自動計測
- 最も反応の良い投稿パターン (文体・時刻・長さ) を学習
- 次週の投稿に自動反映

## 7. 安全機構 (完全自動化における品質保証)

### 7.1 多層ガード (自動検査)
1. **数字の実数照合**: 生成文中の数字は KPI データに存在するもの のみ許可
2. **禁止表現検査**: 「必ず」「確実に稼」等のクレーム対象表現を機械チェック
3. **セグメント適合性**: 生成コンテンツが対象セグメントの購買確度に合致しているか検証
4. **購買予測信頼度**: スコア60点以上の場合のみ有料価格で配信。60点未満は割引または別セグメント向け

### 7.2 検査ルール
- **価格設定の根拠記録**: 毎回の価格決定ロジックを JSON に記録し、後年の検証に備える
- **A/B テスト結果の記録**: どの文面・配信時刻が効果的だったかを自動集計
- **誤配信防止**: 配信対象セグメント・価格帯・コンテンツのトリプルチェック

### 7.3 エスカレーション基準
以下の場合は自動配信を一時停止し、ログで報告:
- 有料記事の自動生成に失敗した場合
- セグメント判定精度が50%以下に低下
- 週間売上が前週比70%以上低下 (異常検知)

## 8. AI感排除の方針

### 8.1 文体・トーン
- 「私たちが」「今月も」など、一人称・季節感を明示的に組み込む
- 試行錯誤・失敗も素直に書く (「うまくいきませんでした」など)
- 数字を出すときは、根拠や背景を人間的に解説

### 8.2 構成・コンテンツ
- 完全論理的な構成よりも、実務での「引っかかり」を優先
- 一般化よりも具体例・事例を多用
- AI生成と見分けがつかないほど完璧な日本語ではなく、読み手の思考に寄り添う自然な日本語

### 8.3 配信メッセージ
- X・LINE の通知文は「記事が完成した」という事実ベースに統一
- 売り込み感が出ないよう、「関心があれば」「試しに」など軽めの触りに

## 12. リスク管理

### 高リスク
- **Claude APIのコスト超過**: 生成頻度が多いと月1万円を超える可能性 → モニタリング + 頻度調整で対応
- **note公式ピックアップの減少**: 掲載機会が減るとセグメント分析の精度が低下 → SNS (X) からの別流入で補完

### 中リスク
- **セグメント予測精度の低下**: ユーザー数が少ないうちは判定が不安定 → 予測スコア60点以下は保守的な判定
- **自動生成コンテンツの品質低下**: 長期運用で定型化するリスク → 月次で人間が成果物をサンプル確認

### 低リスク
- **API接続エラー**: 各APIは定期的な疎通確認 + エラーハンドリング済みで対応
- **ユーザーデータの誤分類**: セグメント判定ロジックのテストを毎月実施
