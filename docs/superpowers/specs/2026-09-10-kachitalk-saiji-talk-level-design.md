# カチトーク催事版(他社向けトークレベル管理)設計書

作成: 2026-09-10 / 決裁: 小柳さん(本チャット・案B採用) / 議事: docs/議事_20260910_カチトーク催事版.md
見直し期限: 2027-03-10

> 本リポジトリは**公開**のため、相手企業の社名・担当者名・契約条件・実データは本書に書かない。
> それらは非公開側(覚書・契約書・カチトーク側の非公開領域)で管理する。

## 1. これは何か(30秒で)

催事場(イベント会場・店頭ブース)で保険の面談アポ取り・インターネット回線・リユース・携帯などを
案内する**特定の1社(外部企業)**向けに、本社ログシステム「カチトーク」の仕組みを複製して立てる
**接客トークのレベル管理システム**。スタッフが本番の接客を録音して送ると、自動で文字起こし・採点され、
スタッフごと・商材ごとのレベルが見える。目的は**評価ではなく育成**(トークのレベルを上げること)。

位置づけ: 商品設計「催事ログ解析v1」(docs/商品設計_催事ログ解析_v1.md)のトーク品質エンジン。
器はフクギイロ経由の法人契約(個人契約は行わない・同v1の方針を踏襲)。

## 2. 作り方の決定: 案B「複製して専用に立てる」

今のカチトークには相乗りせず(案A不採用)、一からも作らず(案C不採用)、
**カチトークの仕組み一式を複製し、その会社専用の環境を別に用意する**。

- 専用のLINE公式アカウント(録音の送り先)
- 専用の保存領域(Azure上・本社データと物理的に分離)
- 専用の台帳(Excel/CSV・本社の営業ログ台帳とは別ファイル)

理由: 他社のお客様の声という最高感度のデータを自社データと**絶対に混ぜない**ため。
契約・説明・事故時の切り分けもこの形が一番簡単。

## 3. そのまま流用する部分(カチトークで実証済み)

1. スタッフがスマホで録音 → 専用LINE公式アカウントに送信
2. 5分毎の自動処理: 文字起こし → **個人情報の自動マスク**(氏名・電話・住所等) → 抽出 → 採点 → 台帳に1行
3. 結果(成約 / 検討 / NG)はLINEのクイックリプライで回収
4. 管理画面から台帳(xlsx/CSV)をダウンロード(PIIを持たない形)

人手入力は「録音を送る」「結果ボタンを押す」の2つだけ。
カチトークの実証教訓**「自動で埋まらない項目は、現場は埋めない」**を設計の大前提にする。

## 4. 催事向けに新しく作る部分

### 4-1. 商材の自動仕分け
録音の中身から「保険アポ / ネット / リユース / 携帯」をAIが自動判定。
判定できなければ**「未分類」とし、推測でラベルを付けない**(誤分類は採点データを静かに汚すため。
カチトークの誤ペア禁止ルールと同じ思想)。録音冒頭にスタッフが商材名を一言添える運用を補助として推奨。

### 4-2. 商材ごとの採点基準(ルーブリック)
例(たたき台・5項目×各採点):
1. 声かけ・つかみ(足を止めてもらえたか)
2. お客様の状況の聞き取り(一方的に話していないか)
3. 説明のわかりやすさ(専門用語を翻訳できているか)
4. 次につなげる一言(アポ打診・見積案内など、商材ごとのゴール)
5. 禁止表現なし(断定・煽り・不正確な説明がない)

**基準の中身は相手企業の教育担当とすり合わせて確定する**(こちらが勝手に決めない)。
商材ごとにゴールが違うため、項目4は商材別に定義する。

### 4-3. スタッフごとのレベル表
- 直近の接客の平均点と項目ごとの達成状況から、**商材ごとにレベル(例: 1〜5)を自動算出**
- 週1回、責任者向けにスタッフ×商材のレベル一覧を出す
- **件数を必ず併記し、件数が少ないスタッフ・商材では傾向を断定しない**(カチトークの30件ルールを流用)
- **用途は育成に限る**(契約に明記。§5-4)

### 4-4. 良いトークの教材化
月1回、高評価の接客から「こう伝えたら伝わった」例を教材化。
- 個人が特定できない伏せ字ルール(氏名・地名・会社名を伏せる)はカチトークと同じ
- 「こうすれば売れる」ではなく「こう伝えたら伝わった」の書き方
- 実際のやり取り(会話例)を1つ入れる

## 5. 個人情報・同意(ここを飛ばすと本番録音は解禁しない)

本番の接客の録音には**お客様の声が入る**。以下を全て満たすまで実データを流さない。
合成音声・スタッフ同士のロールプレイ録音での検証は審査前でも可。

1. **お客様への告知**: ブースに「サービス品質向上のため録音しています」の掲示+スタッフの一言案内を、相手企業の接客ルールにしてもらう
2. **会場の許可**: 催事会場(モール等)側のルールで録音が問題ないことを確認
3. **音声の保存期間**: 文字起こし完了後、元音声は一定期間(例: 30日)で自動削除
4. **相手企業との取り決め(覚書/NDA)**: データの持ち主は相手企業・当方は処理の受託のみ・**採点とレベルは育成目的に限り人事評価に用いない**ことを明記
5. **守り部審査+外部セキュリティ/個人情報専門家の確認**(商品設計v1 §3・受託時情報管理規程draft v1と同じ関門)を通過してから本番データ解禁

## 6. 試験運用の設計(小さく始める)

| 順 | やること | 合格条件 |
|---|---|---|
| 0 | §5の関門(告知・会場許可・覚書・守り部審査) | 全て完了 |
| 1 | スタッフ2〜3名×2週間。**全接客ではなく「1日の代表数件」だけ録る** | 録音が実際に送られてくる(録音率を測る) |
| 2 | AI採点と**人手採点(教育担当)の突き合わせ** | 催事場の騒音下でも文字起こし・採点が使い物になると人が確認 |
| 3 | 採点基準v1を相手企業と確定 | 教育担当の合意 |
| 4 | 全スタッフ展開・レベル表の週次運用開始 | — |

- **録音率(録るべき接客のうち録れた割合)を月次で測り、5割を切ったら設計を見直す**(カチトークの言い忘れ率ルールの流用)
- 精度が合格条件に届かない場合の逃げ道: スタッフ側の声だけ拾う録り方(ピンマイク等)の技術検証(議事ベッカイ案)
