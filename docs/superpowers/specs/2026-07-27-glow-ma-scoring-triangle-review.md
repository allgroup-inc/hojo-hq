# glow-ma 三名体制レビュー記録: スコアリング重み・接触サイクル確定

実施日: 2026-07-27 / スキル: `glow-ma-triangle-review` / 対象: `docs/superpowers/specs/2026-07-26-glow-ma-relation-system-design.md` 6章・8章

## 論点

スコアリングの重み配分とランク別標準接触サイクル日数(設計書6章・8章のたたき台値を確定させる)

### スイシン(推進)

- Phase 2のGAS実装に着手するには具体的な数値が要る。属性スコア(業種のM&A流動性・規模)+流入ルートボーナス+反応スコアの3層構成で進めるべき。
- ランク別サイクルはA=30日/B=60日/C=120日/D=365日として、温度の高い企業にリソースを集中させ、低温度企業はナーチャリング配信(11章)で関係を維持する。
- 初期値は完璧でなくてよい。月次の重み見直し(6章)で実績を見ながら補正する前提で、まず動かしてデータを貯めることを優先すべき。

### ウタガイ(懐疑)

- 「業種のM&A流動性が高い/中/低」の分類基準が未定義。誰がどう線引きするかを決めずに数値化すると、恣意的な業種優遇になり後から説明できなくなる。
- 代表者年齢による加点は、7000社リストに年齢データが全件揃っている保証がない。欠損が多ければこの軸は実質機能せず、流入ルートボーナスだけでランクが決まる歪んだモデルになる。
- Bランクのサイクルを90日→60日に縮めると、GLOWチーム数名の実働キャパシティを超える可能性がある。該当社数とキャパシティの突合をせずに数値だけ決めるのは危険。
- 「意思決定者本人との対話+15点」は良い設計だが、紹介ルートは最初は税理士経由で経理担当と話すことが多く、この軸で不当に低スコアになるリスクがある。

### ベッカイ(別解)

- 7000社×手紙DMのようなロー・タッチ大量アプローチにはスコア一律ランク分けが向くが、①紹介ルート(少数・高単価)には過剰。紹介案件はスコア計算の対象外とし「常に最優先接触」という別ルールにした方がシンプルではないか。
- 属性データ(業種分類・代表者年齢)の整備が7000件分終わっていない今、属性スコアを机上で先に決め打ちするより、「まず反応スコアだけで運用開始し、属性データが揃ってから重みを追加する」段階導入も検討に値する。
- ランク閾値を固定点数でなく「上位n%をAランク」とするパーセンタイル方式にすれば、営業キャパに合わせて常に一定割合をAランクにできる。

### 結論(裁定)

- 採否: **採用(修正版)**
  1. 属性スコアは「業種のM&A流動性(高/中/低の分類リストは初版として暫定作成し、運用しながら精緻化)」と「規模の適正度合い」の2軸を基本とする。代表者年齢は**データがある場合のみの任意加点**とし、欠損時は0点(モデルを歪ませない)
  2. 流入ルートボーナス: 紹介+30/ミカタ+20/DM+0を採用。ただし**紹介ルートはスコアに関わらず接触サイクル30日(Aランク相当)を強制適用**する例外ルールを別途設ける(ベッカイ案を採用)
  3. Bランクの接触サイクルは**90日のまま据え置き**(60日への短縮は見送り)。実キャパシティが判明してから月次レビューで再検討
  4. ランク閾値は固定点数方式を採用(A:70点以上/B:40〜69点/C:15〜39点/D:14点以下)。パーセンタイル方式はデータ蓄積後に再検討
- 理由: 3役の懸念(業種分類の恣意性・データ欠損・キャパシティ超過)は、任意加点化・据え置き・例外ルールで実装上吸収可能。ベッカイの「紹介ルートは別ルール」案はリスクを下げつつ実装もシンプルになるため採用。
- 見直し期限: **2026-10-27**(3ヶ月後。初回の月次スコア重み見直しと合わせて、固定点数方式かパーセンタイル方式かも再検討)
