## 0. 目的(なぜやるか)

診断結果画面を「見やすく・打ちやすく・わかりやすく・迷わない」ホスピタリティの高い体験にブラッシュアップし、
利用者が **①自分の見逃している制度の多さに気づき → ②LINE登録して締切通知・新制度通知・準備のまとめを受け取る** 流れを自然に作る。

第一KPI(診断→LINE登録率30%)に直結する。ただし、もらいわすれ堂の対象は**生活困窮世帯を含む県民**であり、
「取りこぼしをゼロにする」ミッションを最優先する。**制度情報そのものは登録の壁で隠さない。**

---

## 1. 確定した設計判断(三名体制で審議・記録)

| 論点 | 決定 | 根拠 |
|---|---|---|
| 登録方式 | **匿名のままLINE友だち追加で解放**(名前・年齢・携帯は取らない) | 現サイトの「個人情報不要・匿名」の約束/憲法「個人情報最小化」「CV単一」/企業のミカタも同方式で実現済み |
| 金額表示 | **今は出さない(件数を主役)**。将来、検証部が金額を整備したら「目安・要確認」付きで段階追加 | 正確性最優先。現状フクギイロ制度は全件 `amount_note = 要確認` で検証済み金額データが存在しない |
| ゲート | **ソフトゲート**(制度は全件表示。"おまけ"だけLINEで解放) | ミッション(受給率向上・取りこぼしゼロ)順守。困窮世帯を登録の壁で締め出さない |

### 三名体制の議事(ウタガイの反対理由を必ず記録)
- **スイシン(推進)**: 1件以外モザイク→LINE全解放は登録動機が最強。企業のミカタで実証済み。
- **ウタガイ(懐疑・反対)**: 公的給付という「取りこぼしを無くすべき情報」を登録の壁で隠すのは、もらいわすれ堂のミッション・守り部・ホスピタリティに反する。困窮世帯が壁で制度に辿り着けない本末転倒リスク。B2B(企業)と県民世帯(困窮含む)を同じゲートで扱うべきでない。
- **ベッカイ(別解)**: 制度そのものは全部見せ、ゲートは"おまけ"(合計サマリー/準備シートのまとめ/締切通知)に限定する。
- **裁定**: ベッカイ案(ソフトゲート)を採用。最終決裁は小柳さん(§6 参照)。

## 2. 画面構成(診断結果画面・上から)

1. **件数フック(既存強化)**
   - 見出し「あなたの世帯が使える可能性のある制度: **N件**」(既存の `rs.length` を踏襲)
   - 補助「対象の可能性が高い順に並んでいます」

2. **合計サマリーカード(スクロールで現れる)**
   - 「合計 **N件** が対象の可能性」+ 内訳「可能性 高◯件 / 中◯件」(`likelihood` 集計)
   - **金額はこの版では一切表示しない**(UI要素も置かない)。金額の追加は §7 の別タスクとし、整備後に改めて設計する。
   - 断定表現なし。「対象の**可能性**」で統一。

3. **制度カード一覧(全件・モザイクなし)**
   - 既存カード踏襲: 制度名 / 対象世帯 / 次の一歩 / 窓口でのひとこと / 公式ページリンク / 申請準備シートリンク / 「受け取った」記録ボタン + **受給報告導線(PR #6, `/go/fg-jukyu/`)**
   - デザイン整理(§4)。情報の優先順位を明確化。

4. **LINEごほうびボックス(ソフトゲート・結果の要)**
   - 見出し「この **N件**、もらい忘れないために」
   - 提供価値3点:
     1. **締切をLINEでお知らせ** — 締切3層ルール順守。表現は「**締切の約1か月前から**お知らせ」。**「7日前」表現は使わない**(誤り)。
     2. **条件に合う新制度が増えたらお知らせ**
     3. **申請準備シートをまとめて受け取る**(印刷・持ち物チェックリスト)
   - ボタンは `/go/fg-shindan/` 経由(go-link-discipline)。`fgTrack("line_add_click")`。
   - 「登録は無料・名前や住所の入力は不要・いつでも解除できます」を明記(匿名の約束の再確認)。

5. **既存の下部要素**: 共有ボタン / 印刷 / 免責(医療・介護・障がいは非表示方針の説明)/ トップへ戻る。

## 3. データ・正確性の制約(絶対遵守)

- 金額は一切表示しない(この版では)。将来追加時も `verified` な制度の金額を「目安・要確認」付きでのみ表示。
- すべて「対象の**可能性**」表記。「もらえます」等の断定禁止(既存 `FORBIDDEN` 語に準拠)。
- `status = 要確認` の制度には既存どおり「内容の最終確認中」注記を表示。
- 個人情報(名前・住所・電話・年齢)を**サイトで取得しない**。診断の回答は従来どおり端末内(localStorage)のみ、送信しない。

---

## 4. デザイン・ブラッシュアップ方針(固定概念にとらわれず)

- **見やすい**: 余白と情報階層の整理。1カード=1制度で視線が迷わない。可能性「高/中」バッジの視認性。
- **打ちやすい**: すべてのタップ領域 44px 以上(既存CSSを踏襲・徹底)。選択肢ボタンの押しやすさ。
- **わかりやすい**: 専門用語をやさしく翻訳(「家計の見直しやさん」と同トーン)。次の一歩を各カードに明示。
- **迷わない**: 1画面に主アクションは1つ。結果画面の主アクション=LINE登録、副=各制度の「次の一歩」。
- **土台**: main の直近UX改修(静的スクロール/コンパクト化/結果へ戻る動線/resume修正)の**上に**乗せ、それらを壊さない。
- サイズ予算(index.html < 50KB、`check_lp_fukugiiro.py`)と禁止表現ゲートを維持。

- **診断ロジック eval**(`tests/shindan.test.mjs`, `node --test`): サマリーの件数・内訳集計が `matchSeido` 結果と一致することを担保するケースを追加(高/中の内訳、0件時、除外カテゴリ)。
- **LP検査**(`check_lp_fukugiiro.py`): サイズ予算・禁止表現・基本要件(lang/viewport/title/description)を維持。
