# 顧客カルテ(お客様管理)機能 設計書(spec)

作成日: 2026-07-26 / 起案: ブレインストーミング(小柳さん・Claude)
ブランチ: `claude/early-churn-risk-retention-1tu4ej`(早期解約リスク保全システムの拡張)

---

## 1. 目的(何を作るか)

早期解約リスク保全システムに、**お客様一人ひとりの履歴が溜まっていく「顧客カルテ」**を足す。
顧客IDで申込みと接触を束ね、「どんな内容を案内しているか・いつ架電したか・相手は誰か・何度申し込んでいるか・追加案内をしているか」を時系列で確認できるようにする。

一言でいうと:
> 別システムの書き出しを取り込み、顧客IDで束ねて「申込み履歴＋接触タイムライン＋現在のリスク」を1画面(カルテ)に。放置の検知と保全の効果測定まで。

### 確定した前提(ブレストで合意)
| 項目 | 決定 |
|---|---|
| 名寄せキー | **既存の顧客ID**(別システムに固有IDがある) |
| 入力・蓄積の場所 | **別システム側**。本ツールは入力画面を作らず、別システムの書き出し(CSV)を取り込む read-only |
| 取り込むデータ | ①申込み台帳(既存) ②接触履歴(新規)。どちらも顧客IDで束ねる |
| 接触履歴の中身 | 別システムに架電・案内・追加案内・担当まで記録・書き出しできる(1本の取り込みでカルテが作れる) |
| 個人情報 | `private/` 限定・リポジトリに絶対コミットしない(既存ルール継承) |

---

## 2. データの構造(3階層)

```
顧客(顧客ID) ── 1人
  ├─ 属性: 性別・年代・地域 …(申込みから集約)
  ├─ 申込み履歴 ── 複数(=「何度申し込んだか」)
  │     商品 / 金額 / チャネル / 申込形態 / 担当 / 申込日 / 解約日 / 解約理由 / 早期解約フラグ / 現在のリスク%
  └─ 接触履歴 ── 複数・時系列(=架電・案内・追加案内)
        日付 / 種別(架電/案内/追加案内/来店/メール…) / 担当(相手) / 案内した内容 / 結果・メモ
```

- **顧客ID**で申込み(既存 `apply_id`)と接触を束ねる。申込みレコードに `customer_id` を持たせる(既存スキーマへ1項目追加)。
- 別システムの実列名は既存同様 **`column_map` で吸収**(接触履歴用に `interaction_column_map` を追加)。
- すべて `private/` 限定。カルテHTMLも顧客個人情報を含むため `private/` 出力・非コミット。

### 接触履歴レコード(新規スキーマ)
| 内部項目 | 中身 | 備考 |
|---|---|---|
| `customer_id` | 顧客ID | 束ねるキー(必須) |
| `date` | 接触日 | タイムライン並びの基準 |
| `kind` | 種別 | 架電/案内/追加案内/来店/メール 等(正規化) |
| `agent` | 担当(相手) | 誰が対応したか |
| `content` | 案内した内容 | 商品・提案の要旨 |
| `memo` | 結果・メモ | 通話結果・次アクション等 |

## 3. アーキテクチャ(既存の read-only 構成を踏襲)

今の4段パイプライン(取込→学習→採点→出力)に、顧客の束ねとカルテ出力を足す。純Python・標準ライブラリのみ・`private/` 限定・サーバー/DB無しは不変。

### 追加モジュール(`scripts/churn/` 配下)
- `interactions.py` — 接触履歴CSVを `interaction_column_map` で取り込み → 正規化レコード。
- `customer.py` — 顧客IDで申込み＋接触を束ね、顧客プロファイルを構築。返す集約:
  - 属性(年代/性別/地域)、`n_applications`(累計申込)、継続中/解約の件数、`n_additional_guidance`(追加案内回数)、`max_risk_band`(継続中の最大リスク帯)、申込みリスト(各リスク%付き)、接触タイムライン(日付降順)。
- `karte.py` — 顧客1件のカルテHTMLを出力(申込み履歴＋接触タイムライン＋現在リスク＋気づき)。
- 既存 `score.py` を用い、継続中の申込みごとにリスク%・帯・ヒット要因を付与。

### スキーマ変更(最小)
- `schema.normalize_record` の返す辞書に `customer_id` を追加(`column_map` に `customer_id` 対応を追加)。既存の採点・学習・集計には影響させない(顧客束ねだけが利用)。

## 4. 顧客カルテ画面の中身

1顧客ID を開くと:

**ヘッダー(要約)**
- 顧客ID・年代/性別/地域
- **累計申込 ◯回** / 継続中 ◯件・解約 ◯件 / **追加案内 ◯回**
- **現在の最大リスク帯**(継続中契約のうち最も高いもの)

**① 現在のリスク**(churnモデル連携)
- 継続中の契約ごとに リスク% ・帯 ・ヒット要因(なぜ高いか)・推奨アクション

**② 申込み履歴**(表・時系列)
- 各契約:商品 / 金額 / チャネル / 担当 / 申込日 / 状態(継続・早期解約・解約)/ リスク

**③ 接触タイムライン**(日付降順)
- 架電 / 案内 / 追加案内 / 来店 / メール:日付・種別・担当(相手)・案内内容・結果メモ

**④ 先回りの気づき**
- **高リスク × 直近◯日以内に接触なし** → 「要フォロー(放置検知)」フラグ。
- 保全した高リスク先が実際に継続できたかを後で突合(効果測定の素材)。

**⑤ 表示ルール(憲法準拠)**
- リスク%は 100%/0% を出さずクランプ(断定しない)。件数の少ない集計は「参考」明示。

ダッシュボード一覧の顧客をクリック → このカルテへ(連携)。

## 5. スコープと段階(フェーズ)

| 段 | 内容 | 完了の目安 |
|---|---|---|
| P1 | 接触履歴の取込＋顧客の束ね(`interactions.py`/`customer.py`)＋**顧客カルテ**出力(`karte.py`) | 顧客IDを指定するとカルテHTMLが出る |
| P2 | **先回りの気づき**(高リスク×直近接触なし=要フォロー) | 放置先を検知・一覧化できる |
| P3 | **保全の効果測定**(保全接触あり/なしで実解約率を比較) | 効果が数字で見える(以前保留のフックを本物に) |
| 連携 | ダッシュボード一覧 → 顧客カルテへのリンク | クリックで遷移 |

### やらないこと(YAGNI)
- 入力画面・サーバー・DB・別システムとの自動同期は作らない(入力と蓄積は別システム、本ツールは書き出しを読むだけ)。
- 名寄せの推測/ファジー結合はしない(固有の顧客IDがあるため不要)。顧客IDが欠損した記録は束ねず「未紐付」として明示。

## 6. テスト方針
- `unittest`(標準ライブラリ)を各モジュールに:
  - 接触履歴の取込・正規化(`column_map` 吸収、種別の正規化)
  - 顧客の束ね(顧客IDで申込み＋接触が正しく集約、累計申込・追加案内回数)
  - タイムラインの日付降順ソート
  - 「要フォロー」フラグ(高リスク×直近接触なし)の判定境界
  - 効果測定(保全接触あり/なしコホートの実解約率比較)
- 顧客個人データは使わず、合成データで検証。

## 7. リスクと対策(ウタガイの記録)
| リスク | 対策 | 
|---|---|
| 顧客個人情報(氏名・履歴)の誤コミット | カルテ出力も含め `private/` 限定・gitignore・コミットはコードのみ |
| 顧客IDが空/表記ゆれの記録 | 束ねず「未紐付」明示。断定しない |
| 接触履歴の種別表記ゆれ(架電/TEL/電話) | 正規化辞書で吸収。未知種別は原文保持＋「その他」 |
| 「放置検知」の閾値が主観的 | 閾値は設定値・小柳さん決裁。実運用で調整 |
| 別システム書き出し列の変更 | `interaction_column_map` で吸収。取込テスト |
