# Claude Code ⇄ オブシディアン連携 設計書

作成: 2026-08-16 / 小柳さんとの壁打ちにより策定

## 背景

小柳さんはClaude Code on the web(クラウド版・モバイルアプリ)を中心に、ALLGROUP内の
複数事業(hojo-hq/GLOW・フクギイロ・エンライフ・hikari・kakei等)のチャットを並行して
進めている。各チャットの決定事項・引き継ぎ内容がそれぞれのリポジトリ内(`docs/`等)に
閉じてしまっており、事業をまたいだ知識ベースとして横断的に見返す手段がない。

これをオブシディアン(ノートアプリ)に集約したい、という要望。ただし小柳さんはローカルの
Claude Code CLIは使っておらず、クラウド版のみを使っている(2026-08-16 本人確認済み)。
「毎回頼むと忘れる」ため、明示的な指示なしでも自動的に記録される仕組みが必要。

## 1. スコープ

**作るもの:**
- 個人アカウント(`takeshikoyanagi9-lab`)配下に、オブシディアンvault用の非公開GitHub
  リポジトリを新規作成(仮称: `allgroup-vault`)
- 事業ごとにフォルダを分けたvault構成(`hojo-hq/` `glow-ma/` `フクギイロ/` `hikari/`
  `kakei/` `エンライフ/` `個人/` 等)とトップレベルREADME
- 各事業リポジトリのCLAUDE.mdに「セッションの区切りでvaultへ記録する」常設ルールを追記
  (このリポジトリ=hojo-hqからまず着手し、他リポジトリへの展開は別途)
- 「トピック単位で1ファイル、既存があれば追記・更新」という重複防止の運用ルール

**作らないもの(スコープ外):**
- ローカルClaude Code CLIを前提にした直接ファイルシステム連携(小柳さんの環境では使わない)
- 完全自動の意味的重複検出(AIによる類似ノート統合等)。まずは「ファイル名・トピックで
  一致するか」という単純な仕組みで様子を見る
- 1メッセージごとの書き込み(頻度が高すぎてノートが荒れるため見送り。会話の区切り単位のみ)
- 他事業リポジトリ(hikari-hq/kakei-hq等)への同時展開。まずhojo-hqで試験運用し、
  効果を見てから展開するかどうかを別途判断する

## 2. 全体構成

```
[小柳さんのPC: オブシディアンアプリ]
        ↕ (Obsidian Gitプラグイン、自動push/pull)
[GitHub: takeshikoyanagi9-lab/allgroup-vault(非公開)]
        ↕ (Claude Codeが add_repo して読み書き・commit・push)
[各事業のClaude Codeチャット: hojo-hq / glow-ma / フクギイロ 等]
```

vaultリポジトリは「オブシディアンとClaude Codeが両方書き込む共有のノート置き場」として働く。
オブシディアン側はプラグインが自動でGitHubと同期するため、小柳さんは普段通りアプリを
使うだけでよい。

## 3. 書き込みのトリガー(いつ書くか)

「毎回勝手に書く」を、CLAUDE.mdへの常設ルール追記で実現する。既存の`context-limit-handoff`
スキル(会話が長くなった時に引き継ぎメモを作る仕組み)を土台に、書き込み先をこのリポジトリの
`docs/`だけでなくオブシディアンvaultにも広げる形。

書き込みタイミング(いずれか):
1. 会話が一区切りついた(決定事項が確定した、作業が完了した)とき
2. コンテキストが長くなり引き継ぎが必要になったとき(既存の`context-limit-handoff`と同じ発火点)
3. 明示的に「オブシディアンに書いて」と頼まれたとき(引き続き使える)

1メッセージごとの書き込みは行わない(ノートが荒れる・意味のある単位にならないため)。

## 4. 重複防止

「トピックごとに1ファイル、既存があれば追記・更新」を運用ルールとする。

- 書き込み前に、vault内の対象フォルダ(例: `hojo-hq/`)で同じトピックのファイルが
  既にあるか確認する(ファイル名・見出しで判断)
- あれば新規作成せず、その既存ファイルに追記・更新する
- なければ新規ファイルを作る(ファイル名は内容が一目でわかる日本語名を推奨)

完全な意味的重複検出(表現は違うが内容が同じノートを機械的に統合する等)は今回のスコープ外。
まずはこのシンプルな方式で運用し、問題が出たら見直す。

## 5. セットアップ手順(小柳さん側の作業)

1. GitHubで非公開リポジトリ `takeshikoyanagi9-lab/allgroup-vault` を作成
2. オブシディアンに「Obsidian Git」コミュニティプラグインを導入(設定 → コミュニティプラグイン
   → 検索「Git」→ インストール → 有効化)
3. 既存vaultフォルダをこのリポジトリに紐づける(またはこのリポジトリをクローンして
   新しいvaultとして開く。既存ノートの移行方法は既存vaultの構成による)
4. Obsidian Gitの自動push/pull間隔を設定(推奨: 起動時pull・一定間隔でauto-commit&push)
5. hojo-hqのCLAUDE.mdに、vault連携の常設ルールを追記(Claude Code側の作業)

## 6. リスク・注意点

- **競合(コンフリクト)**: オブシディアン側の自動pullとClaude Code側のpushのタイミングが
  重なると、まれにGit上の競合が起きうる。頻発するようなら同期間隔の調整、または
  「Claude Codeが書き込む前に必ずpullしてから書く」を徹底する
- **非公開の徹底**: 個人的なメモ・複数事業の内部情報が集まる場所になるため、vaultリポジトリは
  必ず非公開のまま維持する。今回のセッションで扱った「hojo-hqは公開リポジトリなので機密を
  置けない」という制約とは逆に、こちらは非公開が前提の設計であることを混同しない
- **段階導入**: まずhojo-hq1リポジトリだけで試験運用し、書き込み頻度・粒度・重複防止の
  実効性を確認してから、他事業リポジトリへの展開を検討する
