# GLOW M&A・不動産 企業リレーション管理システム 設計書

作成: 2026-07-26 / 起点: たかしくん依頼 / 位置づけ: 株式会社GLOW(ALLGROUPグループ)の非公開営業支援基盤

---

## 1. 背景・目的

GLOWのM&A・不動産事業を長期的に伸ばすため、以下3つの開拓ルートで生まれる企業接点を、一元的に蓄積・可視化・再活用する専用システムを構築する。

- **①紹介ルート**: 税理士・銀行など士業/金融機関からの紹介
- **②手紙DMルート**: GLOW法人リスト7000件にスコア別の手紙を送付し、電話→「ゆんたく企業相談室」(嶺井さん起点、手紙→電話→訪問で会社相談を聞きながら関係構築)を通じてM&A機会を探る
- **③ミカタ経由ルート**: 「沖縄企業のミカタ」(助成金サイト)から生まれる企業接点を、既存事業(hojo-hq)の「出口2: GLOWへの接続」としてこちらに引き継ぐ

この3ルートで生まれた企業情報を長期的に整理し、定期的に掘り起こしアラートを出し、これまでの対応内容を蓄積し、現状を数値で可視化できるようにする。M&Aを起点としつつ、関係構築の過程・その後で不動産・法人保険の提案にもつなげる。

## 2. 位置づけ・関連事業

- 本システムは hojo-hq(沖縄企業のミカタ / もらいわすれ堂)とは別の非公開営業支援基盤。ただし同一リポジトリ内で管理し、`docs/技術ロードマップ.md` が確立した方針(**公開面は静的サイト/非公開データは別基盤**)を踏襲する。
- 沖縄企業のミカタとの接続点: CLAUDE.md記載の「出口2: GLOW(M&A・融資ニーズ)への接続」を、本システムの③ミカタ経由ルートとして実装する。ミカタ側のLINE登録企業データとの自動連携は本設計のスコープ外(初期は手動連携。将来拡張として4章に記載)。
- 人間側の主担当は、たかしくん(GLOW/現場推進)。手紙DMルートは嶺井さん起点。紹介ルートの相手は税理士・銀行等の外部パートナー。

## 4. 全体アーキテクチャ

### 4.1 データストア

非公開Googleスプレッドシート1冊「GLOW企業リレーション台帳」(仮称)をシステムの真実の源とする。GAS(Google Apps Script)でロジックを実装する。

理由: 複数人が日常的に営業ツールとして直接閲覧・編集できることを優先。`docs/技術ロードマップ.md`で検証済みの「GAS+Sheetsは数千行規模なら性能問題なし、非エンジニアの閲覧性が圧倒的」という判断を踏襲。将来的にデータ量やロジックが複雑化した場合はSupabase等への移行を検討する(移行トリガーは同ロードマップ文書の基準に準拠)。

### 4.2 コード管理

hojo-hqリポジトリ内に新規ディレクトリ `glow-ma/` を作成し、以下を格納する。

- Apps Script(.gs)ソース(claspでリポジトリ管理)
- スコアリング・アラート設定のドキュメント
- セットアップ手順書(スプレッドシートID・トリガー設定・Slack Webhook設定など、値そのものはコミットせず環境設定として分離)

**方針**: コードは公開リポジトリに置くが、実データ(企業名・対応履歴等)は一切コミットしない。アクセス制御はGoogleスプレッドシートの共有権限で行う(既存のGAS+Sheets方針と同一の考え方)。

### 4.3 処理フロー

```
[企業マスタ] ← 7000件一括インポート / 紹介パートナー経由の追加 / ミカタ経由の追加
      ↓ 対応履歴を都度手入力(電話・訪問・手紙送付・相談実施 等)
[GAS 日次トリガー]
   ├ 法人番号での名寄せ・重複統合
   ├ スコア再計算・ランク判定(A〜D)
   ├ 掘り起こし対象の判定 + ネクストベストアクション提示
   ├ 該当企業についてレター文面下書きをClaude APIで生成
   └ ダッシュボード集計シートを更新
      ↓
[Slack通知] 本日の掘り起こし対象・ネクストアクション一覧
```

## 5. データモデル

スプレッドシートのタブ構成は以下の通り。

### 5.1 企業マスタ

| 列 | 内容 |
|---|---|
| 企業ID | 内部一意ID |
| 法人番号 | 国税庁13桁(名寄せの主キー) |
| 会社名 / 業種 / 規模(従業員数等) / 代表者名・年齢 / 所在地 | 基本属性 |
| 流入ルート | ①紹介 / ②手紙DM / ③ミカタ経由(複数ルートから接点がある場合は全て記録) |
| 起点担当者・紹介元 | 嶺井/たかしくん等の社内担当、またはパートナー名 |
| 現在ステージ | 未接触→アプローチ実施→電話済み→相談実施→関係構築中→提案中→案件化→成約/見送り |
| 提案商品 | M&A / 不動産 / 法人保険(複数選択可) |
| 初期スコア / 反応スコア / 総合スコア / ランク(A〜D) | 6章参照 |
| 最終接触日 / 次回アクション予定日・内容 | フォローアップ管理 |
| 担当者 / 登録日 / 備考 | |

### 5.2 対応履歴ログ

企業IDに紐づく複数行。履歴ID / 企業ID / 日付 / 担当者 / 種別 / **対応相手**(オーナー社長本人 / 経理・総務等の窓口担当 / 未接触 — 意思決定者の関与度を可視化) / 内容メモ / そこから生まれた次回アクション(企業マスタへ反映)。

**種別の値(確定・入力規則で選択式にする)**: 手紙送付 / 電話 / ゆんたく相談実施 / 面談実施 / 紹介受領 / ミカタ接点確認 / レターURLアクセス / 返信 / 資料請求 / 提案(M&A) / 提案(不動産) / 提案(法人保険) / 成約 / 見送り / ナーチャリング配信。
このうち「レターURLアクセス・返信・ゆんたく相談実施・面談実施・資料請求」は6章の反応スコアに直接加点される「企業側からの反応」イベントとして扱う。表記ゆれによる集計漏れを防ぐため、SheetSetup.gsで本列にデータ入力規則(プルダウン)を設定する。

### 5.3 紹介パートナーマスタ

パートナーID / 名称(税理士法人・銀行支店等) / 種別 / 担当者名 / 関係性ランク / 累計紹介数 / 成約数 / **提供済み情報ログ**(こちらから業種別ニーズ情報等を提供した履歴 — ギブファースト運用の可視化) / **紹介料率**(取り決め内容) / **逆紹介履歴**(GLOW側からパートナーへ顧客・案件を紹介した記録 — Win-Winの関係を制度化) / 最終接触日 / 次回アクション予定日。

### 5.4 設定

スコア重み、ランク別標準接触サイクル日数、アラート閾値など、コードが参照する調整可能パラメータ。

### 5.5 ダッシュボード(自動生成)

7章参照。

## 6. スコアリング・ランク判定

> 2026-07-27 glow-ma-triangle-reviewにて確定(見直し期限: 2026-10-27)。三名体制の議事は
> `docs/superpowers/specs/2026-07-27-glow-ma-scoring-triangle-review.md` を参照。

総合スコア = 属性スコア + 流入ルートボーナス + 反応スコア

- **属性スコア(上限45点)**:
  - 業種のM&A流動性: 高群+20点/中群+10点/低群0点(分類リストは`設定`シートで初版を暫定管理し、運用しながら精緻化)
  - 規模の適正度合い(従業員数): 10〜50名+10点/5〜9名・51〜100名+5点/それ以外0点
  - 代表者年齢による事業承継リスク: **データがある場合のみの任意加点**(70歳以上+15点/60〜69歳+10点/50〜59歳+5点/49歳以下・不明は0点)。年齢データ欠損がモデルを歪めないよう、欠損時は必ず0点とする
- **流入ルートボーナス**: 紹介+30点/ミカタ経由+20点/手紙DM+0点。
  **例外ルール**: 紹介ルート(①)の企業は総合スコアに関わらず、8章の接触サイクルを常に「Aランク相当(30日)」として扱う(紹介案件は最優先接触を機械的に保証する)
- **反応スコア(上限95点。2026-07-27 反応スコア上限のglow-ma-triangle-reviewにて確定、見直し期限2026-10-27)**: 対応履歴ログの「種別」(5.2節で確定した企業側からの反応イベントのみ)から自動集計・加点。**同一企業について、種別ごとに初回発生時のみ加点し、2回目以降は加点しない**(同じ種別を何度繰り返しても点数は増えない)。種別ごとの加点: レターURLアクセス+5点/返信+15点/ゆんたく相談実施+25点/面談実施+25点/資料請求+10点。加えて、「対応相手」が「オーナー社長本人」の行が1件でもあれば+15点(意思決定者との対話ボーナス、こちらも企業につき1回のみ)。手紙送付・電話・紹介受領・ミカタ接点確認・提案系・成約・見送り・ナーチャリング配信は反応スコアに加点しない(ロジスティクス記録のため)。
  この設計により、同一イベントの水増し(同じURLへの複数回アクセス、同じ相手への複数回架電等)による不当なランク昇格を防ぐ。複数回接触した企業の温度感の細部は、対応履歴ログの閲覧で把握する運用とする(スコアは一次スクリーニングの目安)

**ランク閾値(固定点数方式)**: Aランク70点以上/Bランク40〜69点/Cランク15〜39点/Dランク14点以下。属性スコア上限45点+反応スコア上限95点=総合スコア理論上限140点であり、Aランク閾値70点に対して十分な幅がある。閾値は`設定`シートで調整可能とする(**現状はPhase 2実装で`glow-ma/src/scoring.js`の`DEFAULT_CONFIG`定数として管理しており、`設定`シートからの動的読み込みは未実装**。値を変える場合はコードを編集して`clasp push`し直す運用。動的連携は将来のPhaseで検討)。パーセンタイル方式(上位n%をAランクとする案)はデータ蓄積後に再検討する。

**月次の重み見直し**: スコアの重みは初期値のまま固定せず、月次で実際に成約・案件化した企業の属性を振り返り、`設定`シートの重みを見直す運用をあらかじめ組み込む。CLAUDE.mdの三名体制運営規程「前提破壊レビュー」の対象に含める。

## 7. 提案順序の設計方針(商品選定のガイドライン)

M&Aはオーナーにとって心理的ハードルが高い提案のため、いきなりM&Aを起点にするのではなく、警戒されにくい入口(保険の見直し・経営相談)から関係を構築し、信頼が深まった段階でM&A・不動産に進める順序を基本方針とする。

推奨フロー: **経営相談・法人保険の見直し(入口)→ 関係構築 → M&A・不動産の提案(本命)**

- ステージ「提案中」に移る際、企業マスタの「提案商品」欄には最初に提案した商品を記録し、対応履歴ログで商品の追加・変遷を追えるようにする
- 紹介ルート(①)は紹介元の文脈次第で直接M&A提案から入るケースもあるため、この順序は絶対ルールではなく推奨ガイドラインとして`設定`シートに明記し、現場の判断を優先する

## 8. 掘り起こしアラート・ネクストベストアクション

> 2026-07-27 glow-ma-triangle-reviewにて確定(見直し期限: 2026-10-27)。

- ランク別標準接触サイクル日数(確定値。`設定`シートで調整可能): **A=30日、B=90日、C=180日、D=365日**。Bランクを60日に短縮する案はキャパシティ未検証のため見送り、90日のまま据え置く
- **紹介ルート(①)の企業は総合スコアのランクに関わらず、常にA相当(30日サイクル)を適用する**(6章の例外ルール)
- 次回アクション予定日が設定されていればそれを優先。未設定かつ標準サイクル超過で「掘り起こし対象」フラグを立てる
- ステージ×ランクの組み合わせでネクストベストアクションをルールベースで提示(例: Bランク×未接触90日超→電話推奨、C×手紙送付済み反応なし180日→ゆんたく相談室の再案内)
- 判定結果は毎日GASトリガーからSlackへ通知(専用チャンネル)

**即時アラート(Speed to Lead)**: 上記の日次バッチとは別に、レターURLアクセスや返信など「企業側から反応があったイベント」は対応履歴ログへの記録をトリガーに即座にSlack通知する。法人営業では初動の早さが成約率を左右するため、日次バッチを待たない専用フローとして実装する。

## 9. 名寄せ

3ルートから同一企業が別々に登録されるケースを防ぐため、法人番号(13桁、国税庁法人番号公表サイトで無料照会)を企業マスタのユニークキーとする。重複検知時は1レコードに統合し、流入ルート欄には全ての接点を記録する。

## 10. レター生成・反応計測

- レター文面はスコア・業種別にClaude APIでパーソナライズした下書きを自動生成し、人が最終確認のうえ送付する(嶺井さん起点の手紙もこの仕組みに乗せる)
- 手紙にパーソナライズURL(簡易LP+GASリダイレクト)を記載し、アクセスの有無を反応スコアに自動反映する

## 11. ナーチャリング(育成)コンテンツの定期配信

M&Aの意思決定は数年単位に及ぶことが多く、電話・訪問だけでは接点の間隔が空きすぎて忘れられるリスクがある。事例紹介・税制改正情報などの低頻度コンテンツを全企業に定期配信し、関係を維持する仕組みを設ける。

- 配信対象: 「関係構築中」以降かつ直近接触が一定期間ないランクB以下の企業を中心に、四半期に1回程度を目安とする
- 配信内容: M&A成功事例・税制改正・業界動向など、営業色の薄い情報提供コンテンツ(Claude APIでの下書き生成を活用)
- 配信履歴は対応履歴ログに「ナーチャリング配信」として記録し、反応(URLアクセス等)は通常のレターと同様に反応スコアへ反映する

## 12. ダッシュボード

- ルート別(①②③)×ステージ別のファネル
- 提案商品別(M&A/不動産/法人保険)の提案数・案件化数・成約数
- ランク別の滞留企業数・掘り起こし待ち件数
- 紹介パートナー別の紹介実績・関係性温度・提供済み情報ログ一覧・逆紹介実績

## 13. 実装フェーズ

1. 企業マスタ・対応履歴ログ(対応相手フィールド含む)・紹介パートナーマスタ(紹介料率・逆紹介履歴含む)の器作成 + 法人番号での名寄せ設計 + 7000件一括インポート
2. スコアリング・ランク自動計算(GAS)+ 月次重み見直しの運用手順整備
3. 掘り起こしアラート + ネクストベストアクション判定 + 日次Slack通知 + 反応イベントの即時Slack通知
4. レター下書き生成(Claude API)+ 反応計測URL + ナーチャリングコンテンツの定期配信
5. ダッシュボード自動集計
