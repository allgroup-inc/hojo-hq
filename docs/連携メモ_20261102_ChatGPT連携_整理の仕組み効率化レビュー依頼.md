# 連携メモ: ChatGPTと連携して「整理の仕組み」をさらに効率化する

- 発信: 整理担当セッション(hojo-hq)
- 宛先: 小柳さん(ChatGPT側へ渡す下書きとしてもそのまま使える形にしてあります)
- 目的: 2026-09-21から作ってきた「情報が自動で溜まり、小分けに取り出せる」仕組み全体を、
  ChatGPTにも外部の目でレビューしてもらい、さらに効率を上げる改善案をもらう

**公開リポジトリの文書のため、機密(顧客情報・営業数値・M&A戦略等)は一切含めていません。**
ChatGPTへそのまま貼ってよい内容です。非公開リポジトリ(glow-docs-private・kakei-crm・
koyanagi-compass)の中身を貼るときは、先に守り部の確認を通してください。

## 1. ここまで作ってきたもの(全体像)

```
各チャット(❶〜❻・山梨版・家計側など)
   ↓ 決定・学び・仕組みを docs/ に議事・連携メモとして残す
hojo-hq(公開・正本)          glow-docs-private / kakei-crm(非公開・正本)
   ↓ 毎朝6時 自動同期(全文)        ↓ 写さない(索引への案内のみ)
obsidian-vault(GitHub上の保管庫)
   ↓ Obsidianの Git プラグインが10分ごとに自動取り込み
小柳さんの手元のObsidian
```

| 仕組み | 何をするか | 場所 |
|---|---|---|
| 全体マップ | どのチャット・どの文書・どのスキルに何があるかの索引 | `docs/全体マップ.md`(本リポジトリ)+ glow-docs-private・kakei-crm に同形式 |
| 部品庫 | 再利用できるコード・運用の型・スキルのカタログ。類似システム販売時の手順も | `docs/部品庫.md`(同上) |
| koyanagi-compass | 事業をまたいで共通する小柳さんの判断基準・価値観(全事業のCLAUDE.mdから参照) | 非公開リポジトリ `allgroup-inc/koyanagi-compass` |
| Obsidian自動同期 | hojo-hqの文書を毎朝6時に自動でObsidianへ反映 | `obsidian-vault`リポジトリの GitHub Actions |
| 月1棚卸し(Routine) | 毎月1日に自動起動し、議事・連携メモの本数集計、部品庫・全体マップへの追記、決裁キューの確認をしてPRを作る | このセッションに紐づく定期実行 |
| 月次の議事化依頼(Routine) | 毎月1日、主要チャット(❶営業管理システム・❷市場調査・山梨版・家計総合システム)へ「先月の決定を議事化して」と自動送信 | 同上 |
| 記憶の仕組み(WikiSkill Phase 1・2・10月導入) | 新しいチャットが起動すると、関連する過去の議事・失敗台帳・再発防止メモ・承認済み知識(Wiki)だけを自動で注入(6,000字上限) | `docs/wikiskill/`・`scripts/decision_memory.py` 等 |
| スキル品質管理パイプライン(10月導入) | スキルの新設提案・形式検証・効果測定を機械化 | `scripts/skill_proposer.py` 等 |

**実績**: この仕組みの上で、沖縄向けサイトの資産を組み合わせて山梨版・もらいわすれ堂を
短期間で立ち上げられた(部品庫からの横展開の第1号)。

## 2. 今、気づいている摩擦点(ここをChatGPTに見てほしい)

1. **PRが「取り込んで」の一言を待つ間に、mainが先に進んでコンフリクトする**。
   2026-10-01に作った月次棚卸しPRが1か月放置され、11/1の2回目実行時には
   作り直しが必要になった。自動実行→人の承認待ち→承認が遅れる、という構造自体の改善余地。
2. **新しい事業・チャットが増えたとき、自動化の対象に入れ忘れる**。
   2026-10-04に新事業(❻GLOW世界へ推進)が増えたが、月次の自動議事化依頼(Routine)の
   宛先には入っていなかった(11/1棚卸しで発覚)。「新しい場所を作ったら索引に1行足す」運動は
   浸透してきたが、「新しい場所を作ったら自動化の対象リストにも足す」はまだ抜けがある。
3. **全体マップ/部品庫/koyanagi-compass/WikiSkillの役割分担が、人間から見て直感的か**。
   全体マップ・部品庫(人が読む索引・カタログ)と、WikiSkill(AIが自動で読み込む記憶)は
   別物として設計したが、同じような情報を2系統で持つことになっていないか、重複や矛盾が
   出ていないかは定期的な目視が要る。
4. **スキル数の増加(現在110個、うち事業専用26個)に対して、陳腐化・重複を検知する仕組みが弱い**。
   新設は`skill_proposer.py`等で機械化されたが、「もう使われていないスキル」「内容が重複した
   スキル」を定期的に削る仕組みはまだ無い。
5. **決裁キュー(`docs/決裁キュー.md`)が長大化し、古い項目が埋もれやすい**。
   「上から順にやれば最速」の並び順ルールはあるが、本当に重要な項目が後方に埋もれていないかの
   機械チェックはまだ無い。
6. **非公開リポジトリ(機密側)はObsidianに複製しない設計にしたが、そのぶん小柳さんが
   機密側の最新状況を一目で把握する手段が薄い**(索引リンクをたどる必要がある)。

## 3. ChatGPTに依頼したいこと

- 上記1〜6を含め、この仕組み全体を外部の目でレビューし、**効率を上げる改善案**を出してほしい
- 特に「自動化はしたが、人の承認待ちがボトルネックになる」構造(摩擦点1)について、
  他の実例・定石があれば教えてほしい
- 新しい場所・チャットが増えるたびに自動化対象への追加漏れが起きる問題(摩擦点2)について、
  漏れを構造的に防ぐ方法(チェックリストより機械的な方法があれば)を提案してほしい
- 全体マップ/部品庫(人間向け)とWikiSkill(AI向け自動記憶)の役割分担が妥当か、
  重複や矛盾のリスクをどう継続的に検知すればよいか
