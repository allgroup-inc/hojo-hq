## 事象背景

2026-10-30、もらいわすれ堂の診断ページ（site/fukugiiro/shindan/）が「データ読み込み失敗」エラーを表示する障害が発生。

**根本原因**: 作業ブランチが main から3コミット遅れており、自動ワークフローで生成される最新ファイルが同期されていなかった。

**ビジネス影響**: その後の2週間で外部からの指摘が4件に達し、新規顧客獲得に支障が生じた。

---

## 実装内容：4層の防御システム

### 📊 システム全体図

```
             自動化層            通知層           人間層            対応層
              
    [Layer 1]              [Layer 2]        [Layer 3]         [Layer 4]
  自動ワークフロー  →  Slack即時通知  →  人による確認  →  人間対応フロー
   (6時/12時 UTC)     (数分以内)      (9時/14時 JST)    (直ちに実行)
   
   • ブランチ同期       • webhook        • チェックリスト   • 原因分析
   • ファイル検証         通知          • 記録              • GitHub修復
   • 冗長実行                         • 判定              • Slack報告
```

### Layer 1: 自動ワークフロー（毎日2回）

**ファイル**: `.github/workflows/daily-sync-branches.yml`

**動作**:
1. 毎日 6:00 UTC と 12:00 UTC の2回実行
2. `claude/*` ブランチを `origin/main` と自動同期
3. マージ後、生成ファイルの完全性を検証
   - site/fukugiiro/index.html
   - site/fukugiiro/shindan/index.html
   - site/fukugiiro/area/*/index.html
   - site/fukugiiro/kit/*/index.html
   - site/fukugiiro/life/*/index.html
4. 全ファイル存在確認 → コミット・push
5. 失敗時 → Slack webhook で通知

**冗長性**: 6時実行が失敗しても、12時実行があるため最大12時間以内に復帰

### Layer 2: Slack 即時通知

**実装内容**: GitHub Actions の `failure()` トリガーで Slack webhook を呼出

**通知内容**:
```
🚨 Daily Sync Workflow Failed

Branch: claude/okinawa-disposable-income-plan-axxs6v
Repository: allgroup-inc/hojo-hq
Action: View Details [リンク]
```

**効果**: 
- **気づきラグ短縮**: 従来 6+ 時間 → **1時間以内**
- 人間が迅速に対応できる時間を確保

### Layer 3: 人による日次目視確認（平日 9:00 / 14:00 JST）

**実施内容**: `docs/診断ページ日次確認チェックリスト.md`

**確認項目** (1回 約2分):
1. 本番ページの読み込み確認（moradou.jp/shindan/ にアクセス）
2. 診断機能の動作確認（「農業」で診断を実行）
3. ブランチ状態確認（`git log` で main と比較）
4. ワークフロー実行状態確認（GitHub Actions ジョブの成功/失敗）

**記録**: `docs/診断ページ日次確認記録_YYYYMM.md` に逐日記録

**効果**:
- 自動検査が見落とす問題を人間が検知（偽陰性防止）
- 一過的なネットワーク障害等を早期発見

### Layer 4: 人間対応フロー

**トリガー**: Slack 通知受信 → 技術チームが直ちに確認

**対応内容**:
1. GitHub Actions ログを確認（失敗箇所の特定）
2. ブランチの git 状態を確認
3. 問題があれば修復・push
4. チーム全体に Slack で報告
