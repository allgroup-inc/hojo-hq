# 保険引き受け目安検索 導線設計
作成: 2026-08-17 / 実装ステータス: insurance-underwriting-tool.html
関連: [LINE運用設計.md](LINE運用設計.md) / [診断動線ゼロベース設計.md](2026-07-27-診断動線ゼロベース設計.md)

## 事業上の位置づけ
保険引き受け目安検索は、沖縄企業のミカタの**補助的ツール**として位置づけられる。
主流の出口は士業送客・GLOW接続だが、特に小規模経営者層（従業員1〜10名）では、
経営課題を整理する前に「うちはどんな保険に入るべき？」という**保険的リスク意識**が動機になることが多い。
このツールはそのニーズをキャッチし、**保険会社パートナーシップ**経由で企業リード化する出口。

| 観点 | 説明 |
|---|---|
| **ユーザー層** | 中小企業経営者・経営管理職（Bizdev/CFO） / 士業クライアント |
| **主要タスク** | 「経営プロフィール（業種/規模/課題）」から「引き受け対象の保険商品」を検索 |
| **LINE連携** | LINE登録後、セグメントタグ『保険関心』に基づき、保険商品アラート配信（パートナー社単位） |
| **パートナー** | なないろ生命・FWD生命・チューリッヒ生命（将来: 日本生命・東京海上など） |

## ❶〜❼ との接続
本ツールは診断動線❶〜❼の**外部リンク**として機能する。

```
サイト診断(❶〜❺)
  ├─ 補助金マッチング → LINE登録 → 制度アラート配信（主流）
  └─【分岐】経営課題が「人件費/リスク管理」 → 
      ┌─ 👉 【保険引き受け目安検索】← このツール
      │   └─ 業種/規模から引き受けOKの保険商品を一覧
      │   └─ 気になる商品 → 保険会社Webサイトへ遷移
      │   └─ LINE登録時に『保険関心』タグ付与 → 商品アラート配信
      └─ 【融資診断】（GLOW連携・将来実装）
          └─ 融資ニーズ → GLOW営業チームへ
```

接続条件:
- **入口**: 診断結果画面から「保険引き受け目安も見る」リンク（/go/insurance-shindan/）
- **LINE統合**: LINE登録時に会社情報と共に「保険関心あり」セグメントタグを付与（tsunagu.md と協調）
- **バナー配置**: サイト公式キャラ（ツナグさん）が「経営課題が『人件費管理』『後継者育成』なら、このツールもオススメ」と案内

## 画面仕様

| 要素 | 仕様 | 備考 |
|---|---|---|
| **タイトル** | 保険引き受け目安検索 | 診断結果画面からのリンク明示 |
| **サブタイトル** | 業種・規模から、あなたの会社が加入できる保険がわかる。 | ブランドトーン準拠 |
| **検索方式** | 病名キーワード検索（非構造化） / 保険種目タブ切り替え（なないろ・FWD・チューリッヒ） | 現実装：キーワード検索 / タブ3つ |
| **検索結果** | 病名 → 該当保険会社の商品ラインアップ（◎=加入OK / △=要確認 / ✗=加入不可） | 3社統合JSON（8.8MB） |
| **アクション1** | 「詳しく見る」ボタン → 保険会社公式サイトへ遷移（utm_source=hojo_hq / medium=insurance_tool） | 計測目的 |
| **アクション2** | LINE登録前: 「全商品を見るにはLINE登録」オーバーレイ / 登録後: 全表示解禁 | localStorage活用（実装済み） |
| **CSV出力** | 検索結果をCSV（病名/保険会社3社の可否/判定理由）としてダウンロード | 内部利用・経営会議資料化 |

## LINE統合シーケンス

```
利用者が保険検索 → 「この保険が気になる」
  ↓
LINE登録ボタンクリック（スムーズ移行: 登録後に検索結果へ戻す）
  ↓
LINE友だち追加 + 会社情報入力フォーム表示
  ↓
会社情報投稿 → OAMessage【会社情報登録】受信（tsunagu.md）
  ↓
返信文自動生成ツール（reply.html）で『保険関心』タグ付与
  ↓
翌週の保険商品アラート配信（火曜朝 / 該当保険会社の新商品のみ）
```

**技術実装**:
- `site/insurance-underwriting-tool.html` の LINE登録ボタンは、`go/shindan/` を経由して LINE Official Account に遷移（現状実装済み）
- 登録後に医元のページへ戻す仕組み: sessionStorage に「保険検索中」フラグを保持して、LINE登録完了後に自動リダイレクト
- OAMessage フォーマット: `【会社情報登録】会社名: ○○ / 市町村: ○ / 業種: △△ / 保険関心: あり`

## セグメント・タグ設計

| タグ | 付与条件 | LINE配信対象 |
|---|---|---|
| `関心:保険_なないろ` | 検索結果で「なないろ生命◎」or 【会社情報登録】で『保険関心:なないろ』 | なないろ生命の新商品アラート |
| `関心:保険_FWD` | 検索結果で「FWD生命◎」or 【会社情報登録】で『保険関心:FWD』 | FWD生命の新商品アラート |
| `関心:保険_チューリッヒ` | 検索結果で「チューリッヒ◎」or 【会社情報登録】で『保険関心:チューリッヒ』 | チューリッヒ生命の新商品アラート |
| `関心:保険` | 上記いずれか 1 件以上 | LINE配信「保険関連」として扱う（KPI計測用） |
| `状態:保険検索済み` | 保険検索ツール使用完了（Google Analytics イベント `insurance_search_complete`） | LINE配信の「スコア」に +1（関心度指標） |

## 配信シーケンス（LINE部・tsunagu.md 決定）

| 配信 | 頻度 | 内容 | ソース |
|---|---|---|---|
| 保険商品アラート | 週1（火朝） | 対象企業に引き受けOKの新商品・改定情報（1〜2件） | パートナー保険会社提供 / 自動配信（Power Automate） |
| 保険活用事例 | 月1 | 業種別・課題別の活用事例（e.g. 小売業でのリスク管理） | note編集部（tsuzuru.md） |
| 保険 ✕ 補助金 クロス施策 | 月2 | e.g. 「育休復帰手当+団体保険加入」で企業負担を軽減 | SNS部・LINE部協調 |

配信ルール:
- 【保険関心】タグ保有企業のみ配信
- ブロック率 5% 超の場合、翌週の配信を 1 本中止（補助金アラートと同じルール）
- 保険会社別セグメント（なないろ/FWD/チューリッヒ）による個別配信（同時に全社アラートは送らない）

## 計測・KPI

| KPI | 目標値 | 計測方法 | 責任者 |
|---|---|---|---|
| **保険検索実行数/月** | 50件 | Google Analytics イベント `insurance_tool_search` | LINE部 |
| **検索→LINE登録率** | 30%以上（診断と同じ基準） | UTM 計測（/go/insurance-shindan/） | LINE部・SNS部 |
| **LINE登録者の『保険関心』タグ付与率** | 80%以上 | reply.html の自動タグ付与数 / 登録数 | LINE部 |
| **保険商品クリック→遷移数/月** | 20件 | utm_source=hojo_hq のクリック（保険会社Webサイト側） | パートナー保険会社 / LINE部が月次確認 |
| **Lighthouse スコア** | 4項目 95 以上 | CI/CD （GitHub Actions） | 技術部 |

保険パートナーシップの基本：
- **BtB契約**: クリック単価型（CPM ¥100/click）/ リード生成型（CPL ¥1,000/lead）のいずれか
- **月次報告**: LINE部 → パートナー保険会社への実績レポート（友だち数・検索実行数・アラートクリック数）
