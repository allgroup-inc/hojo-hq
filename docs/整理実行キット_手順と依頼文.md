# 整理実行キット — 安全ルール・手元手順・貼るだけ依頼文

## 1. 安全ルール(これだけ守れば事故が起きない・3つ)

1. **置き場所に迷ったら、非公開側(glow-docs-private)へ置く**。
   このリポジトリ(hojo-hq)は誰でも見られる公開設定。顧客名・営業数値・
   M&A戦略・個人情報は絶対にこちらへ書かない(CIの機械検査もあるが、最初から書かないのが一番安全)
2. **正本(オリジナル)は常にGitHub、Obsidianは自動で写る「鏡」**。
   Obsidian側だけに決定事項を書かない(鏡に書いても元には映らない)
3. **チャットで大事なことが決まったら、その場で「docsに議事として残してプッシュして」と一言頼む**。
   これが「自動で溜まる」を支える唯一の人間側の作業

## 2. 小柳さんの手元手順(Obsidianに自動で溜める設定)

どちらか1つでOK。迷ったら【かんたんコース】から始めて、慣れたら自動化。

### かんたんコース(マウス操作だけ・毎回ワンクリック更新)
1. **GitHub Desktop** をインストール(desktop.github.com)し、GitHubアカウントでログイン
2. 「File → Clone repository」で次を1つずつ取得(保存先はまとめ用フォルダ、例: `ALLGROUP保管庫`):
   - `allgroup-inc/hojo-hq`
   - `allgroup-inc/glow-docs-private`
   - `allgroup-inc/kakei-crm`(家計側も見たい場合)
3. **Obsidian**で「保管庫(Vault)を開く」→ `ALLGROUP保管庫` フォルダを指定
4. 以後、最新にしたいときは GitHub Desktop を開いて各リポジトリで **「Fetch/Pull」ボタンを押すだけ**(週1回でも十分)

### 自動コース(設定は少し手間・以後は完全放置)
1. かんたんコースの1〜3まで同じ
2. Obsidianの設定 → コミュニティプラグイン → **「Git」** を検索して入れる
3. Gitプラグインの設定で「Auto pull(自動プル)」を **30分間隔** にする
4. 以後、議事が増えるたび自動でObsidianに現れる(操作ゼロ)

### 確認方法(設定がうまくいったかのテスト)
- Obsidianの検索で `全体マップ` と打ち、`hojo-hq/docs/全体マップ.md` が開けば成功
- 数日後に `議事_` で検索し、新しい日付の議事が増えていれば同期も成功

## 3. 貼るだけ依頼文(コピーしてそのまま各チャットへ)

### 宛先一覧(どの依頼文をどのチャットに貼るか)

| 依頼文 | 貼るチャット(名前) | 補足 |
|---|---|---|
| A(非公開側マップ作成) | **❸ 事業構成&ゆんたく【GLOW】だけ** | glow-docs-privateの索引はこの1チャットが作る。**❷にも貼ると同じファイルを同時編集して衝突する**(2026-08-19の事故と同型)ので貼らない |
| A'(❷向けの短い版) | ❷ 沖縄県M&A市場調査【GLOW】 | 「❸が索引を作るので、市場調査側の資産の一覧を❸へ渡して」と依頼(下記A') |
| B(kakei-crm側マップ作成) | 家計のポっ・面談予約表(アポ管理)を扱っているチャット | 2026-08-22にkakei-crmへ移設した作業をしたチャット。見当たらなければ新しいチャットにkakei-crmを開かせて依頼文BとDを一緒に貼る |
| C(月1定期便) | ❷・❸・❹ 沖縄企業のミカタ【GLOW】・山梨版担当・家計側 の5つ | 毎月初に同文でOK。❶と本体チャット(このリポジトリで作業するチャット)は日々の運用で自動的に溜まるため不要 |
| D(新チャットの最初に貼る) | 今後新しく作るチャット全部 | 山梨版のような新地域・新事業のチャットを作るときは必ず最初に貼る |
| ❺ 事業構成【GLOW】(過去) | **何も貼らない** | 参照専用。新規の依頼をしない |

### 依頼文A'(❷市場調査向け・短い版)

```
【依頼】非公開リポジトリ glow-docs-private の索引(全体マップ・部品庫)は
❸事業構成&ゆんたくのチャットが作成します。このチャット(市場調査)が作った資産
(企業リスト・調査手法・調査プロンプト等)の一覧を、連携メモの形式で❸へ渡してください。
ファイルの新規作成・編集はせず、一覧の受け渡しだけお願いします。
```

### 依頼文A: 非公開側にも「全体マップ+部品庫」を作らせる
(貼る先: ❷市場調査、❸事業構成&ゆんたく など glow-docs-private を扱うチャット)

```
【依頼】非公開リポジトリ allgroup-inc/glow-docs-private に、次の2つの索引文書を
作ってプッシュしてください。公開側 hojo-hq の docs/全体マップ.md と docs/部品庫.md と
同じ形式にしてください(形式はそのファイルを参照)。

1. 全体マップ.md: このリポジトリに何があるか(議事・戦略・LPビルド元・ツール)の索引。
   冒頭に「ここは非公開。顧客情報・営業数値・M&A戦略はこちら側に置く」と明記
2. 部品庫.md: ここで作った再利用できる仕組み(手紙アプローチの型、QRカード生成
   ツール等)の一覧。各行に「場所」と「取り出すときのコツ」を書く

完成したら、公開側に置ける範囲の要約だけを hojo-hq の
docs/連携メモ_YYYYMMDD_非公開側マップ整備.md として送ってください(機密の中身は書かない)。
```

### 依頼文B: kakei-crm(家計側)にも同じ索引を作らせる
(貼る先: 家計の見直しやさん/アポ管理を扱うチャット)

```
【依頼】非公開リポジトリ allgroup-inc/kakei-crm に、公開側 hojo-hq の
docs/全体マップ.md と docs/部品庫.md と同じ形式で「全体マップ.md」と「部品庫.md」を
作ってプッシュしてください。アポ管理(家計のポっ)・面談予約表など、ここにある
システムの一覧と再利用できる部品を索引化するのが目的です。顧客の個人情報そのものは
索引に書かず、「どのファイルにあるか」だけを書いてください。
```

### 依頼文C: 月1の定期便(決定事項の吸い上げ)
(貼る先: 毎月1回、❷❸❹・山梨・家計など「リポジトリ外で会話しているチャット」全部)

```
【月次依頼】今月このチャットで決まったこと・作ったもの・変えたルールのうち、
まだ文書(議事・連携メモ)として残っていないものを洗い出してください。
そのうえで:
1. 決定事項 → 議事_YYYYMMDD_<件名>.md の形式で(ウタガイの反対理由も必ず記録)
2. 他チャットに関係するもの → 連携メモ_YYYYMMDD_<件名>.md の形式で
それぞれ担当リポジトリ(公開してよいものは hojo-hq/docs、機密は glow-docs-private)に
プッシュしてください。迷ったら非公開側へ。完了したら作った文書の一覧を報告してください。
```

### 依頼文D: 新しいチャットを始めるときの冒頭に貼る文

```
【最初のルール】過去の決定・文書・仕組みを探すときは、まず
hojo-hq/docs/全体マップ.md(索引)と docs/部品庫.md(再利用カタログ)を見てください。
このチャットで大事なことが決まったら、その場で議事(議事_YYYYMMDD_件名.md)として
docsに残してプッシュしてください。機密は公開側に置かず glow-docs-private へ。
```
