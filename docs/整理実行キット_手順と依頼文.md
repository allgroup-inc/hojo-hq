## 1. 安全ルール(これだけ守れば事故が起きない・3つ)

1. **置き場所に迷ったら、非公開側(glow-docs-private)へ置く**。
   このリポジトリ(hojo-hq)は誰でも見られる公開設定。顧客名・営業数値・
   M&A戦略・個人情報は絶対にこちらへ書かない(CIの機械検査もあるが、最初から書かないのが一番安全)
2. **正本(オリジナル)は常にGitHub、Obsidianは自動で写る「鏡」**。
   Obsidian側だけに決定事項を書かない(鏡に書いても元には映らない)
3. **チャットで大事なことが決まったら、その場で「docsに議事として残してプッシュして」と一言頼む**。
   これが「自動で溜まる」を支える唯一の人間側の作業

## 2. 小柳さんの手元手順(2026-09-21 改訂: 1分で終わる)

Obsidianの保管庫は GitHub の非公開リポジトリ `allgroup-inc/obsidian-vault` として既に存在し、
公開側 hojo-hq の文書は毎朝6時に自動で写される(詳細: docs/Obsidian連携ガイド.md)。
手元で必要なのは**初回だけ**: Obsidianでコマンドパレット(Ctrl/Cmd+P)→「Git: Pull」→ Obsidianを再起動。
以後は10分ごとに自動で取り込まれる。`00_はじめに.md` が見えれば成功。

## 4. 月1棚卸しチェックリスト(5分で終わる)

**自動化済み(2026-09-21 小柳さん依頼)**: 毎月1日 朝9時(日本時間)に、整理担当のClaude Codeセッション
(Routine「月1棚卸し(全体マップ・部品庫・議事の点検)」)が自動で起動し、下記のうち
「議事・連携メモの本数集計」「全体マップ・部品庫への不足行の追記(PR作成まで)」「決裁キューの
返事待ち確認」「依頼文Cの宛先つき再掲」を実行して報告する。**取り込み(マージ)は自動では
しない**(レビューなしのマージは不可の方針)。報告に「取り込んで」と返信すれば、CI合格を確認のうえ
取り込まれる。人が行うのは、下記のうち依頼文Cの貼り付けとObsidian側の確認だけ。

- [ ] 依頼文Cを各チャットに貼った(月初のどこかで。文面と宛先は自動報告に再掲される)
- [ ] Obsidianで `議事_` を検索 → 今月の日付の議事が増えている
- [ ] 全体マップ・部品庫に「新しく作った仕組み」の行が足りているか見る(足りなければ「部品庫に○○を追加して」と本チャットへ)
- [ ] 決裁キュー(docs/決裁キュー.md)に返事待ちが溜まっていないか見る
- [ ] Obsidianの手書きメモで「事業の決定」に当たるものがあれば、docs側へ移すよう依頼
