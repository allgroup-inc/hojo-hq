# 顧客データ・セキュリティ運営体制(最高水準)

作成日: 2026-07-26 / 起案: Claude(churn-pii-guard 準拠)/ 最終決裁: 小柳さん
方針: **早期解約リスク保全システムは、最高水準のセキュリティで運営する。** 本書は、そのための"体制"(誰が何に責任を持ち、どの順で承認・決裁するか)を定義する。個別の判断はこの体制の中で行う。
関連: `docs/顧客データ分離アーキテクチャ案.md` / `docs/守り部審査チェックリスト_実データ投入前.md` / スキル `churn-pii-guard`

## 0. 大前提(正直な線引き)
- 「最高水準」はコード・設計だけでは達成できない。**環境・組織・第三者検証**まで含む。
- AI・エージェントは**判定者にならない**。安全性の可否判断は守り部＋専門家＋小柳さんが行う。本体制はそれを確実に回すための枠組み。

## 1. 体制図(誰が何に責任を持つか)

```
                         小柳さん(最終決裁)
                              │
                 最高セキュリティ統括(CISO相当)   ← ★決裁事項:誰が担うか
                 情報統制・最高水準運営の総責任
        ┌─────────────────┼─────────────────┐
   守り部トライアングル      独立監査トライアングル      外部専門家(第三者)
   マモル(法務全般)         テキホウ(適法性)          セキュリティ監査/
   コジン(個人情報)         ダトウ(妥当性)            個人情報の専門家
   シギョウ(資格・業法)      コウヘイ(独立・公平)       ★決裁事項:必須化
        │                    │
   現場運用(データ基盤部)     ニドナシ機構(再発防止・監視)
   ソナエ/キンコ(格納・統制)   ※小柳さん直・独立
```

- **最終決裁: 小柳さん** — 予算・体制・実データ投入・提携の最終決定。
- **最高セキュリティ統括(CISO相当)** — 最高水準運営の総責任。関門(実データ投入ゲート)の運行、方針・変更の取りまとめ、有事の指揮。※誰が担うかは決裁事項(案:QCMさんの"統制"マンデート拡張、または専任者)。
- **守り部トライアングル(マモル/コジン/シギョウ)** — 法務・個人情報・資格の審査。
- **独立監査トライアングル(テキホウ/ダトウ/コウヘイ)** — 指揮系統の外から点検。小柳さん直。
- **外部専門家(第三者)** — セキュリティ監査・個人情報実務のプロ。**最高水準を名乗る肝**(内部評価だけでは"最高"にならない)。
- **現場運用(データ基盤部 ソナエ/キンコ)** — 格納・アクセス制御・誤コミット防止の実務。
- **ニドナシ機構** — 再発防止・監視(小柳さん直・独立)。

## 2. 意思決定・承認フロー(関門=ゲート方式)

**実データ投入ゲート(本物の顧客個人情報を入れる前に必ず通す):**
```
① 守り部審査チェックリスト(11分野)を全項目「可」にする
      ↓
② 守り部トライアングルが審査・記名
      ↓
③ 独立監査トライアングルが点検(適法性・妥当性・公平性)
      ↓
④ 外部専門家が第三者レビュー(勧告に従う)
      ↓
⑤ 最高セキュリティ統括が取りまとめ → 小柳さんが決裁
      ↓
✅ ここで初めて実データ投入可(未通過の間は合成データのみ)
```

**変更管理(閾値・カルテ共有範囲・環境・連携先などの変更):**
- 意思決定を伴う変更は**三名体制(`hojo-triangle-review`)で議事化**(ウタガイの反対理由必須)→ 守り部確認 → 小柳さん決裁。無断で業務パラメータや統制を変えない。

## 3. 定例・監視のカデンス
| 頻度 | 内容 | 主体 |
|---|---|---|
| 都度(実データ投入前) | 関門ゲート審査 | 守り部＋監査＋外部＋小柳決裁 |
| 月次 | セキュリティレビュー(アクセスログ点検・権限棚卸し・誤コミット有無) | 最高セキュリティ統括＋データ基盤部 |
| 四半期 | 外部専門家による監査 | 外部専門家＋独立監査 |
| 随時 | 前提破壊レビュー・全会一致警戒(視点の同化検知) | 監査(運営規程準拠) |
| 見直し期限 | 最長6ヶ月、または法令・環境・連携先変更時に再審査 | 全体 |

## 4. インシデント対応(有事)
- **初動指揮**: 最高セキュリティ統括。誤って公開リポジトリにPIIをコミット等の緊急事象は**即時停止・遮断**を最優先(事後48時間以内に3役レビュー=運営規程の緊急例外に準拠)。
- **報告ルート**: 現場 → 最高セキュリティ統括 → 小柳さん。必要に応じ当局・本人への対応(コジン/マモル/外部専門家)。
- **手順の常備**: 取り消し・履歴削除・影響評価・再発防止(ニドナシ機構)。

## 5. 三名体制の議事(体制の要の決定)

### 論点: 最高水準運営の体制をどう置くか(CISO相当の設置・外部監査の必須化)

**スイシン(推進)**
- 最高セキュリティ統括(CISO相当)を明確に置き、関門ゲートを運行。**外部専門家の第三者監査を必須**にする。内部評価だけでは"最高水準"を名乗れない。責任の所在と説明責任が立つ。

**ウタガイ(懐疑)** ← 反対必須
- 役職と関門を"作った気"になり、**現場の環境統制(端末・保管・権限)が伴わなければ無意味**。体制図より実装が本丸。
- 外部監査は**コスト・時間**がかかる。まだ導入前・小規模の段階で、関門を重くしすぎると**いつまでも実データに進めない**逆リスク。専任CISOも人的コスト。
- 内部の守り部＋監査で回せる範囲を超えて過剰体制になると、形骸化・責任の分散を招く。

**ベッカイ(別解)**
- 専任CISOを置く前に、**外部専門家に"体制設計そのもの"を委ね**、その勧告どおりに最小限で構築する(過不足を専門家に判定させる)。
- 段階導入: まず限定データ・限定人数で回し、外部監査を通しながら範囲を広げる(全部を最初から最大にしない)。

**裁定(小柳さんへ上申)**
- 方向は**スイシン(統括設置＋外部監査必須)を推奨**。ただしウタガイの「本丸は環境統制」「重すぎると進めない」を容れ、**ベッカイの段階導入**を採る:
  1. まず**外部専門家に体制・水準の設計を相談**(過不足の判定を委ねる)。
  2. その勧告に沿って、環境統制(③顧客データゾーン)を先に固め、関門ゲートを整える。
  3. 限定範囲で外部監査を通してから、範囲を拡大。
- CISO相当を誰が担うか・外部専門家を誰にするか・予算は**小柳さん決裁事項**。
