## Phase 2 での UI 配線：責任分担・インターフェース仕様

### ②UI から呼び出す際のインターフェース（呼び出し仕様）

#### A. 呼び出し先

```javascript
// 管理システム内部（API）
POST /api/hozen/board/sync
{
  "customer_id": "KM-000001",
  "category": "未収案内",
  "carrier": "YAMATO",
  "disposition": "解約阻止/継続合意",
  "checklists": [
    {
      "group": "同意確認",
      "options": ["契約者同意済み"],
      "selected": ["契約者同意済み"]
    }
  ],
  "insurer_request": "依頼済",
  "crm_sync": "済",
  "contact_method": "電話"
}
```

#### B. customer_id・category・carrier の特定方法

| パラメータ | 取得方法 | 出典 |
|---|---|---|
| `customer_id` | 顧客カルテ画面の URL から取得（既存） | `GET /api/customers/dossier?id=KM-000001` の結果 |
| `category` | board row の対応する行から読み出し | 既に表示中の受渡・管理タブのテーブルから |
| `carrier` | board row の対応する行から読み出し | 既に表示中の受渡・管理タブのテーブルから |

**設計ポイント：** 
- customer_id は「今開いている顧客」で確定
- category・carrier は「更新対象の行をクリック」or「行全体を単位に同期」で特定
- つまり、コール画面での操作 → board_store.update_case() → 軸へ POST → 管理システムが受け取り表示

#### C. 更新フロー（時系列）

```
[保全 CRM] コール画面で処理状況入力
  ↓
[保全 CRM] record_call() で call_log へ記録
  +
[保全 CRM] board_store.update_case() で board_store へ反映
  ↓
[軸] 定期的に（現在は 1 日 1 回）GET /board_store
  ↓
[軸] 変化があれば管理システムへ POST /api/hozen/board
  ↓
[管理システム] 受け取り・顧客カルテの「受渡・管理」タブをリアルタイム更新
```

**実装タイミング：**
- 保全 CRM は現状のまま。board_store.update_case() が呼ばれるたびに軸へ送信する仕組みは後で検討（現在は定期バッチ）
- 管理システムは Phase 2（10月末）から `/api/hozen/board` 受信側の実装を開始
