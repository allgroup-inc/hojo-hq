## 2. 各軸の設計

### 軸A: note有料メンバーシップ「月刊 沖縄補助金白書」
- 無料の週刊定点観測(vol.N)が集客、白書が課金の二層構造。noteのメンバーシップ機能を使い決済・会員管理は持たない(固定費0)
- 内容(全自動生成): 今月の全体像/金額帯の分布/目的別マップ(省エネ・IT・設備・人材・創業承継)/向こう3ヶ月の締切カレンダー(**掲載は締切30日以上のみ**・3層ルール準拠)
- 有料でも憲法は同じ: 断定しない・原文URL併記・30日未満は件数+LINEアラート誘導
- 収益試算(参考): 会員100人×980円=月9.8万円。ただし主目的は「有料でも読みたい」実績による士業・金融機関への信用形成

### 軸B: パートナー版白書(士業・商工会・金融機関向け)
- 軸Aと同じデータから**顧客に話すための資料**として再編集: 各カテゴリに「顧客への声かけ例」を付け、LINE誘導CTAを外し提携窓口案内に差し替え
- 使い方(ムスブさん): ①専門家掲載モデルの掲載特典として同梱(掲載料の価値を上げる) ②非掲載の士業・金融機関へ単体販売(提案価格10,000円/月) ③商工会へは無償提供して紹介動線の対価とする
- 出力先: reports/partner/(サイトには載せない。配布はムスブさん経由のみ)

### 軸C: 週刊記事内スポンサー枠
- 週刊定点観測の記事末尾に「この制度、誰に頼めばいい?【PR】」枠(最大2枠)
- data/note_sponsors.json で管理。`active: false` の間は記事に一切出ない=**決裁までは現状と同一の記事**
- 法務(専門家掲載モデルの確定ルールを継承): 定額掲載料(広告)のみ・成果報酬型紹介料なし・弁護士枠なし・**ステマ規制対応で【PR】表記を機械的に強制**(スクリプトが必ず付す)

## 3. 三名体制の論点(スイシン/ウタガイ/ベッカイ)

### スイシン(推進)
- 3軸とも既存資産(DB・note生成基盤)の再編集のみで限界費用ほぼゼロ。人の追加作業は月1回のコピペ+配布のみ
- 軸Bは「登録◯◯社が見る媒体」実績を待たずに始められる唯一の収益(白書そのものに商品価値がある)ため、掲載モデルの第2期開始(LINE300社)より早く現金化できる
- 軸Aの会員数は公開情報になり、それ自体が提携営業の証拠になる

### ウタガイ(懐疑・反対理由の記録)
1. **リード獲得装置との利益相反**が最大の懸念。情報を有料化するほど「無料で全部見せてLINEに集める」本来の設計と食い合う。白書に価値を寄せすぎると無料側=LINE登録の動機が痩せる
2. 軸Cは読者から見れば広告。**開始が早すぎるとメディアの中立性・信頼が育つ前に毀損**する。専門家掲載モデルがLINE300社をトリガーにした判断と矛盾しかねない
3. 軸Bの単体販売は、士業側から「うちの商売道具を競合他所にも売るのか」と提携関係を悪化させる恐れ(排他性の設計がない)
4. 収益規模はいずれも月数万〜十数万円で、**本業KPI(1,000社)への集中を薄めるほどの管理コストに見合うか疑問**。運用が増えるほど正確性事故の面も増える

### ベッカイ(別解・前提を疑う)
- 懸念1への別解: 「無料=速報とフロー、有料=整理とストック」で情報の**種類**を分ける。白書に載る個別制度情報はすべて無料サイトにもある(隠さない)。有料の価値は「整理・俯瞰・カレンダー化」という編集にのみ置く → LINEの価値(個別アラート)とは競合しない
- 懸念2への別解: 軸Cは**実装と販売を分離**する。仕組みだけ先に入れて空枠のまま眠らせ、販売開始は専門家掲載モデルと同じトリガー(LINE300社+小柳さん決裁)に揃えれば矛盾しない
- 懸念3への別解: パートナー版は「地域・分野で緩い排他」(同一市町村×同一士業種で最大3、掲載モデルと同じ3枠思想)を販売条件に明記する
- 懸念4への別解: 3軸とも生成は同一パイプラインの派生で、増える定常運用は「月1回の白書コピペ」だけ。管理コストはほぼ増えない。逆に収益実績はALLGROUP内での本事業の予算確保材料になる

### 部門長の裁定
- 採否: **軸A/B/C採用(実装+決裁ゲート)、D提案のみ、E不採用**
- 理由: ベッカイの「無料=フロー/有料=編集」の切り分けでウタガイ懸念1を回避できる。軸Cはベッカイ案どおり実装と販売を分離し、販売トリガーは専門家掲載モデルに揃える。懸念3の排他条件は販売開始前にムスブさん経由で条件文書化する
- ウタガイ懸念の監視: 白書公開後、無料記事→LINE登録率が悪化(3週連続で前月比▲20%超)した場合は白書の内容を縮小し再議論
- 見直し期限: **2027-01-31**(note自動化と同時レビュー。軸別の収益実績と工数で継続判断)
