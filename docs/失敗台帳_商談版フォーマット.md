# 失敗台帳(商談版)— 売上側の学習ループ用(削除禁止)

作成: 2026-08-02 / 根拠: docs/達成確率を上げる設計_仕組みの接続_2026-07-31.md ループ4(失敗台帳を売上側にも使う)
運用: 本体の docs/失敗台帳.md と同じニドナシ機構管理(ノコスさん記録→フカボリさん真因→ミハリさん監視)。
原則: 人を責めない・隠さない・忘れない。**断られた理由こそ市場検証ゼロ問題の解毒剤**。「営業を頑張る」は反映案ではない。

## 対象となる事象(発生から48時間以内に記録)

- **断られた商談**: 提案提示後の失注(検討止まり・音信不通も30日経過で失注として記録)
- **解約**: 月額型商品の解約・更新拒否(早期警報の解約率🔴とも連動)
- **ゲート不合格**: ステージゲート判定テンプレでの不合格・撤退判定(判定記録とID相互参照)

## 記入ルール(本体台帳との差分)

- 分類は本体台帳の「商流」を細分: **失注 / 解約 / ゲート不合格**
- **顧客属性に個人・法人を特定できる情報を書かない**(業種・規模帯・流入経路まで。社名・氏名・所在地・固有の事情は禁止 — PIIガードの対象)
- 「断られた理由の原文」は顧客の言葉をできるだけそのまま残す(要約・善解しない。原文が真因分析の一次資料)
- 反映先は必ず**商品・価格・売り方のどれか**に落とす(精神論・努力目標は差し戻し)
- 月末の**前提破壊レビュー**(三名体制規程5)で当月全行を読み合わせ、反映案の採否を三名体制で裁定→商品・価格変更は小柳さん上申
- 行の削除は誰にもできない。反映済み後も残す(新商品・新チャネル設計時の必読資料)

## 記入例の読み方(SD-000)

- 原文をそのまま残したことで、真因が「価格の高さ」ではなく「**社内説明の材料不足+お試し階段の欠如**」と特定できた(値下げという誤った反映を回避)
- 反映案が商品(2段設計)・売り方(成果物リスト先渡し)に具体化されており、次月の前提破壊レビューで採否を裁定できる
- ゲート不合格の行では、事象欄にステージゲート判定記録のID(例: ノビシロ・ゲート1)を必ず参照として書く
