## C. 締切アラート配信(締切3層ルール — 憲法準拠)
**大原則: 「締切7日前アラート」は誤り**(7日前では書類・gBizIDの準備が間に合わない)。利用者向け表現は「締切の約1か月前から」で統一。

### 層1: 残り30日以上 → SNS投稿(LINE個別配信はしない)
- 新着・締切に余裕がある制度は Instagram 等で広く告知。LINEでの個別プッシュはまだしない。

### 層2: 残り7〜29日 → LINE個別アラート(このタイミングが主役)
配信テンプレ:
> 【もらい忘れ注意】〇〇(制度名)の申請、締切が近づいています📌
>
> ・対象になりそうな方: (対象の一言)
> ・締切: 〇月〇日ごろ(必ず公式でご確認を)
> ・必要そうなもの: (持ち物2〜3点)
> ・まず見る: (準備シートリンク)
>
> 「自分は対象?」と思ったら、3分診断で確認できます → (診断リンク)
> ※金額・締切・要件は必ず公式ページでご確認ください。

### 層3: 残り7日未満 → 次回公募予告(今回は無理せず、次に備える)
配信テンプレ:
> 【次回に備えましょう】〇〇(制度名)は今回の締切が間近です。
> 慌てて不備が出るより、次の募集にしっかり備えるのがおすすめです。
>
> ・次回に向けて今できること: gBizIDの準備など(→ 案内リンク)
> ・準備ができたら、次回の受付開始をこちらでお知らせします。

補足: 配信の出し分け(誰に・いつ)は Power Automate と制度DBの締切データで自動化。実装はツナグさん。まずは層2テンプレの手動配信からでも開始可。

## E. 受け皿応答(診断結果・もらえた報告の貼り付けに返す1通)— 2026-08-10 追加

**仕組みの注意(重要)**: LINE公式のキーワード応答は**完全一致でしか発動しない**。
リッチメニューの固定文言(「受給を報告する」など)は一致するが、サイトからコピーして
貼り付けられる「【わたしの診断結果】…」「【もらえた報告】…」は本文が毎回違うため一致しない。
→ これらは **「キーワードなしの応答メッセージ」(どのキーワードにも一致しなかったときに届く返事)** で受ける。

### 設定手順(携帯の「LINE公式アカウント」アプリ・5分)
1. アプリを開く → **応答メッセージ**(ホームの「自動応答メッセージ」)
2. **作成** → タイトル「受け皿応答」
3. **キーワードは設定しない**(空のまま)→ これが「一致しなかったとき」の返事になります
4. 下の文面を貼り付け → **利用をオン**・応答時間は「常時」
5. テスト: 自分のスマホで診断→結果画面のボタン→トークに貼り付け→この返事が来ればOK

### 文面(そのままコピペ)

```
メッセージありがとうございます🌈

📋 診断結果を貼ってくれた方へ
保存できました!このトークがそのまま控えになります。
機種変更しても消えないので、いつでも見返してください。
次の一歩は「申請準備シート」から。持ち物と窓口での言い方まで用意しています↓
https://allgroup-inc.github.io/hojo-hq/fukugiiro/kit/

💬 「もらえた報告」を送ってくれた方へ
ご報告、にふぇーでーびる(ありがとうございます)。
内容を確認して、あらためてお返事しますね。

その他のメッセージも、順に確認してお返事します。
※お名前・ご住所・口座番号は送らないでください。

あなたが受け取るまで、いっしょに。— もらいわすれ堂
```

**運用メモ**:
- この応答は「即時の受け取り確認」。受給報告への正式な御礼は、決定済みの**A案文面**
  (docs/もらいわすれ堂_受給報告フロー運用.md)を人が続けて返信する(二段構え)
- 将来Messaging API接続後は、貼り付け内容ごとの自動出し分けに置き換える(その際この節を更新)

## F. 診断結果別「最初の1通」テンプレ(手動返信・9分類)— 2026-08-31 追加

**ねらい**: 診断結果に応じて最初の返事を出し分けると、その後の反応が大きく上がる
(他業種で予約CVR1.5倍の事例。docs/成功事例ウォッチ_ログ.md 2026-08-23 §4)。
Messaging APIの自動化前でも、**人がトークを見て下のテンプレを1つ選んで貼るだけ**で同じ効果を狙える。

**使い方**: 貼られた「【わたしの診断結果】」の制度名を見て、いちばん多いカテゴリのテンプレを返す
(迷ったら上にあるものを優先)。§Eの自動応答が先に届いているので、こちらは「人からの2通目」になる。
