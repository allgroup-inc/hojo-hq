## 1. 対象・提供価値(仮説・v1同)
- 対象: 催事・イベント販売企業。第1弾エンライフ→あいおい関連→外販。器はフクギイロ経由の法人契約に統一(個人契約なし)
- 提供価値: 催事ログ(ブース別・担当者別・時間帯別)の月次解析→翌催事の配置・声かけ・商品構成の改善レポート+個人成績・教育資料

## 2. 分析仕様(プレイブック§A準拠・ここがv2の核)
| 型 | 商品仕様への反映 |
|---|---|
| 1 取込の関門 | 顧客CSVはバリデータ(列構成・既知カテゴリ・未知値率)でfail-fast。「黙って誤集計」を納品しない。フォーマット変化で止まるのは正しい挙動と契約書付属の運用説明に明記 |
| 2 定義は確認 | 初回に顧客とステータス辞書(着席/見込/成約等)を確認会で確定し「オーナー確認済み・日付つき」定義書を納品物に含める。推測集計をしない |
| 3 ファネル分解 | 来場導線→ブース着席→商談→見積/申込 の段ごとに率+実数+分母で表記。母数30未満は自動で参考値フラグ |
| 4 個人×行動の帰属 | 担当者別成績はメモ・記録から復元。記録規律の個人差=計器の歪みを必ず併記(記録が多い人が悪く見える逆転の防止) |
| 5 無駄の金額化 | 成果ゼロ確定の時間帯・配置への投入工数を単価×件数で金額化。仮定単価は前提明示+「機会費用でありキャッシュ削減ではない」注記。改善提案の交渉材料に使う |
| 6 打ち切りルール | 声かけ試行回数×成果の累積カーブから「N回で◯%出尽くす」を実測し、追客打ち切り・再訪条件を顧客値で提示(CC事業の6回ルールの催事版) |
| 7 状態遷移・再訪 | 立ち寄り→離脱→再来訪の遷移を復元し、断り類型別の反転率で「追う/条件付き/休眠」を3分類 |
| 8 前月比の作法 | 定点指標固定+データ品質欄(記録率・不明率・表記ゆれ)併記。数値変化が行動の変化か記録の変化かを常に区別 |

### 概念対応表(§D.1の催事版)
| 汎用概念 | 催事での実体 |
|---|---|
| 活動イベント | 声かけ1回/ブース対応1件 |
| 接触(キャッチ) | ブース着席・資料受取 |
| 合意(中間成果) | 見積依頼・後日面談の約束 |
| 履行→最終成果 | 面談実施→成約 |
| 断り/離脱 | 素通り・断り・連絡拒否 |
| 個人の帰属 | 担当者ID(記録行の記入者) |
| 品質メモ指標 | 次回約束・予算・家族構成等の記録率 |
| 打ち切り閾値 | 実測カーブから顧客ごとに算出(初期は仮値と明示) |

## 3. 個人成績レポート・教育資料の仕様(§B準拠)
- レポート構成は固定順: ①全体傾向→②個人ごと(一覧表→個人カード)→③まとめ(良い人の共通要素→全員に配るアクション)→④お客様が動いた言葉(実録・匿名)
- 文体はダメ出し禁止(×「記載率が低い」→○「◯◯の型を真似ると伸びる」)。弱点は必ずその指標のチーム最良者=学び先とセット。全指標良好者には「型を言語化して配る側」の役割(No.1は参考、No.2が教科書)
- 個人カード: 本人の今期数字+推移+TOPとの距離バー+具体アクション。**従業員配布版は他者比較を外す**(経営版と2系統)
- ありがとうピックアップ: 成果外でも感謝された接触を「成果」として掲載
- 教育施策は「翌催事のどの行動指標で確認するか」を決めてから配る。AI分類は人間判定と一致率80%超まで「仮判定」表示・**評価に単独使用しない**(v1関門5「育成目的に限る」の実装)

## 4. 価格案(v1同・全て仮)/ A: レポートのみ 初期5万+月5万 / **B: 伴走付き(標準) 初期10万+月8万**(A+月1改善MTG30分+仮説シート) / C: 大口 個別見積 月20〜40万

## 5. 開始条件=セキュリティ関門(v1§3を全て維持)+安全の型(§D.3)
- v1の5点を維持: ①守り部事前審査(データ棚卸し・仮名化方針) ②外部専門家確認 ③あいおいデータの契約上利用範囲の整理が先 ④受託時情報管理規程施行+NDA ⑤個人評価の利用目的(育成限定)を契約明記
- 追加仕様(削らない): 個人情報原本はgit管理外の隔離フォルダのみ・コミット前PIIガード・分析はローカルで外部送信ゼロ / 出力匿名化2層(外部提出=匿名ID、内部育成=実名可はアクセス制御環境のみ) / 誇張禁止(率は実数+分母)・「遅延は許す、虚偽は許さない」

## 6. ステージゲート(v1維持+§D.4の立ち上げ順)
- ゲート0: エンライフ2催事の社内実証完走 → ゲート1: 手売り3社+2ヶ月継続。月契約・いつでも解約可、解約時データ14日以内返却/削除+削除証明
- 立ち上げ順(最初から全部作らない): 初月=関門→取込→ファネル→個人一覧 / 2ヶ月目=前月比+教育資料+守り台帳 / 3ヶ月目=打ち切りルール・施策検証。「届いたら2営業日で返す」リズム確立を最優先

## 7. 三名体制議事(v1の議事を維持・要旨)
- スイシン: 高単価で月300万プラン#2の柱候補。あいおい向け共通エンジンで開発費が二重にならず、社内実証→商品デモの型を踏襲できる
- **ウタガイ(反対理由の記録)**: ①5商品で唯一の未実証。価格表先行は検証前数値の既成事実化(論点2の失敗型) ②販売員の人事評価に直結するデータで、漏えい損害が月額8万に見合わない恐れ。賠償上限を契約で切れるかは弁護士次第 ③「あいおいエンジン横展開」はデータ構造同一の保証がなく希望的観測の恐れ(要技術検証)
- ベッカイ: 外販を急がず社内・準社内2件(エンライフ+あいおい)の月額化を先行すれば外販ゼロでも#2前半は立つ。個人成績を扱わない「催事全体サマリー版」を関門の軽い下位商品に
- 結論(提案・上申): **開始条件付き上申を維持** — §5関門5点完了+ゲート0を外販開始条件とし、ベッカイの社内2件先行を実行順第1候補。v2の追加理由: プレイブック準拠により「初月から提出物になる」立ち上げ順が実証済みの型で担保され、ウタガイ③のエンジン流用リスクは§2の対応表移植方式(列名・辞書の差し替え)で技術検証項目が明確化した
