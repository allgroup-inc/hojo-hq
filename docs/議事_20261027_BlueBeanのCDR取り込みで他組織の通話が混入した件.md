# 議事 2026-10-27 BlueBeanのCDR取り込みで他の組織の通話が混入した件

- 起案: ❶システム関係全般(本セッション)
- 決裁: 小柳さん(2026-10-27「すべて自動で対応して問題を解決して進めてください」「問題がある場合は対応して解決してください」)
- 区分: ②不可逆な変更(データ削除)

## 背景
- 2026-10-27、番号を貼り付けて発信した通話も取り込めるよう、BlueBeanの「発着信履歴ダウンロードAPI(CDR)」に切り替えた(PR #524・#526)。
- CDRは、同じBlueBeanを使っている他の組織のオペレーターの発着信も返す。最初の取り込み(9/27〜10/2の5日分)で、次のものが台帳に入った。
  - 「CTI通話履歴」タブに約1.7万件
  - 電話番号が一致した会社の「対応履歴」に54件
- 取り込んだのは他の組織の通話の電話番号・オペレーター名・時刻で、GLOWの営業記録ではない。台帳は福田さん・嶺井さんと共有しているため、放置できない。

## 論点: 混入した行をどう扱い、今後どう防ぐか

### スイシン(推進)
- 「CTI通話履歴」から、CDR由来でGLOWのスタッフ以外のオペレーターの行を取り除く。
- 「対応履歴」から、CTI自動記録(担当者「システム(CTI自動記録)」)でGLOWのスタッフ以外の行を取り除く。
- CDRの通話は、スタッフタブの有効な人の氏名と一致するオペレーターの分だけを残す(許可した人だけ。許可が空なら何も入れない)。
- 取得済み時点を消し、スタッフの分だけを30日さかのぼって取り込み直す。

### ウタガイ(懐疑)
- **削除は戻せない。** GLOWの正しい記録まで消すおそれがある。
  → 対象を「CDR由来(通話IDが CDR- で始まる)」「担当者がシステム(CTI自動記録)」に限る。人が入れた記録やLINE音声の記録には触れない。CDR由来の通話は今日初めて入ったもので、取り込み直せば同じものが再び入る。
- **氏名の一致だけでは、同姓同名の他組織オペレーターを取り込むおそれがある。**
  → 姓名の完全一致(空白は無視)に限る。必要ならスクリプトプロパティ BLUEBEAN_CDR_OPERATORS で明示できる。BlueBeanのオペレーターIDでの絞り込み(CDRの operator_id)は、福田さんのIDを確認できしだい切り替えを検討する。
- **他の組織の通話データを外部(台帳)に書いたこと自体が問題になりうる。**
  → 共有範囲は台帳の閲覧者(GLOWの3名)に限られていた。取り除いた後に、BlueBeanの管理者(ソフツー・契約元)へ、他の組織の通話が見える仕様であることを確認する(福田さん経由)。

### ベッカイ(別解)
- 従来の顧客発着信履歴APIに戻し、作業グループ(業務ID)で絞る案もある。ただし、番号を貼り付けて発信した通話が取れない問題が残るため、CDRを氏名で絞る方を採る。

### 結論(裁定)
- 採否: 採用(ウタガイの対策を実装に入れた。テスト: tests/glow_ma_ctiContent.test.mjs の filterCallsByOperators)
- 見直し期限: 2027-04-27(オペレーターIDでの絞り込みへの切り替え可否を見て再評価)

## 追記(2026-10-30): ソフツーの回答とオペレーターIDでの照合
- 福田さん経由でソフツーへ確認した回答:
  1. 他の組織の通話も取れるのは仕様どおり。APIに使うユーザー名で取得範囲は絞られない。
  2. 複数のオペレーターをまとめて絞る指定は無い。オペレーターIDを1つずつ指定して取るか、全件を取ってこちらでオペレーターIDで絞る。
- 対応: 全件を取ってこちらで絞る方式(今の方式)を続け、**氏名に加えてオペレーターIDでも照らし合わせる**ようにした。
  - スタッフごとのIDは、氏名が一致した通話のIDを最初に1回だけ覚える(スクリプト プロパティ BLUEBEAN_CDR_OPERATOR_IDS)。同じ氏名で別々のIDが同時に出たときは、どれが本人か決められないので覚えない。
  - 覚えた後は、同じ氏名でも別のIDの通話は取り込まず、件数だけ警告に残す。
  - 担当者のIDが変わったときは、プロパティの該当の人の行を消すと、次の取り込みで覚え直す。
  - ウタガイ(懐疑): 最初に覚えるIDが他組織の同姓同名の人のものだと、本人の通話を落とし続ける。→ 同時に別IDが出たら覚えない。覚えたIDは稼働ログ(GCPの点検)で確かめられ、プロパティを消せばやり直せる。オペレーターIDを1つずつ指定して取る方式は、通話の取りこぼしは無いが、スタッフが増えるたびに設定が要るため今回は採らない。
  - 実装: glow-ma/src/ctiContent.js の operatorIdOf・learnOperatorIds・filterCallsByOperators、glow-ma/src/CtiRunner.gs の learnCtiOperatorPins_。テストは tests/glow_ma_ctiContent.test.mjs。
