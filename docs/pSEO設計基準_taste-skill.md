# pSEO(市町村×カテゴリ制度ページ)設計基準 — taste-skill準拠 2026-08-07

次スプリントの本丸「市町村×カテゴリの制度別ページ」(検索200社チャネル)を作る際の
デザイン・品質基準。`.claude/skills/taste-skill` のBrief Inference→Dials→Anti-Defaultの
流れをこのプロジェクト向けに固定する。

## Design Read(固定)
**「沖縄の経営者(非デザイナー・信頼第一)向けの、公的情報系ローカルLP。
既存ブランドシステム(ネイビー#00335C×オレンジ#F88800・Noto Sans JP)を使い、
落ち着いた・信頼される・速い、を優先する」**

- Quiet constraint: 公的情報+お金の話=trust-first。装飾より正確さ・読みやすさが優先
- 使うのは**実在の自社デザインシステム**(site/index.htmlのCSS変数・部品)。新しい見た目を発明しない

## テンプレ量産感(AI-slop)を出さないための必須要件
pSEOはページを量産するほど「全部同じ・中身が薄い」と検索とユーザーの両方に嫌われる。
1ページごとに以下の**固有要素**を必ず入れる:

1. **固有の数字**: その市町村×カテゴリの掲載件数・上限額最大値・直近締切(データから自動生成)
2. **固有の一文**: 地域文脈のリード文(例: 宿泊業×石垣市なら離島加算・観光文脈)。テンプレ文の語順入替は不可
3. **生きた制度リスト**: subsidies.jsonから毎日更新(空なら「現在募集中の制度はありません+アラート登録」を正直に表示。偽の充実を見せない)
4. **内部リンク**: 隣接市町村・同カテゴリ他地域・診断への3方向
5. **構造化データ**: BreadcrumbList+ItemList(JSON-LD。healthcheckのJS構文チェック対象外のtype指定を忘れない)

## 禁止事項(Anti-Default)
- 絵文字の見出し多用・グラデーション乱用・カード羅列だけのページ
- 「〜をご存知ですか?」型のテンプレ導入文
- CVボタンの乱立(CV単一=LINE登録のみ。診断orLINEの2ボタンまで)
- 実装は静的HTML+既存CSS(新規フレームワーク・外部フォント追加は不可。Lighthouse 95維持)

## 現行LPのtaste監査(2026-08-07・参考)
現行LPは独自設計でテンプレ感なし・ブランド一貫性あり。改善候補3点(いずれも軽微・A/B推奨):
1. 診断フォームのselectがブラウザ標準見た目のまま(ブランド色のフォーカスリング・矢印カスタムで質感が上がる)
2. ヒーロー直下の情報密度が高い(件数・CTA・サブ文言)— スマホ1画面目の要素を1つ減らす案はA/Bで検証
3. セクション間の余白リズムが不均一(--sp-*の使用を統一すると「整った感」が出る)
※コンバージョン最適化済みのLPなので、大改修はせずA/Bテストでの検証を推奨(ab-testingスキル)
