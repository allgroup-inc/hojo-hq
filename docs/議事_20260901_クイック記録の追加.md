# 議事 2026-09-01: 管理画面からの対応履歴クイック記録の追加(glow-ma v1.6.0)

- 発端: 小柳さん要望「各企業との話などを蓄積して行く画面の部分や打ち込みのしかたを、もっと使いやすく見やすく」
- 決裁: 小柳さん(2026-09-01 チャットで実装プロンプトを提示し「進めて」)
- 議事必須の理由: 対応履歴ログへの**新しい書き込み経路**の追加(不可逆類型②)

## 対応内容

1. 対応履歴タブをタイムライン表示に(日付+種別の色分けバッジ+キーワード絞り込み)
2. 詳細画面に「クイック記録」を追加: 種別ボタン(電話/入電/アポ獲得/面談実施/手紙送付)+一言メモ→Enterで対応履歴ログへ1行追記。日付・担当者(ログイン中スタッフ)は自動。記録と同時に最終接触日を当日へ更新
3. 記録後「次回アクションを設定 →」で次回予定の入力へ誘導(次を決めてから終わる、の動線)
4. ヘッダーに「最終接触: 日付(◯日前)」を常時表示
5. 関係メモを【日付 種別】ごとのブロック表示に整形

## 三名体制

### スイシン(推進)
- LINE音声ログが使えない場面(PCで作業中・短い電話の連続)でも3秒で記録でき、記録漏れが減る
- 記録→次回アクション設定の動線が1画面で閉じ、見込の埋もれ防止(v1.1〜のポップアップ)と噛み合う

### ウタガイ(懐疑) ※反対理由の記録
- **書き込み経路が増えるほど、台帳が汚れるリスクも増える**(誤タップでの空記録・種別の誤選択)。→ 対策: 種別はINTERACTION_TYPESの語彙に限定(純ロジックvalidateQuickLogで検証・表記ゆれを入れない)。メモ空は「電話不在」等の実需があるため許可するが、種別なしでは記録できない
- クイック記録が楽すぎると、内容の薄い記録ばかりになりLINE音声(要約の質が高い)が使われなくなる恐れ。→ 使い方ガイドで「訪問など内容が濃いものはLINE音声、短い電話はクイック記録」と使い分けを明記(ガイド①に記載)
- 最終接触日の自動更新は掘り起こしアラートの母数に影響する(接触扱いが増える)。→ 記録=実際の接触行為に限る運用をガイドに明記。スコアリングへの反応スコア加点は既存ロジック(種別ベース)に従い、新経路でも同じ扱い

### ベッカイ(別解)
- 一覧画面の行から直接記録できる方が速いのでは。→ 詳細を開かず記録すると過去の経緯を見ずに電話することになり、営業品質が下がる。詳細ドロワー内に置くのが正(採用せず)
- 記録フォームを対応相手・次回アクションまで含むフル項目にする案。→ 3秒動線が失われる。次回アクションは既存の専用欄への誘導で足りる(採用せず)

### 結論(裁定)
- 採否: **採用**(v1.6.0として実装・全481テスト成功)
- 理由: 記録の摩擦を下げることが蓄積量=教材化の土台に直結する。リスクはバリデーションと運用ガイドで許容範囲
- 見直し期限: 2027-03-01(空メモ記録の比率・誤種別の実態を見て再議論)
