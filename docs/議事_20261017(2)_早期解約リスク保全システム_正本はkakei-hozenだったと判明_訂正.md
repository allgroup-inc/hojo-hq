## なぜ(背景)

同日(2026-10-17)付の議事 `docs/議事_20261017_早期解約リスク保全システム_決裁待ち事項の決定.md` で、
close済みPR #7(hojo-hq・2026-08-26 close)の内容を `allgroup-inc/hojo-churn` へ移設・マージした。

その後、軸(`allgroup-inc/kakei-crm`)とのやり取りの経緯を確認する過程で、`allgroup-inc/kakei-hozen`
(非公開)というリポジトリが既に存在し、**2026-08頃からそこで「保全CRM」として本システムが継続開発
されていた**ことが判明した。kakei-hozen/CLAUDE.mdには「正(カノニカル)はここ」と明記されており、
2026-10-17時点でテスト953件・`kakei-crm`(軸)とのI/F契約(契約①②)まで実装済みという、PR #7
(テスト319件・2026-08-24時点のスナップショット)より大幅に進んだ状態だった。

つまり本日の一連の作業(hojo-hq復元→repo-scope違反発覚→hojo-churnへ移設→決裁4件→PR作成・マージ)
は、**既に廃止・移管されていた古いコードを復活させていた**ことになる。

## 前提

- kakei-hozenは「家計の見直しやさん(enLife)総合システム」の一部(軸=kakei-crm、保全=kakei-hozen、
  アポ=kakei-apoの3リポ構成)。hojo-hq(沖縄企業のミカタ/GLOW)とは別事業・別憲法。
- kakei-hozen/CLAUDE.mdは「hojo-hq(公開)は家計系使用禁止。remoteに足さない」と明記している。
- PR #7は2026-07-25作成・2026-08-26 close(未マージ)。kakei-hozenの初期の決裁・議事は2026-08-17
  前後から見られ、2026-08-29に「push先はkakei-hozenのみ」の鉄則が小柳さん決裁されている。
  時系列から、PR #7がclose された前後の時期に、本システムはhojo-hqからkakei-hozenへ
  正式に移管されたとみられる。

## 代替案

- hojo-churnへの移設をそのまま残し、kakei-hozenと並存させる案も考えられたが、不採用。
  「正本が2つある」状態は、どちらを見ればよいか分からなくなり、本日のような誤認が今後も
  繰り返される。正本を1つ(kakei-hozen)に揃える。

## 三名体制の議論

- **スイシン(推進)**: 誤りに気づいた時点で速やかに訂正し、記録を残す。hojo-churnの内容はrevert済み。
- **ウタガイ(懐疑・反対理由)**:
  1. 本日の決裁4件(①QCM事業部という名称 ②リスク帯閾値は実データで調整 ③④ID権限方針)を
     小柳さんに決めてもらった工数が、正本の状態を先に確認していれば不要だった。
     **古いコードを扱う前に、同じ主題の既存リポジトリ・セッションが無いか先に確認すべきだった。**
  2. 「QCM事業部」という名称は、kakei-hozenの実際の呼称(「保全CRM」)と異なる。今後hojo-churn側の
     記録だけを見た人が、誤って「QCM事業部」をkakei-hozen側の正式名称と誤認するおそれが残る
     (hojo-churn README に訂正済みの注記を追加済みだが、完全に防げるわけではない)。
  3. kakei-hozen側には既に「帯の境目は未決裁(小柳さん決裁2026-09-23: 実データのバックテスト後に
     決める・期限2026-11-30)」という、より具体的で既に走っている決定がある。本日の②の決裁
     (実データで調整する方針)は、この既存決定と内容的に重複するだけで、新しい決定ではない。
- **ベッカイ(別解・前提を疑う)**: 今回の誤りの根本原因は、小柳さんが日々多数の並行チャット
  セッションを横断しており、どのチャットがどのリポジトリの最新状態を持っているか本人も都度は
  把握しきれないこと。再発防止としては、`docs/全体マップ.md`相当の「リポジトリ×チャットの対応表」
  をkakei-hozen/kakei-crm側にも用意し、新しいチャットが同一主題に着手する前に必ず参照する運用が
  考えられる(本議事では提案のみ・実装は別途)。

## 裁定

1. **hojo-churnへの移設はrevert済み**(コミット: hojo-churnリポジトリ参照)。hojo-churnのREADMEに
   「正本はkakei-hozen」である旨を追記済み。
2. **本日の決裁4件(D20261017-churn-decisions)は、PR #7という古いスナップショットに対しての
   ものであり、kakei-hozen(正本)の体制・決裁を変更するものではない。** kakei-hozen側で
   同種の論点(名称・閾値・アクセス権限)を決める必要があれば、改めてkakei-hozen側のチャットで
   議事を起票する。
3. **以後、本システム(早期解約リスク保全/保全CRM)に関する作業は `allgroup-inc/kakei-hozen` で
   行う。** hojo-hq・hojo-churnでは行わない。
4. kakei-hozen側で止まっていた軸(kakei-crm)連携の401エラー調査を、引き継いで再開する
   (別途対応)。

## 見直し条件

本訂正自体の見直しは不要(事実の訂正であるため)。再発防止策(リポジトリ×チャット対応表の整備)は
別途提案として起票する。
