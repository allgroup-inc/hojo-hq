# 連携メモ 2026-11-23: ゆんたくコラムの運用設計と、GLOW全体の接点連携

- 送り元: ❶ システム関係全般(glow-ma)
- 宛先: ❸ 事業構成&ゆんたく(コラムの表示・運用)。全体連携は ❷・❹・世界の架け橋・フクギイロの担当にも共有
- 根拠: 代表者の正式決裁(2026-11-23)。掲載・公開・配信・写真の掲載は、別途の承認が要る

## 1. ゆんたく経営相談室のコラム(❸の設計案)

### 表示の構成
- **一覧ページ**:シリーズ名「嶺井の経営ゆんたく」。各記事のタイトルと投稿日を、新しい順に表示。
- **記事ページ**:記事の全文、投稿日、前後の記事へのリンク。記事末尾は、株式会社GLOW 代表取締役 嶺井 の表記。営業の案内は、希望がないため入れない。
- **過去記事の蓄積**:記事数が増えても一覧が重くならないよう、年月ごとのまとまり(アーカイブ)か、ページ送りで分ける。記事は随時追加できる構成にする。

### 更新の運用
- 更新は10日〜2週間に1回を基本とする。
- 公開日は、小柳さんの確認後に決める(第1回は水曜 9:00 を目標。確定ではない)。
- DM でのお知らせは、配信手段の決裁後に決める。LINE 以外の配信は承認が要る。

### スマートフォンでの読みやすさ
- 画面の左右の余白は 16px。横スクロールを出さない。
- 見出し(h1〜h3)以外には、文字の割り方を強くかける装飾を使わない(パフォーマンスの決まり。繰り返し要素への適用は、計測してから行う)。
- 本文は行間を十分に取り、1段落を短くする。

### 写真・プロフィール
- 嶺井さんの写真と短いプロフィールは、本人の同意を確かめてから掲載する。届くまでは、表記のみ。

### 計測(閲覧・再訪問・相談件数)
- 記事の閲覧数・再訪問・相談件数は、**専用の計測名**で数える。既存の導線(LINE 登録など)の計測名は使わない(数字が混ざるため)。
- LINE 登録数とは別の欄で見る。相談件数は、台帳の対応履歴に記録される件数と照らして確かめる。
- 計測の仕組みは、❸が設計し、個人情報を含めない形にする。

## 2. GLOW 全体の接点連携(設計の方向)

### 基本の考え方
- 企業との接点は、**企業ID**をキーに、台帳(企業リレーション台帳)へ集める。
- 各サービス(ゆんたく経営相談室・沖縄企業のミカタ・世界の架け橋・フクギイロ・事業承継・不動産)は、個別に動く。台帳へ集まった接点を見て、必要なサービスへつなぐ。

### 既存の仕組み(台帳)
- **流入ルート**:①紹介、②手紙DM、③ミカタ経由、④世界の架け橋(Alibaba)。新しい接点の入口は、この枠に加えるか、別の枠として決める。
- **対応履歴**:電話・面談・手紙などの記録。録音の確認を経て残る。
- **今日の連絡先**:予定日・フォロー・手紙のあと・新規の4区分。今日すでに連絡した会社は出さない(2026-11-23 の変更。Draft・PR #634)。

### 決めたいこと(小柳さんの決裁)
1. ゆんたく経営相談室の問い合わせ・閲覧の接点を、台帳へどう入れるか(自動連携か、手で記録するか)。自動連携は、個人情報の外部連携にあたるため、承認が要る。
2. 流入ルートの枠を増やすか。増やす場合、既存の集計(ダッシュボード)への影響を確かめる。
3. CV は LINE 登録のみという決まり(沖縄企業のミカタ)と、相談件数の計測の関係。計測は導線として数えず、別の欄に置く。

### 各担当への依頼
- **❸**:コラムの表示・計測名の案を出す。台帳へ入れる項目(流入ルートの候補、記録の仕方)を、❶へ連携メモで伝える。
- **❷・❹**:台帳の項目に変更が必要なときは、直接触らず、連携メモで要件を❶へ送る(体制決定 2026-08-19)。

## 3. 承認が必要な事項(この連携メモでは実行しない)
- コラムの公開、DM・LINE 等の実配信
- 写真・プロフィールの掲載
- 個人情報の外部連携(台帳とサイトの自動連携)
- 本番の設定変更、台帳の本番データの変更

以上。顧客情報・メールアドレスは含めていない。
