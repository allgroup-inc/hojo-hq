## 0. この棚卸しが答えを出す問い

**「獲得後の事務が、営業の新規開拓時間をどれだけ奪っているか」**

「管理本部の効率化」ではないことに注意する。効率化を問いにすると、LINE登録8人(2026-08-15)
という現状で北極星(登録数の立ち上げ)と資源を奪い合う。営業の時間を取り戻す話にすれば、
KGIと同じ方向を向く。三名体制のベッカイ役の指摘を採用した設定。

**この棚卸しは「作らない」で終わってよい。** 結果がチェックリスト1枚で足りるなら、
システムは作らない。§5の判断ゲートを先に決めてあるのはそのため。

## 1. やり方: 実案件1件を、獲得から完了まで実物で追う

口頭ヒアリングでは**本人が意識していない定型作業(転記・突合・催促)が漏れる**。
そこが自動化余地の本体なので、記憶ではなく実物から復元する。

### 集めるもの(直近で獲得が完了した案件を1件)

- 営業↔管理本部のやりとり(メール・チャット・電話メモ)
- 使ったシート・帳票・システム画面(スクリーンショット可)
- 顧客に送った書類・returnされた書類
- 「これ待ちで止まっていた」期間がわかるもの

個人情報は伏せる。**このリポジトリにPIIを入れない**(絶対ルール・churn-pii-guard 相当)。
氏名・住所・電話・証券番号はマスクし、工程と所要時間だけを持ち込む。

### 追跡シート(工程ごとに1行)

| # | いつ | 何が起きた(工程名) | 実行者 | 使ったもの | 所要時間 | **営業の関与時間** | 待ち時間 | 前工程からの受け渡し方法 |
|---|---|---|---|---|---|---|---|---|
| 1 | | 例: 申込書の受領 | | | | | | |
| 2 | | | | | | | | |

- **営業の関与時間**が本命の列。ここが積み上がるなら、この棚卸しはKGIの話になる
- **待ち時間**は自動化で最も効く箇所(人が動くのを待っている時間は、通知や自動転記で消える)
- **受け渡し方法**が「口頭」「都度チャット」なら、それ自体が抜け漏れの温床

## 4. 数える(件数が出なければ、構築判断そのものができない)

| 指標 | 測り方 | 実測値 |
|---|---|---|
| 月あたりの獲得件数 | 直近3ヶ月の実績 | (未測定) |
| 1件あたりの管理本部の総作業時間 | 追跡シートの所要時間合計 | (未測定) |
| **1件あたりの営業の関与時間** | 追跡シートの営業関与列の合計 | (未測定) |
| 1件あたりの総リードタイム | 獲得から完了までの日数 | (未測定) |
| うち待ち時間の割合 | 待ち時間合計 ÷ 総リードタイム | (未測定) |
| 不備返戻の発生率 | 差し戻し件数 ÷ 獲得件数 | (未測定) |

### 営業時間の金額化(§A5)

`月あたりの獲得件数 × 1件あたりの営業関与時間 = 営業が事務に取られている月間時間`

これを「新規開拓に回せる時間」として表す。**機会費用であってキャッシュ削減ではない**ことを
必ず併記する(§A5の注記を削らない)。仮定単価を置く場合は前提として明示する。

## 5. 判断ゲート(先に決めておく — 後から動かさない)

棚卸しの結果を見てから基準を作ると、作りたい方に基準が寄る。先に置く。

| 実測 | 判断 |
|---|---|
| 営業の関与が **月5時間未満** | **作らない。** チェックリスト1枚で終える |
| 営業の関与が月5〜20時間 | 部分自動化のみ検討(通知・テンプレ化など、コードを書かない対処を優先) |
| 営業の関与が **月20時間以上**、または待ち時間が総リードタイムの50%超 | システム化を三名体制で再裁定。**glow-maへの統合を前提とし、独立した3つ目のシステムは作らない** |
| 月あたり獲得件数が **3件未満** | 件数不足。**どの数値でも作らない**(自動化の投資対効果が成立しない) |

最後の行が最も重要。件数が出ないうちに作ると、効果測定できない仕組みだけが残る。
