### 統合パターンの決定

| 項目 | 確定内容 | 影響範囲 |
|---|---|---|
| **Q1-1: KAKEHASHI 技術構成** | React Web アプリケーション | UI フレームワーク・認証パス決定 |
| **Q1-2: kanri_system 配置先** | Web ビュー（KAKEHASHI 内に埋め込み） | CORS 簡略化・同一ドメイン認証 |
| **Q1-3: API通信方式** | REST API | call-log API の実装パターン確定 |
| **Q2-1: 統合パターン** | Web ビュー + Session Cookie 引き継ぎ | 認証情報の受け渡し方式確定 |
| **Q2-2: CORS対応** | 同一ドメイン配下で動作 | クロスオリジン設定不要 |
| **Q2-3: 本番配置先** | Azure Blob Storage（短期）→ kakei-crm 配下へ移行予定 | デプロイ柔軟性・インフラ統合計画 |

### 重要な含意

```
KAKEHASHI（エンライフ） + kanri_system（GLOW）の統合方式:

  KAKEHASHI Web ビュー上で
    ↓
  kanri_system（顧客カルテUI）を iframe または HTML埋め込みで表示
    ↓
  KAKEHASHI の Session Cookie を引き継ぎ
    ↓
  kanri_system が認証済みユーザーの権限情報を取得
    ↓
  Entra ID SSO で権限チェック
    ↓
  ✅ 権限あり → カルテ表示 / ❌ 権限なし → 403 エラーページ
```

□ ブラウザセッション終了時の取扱い

### D-2: 契約管理タブの項目定義
