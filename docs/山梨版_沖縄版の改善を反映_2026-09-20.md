# 山梨版へ沖縄版の改善を反映(2026-09-20)

沖縄版で積み上げた導線・計測の作り込みが山梨版に届いていなかったため、差分を埋めた。

## 反映前後

| 区分 | 受給報告導線 | LINE誘導 |
|---|---|---|
| ライフイベント別(10) | **0 → 9** | **0 → 9** |
| 市町村別(28) | **0 → 27** | 28(据え置き) |
| 申請準備シート(53) | 52 → **53**(一覧を追加) | 53(据え置き) |
| 診断・トップ | 各1(据え置き) | 各1(据え置き) |

(各一覧ページは単なるナビのため対象外。houkoku は報告ページ自身、teisei は訂正受付)

**最大の穴はライフイベント別ページだった。** 出産・子育て・介護など「もらい忘れ」が
最も起きる場面のページに、LINE誘導も報告導線も1つも無かった。山梨版はLINE公式アカウント
(@630pbjqq)を2026-09-03に開設済みで受け皿はあったのに、そこへ入る道が無い状態だった。

`/go/ymn-life` チャネルを新設し(lin.ee直貼り禁止の規律に準拠)、既存の `ymn-area` `ymn-kit` と
同じく channel で沖縄版と分けて集計できるようにした。

## あわせて直した計測の混入(重要)

山梨版は**沖縄版と同一のGA4プロパティ**(G-TQMX3MPFSR)を使う。
市町村・準備シート・ライフイベントの各ジェネレーターは `ymn_` 接頭辞付きのイベント名を
使っていたが、**沖縄版のHTMLを変換して作るページ(トップ・診断・報告・訂正・privacy)は
沖縄のイベント名をそのまま持ち込んでいた**。

結果、以下が沖縄の数字に混ざっていた:

- `shindan_start` / `shindan_step_q*` / `shindan_complete` / `shindan_zero`(**診断ファネル全体**)
- `line_add_click`(3箇所)/ `jukyu_report_click` / `jukyu_report_link_top` / `kit_click` ほか

KPI「診断実施→LINE登録率30%」は沖縄版の指標だが、**山梨の診断が同じイベント名で加算される**ため、
沖縄の現在地を見誤る状態だった。

### 対処

山梨版の `assets/fg-analytics.js`(沖縄からコピーしたもの)の末尾に、
`fgTrack` を包んで `ymn_` を付けるラッパーを追記する方式にした。

- **実行時に組み立てる名前も確実に捕まえる**: `shindan_step_q" + (state.step+1)` のような
  動的生成は、個別の文字列置換では漏れる
- **二重付与しない**: 既に `ymn_` が付いているものはそのまま通す
- **冪等**: ビルドのたびに沖縄から再コピーしてから追記するため、何度実行してもラッパーは1つ
- **沖縄版には一切触れない**(確認済み)

## 残っている差分(未対応)

- **山梨版に Instagram 導線は置いていない**(アカウント準備中のため。入口を勝手に作らない)
- **山梨県・市町村の制度は未掲載**(国の制度52件のみ)。県・市町村サイトの利用規約確認が先
- 受給報告の台帳・週次レポは沖縄版のみ。山梨版の報告が増えてきたら分離が要る
