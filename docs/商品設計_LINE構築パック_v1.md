## 1. 対象・提供価値(仮説)
- 対象: LINE活用を始めたい沖縄の店舗・サービス業・士業事務所
- 提供価値: リッチメニュー・あいさつ・会話ボット・顧客情報の台帳自動記録・配信自動化を「導入パック」として構築し、保守まで請け負う。会話→台帳自動記録まで提供できる地場業者はほぼ居ないと見込む(要実地確認)

## 3. テンプレ化する構成要素
1. リッチメニュー雛形(業種別3種: 店舗/サービス/士業)
2. あいさつ・応答メッセージの文面集(ミカタ/もら堂の運用原稿を汎用化)
3. 会話ボット v1.2 のシナリオ定義(ヒアリング項目を設定ファイル化)
4. GAS台帳スクリプト(スプレッドシート雛形+Webhook受け・列定義を設定化)
5. 配信自動化(予約配信+セグメント配信の基本形)
6. 引き渡しドキュメント(管理画面の操作手順・障害時連絡フロー)

## 4. 導入手順の概要(標準2〜3週間を想定・仮)
1. ヒアリング(60分): 目的・顧客層・取得したい情報の確認
2. 顧客側でLINE公式アカウント開設(アカウントは**顧客名義**。当方は運用権限のみ預かる)
3. テンプレ適用+文面カスタム → 顧客承認
4. テスト(実機・三名体制の抜き取り点検1回)→ 公開
5. 保守: 月次の応答ログ確認+文面改善提案1回、障害対応

## 5. ステージゲート・解約条件
- 最初の3件は手売り。合格基準: 3件納品完了+保守継続2ヶ月+構築実工数が見積り±50%以内
- 保守は月契約・いつでも解約可。解約時は権限返却・預かりデータの返却/削除(受託時情報管理規程ドラフト準拠。**規程施行が開始条件**)

## 6. 三名体制議事

### スイシン(推進)
- 2アカウント実運用という実証があり、テンプレ化で構築工数を圧縮できる。構築フィーが入るため キャッシュフローが早く、保守が月額ストックになる二段構え

### ウタガイ(懐疑)
- 構築10〜30万は「テンプレ化が完了していれば」の価格。現状はミカタ固有実装であり、汎用化(§3の6点)自体が未着手の開発作業。**「追加開発ほぼゼロ」は言い過ぎ**で、テンプレ化工数を先に見積もるべき
- 顧客の友だち(=個人情報)が台帳に自動蓄積される。個人情報の取扱いはSNS代行より一段重く、顧客側のプライバシーポリシー整備まで面倒を見ないと当方の紹介責任が問われかねない
- LINE公式アカウントの料金プラン改定リスク(従量課金)を顧客に説明しないと、後から「聞いていない」トラブルになりやすい

### ベッカイ(別解)
- 構築を売る前に**「テンプレ化スプリント」を社内案件として1本先に完了**させ、もら堂/ミカタ以外の第3アカウント(Grp内: エンライフ等)で適用検証してから外販する順序が安全
- 士業事務所を初期顧客にすれば、ミカタ提携部の士業ルートと重なり紹介協定とセット提案できる(ウォッチProのB-2構想とも接続)
