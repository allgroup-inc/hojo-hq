### 2.2 データ統合用GAS関数の設計

#### 必要な関数（案）

**`importHistoricalData(dataArray)`**
- 過去100件のデータを台帳に一括取り込み
- 入力: `[[企業名, 電話番号, 手紙送付日, 架電日, 通話結果, ...], ...]`
- 出力: 成功件数・エラー件数・警告一覧

**`deduplicateCompanies(dataArray)`**
- 既存の企業台帳と照合し、重複を検出
- 同一電話番号の関連会社も自動検出
- 出力: 重複リスト（人間の最終確認用）

**`validateHistoricalRecord(record)`**
- 個別レコードのデータ品質チェック
- 必須フィールド確認・日付形式確認・電話番号形式確認
- 出力: OK / 警告 / エラー

**`buildInteractionLogFromHistory(company, historicalData)`**
- 過去100件のレコードを「対応履歴ログ」形式に変換
- フィールドマッピング（手紙送付日→「架電種別」="手紙送付", 架電日→「架電種別」="電話着信"等）
- 出力: 対応履歴ログのテーブル行

#### フィールドマッピング案（Fukudaデータ → 台帳形式）

| Fukudaデータ | 台帳フィールド | 対応履歴ログ |
|---|---|---|
| 企業名 | 企業名 | （参照用） |
| 電話番号 | 電話番号 | （参照用） |
| 手紙送付日 | 最後の接触日（履歴より計算） | `架電種別`="手紙送付", `対応日時`=該当日 |
| 架電日 | 最後の接触日（履歴より計算） | `架電種別`="電話着信"等, `対応日時`=該当日 |
| 通話結果 | （対応履歴の「メモ」に記載） | `メモ`="繋がった"/"不在"等 |

## 3. 統合プロセス（フロー）

### ステップ 1: Fukudaからデータ受領
期限: 2026-10-06  
Fukudaから以下を受け取る：
- 過去100件のファイル（Excel / CSV / Google Sheet）
- 記録に含まれるフィールド一覧
- 企業名・電話番号などの形式説明

### ステップ 2: データ品質チェック＆デクレンジング
実装者: GAS側の `validateHistoricalRecord()` 関数  
チェック内容: 上記「2.3 データ品質チェック項目」参照

出力: 
- クリーン版データ（100件全件）
- 警告リスト（e.g. 日付形式が異なる3件）
- エラーリスト（e.g. 無効な電話番号5件）

### ステップ 3: 重複検出＆最終確認
実装者: GAS側の `deduplicateCompanies()` 関数  
Fukudaへの最終確認内容：
- 100件のうち既存台帳と重複する件数
- 関連会社の自動検出結果（同一電話番号）
- 修正・除外すべき件数

### ステップ 4: 一括取り込み
実装者: GAS側の `importHistoricalData()` 関数

処理内容：
1. 重複排除後のクリーン版を台帳に追加
2. 架電履歴を対応履歴ログテーブルに記録
3. 企業スコアの再計算（反応スコア加点・ステージ更新）
4. 集計結果をFukudaへレポート

### ステップ 5: 検証＆フィードバック
Fukudaが Web管理画面で：
- [ ] 100件の企業が一覧に表示されるか
- [ ] 企業詳細での対応履歴（手紙送付日・架電日）が正しく表示されるか
- [ ] スコア・ステージが正しく反映されているか

## 4. リスク＆対策

| リスク | 影響度 | 対策 |
|---|---|---|
| Excelのフォーマットが複数パターン | 中 | Fukudaに標準フォーマットを事前提示・サンプル貼付 |
| 企業名の表記ゆれ（カナ/漢字混在） | 高 | 自動正規化スクリプト + 人間の目視最終確認 |
| 電話番号の重複が多い（関連会社） | 中 | `deduplicateCompanies()` で自動検出・Fukuda確認 |
| 既存台帳との完全な重複 | 低 | 重複キーをハイフン除去版電話番号で照合 |
| 取り込み後のスコア計算エラー | 高 | 事前テスト（フェーズA試験と同様の仕組み） |
