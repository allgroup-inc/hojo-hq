# 議事 2026-10-17 LINE会話ボットv1.8

- 起案: ❶システム関係全般(本セッション)
- 決裁: 小柳さん(2026-10-17「すべて自動で進めて改善対応してあげてください」「必要なものはすべて承認します。」)
- 区分: ②不可逆な変更(本番設定・外部送信)
- 依頼元: 福田さん(2026-10-08【修正依頼】LINE公式アカウントの自動応答における質問の重複 / LINE顧客メッセージ自動転送機能)

## 背景
- 会社情報テンプレ(【会社情報登録】/会社名：/代表者名：…)は、項目名とコロンが一字一句同じときしか読めなかった。
  お客様が「代表者：」「社名 ◯◯」「値を次の行に書く」などで返信すると会社名・代表者名が空と判定され、
  **同じ記入依頼が返り続けていた**(福田さんのスクリーンショットの事象)。
- 福田さんから、お客様のメッセージを送信日時・LINE User ID・本文つきで指定アドレスへ転送してほしいと依頼(自動返信は現状のまま)。
- ボットのコードは文書に貼ったものを小柳さんがエディタへ貼り替える運用で、v1.7.1が9/1から「貼り替え待ち」のまま止まっていた。

## 論点: 読み取りを緩め、転送を足し、反映を自動にするか

### スイシン(推進)
- 項目名の言い換え・区切りの有無・次の行への記入・見出しなしの返信を読む。読めた項目は承り、**足りない項目だけ**を1つずつ聞く。
- 空のテンプレへの記入依頼は1回だけにし、2回目からは1問ずつの質問へ切り替える(同じ文面を2度返さない)。
- お客様のメッセージは `FORWARD_EMAILS` の宛先へすべて転送。宛先はスクリプトプロパティに置き、リポジトリに書かない。
- コードの正本を `gas/line-bot/` に移し、mainへ入ったら Actions がテスト→反映→本番デプロイ更新まで行う。貼り替え待ちで止まらない。

### ウタガイ(懐疑)
- **読み取りを緩めると誤登録が増える。** 「メールで連絡ください」「会社名は…」のような普通の文が会社情報として台帳に入りうる。
  → 見出しなしの文は「会社名」か「代表者名」が項目名つきで書かれているときだけ登録扱い。短い項目名(代表・電話など)は
  区切りが無いと項目名とみなさない。メールは@が無ければ拾わない。項目名なしの2行は**復唱して「はい」を待つ**(v1.3の誤記録防止を踏襲)。
- **全メッセージのメール転送は、相談の通知メールと二重になる。** また個人Gmailの MailApp は1日の送信上限(約100通)がある。
  → 件名を「【ミカタLINE】お客様からのメッセージ」に固定して振り分けやすくする。現状の受信量では上限に届かないが、
  届いたら転送を相談以外に絞る(見直し条件)。転送の失敗はLINEの返信を止めない。
- **エディタで直接足された修正を、自動反映が上書きで消すおそれ。** 9/1以降、誰かがエディタで直していても文書には残っていない。
  → 反映前にライブを読み、**ライブにだけある関数があれば止める**。本番デプロイは「新しいデプロイ」を作らず既存IDを新バージョンへ更新(8/12の別デプロイ事故の再発防止)。
- お客様のLINE User IDと本文が個人Gmailに残る。→ 宛先は運営スタッフのみ。公開リポジトリには宛先も本文も置かない。

### ベッカイ(別解)
- LINE公式アカウントの管理画面の「チャット」通知設定(メール通知)で足りるのでは。→ 管理画面の通知は本文が入らず、User IDも出ない。依頼の形式を満たさない。
- テンプレをやめ、常に1問ずつの会話にする案。→ リッチメニューのテンプレは福田さんの依頼(8/31❸)で入れたもの。両方残し、読めなかった分だけ会話で補う形にする。

### 結論(裁定)
- 採否: 採用(ウタガイの対策をすべて実装に入れた。テスト11件: `tests/line_bot.test.mjs`)
- 理由: 現場で実際に起きている繰り返しを止め、依頼済みの転送を実現する。反映待ちで止まる構造も同時に解消する。
- 見直し期限: 2027-04-17(転送メールが1日80通を超えたら前倒しで再議論)
