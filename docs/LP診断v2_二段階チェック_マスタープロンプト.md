# LP診断v2「二段階チェック」マスタープロンプト(2026-08-31)

起案: 小柳さん「申請する上で最低限確認しなければいけないものを分かりやすく調べられる仕組みを。
1回目は軽く確認してざっと申請できる可能性が高い一覧が出る。そこから更に絞る仕組み」

## 結論: 導入できる(既存の仕組みにそのまま乗る)

現行の診断がすでに「1回目の軽い確認」(4問→ざっくり一覧)なので、その結果画面の上に
**STEP2「申請前の最終チェック」**を重ねる二段構えにする。新規ページは不要で、
データも今ある項目(締切・従業員数・地域・業種・電子申請の有無・金額)で動く。

```
STEP1(現行・30秒)          STEP2(新設・+30秒)
4問えらぶ                    最終チェック 5問
市町村/業種/従業員/テーマ  →  結果一覧   →  gBizID/準備期間/立替/滞納なし/書類  →  絞り込み済み一覧
                            (ざっくり)                                        +「申請の土台」表示
                                                                              ↓
                                                                        LINE登録(CV・従来どおり)
```

## STEP2の質問セット(5問・すべて選択式)

「制度ごとの個別要件」ではなく、**どの補助金にも共通する“申請の土台”**だけを聞く。
これなら制度データに詳細要件がなくても、正確性ルール(断定しない)を守ったまま絞り込める。

| # | 質問 | 選択肢 | 絞り込み/表示への効き方 |
|---|---|---|---|
| 1 | GビズIDプラインは持っていますか | 持っている/申請中/持っていない | 「持っていない」→ 電子申請の制度に「ID取得に1〜2週間」の注記を付け、県・市町村の独自申請の制度を上位に |
| 2 | 申請の準備に使える時間は | すぐ動ける/1か月くらい/急がない | 締切日と突合。「準備が間に合う制度」を上位に(締切3層ルールの表現で。30日未満は「次回公募に備える」枠へ) |
| 3 | 経費をいったん立て替えられますか | できる/むずかしい/わからない | 補助金は原則後払い。「むずかしい」→ 上限額が小さめの制度を上位に+「後払いが基本」の説明カードを表示 |
| 4 | 税金・社会保険料の滞納はありませんか | ない/ある・わからない | ほぼ全制度の共通要件。「ある・わからない」→ 絞らず「先に解消・確認を。相談も受けます」の案内を表示 |
| 5 | 事業計画書はどう作りますか | 自分で書ける/手伝ってほしい | 「手伝ってほしい」→ 結果の下に専門家相談導線(既存の相談フロー)を前に出す |

### 必ず一緒に表示する「申請の土台」3点(共通知識カード)
- 補助金は**後払い**が基本(経費は一度立て替える)
- **交付決定前に使ったお金は対象外**(買ってから申請、はNG)
- 国の電子申請には**GビズIDプライム**が必要(取得1〜2週間)

## 守るルール(このプロンプトの絶対条件)

1. **断定しない**: 判定は「並べ替え」と「注記の付与」まで。「あなたは申請できます」とは言わない。
   表現は「申請できる可能性が高い順に並べ替えました」「個別の要件は必ず原文でご確認ください」
2. **CV単一**: STEP2の結果画面もLINE登録が唯一の出口(全CTAは/go/経由・lin.ee直貼り禁止)。
   マスク解禁の仕組み(1件表示+残りLINEで全件)は現行のまま
3. **締切3層ルール**: 準備期間の表現は「締切の約1か月前から」。30日未満の制度を「急げ」と煽らない
4. **STEP2は任意**: STEP1の結果だけでもLINE登録に進める(段数を増やして離脱を増やさない)
5. **回答は端末内(localStorage)のみ**でサイトに保存しない(現行の法務ラインを踏襲)。
   LINE登録済みの人の回答が台帳に載るのは、既存のLIFFフォーム経由のみ
6. パフォーマンス: 追加CSSは既存規律に従う(word-break等の適用範囲拡大禁止)。実装後にLighthouse実測

## 期待できる効果(KPI接続)

- 最大離脱点「結果表示→LINEタップ(89%離脱)」への一手。STEP2で「自分ごと化」が一段深まった人は
  登録率が上がる見込み(支持KPI: 診断→LINE登録率30%目標)
- 質問5「手伝ってほしい」は真のKPI(相談・面談 月10件)への入口になる

## 三名体制の論点(実装前に踏まえる)

- **ウタガイ**: 質問を増やすほど途中離脱が増える。STEP2を必須にしたら診断完了数そのものが落ちる。
  → だからSTEP2は任意・結果画面の中に置く(STEP1のCVを一切触らない)
- **ベッカイ**: 絞り込みよりも「並べ替え+理由の表示」の方が誠実で納得感が出る(消すと「なぜ消えた?」になる)。
  → 原則ソート+注記。非表示にするのは締切超過など機械的に確実なものだけ

## 実装プロンプト(ここからコピーしてAIに渡す)

あなたは「沖縄企業のミカタ」(hojo-hq)のLP実装担当です。site/index.html の診断機能に
STEP2「申請前の最終チェック」を追加してください。

### 実装要件
1. 現行の診断(4問→#match-btn→#match-result)は一切変更しない。結果一覧の直後に
   「申請前の最終チェック(30秒・任意)」の折りたたみセクションを新設する
2. 質問5問は上記の表のとおり(選択式ボタン・チップUIは既存 .chip を流用)
3. 回答に応じて result-list を並べ替え、各カードに注記バッジを付ける:
   - gBizIDなし × 電子申請制度 →「GビズID取得に1〜2週間」
   - 準備期間と締切の突合 →「準備が間に合いやすい」/ 締切30日未満は次回公募枠へ移動
   - 立替むずかしい → 上限額の小さい順を優先
4. 「申請の土台」3点の共通知識カードをチェック結果の下に常時表示する
5. 質問4で「ある・わからない」→ 絞り込みは変えず、案内カード(先に確認を+相談導線)を表示
6. 質問5で「手伝ってほしい」→ 既存の専門家相談導線(oaMessage「相談」)を結果直下に複製表示
7. 表現ルール: 断定禁止(「可能性が高い順」「必ず原文で確認」)・締切は「約1か月前から」・
   絵文字最小・CV導線はLINE登録のみ(/go/経由)
8. 回答はlocalStorageのみ。計測はPlausibleのカスタムイベント(step2_done等)を1つ追加
9. 実装後: 全キャプション系はscripts/check_humanizer.py、表示はモバイル3サイズ(320/375/414)、
   LighthouseはローカルCLIで実測してから出すこと

### 受け入れ条件
- STEP1だけで従来どおりLINE登録まで完走できる(STEP2未回答でも一切阻害しない)
- STEP2回答後、一覧の順序と注記が変わり、「なぜこの順か」の一行説明が表示される
- 断定表現・lin.ee直貼り・7日前表現がないこと(scripts/shipping_gate.pyの禁止パターンに抵触しない)
