# 議事 2026-10-30 履歴取り込みの取込済タブを1枚にまとめる

- 起案: ❶システム関係全般(本セッション)
- 決裁: 小柳さん(2026-10-30「福田からメールきてるので対応してください」。福田さんの確認事項①〜③への対応)
- 区分: ②データの削除(古いタブを消す)

## 背景
- 台帳の「福田_履歴インポート」タブに貼ると、数分で企業マスタと対応履歴へ取り込まれる(2026-10-25〜)。取り込んだ表は「福田_履歴インポート_取込済_日時」へ名前を変えて残していたため、取り込むたびにタブが1枚ずつ増える(10/30 時点で4枚)。
- 福田さんから3点の確認があった(10/30 メール)。
  1. 取込済のタブが増え続ける。消えるのか、1枚にまとめられないか。
  2. 台帳に無い会社と面談したとき、どこに残すか。
  3. 録音できなかった面談の内容を、直接残す場所はあるか(入電は取り込みタブで残している)。
- 取り込みは、通話結果が「入電」の行も種別「電話」で残していた。台帳の種別には「入電」「面談実施」がある。

## 論点: 取込済タブのまとめ方と、入電・面談の残し方

### スイシン(推進)
- 取り込んだ行は「福田_履歴インポート_取込済」タブ1枚の末尾へ、取込日時つきで足す。取り込みタブは見出しだけに戻す。
- 既に増えた4枚は、1回だけ1枚へ写してから消す。
- 通話結果が「面談」「訪問」なら種別を面談実施、「入電」なら入電、「アポ」ならアポ獲得にし、備考を内容として残す。面談した会社は現在ステージを「相談実施」まで進める。見出し「面談日」「対応日」も日付として読む。

### ウタガイ(懐疑)
- **タブを消すのは戻せない。** 写し損ねると、取り込んだ元の表が失われる。
  → 写した行数が合ったタブだけを消し、合わなければ残して警告をログに出す。元の表の中身は企業マスタと対応履歴に取り込み済みで、台帳は毎朝バックアップされている。
- **見出しを言い換えた表(「企業名」「TEL」等)を写すと、列がずれる。**
  → 標準の見出しの順にそろえてから写す(historyImport.js の toArchiveRows。テストあり)。
- **取り込みタブで面談を残す方法は、スマホでは書きにくい。**
  → 当面はこの方法で受け、録音がある面談はこれまでどおりLINE・ドライブで残す。文字のメモをLINEで送って残す方法は、使われ方を見て検討する。
- **過去に「電話」で取り込んだ入電の行は、種別が直らない。**
  → 過去分は直さない(内容メモに「結果: 入電」が残っている)。

### ベッカイ(別解)
- 取込済タブを一定期間で自動で消す案。取り込んだ元の表を後から確かめられなくなるため採らない。
- 管理画面(Web)のクイック記録で面談を残す案。台帳にある会社にしか使えないため、台帳に無い会社の面談(福田さんの確認事項②)には向かない。

### 結論(裁定)
- 採否: 採用(ウタガイの対策を実装に入れた。実装: glow-ma/src/HistoricalDataImporter.gs の archiveStagingSheet_・mergeOldArchiveSheetsOnce_、glow-ma/src/historyImport.js の callTypeOf・toArchiveRows。テスト: tests/glow_ma_history_import.test.mjs)
- 担当者向けの説明: docs/glow-ma_訪問ログの記録方法_担当者向け.md
- 見直し期限: 2027-04-30

## 追記(2026-10-30 その2): 取り込みの時刻を決める・メール送信日を足す
- 福田さんから(10/30 メール): ①数分以内に取り込まれるため、入力の途中で取り込まれる。時刻を決めてほしい(例: 22時・翌朝8時) ②手紙(DM)は今は送っておらず、メールで案内している。メール送信日の列がほしい。
- 対応:
  - 取り込みは毎日 8時と22時(日本時間)の1回ずつにした。時刻に行が無くても、その時刻は使い済みにする(時刻の後に書き始めた行を、書いている途中で取り込まない)。すぐ取り込みたいときはメニュー「GLOW台帳 > 過去記録の取り込みを今すぐ行う」。
  - 取り込みタブの末尾に「メール送信日」を足し、対応履歴の種別に「メール送信」を足した(行動量ダッシュボードでは「手紙」と同じ欄に数える)。列は末尾にだけ足す(福田さんは手元の表を貼るため、途中に入れると貼った列がずれる)。
  - メールは送るたびに1行で残す(1つの欄を書き換えると前の記録が残らない)。
- ウタガイ(懐疑): 取り込みが1日2回になると、入電や面談が台帳に載るまで最大14時間ほど遅れる。→ すぐ載せたいときはメニューから今すぐ取り込める。録音(LINE・ドライブ)の記録は今までどおりすぐ届く。
- ウタガイ(懐疑): 「取込済」タブを直しても台帳は変わらないため、直したつもりで台帳が古いままになるおそれ。→ 担当者向けの説明に「控えであり、直すのは対応履歴ログ」と明記した。
- 実装: glow-ma/src/historyImport.js の currentImportSlot・メール送信日、glow-ma/src/HistoricalDataImporter.gs の historyImportSlotDue_・updateStagingHeadersIfEmpty_、glow-ma/src/schema.js(種別「メール送信」)。テスト: tests/glow_ma_history_import.test.mjs・tests/glow_ma_schema.test.mjs

## 追記(2026-10-31): 書いている途中の行が台帳に載らないまま取込済へ移された件
- 10/30 13:46(取り込み時刻を決める前)、福田さんが書いている途中の行(来店の記録1件)を取り込みが読み、日付が空のため「取り込めず」になった。その数秒後に取込済へ移す処理が表を読み直し、日付の入った行を取込済へ移したため、**台帳に載らないまま取り込みタブから消えた**。
- 対応:
  - 取込済へ移すのは、取り込みのときに読んだ行だけにした。そのあいだに書き換えられた行・書き足された行は取り込みタブに残し、次の取り込みに回す(historyImport.js の changedRows)。
  - 10/30 13:46 の行は、1回だけ取り込みタブへ戻し、次の取り込み時刻に取り込む(HistoricalDataImporter.gs の restageMissedRowsOnce_)。同じ会社・同じ日・同じ種別の対応履歴は二重に書かれないので、戻しても重複しない。
  - 通話結果の「来店」「来社」も面談実施として読む。
- ウタガイ(懐疑): 取り込みタブに戻すと、福田さんが「消えたはずの行がまた出てきた」と戸惑う。→ 福田さんへの連絡で、戻したことと、そのまま置いておけばよいことを伝える。
