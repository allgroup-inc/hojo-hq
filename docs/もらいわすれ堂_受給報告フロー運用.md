# 受給報告フロー 運用手順(2026-08-10 稼働開始)

北極星❷「受給できた報告1,000件」の受け口。利用者が https://allgroup-inc.github.io/hojo-hq/fukugiiro/houkoku/ から
「もらえた報告」をLINEに送り、御礼を返し、台帳に貯める。

## 流れ(全体図)
1. 導線: 診断結果 / 申請準備シート(全143ページ) / トップの3か所から報告ページへ
2. 報告ページで 制度名・市町村(任意)・ひとこと(任意) を入力 → 「LINEで報告を送る」
   - LINEベーシックID設定後: LINEが開いて本文が自動セット(ワンタップ)
   - 未設定の間: 本文が自動コピーされ「LINEを開いて貼り付けて送る」案内(現在はこちら)
3. 御礼を返す(下の文面をコピペ・当面は手動)
4. 台帳に転記: `python scripts/add_jukyu_report.py --seido-id ... --status 計上` (検証部が公式制度と突合できたら --verified)
5. 検証済み件数はサイトの実績カードに自動表示(0件の間は非表示)・週次レポに自動集計

## 御礼メッセージ(小柳さん選定待ち・どちらかをLINEで返信)
**A案(あたたかい沖縄トーン)**
> ご報告、にふぇーでーびる(ありがとうございます)🌈
> 「もらえた」の一言が、次の誰かの「調べてみよう」につながります。
> これからも締切や新しい制度を、そっとお知らせしますね。
> あなたが受け取るまで、いっしょに。— もらいわすれ堂

**B案(簡潔・丁寧)**
> ご報告ありがとうございます。無事に受け取れて何よりです。
> いただいた内容は、個人がわからない形で「次の誰かのもらい忘れ防止」に役立てます。
> 引き続き、締切や新しい制度をLINEでお知らせします。— もらいわすれ堂

## 小柳さんにお願いする設定(2つ)
1. **LINEベーシックIDを教えてください**(https://manager.line.biz/ → 設定 → アカウント設定 → ベーシックID「@〜」)
   → こちらで `site/fukugiiro/analytics-config.js` の FG_LINE_OA_ID に設定=報告がワンタップ送信になります
2. 御礼文面 A/B の選定(以後、報告が届いたらコピペ返信。将来Messaging API連携で自動化予定)

## PII・正確性ルール(守り部)
- 報告ページは「名前・住所・金額を書かない」を明記。台帳にも個人特定情報は入れない(household_keyは匿名キーのみ)
- サイト計上は **検証部が公式制度と突合できた件数のみ**(自己申告のままの数字は公開しない)
- 台帳: data/fukugiiro/jukyu_reports.json(summaryのdisclaimer参照)

## 計測イベント
- jukyu_report_link_top / _shindan / _kit: 各導線のクリック
- jukyu_report_click: 報告ページで「LINEで報告を送る」を押した数(=送信意思。週次レポ集計対象)
