# 面談予約表(お客様が営業マンを選んで予約)— 指示の出し方ガイド

作成: 2026-08-14 / 発端: 小柳さんからのLINE(思いつき共有)
位置づけ: 真のKPI(出口への相談・面談転換 月10件)に直結する構想。**現時点は保留・上申**(決裁3点は §5)。

もとのLINE文:

> お客様から予約できる面談予約表みたいなのがあると今後いいかもです。
> 営業マンの顔写真付きで、この営業マン選ぶ→空きアポ情報でてきて選択みたいなイメージです。

---

## 0. 先に結論

**この文のままで十分です。**思いつきは削らずそのまま送ってください。
ただしこの1文だと、AI側が勝手に決めてしまう(=あとで作り直しになる)点が3つあります。

| 勝手に決まってしまう点 | なぜ危ないか |
|---|---|
| **どこに置くか**(公開サイト or LINEの中 or 社内だけ) | 公開サイトに置くと絶対ルール4「CV単一(LINE登録のみ)」に抵触。KGIの1,000社が落ちる |
| **誰の予定か**(GLOW営業マン / 士業 / 嶺井さん) | 空き枠の取り方も、面談後の出口も変わる |
| **予約後にどうなるか**(通知・カレンダー登録・リマインド) | ここが抜けると「予約したのに連絡が来ない」が起きる。信頼毀損が一番大きい |

なので、次から思いつきを投げるときは **§2の1行を足すだけ** で、こちらが勝手に決めずに済みます。
今回の構想そのものの採否は §4 の議事、決めてほしいことは §5 にまとめました。

## 1. 指示の出し方 5原則(この構想に限らず全部に効く)

1. **思いつきはそのまま送る。整えない。**
   整った指示ほど別解が出せなくなります。「〜みたいなイメージ」で十分です。
2. **「何が良くなってほしいか」を1行足す。**
   ×「予約表がほしい」→ ○「面談が月◯件に増えてほしい。そのために予約表がいいかも」
   目的が書いてあれば、予約表より効く手があるときにそれを出せます。
3. **置き場所を書く。**「公開サイト/LINEの中/社内だけ」の3択で十分です。
   ミカタはCV単一ルールがあるので、置き場所が書いてない構想は必ずそこで止まります。
4. **やって終わりでなく「その後」を書く。**
   予約が入ったら → 誰に通知 → カレンダーに入る → 前日にリマインド。ここまで書くと、作るものが半分決まります。
5. **「今すぐ試したい」か「じっくり作りたい」かを書く。**
   前者なら既製ツール(TimeRex等)で1週間、後者ならglow-maに内製。作る量が10倍変わります。

**全部埋めなくて大丈夫です。**分からないところは「わからない」「任せる」と書いてください。
そう書いてあれば、こちらが選択肢を並べて決裁キューに上げます(黙って決めることはしません)。

## 2. そのまま貼れる型

### 型A: 思いつきを投げるとき(30秒・これが基本)

```
【思いつき】
<やりたいことを、思いついたまま。整えなくていい>

【良くしたいこと】
<例: 面談が増えてほしい / お客様の手間を減らしたい>

【置き場所】公開サイト / LINEの中 / 社内だけ / わからない
【急ぎ度】今すぐ試したい / じっくりでいい

決裁が要る点があれば決裁キューに上げてください。
```

今回のLINEを型Aに直すと、こうなります(これが理想形):

```
【思いつき】
お客様から予約できる面談予約表みたいなのがあるといいかも。
営業マンの顔写真付きで、この営業マン選ぶ→空きアポ情報でてきて選択、みたいなイメージ。

【良くしたいこと】
LINE登録のあと面談まで進む数を増やしたい(今は人力で取りこぼしてる感覚がある)

【置き場所】わからない(公開サイトに置いていいのかが判断つかない)
【急ぎ度】今すぐ試したい

決裁が要る点があれば決裁キューに上げてください。
```

### 型B: 方向性を決めたいとき(壁打ち)

```
<構想>について、三名体制で議論して結論を出してください。
特にウタガイ役には「やらない理由」を厳しめに出させてください。
私が決めるべき点は決裁キューに1行で。
```

### 型C: 実際に作らせるとき

```
<構想>を作ってください。

決まっていること:
- 置き場所: <どこ>
- 対象者: <誰の予定を出すか。人数も>
- 予約後の流れ: <誰に通知 → どこに記録 → リマインドの有無>

決まっていないこと:
- <ここは提案してほしい>

守ること:
- 個人情報・顔写真は公開リポジトリにコミットしない
- 空き枠が取れないときは予約を受け付けない(誤った枠を出さない)
- 完了したらドキュメントに記録を残す
```

型Cの「守ること」3行は、この種の自動で動くものを頼むときは毎回入れてください。
特に2行目は、resilient-agent-design の「取得できないときは止まる(フェイルクローズ)」に当たります。
カレンダーが繋がらないときに古い空き枠を出してしまうのが、この手の仕組みで一番起きる事故です。

## 4. 議事: 面談予約表の採否・置き場所(三名体制)

### 論点: お客様が営業マンを顔写真から選んで空き枠を予約できる「面談予約表」を作るか

#### スイシン(推進)

- 真のKPI(出口への相談・面談転換 月10件)に**直接効く唯一の装置**。KGIのLINE登録1,000社は経由指標であり、面談に変わらなければ「進んでいない」。今その転換部分だけ人力で、装置がない
- 経営者は「誰に相談するのか分からない」ことで止まる。顔と名前が出ていて自分で枠を選べると、電話・往復のやり取りを挟まずに済む
- 既製ツール(TimeRex・Spir・Googleの予約ページ)なら**1週間で置ける**。作らずに検証できる
- glow-ma側に予約履歴が入れば、対応履歴ログ・スコアリングとそのまま繋がる(Phase 19相当)

#### ウタガイ(懐疑)

- **絶対ルール4に抵触する恐れ**。公開サイト(ミカタLP)に「予約する」を置いた瞬間にCVが2本になる。LINE登録より予約ボタンの方が強い訴求なので、登録数(KGI 1,000社)は確実に落ちる。**公開サイト設置は決裁なしには不可**
- **顔写真は肖像・個人情報**。hojo-hqへの画像コミットはPII非コミット原則に触れる。本人の書面同意、退職時の削除運用、掲載範囲(社外に出る)の合意が要る。運用規程1-3のデータ基準にも掛かる
- **空き枠の鮮度が命**。カレンダー連携が切れて古い枠を出す/二重予約する事故は、面談前に信頼を壊す。月10件を取りに行って1件壊すなら割に合わない
- **今の面談数に対して過剰**。月10件が目標の段階で予約システムを内製するのは、投下時間が合わない。既製ツールで足りる
- **資格業務の線引き**。士業への送客面談を当社営業マンが受ける形は、申請代行と誤認されうる。面談の名前とページの説明文を守り部審査に通す必要がある
- **指名制の副作用**。人気の偏り、社内の取り合い、選ばれない人が出る。少人数では士気の問題になる

#### ベッカイ(別解・前提を疑う)

- そもそも欲しいのは「予約表」ではなく **「面談の取りこぼしをなくすこと」** では。だとすれば作るべきUIではなく、LINEで日程候補を3つ出して返信で確定する運用の方が、経営者にとって手数が少ない(アプリを開かせない)
- 営業マンが少数なら、**選ばせるより「この人が担当です」と1人見せる方が強い**。選択肢は安心ではなく迷いになりうる。顔写真の効果は「選ばせる」ことより「顔が見えている」ことにある
- 置き場所の別解: 公開サイトではなく **LINE登録後のリッチメニュー/自動応答の中**に置けば、CV単一を崩さずに済む(登録が前提条件になるので、むしろ登録の動機になる)
- 順番の別解: 予約装置を先に作るのではなく、**まず面談を10件人力でやって、詰まった箇所を装置にする**。今は「予約枠がないから面談が増えない」のか「そもそも相談したい人が少ない」のかが分かっていない

### 結論(裁定)

- 採否: **保留・上申**(方向性は前向き。ただし小柳さん決裁3点が先)
- 理由:
  - 真のKPIに直結する構想であり、スイシンの主張は妥当。取り下げない
  - ただし置き場所を公開サイトにするとルール4に真正面から抵触するため、エージェント判断では進められない(規程1-2)
  - ベッカイの「LINE登録後に置く」案は、CV単一を守ったまま同じ効果が取れるため**第一候補**とする
  - 内製は時期尚早。**既製ツール+LINE内設置で最小検証 → 予約が実際に入ってからglow-maに内製**の二段構えを推奨案として上申する
  - 顔写真は本人同意と保管場所(非公開領域)が確定するまで着手しない
- 見直し期限: **2026-11-14**(期限切れは自動で再議論)

## 5. 小柳さんに決めていただきたいこと(決裁キュー記載済み)

1. **置き場所** — ①LINE登録後だけ(推奨・CV単一を守れる) / ②公開サイトにも置く(CV2本化を承知の上で) / ③社内のみ
2. **作り方** — ①既製ツールで1週間の最小検証(推奨) / ②最初からglow-maに内製
3. **顔写真の掲載** — 対象者(誰の顔を出すか)と本人同意の取り方。掲載可否が決まるまで画像は一切扱いません

決裁の返信は「①/②/③+理由1行」で足ります。
