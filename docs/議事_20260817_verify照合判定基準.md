# 議事: verify-sources照合の「未掲載」をNGと数えるか(2026-08-17)

背景: 2026-08-16のverify-sourcesで「沖縄ものづくり製品開発・技術導入支援事業」がNG判定
(Issue #188)。掲載データの上限額は None(サイト上は「要確認」表示)、原文には
「1,200万円以内」の記載があり、Geminiがこれを不一致として報告した。
しかし fetch_local.py は市町村・公社系のクロールで金額を抽出しない設計
(誤抽出=正確性違反を避けるため)であり、None は絶対ルール1
「不明時は要確認表示で公開し断定しない」に沿った状態。この「未掲載」を
「不一致(NG)」と数えるべきかを裁定する。

## 論点: 掲載値がNone/「要確認」の項目を原文との不一致(NG)扱いにするか

### スイシン(推進)
- 未掲載は矛盾ではない。NG=「掲載が原文と食い違う(利用者を誤らせる)」に限定すべき。
  現状はサンプルに公社系が入るたびに赤CI+Issue追記が起き、真の不一致(締切・金額の
  誤記)の警報が薄まる。オオカミ少年化こそ検証体制の最大リスク。
- 照合プロンプトに「None/要確認=未掲載(サイトでは非断定表示)であり矛盾ではない。
  報告するのは掲載値が存在して原文と実質的に食い違う場合のみ」と明記する。

### ウタガイ(懐疑)  ← 空欄不可
- **反対理由**: 未掲載を一律OKにすると「原文に金額が明記されているのに掲載が空」という
  データ品質の欠落が永久に見えなくなる。利用者にとって金額は制度を見る第一の情報で、
  空欄放置は「正確だが役に立たない」サイトへの後退。Geminiの指摘自体は
  (判定区分はともかく)改善機会の発見として正しかった。
- また「NGの定義を狭める変更」は、閾値緩和と同様に検証を骨抜きにする坂道になり得る。
  変更は議事に残し、効果測定(2026-11-06のマルチAI見直し)で誤検知/真検知の集計に
  影響が出ていないか確認すること。

### ベッカイ(別解)
- 二値(OK/NG)で扱うのが前提の誤り。「矛盾(NG=CI失敗)」と「追加候補(情報表示)」の
  二層に分ければ両立する: 照合AIに「原文に明記された上限額」を拾わせ(amount_in_source)、
  掲載がNoneのときは失敗させず「ℹ 追加候補」としてレポートと照合履歴に記録。
  人(検証部→小柳さん)が原文を目視確認してから追記する既存の昇格運用に載せる。
- fetch_local.py に金額自動抽出を足す案は不採用が妥当(自由書式の公社ページからの
  正規表現抽出は誤抽出リスクが高く、絶対ルール1に反する)。

### 結論(部門長の裁定)
- 採否: **採用(スイシン+ベッカイの併用)**
  1. 照合プロンプトに「None/要確認=未掲載であり矛盾ではない」を明記(NGの定義を
     「掲載値が存在して原文と食い違う」に限定)
  2. 同時に amount_in_source を判定スキーマに追加し、未掲載×原文に金額ありの場合は
     「ℹ 追加候補」として非失敗でレポート・照合履歴(verify_history.json)に記録
     (ウタガイの「欠落が見えなくなる」を解消)
  3. okinawa_ric-18 の上限額は AI引用(1,200万円以内)のみでは追記しない
     (AI一致は断定の十分条件ではない)。決裁キューの目視確認1件として記録し、
     人の原文確認後に追記する
- 理由: NGの警報価値を守りつつ(ウタガイ)、欠落の可視化は非失敗の層で担保する
  (ベッカイ)。絶対ルール1(不明時は要確認・断定しない)とマルチAI決裁
  (2026-08-06)の「どちらかが矛盾検知でNG」の原則はどちらも変更しない —
  変わるのは「未掲載は矛盾に当たらない」という定義の明確化のみ。
- 見直し期限: 2026-11-06(マルチAI連携の効果測定と同時。追加候補の件数と
  誤検知/真検知の比率を確認)
