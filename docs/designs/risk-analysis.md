# リスク分析（Task 13）

| リスク | 確率 | 影響 | 対策 |
|---|---|---|---|
| **スケジュール遅延** (10月30日～11月中旬の認証実装が難航) | 中 | 高 | ① 早期に Entra ID OAuth POC 実施、② OAuth ライブラリ（passport.js）の評価期間 2週間確保 |
| **セキュリティ脆弱性** (JWT トークン管理の不備) | 低 | 高 | ① OWASP Top 10 チェックリスト作成、② 外部セキュリティレビュー実施（本番投入 1ヶ月前） |
| **パフォーマンス問題** (営業マン 12 名で 100 アポ/日の場合、WebSocket オーバーロード) | 中 | 中 | ① 負荷テスト 200 アポ/日想定で実施、② Redis キャッシュ導入、③ 必要に応じて GraphQL に移行 |
| **ユーザー受け入れ拒否** (営業マンが「使いにくい」と判断) | 低 | 高 | ① アルファテスト段階で営業マン 3 名を参加させ、② 毎週フィードバック反映、③ UI 改善サイクル 1 週間単位 |
| **技術的行き詰まり** (Node.js × PostgreSQL 環境で予期しないバグ発生) | 低 | 中 | ① 技術選定段階で PoC 実施（2 週間）、② 既存 GAS ロジック転用テスト、③ Tech Lead が早期に問題検知 |
| **API 依存トラブル** (Slack API・Entra ID サービス障害) | 低 | 低 | ① フォールバック通知（Slack 障害時は LINE のみ）、② 監視アラート 24/7 実装 |

**リスク対策の優先度:**
1. セキュリティ脆弱性対策（影響が高い）
2. スケジュール遅延対策（確率が中程度）
3. パフォーマンス問題対策（営業マン満足度）
