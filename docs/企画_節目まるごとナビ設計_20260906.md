## 結論(先に要点)

- **何をするサービスか**: 出産・入学・引越し・介護の始まりなど、**人生の節目を選ぶと「やる手続き・もらえるお金・減らせる支出」が市町村別に1枚のチェックリストで出てくる**サービス。
- **もらいわすれ堂との役割分担**: もらいわすれ堂=「いま」のもらい忘れを診断する。本サービス=「節目が来たとき」に取りこぼさないようにする。**入口が2つになり、出口(LINE登録→伴走→受給報告)は共通**。
- **最初は小さく**: 節目2つ(出産・引越し)×5市町村(那覇・沖縄・うるま・浦添・宜野湾)=10ページから。既存の制度DB・パイプライン・LINEを使い回すので費用はほぼ0円。
- **注意が要る点が2つ**: ①「おくやみ(家族が亡くなったとき)」は需要最大だが士業の業際に近いため守り部審査を通してから(Phase2)。②節目の手続きは「出来事から14日以内」のような**相対締切**で、補助金の締切3層ルールがそのまま当てはまらない。配信ルールの追補が必要(下記§7)。

## 3. 利用の流れ(UX)

```
① 節目を選ぶ 「赤ちゃんが生まれた」「引越しする」…(絵と大きなボタン)
        ▼
② 市町村を選ぶ 「那覇市」…
        ▼
③ チェックリスト表示(1ページ)
   ┌────────────────────────────┐
   │ 那覇市で赤ちゃんが生まれたら やること12個   │
   │ □ 出生届(生まれてから14日以内・市役所)     │
   │ □ 児童手当の申請(15日以内!遅れると損)     │
   │   → もらえる額:月◯円 / 持ち物:◯◯        │
   │ □ こども医療費助成 …                     │
   │ 合計で受け取れる可能性: 年◯◯円〜          │
   └────────────────────────────┘
        ▼
④ 「このリストをLINEで受け取る」ボタン
   → 出来事の日付を入れると、あなた専用の期限つきリストに
   → 期限が近づいたらお知らせ+「申請しましたか?」「振り込まれましたか?」
        ▼
⑤ 受給報告(もらいわすれ堂と共通の❷北極星に合流)
```

- 会員登録なし・氏名不要でチェックリストまで見られる(LINE受け取りは任意)
- 専門用語には必ず補足(もらいわすれ堂の平易化ルールを共通適用)
- 迷う人向けに「どの節目かわからない」→ もらいわすれ堂3分診断へ渡す相互導線

## 4. データ設計(既存スキーマへの追加)

フクギイロ_データスキーマの制度レコードに以下を追加する(別テーブルにしない。1制度=1レコードのまま節目タグで引く):

| フィールド | 内容 |
|---|---|
| milestone_tags | 配列: 出産/引越し/入学/失業/介護/… (複数可) |
| municipality | 市町村コード(全県共通制度は "県" / "国") |
| **deadline_type** | **absolute(日付固定)/ relative(出来事からn日以内)/ none** |
| deadline_relative_days | relative のときの日数(例: 出生から15日) |
| checklist_order | 節目ページ内での表示順(先にやるべき順) |
| required_docs / window / amount_note | 持ち物/窓口/金額の目安 |
| source_url / last_verified | 出典と最終確認日(必須。欠けたら公開不可) |

**deadline_type: relative がこのサービスの技術的な核**。補助金DB(絶対締切)には無かった概念で、LINEで出来事の日付を預かって初めて「あなた専用の期限」が計算できる=LINE登録の必然性そのもの。

## 5. MVP(最小版)の範囲

- **節目2つ × 5市町村(那覇・沖縄・うるま・浦添・宜野湾=県人口の約半分)= 10ページ+入口1ページ**
- 静的ページ自動生成(制度DB→ページ。企業のミカタ/もらいわすれ堂と同じ仕組み)
- LINEの「日付を預かって期限リスト化」はMVPでは手動セグメント配信で代替可(まず「リストを受け取る」だけでも成立)
- 作らないもの: 全節目対応/全41市町村/おくやみ/専用アプリ
- 公開判定: 全項目に出典URL+最終確認日/検証部の原文照合済み/守り部の公開前チェックリスト通過/小5でも読める文章

## 6. 収集・検証(既存規律をそのまま適用)

- 一次情報のみ(市町村公式・国公式)。締切・金額・持ち物は原文照合、不明は「要確認」で断定しない(hojo-accuracy-check 準拠)
- 市町村ページのURL死活チェックを日次巡回に追加
- 相対締切(「14日以内」等)は条例・案内ページの文言をそのまま引用し、独自の言い換えで日数を丸めない

## 7. 配信ルールの追補が必要(ウタガイ指摘・決裁事項)

締切3層ルール(SNS=残り30日以上/7〜29日=LINE個別/7日未満=次回予告)は**絶対締切**を前提にしている。節目の相対締切(出生から15日以内等)はそもそも「残り30日以上」が存在しないケースが多い。よって:

- SNS・一般向け表現: 「生まれたら**15日以内**に」等、**期限の事実だけを事前教育として伝える**(特定個人の煽りをしない)
- LINE個別: 本人が日付を預けた場合のみ、個人の残り日数でお知らせする
- この追補は配信ルールの変更=不可逆類型のため、**ツナグさん(LINE部)+守り部で議事を作成のうえ小柳さん決裁**とする(本書では方針提案まで)

## 8. KPI(4目標への合流)

独自KGIは立てない。もらいわすれ堂の4目標に流し込む:

- ❶サイト利用: 節目ページの閲覧(検索流入「沖縄 出産 手続き」等が主戦場)
- ❹LINE登録: 「リストをLINEで受け取る」経由の登録数(計測イベント名は line_redirect と**必ず分ける**。go-link-discipline 準拠)
- ❷受給報告: 節目経由の受給報告件数
- 補助指標: 節目ページ→チェック完了率/日付預かり率
