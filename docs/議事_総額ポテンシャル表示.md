# 議事: 診断結果への「公募上限額 合計」どんと表示(総額ポテンシャル)

- 日付: 2026-07-26 / 起案: 小柳健さん(発案)・SNS/LINE/サイト横断
- 目的: 診断→LINE登録→専門家相談(成約)の流れを、金額インパクトで加速する

## 論点: マッチした制度の「上限額合計」を診断結果に大きく表示してよいか。表示するならどう表示するか。

### スイシン(推進)
- 診断結果が「制度カードの羅列」で終わっており、経営者の心が動く一撃がない。「最大◯◯円分の可能性」という一つの数字は最強のフックで、LINE登録・専門家相談への転換を一気に押し上げる。
- 数字は既存データ(max_amount)から機械的に計算でき、実装コストが低い。カウントアップ演出で体感価値も高い。
- 成約までの構造: 診断 → 総額どんと表示 → 「可能性を確認する」→ LINE登録 → 会社情報登録 → 専門家マッチング → 士業成約/GLOW接続、と一本の物語になる。

### ウタガイ(懐疑)
- **誇大表示リスクが最大の懸念。** 上限額の単純合計は「もらえる額」ではない。要件・採択率・併給調整を無視した理論値であり、「最大3億円!」のような数字を無留保で出せば、絶対ルール#1(断定禁止)違反かつ景品表示法の有利誤認(優良誤認)を疑われる恐れがある。守り部(シギョウ/ホウム視点)は無留保表示なら差し戻し。
- 全国の大型公募(上限5億円等)が1件混ざるだけで合計が非現実的に跳ね、**数字の信頼が崩れてサイト全体の信頼まで毀損**する。「どうせ盛ってる」と思われたら逆効果。
- max_amount が未公表(0/None)の制度が多く、合計は常に過小・過大のどちらかに歪む。数字の根拠を問われたとき説明できない表示は出すべきでない。

### ベッカイ(別解)
- 前提を疑う: 刺さるのは「総額」ではなく「自分ごと感」では? 別案①「あなたの会社が対象になり得る制度 ◯件(うち上限1,000万円超が◯件)」と件数主導で見せる。別案②合計ではなく「マッチ中の最大単体上限: ◯◯円」を見せる(1制度の実額なので誇大になりにくい)。
- 別案③総額はサイトに出さず、LINE登録後の「貴社専用レポート」で専門家の目を通した現実的な範囲を提示する(数字を会話の入口でなく成約直前の材料にする)。

### 結論(部門長の裁定)
- 採否: **採用(条件付き)** — スイシンの効果とウタガイの懸念を両立させる表示に限定する
- 理由: 数字のフック効果は大きいが、無留保では憲法違反。以下の5条件で「参考値」として成立させる。ベッカイ別案①②の要素(件数・最大単体)も同画面に併記し、単一数字への依存を下げる。
  1. 名称は「**公募上限額の合計(参考値)**」とし、「もらえる額」「受給額」とは絶対に表現しない
  2. 直下に免責を常時表示: 単純合計の理論値であり受給額・採択を保証しない旨+原文確認の案内
  3. 対象は「**診断で表示中の制度(上限額公表分のみ)**」に限定し、根拠を説明可能にする。非公表件数は「+上限額非公表◯件」と正直に併記
  4. CTAはLINE登録のみ(CV単一ルール維持)
  5. 文言変更時は守り部確認。数値ロジック変更時は本議事を更新
