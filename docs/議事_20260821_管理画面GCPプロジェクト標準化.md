# 議事_20260821_管理画面Web AppのGCPプロジェクト標準化

## 背景
管理画面Web App(P18a、`?page=admin`)へ、開発者(小柳さん)以外のアカウント(福田さん・非許可のテストアカウント双方)がアクセスすると、デプロイ設定(実行ユーザー=自分/アクセス=Googleアカウントを持つ全員)が正しいにもかかわらず、一律で「アクセス権がありません」(アプリ側)ではなくGoogleドライブ側の「リクエストされたファイルは存在しません」エラーとなり、企業一覧に到達できないことが2026-08-20〜21の実機検証(福田さん: 複数ブラウザ・PC双方で再現、スプレッドシート自体は正常に開ける)で確認された。

原因は、appsscript.jsonが宣言する`drive`フルスコープ(2026-08-13、QR機能対応のため小柳さん承認済み)により、このアプリがGoogleから「センシティブスコープ未検証アプリ」として扱われ、開発者があらかじめ許可した人(テストユーザー)以外は、アプリ側の許可リスト(スタッフタブ)判定に到達する前に一律ブロックされるため、と推定される。

この制限を解除する(テストユーザーを追加できるようにする)には、Apps ScriptのGoogle Cloud Platform(GCP)プロジェクトを、現在の「デフォルト(自動管理)」から「標準(自己管理)」プロジェクトへ切り替える必要がある。**この切り替えはGoogle仕様上、不可逆(デフォルトには戻せない)**。CLAUDE.md三名体制ルール②(不可逆な変更・本番設定の変更)に該当するため議事化する。

## 論点: GCPプロジェクトを「標準」へ切り替え、テストユーザーを追加してよいか

### スイシン(推進)
- 現状、開発者本人以外は管理画面に一切入れておらず、機能として実質使えていない。切り替えないと福田さん・嶺井さんは永久にこの機能を使えない
- 切り替え自体は「標準プロジェクトになる」だけで、既存のデプロイ・スプレッドシート・トリガー等の動作には影響しないとGoogle公式ドキュメントに明記されている
- テストユーザー登録は最大100人まで無料・即時反映で、Googleによる審査(verification)を待つ必要がない

### ウタガイ(懐疑)
- 「デフォルトに戻せない」という不可逆性がある以上、万一切り替え後に想定外の副作用(既存デプロイURLの認証エラー等)が出た場合、後戻りする手段がない
- テストユーザーは最大100人までという上限があり、将来的にスタッフが増えた際に運用を忘れると同じ問題が再発する(スタッフタブへの登録と、テストユーザーへの登録という「二重管理」になる)
- 根本的には、`drive`フルスコープを要求していること自体がこの制限の発生源。将来的にGoogleの検証(verification)を受けて「本番公開」にしない限り、この「テストユーザー上限100人」問題からは逃れられない

### ベッカイ(別解)
- スコープを`drive.file`等の非センシティブな範囲に戻せれば、この制限自体を回避できる可能性がある。ただし2026-08-15の本番動作確認で`DriveApp.createFolder`が`drive.file`スコープでは動作しないことが判明済みであり、QR機能側への影響検証が別途必要になるため、今回はスコープ変更ではなく標準プロジェクト化+テストユーザー登録で対応する
- 将来的な検証・本番公開(誰でも使える状態にする)は、社内利用の範囲であれば必須ではない。現状の利用者(小柳さん・福田さん・嶺井さん)3名をテストユーザーに登録するだけで運用上は十分

### 結論(裁定)
- 採否: 採用
- 理由: 管理画面が実質使えていない現状を優先して解消する。不可逆性のリスクはあるが、Google公式ドキュメント上は既存動作への影響がないと明記されており、切り替えないと機能が使えないままという確実なデメリットの方が大きい。スタッフタブとテストユーザーの二重管理は、README・再発防止メモに明記して運用でカバーする
- 見直し期限: 2026-11-21(3ヶ月後。テストユーザー上限100人に近づく、または検証(verification)取得の要否を再検討するタイミングで見直す)
