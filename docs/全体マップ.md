# 全体マップ — どこに何があるか、この1枚から

最終更新: 2026-09-07 / 管理: 統括(アカリ) / 見直し期限: 2027-03-07

**使い方**: どのチャットセッションでも、過去の決定・文書・担当を探すときは
まずこのマップを見る。ここに載っていない場所に新しい文書を作ったら、
このマップにも1行足す(足りない1行が、次の「どこだっけ?」を生む)。

> 機密注意: このリポジトリ(hojo-hq)は**公開**。ここには公開して問題ない
> 情報の索引だけを載せる。GLOW機密(M&A戦略・営業数値・顧客情報)の索引は
> 非公開リポジトリ glow-docs-private 側に置く。

## 3. 本リポジトリの構成(フォルダの役割)

| フォルダ | 中身 |
|---|---|
| `docs/` | 事業文書すべて(下の§4で分類) |
| `site/` | 公開サイトのHTML等 |

## 4. docs/ の探し方(ファイル名の型で引く)

| 探したいもの | ファイル名の型 | 例 |
|---|---|---|
| 決定事項(議事) | `議事_YYYYMMDD_<件名>.md` | 議事_20260824_計測GA4切替.md |
| 他セッションとのやりとり | `連携メモ_YYYYMMDD_<件名>.md` | 連携メモ_20260903_山梨版への沖縄資産引き継ぎ.md |
| ルール・規程 | `<名前>規程*.md` ほか | 三名体制運営規程.md / note運用規程.md |
| 事業別の設計・原稿 | `<事業名>_<件名>.md` | もらいわすれ堂_* / フクギイロ_* / みらいひらけ堂_* / glow-ma_* / 勝てるくん_* |
| 台帳(継続更新するもの) | `*台帳*.md` / 決裁キュー.md | 失敗台帳.md / 引き継ぎ台帳.md / 決裁キュー.md / 小柳さん全タスク台帳_優先順位付き_2026-07-30.md |
| 再利用できる仕組み(部品) | `docs/部品庫.md` | コード部品・運用の型・販売時の手順を一覧化(2026-09-07新設) |
| 整理の手順書・依頼文 | `docs/整理実行キット_手順と依頼文.md` | Obsidian設定手順+各チャットへ貼るだけの依頼文A〜D+月1棚卸し(2026-09-07新設) |
| 過去の総点検 | `docs/archive/` | 2026-08-02-組織体制総点検.md |
| 保険関連リサーチ | `docs/insurance/` | 商品ラインナップ表_3社統合_v0.1_2026-08.md |

- 議事は必ず `docs/議事_YYYYMMDD_<件名>.md` 単体で置く。他文書への埋め込み禁止
  (2026-08-17の再発防止メモ)。
- 議事が必須なのは「小柳さん決裁事項」と「不可逆な変更」の2類型のみ
  (2026-08-17決裁。迷ったら書く)。

## 5. スキル・コマンド早見(状況に合った質を出すために)

**この事業専用のスキル**(該当作業では必ず使う):

| 状況 | 使うスキル |
|---|---|
| 制度データの締切・金額・要件を扱う | hojo-accuracy-check |
| 締切アラート・告知文面を作る | hojo-deadline-alert |
| 意思決定を伴う議論をまとめる | hojo-triangle-review(glow-maは glow-ma-triangle-review) |
| Lighthouse失敗・表示速度改善 | hojo-lighthouse-triage |
| 早期解約リスク(churn)系の作業 | churn-pii-guard / churn-model-quality-gate / churn-retention-ops |
| 会話が長くなりコンテキスト上限が近い | context-limit-handoff |
| KGI/KPIの設計・接続 | kgi-ksf-kpi-cascade |
| AI二重照合 | multi-ai-crosscheck |
| 新機能を分業で作る | feature-factory |

- 応答スタイルコマンド38個は `.claude/commands/README.md` に一覧。
  明示されなくても状況に合えば自発適用(CLAUDE.md)。
- スキルを参照するコメントを書いたら、実在確認を忘れない(再発防止メモ)。
