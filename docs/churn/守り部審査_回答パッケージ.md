## 項目別 回答

### ★1. 利用目的の適合（リクナビ事件の教訓）
- **コード側**: 該当なし（法的判断）。
- **人が判断**: 取得時の利用目的に「継続的な分析・保全のためのデータ蓄積」が含まれるか。
  範囲外なら**追加公表または同意取得**の要否。外部専門家（弁護士／個人情報保護士）レビュー対象。
- 論点のたたき台: 保全＝契約者への継続的なサポートは契約履行に資するが、**「予兆データを長期蓄積して
  モデル学習」**は利用目的の明示が要る可能性。→ 目的文言の確認を専門家へ。

### ★2. データ最小化との整合
- **コード側で担保**:
  - 分析は**顧客IDベース**。氏名は使わない（`schema.normalize_record`）。
  - 年齢は**年代にビン化**（`config.AGE_BANDS`）してから要因に使う。
  - リスク要因は `FACTOR_FIELDS` の範囲に限定（過剰な項目を持ち込まない）。
  - 出力（一覧・カルテ・コンソール）は `private/` 限定・公開リポに出さない。
- **人が判断**: 「消さずに残す」対象を**目的と期間で限定**できるか。保持する列の要否。

### ★3. 保持期限・削除
- **コード側**: 現状**未実装**（保持年数・削除は決めごと。決まれば実装する）。
  スナップショットは月次で `manifest.json`（行数・sha256）を残すため、**どの月を消すか**を
  後から特定・検証できる形にはなっている。
- **人が判断**: 保持年数／期限後の確実削除（バックアップ含む）の手順。
- 決定後の実装先: `hojo-churn_セットアップ手順.md` 7章（削除ジョブをべき等・監査ログ付きで追加）。

### 4. 口座“普段使い”フラグ
- **コード側で担保**:
  - フィールドは `account_daily`（普段使いか）と `debit_result`（初回引落結果）の**カテゴリ値のみ**。
    口座番号・残高などの**明細は一切持たない**（`schema.py` は該当列を保持しない）。
  - 予防トリガー（`triggers.py`）は「口座確認」の**要否判定**にしか使わない。
- **人が判断**:
  - 目的内であること・**要配慮個人情報でない**ことの確認。
  - 入力値を「はい／いいえ／未確認」に**限定する運用**（＝CRM入力側の制約）。コードは値を強制
    しないため、**入力ドメインの担保は運用ルールで**行う点を確認（必要ならcode側でバリデーション追加可）。

### 5. アクセス制御
- **環境側で担保**（`hojo-churn_セットアップ手順.md` 1・3・4章）:
  非公開リポ・最小メンバー・self-hosted runner の権限最小化・Secrets管理。
- **人が判断**: 閲覧/書出しの権限者リスト・多要素・共有範囲の妥当性。

### 6. 暗号化
- **環境側で担保**（手順3・4章）: runnerディスク暗号化・エクスポート/転送経路の暗号化。
- **人が判断**: 具体の暗号化方式・鍵管理が基準を満たすか。

### 7. 監査ログ
- **コード側で担保**:
  - `snapshot.py` … 取得ごとに `manifest.json`（snapshot_id・行数・sha256）。
  - `pipeline.py` … 実行ごとに `run_state_<日付>.json`（status・completed_steps・last_error・auc）。
  - hojo-churn では Git コミット履歴＋Actions実行履歴がそのまま実行ログになる。
- **人が判断**: 「誰が閲覧したか」のアクセスログ（環境側）と、監査の独立点検可否。

### 8. 保管場所・公開分離
- **コード＋環境側で担保**:
  - `.gitignore` に `private/`（実データ・モデル・HTML出力はコミット対象外）。
  - 公開リポにはコードと設計のみ。実データ処理は hojo-churn（非公開・社内・ネット非露出）。
  - `churn-daily.workflow.yml` は**公開リポの `.github/workflows/` に置かない**旨を明記。
- **人が判断**: 社内環境が「ネット非露出・統制」の基準を満たすか。

### 9. 委託・エクスポート経路
- **環境側で担保**（手順4章）: エクスポート経路と保管先を Secrets／統制環境内に限定。
- **人が判断**: 経路の安全性・保管先の**委託契約・安全管理措置**。
