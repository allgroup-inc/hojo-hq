# 早期解約 3%未満へ：強化フェーズ サマリ（3%へ効く順）

契約から6ヶ月以内の早期解約を **3%未満** にするため、保全システムに5つの強化を入れた
（すべて合成データ・TDD・小柳さん決裁事項の定数は据え置き）。ここでは「**3%へ効く順**」に
何がどれだけ寄与しうるかを1枚に整理する。

> 注意: 寄与度は**方向性の見立て**。実データが入るまで定量はできない。数値の証明は
> ①（因果）が担う。他は「打ち手を早く・正しく・当てる」ための土台。

## 効く順

### ① 効果を因果で測る（experiment.py）— 最上流・これが無いと3%を語れない
- 何をする: 保全対象を先行群/後発群に決定的割付（顧客IDのhash）。群間の早期解約率差を
  Wilson＋Newcombeで区間推定（uplift）。単純比較と並置し**結論は対照群**を使う。
- 3%へどう効く: 「本当に効いた一手」を証明できる。効く手に投資し効かない手を捨てる判断の土台。
  **これが無いと、他の施策が3%に寄与しているか判定できない。**
- 見方: `uplift.diff`（＝対照−介入・正が良い）と `diff_ci` の下限>0で有意に減少。母数不足は参考。

### ② 早期検知の鋭さ（triggers.py 初動）— 手前で止めるほど解約は減る
- 何をする: 契約後N日以内・未接触の継続契約を「初動要接触」に出す。既存の着金前・不着/遅延に追加。
- 3%へどう効く: オンボーディングの取りこぼしを拾い、**最も可逆な時点**で保全を打てる。
  今日の要接触に「初動」を優先度（不着>遅延>口座確認>初動>高リスク）で載せた。

### ③ 較正・精度@キャパ（evaluate.py）— 限られた30件/日を当てる
- 何をする: 予測%と実測%の一致（ECE）と、上位CAPACITY件の実解約率（precision@capacity）を算出。
- 3%へどう効く: キャパは有限。**当てる精度**が上がるほど同じ工数で防げる解約が増える。
  ECEが悪ければ「リスク%が信用できない」と警告（AUCが唯一の停止ゲート・較正は警告）。

### ④ コホート着地見込み（cohort.py）— 成熟を待たず手前で動く
- 何をする: 観測中コホートに「着地見込み率」（継続中の予測リスクからの推計）を確定値と別列で表示。
- 3%へどう効く: 6ヶ月の確定を待つと手遅れ。**今のコホートが何%で着地しそうか**を先読みして、
  悪化しそうな月に先回りで保全を寄せる。推計は参考・断定しない。

### ⑤ 理由ドリブンの打ち手（playbook.py）— 正しい一手を当てる
- 何をする: 解約理由をセグメント別に集計し、learning（効いた一手）と突き合わせて
  「この層には、この一手」を出す（例: 負担→減額提案）。
- 3%へどう効く: 打ち手の**質**を上げる。生存者バイアスが残るため参考位置づけで、
  確証は①の段階導入で取る。

## 閉ループ（どうつながるか）
```
④着地見込みで危ない層を先読み → ②初動＋予防トリガーで手前に接触先を出す
→ ③精度@キャパで限られた枠を高リスクに当てる → ⑤理由で正しい一手を選ぶ
→ 実行・結果記録 → ①因果で「効いた」を証明 → 効く手に寄せる（最初の一手へ戻る）
```

## 残る人手（3%運用の前提）
- 業務定数（AUC_MIN・CAPACITY・INITIAL_CONTACT_DAYS・EXPERIMENT_TREATED_FRACTION・
  CALIBRATION_ECE_WARN 等）の値確定＝小柳さん決裁（`業務定数_決裁ログ.md` の🟡）。
- 実データ実行は統制環境 hojo-churn・審査後（`本番投入チェックリスト.md`）。
- ①の段階導入は「後発群を長く放置しない」設計と両立させる（守り部・現場と調整）。
