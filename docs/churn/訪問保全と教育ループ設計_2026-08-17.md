# 訪問保全 × 対話ログ × 教育ループ 設計（2026-08-17 小柳さん発案）

「申込が入る → 過去解約者と照合し高リスクと分かったら、電話でなく**訪問保全（挨拶含む）**で
解約確率を下げる → その**対話内容をログに残し** → CRMが**教育・対応レベルを積み上げる**」
という一連の流れを、既存システムに乗せる設計。検知→行動→記録→学習→教育の閉ループを完成させる。

## 全体像（既存部品への接続）
```
申込データ → score/triggers（過去解約者から学習した高リスク検知・初動/未払消滅目前）
  → 【訪問エスカレーション】高リスク×守れる金額大 は「架電」でなく「訪問保全」に格上げ
  → 【対話ログ】訪問の会話（懸念・返し方・次アクション）を記録
  → transitions/experiment/effect_learning（どの対応が救えたか＝因果は段階導入で）
  → 【教育ナレッジ】効いた対応をトークスクリプト化 → 新人・全体の対応レベルが上がる
  → 次の申込へ
```

## 足す3つの部品

### A. 訪問エスカレーション（架電 → 訪問）
- **仕組み**: `triage`/`recommend_action` に「接触手段（架電／訪問）」を追加。
  高リスク帯 × 守れる金額 ≥ しきい値（または未払消滅目前）を **訪問**に格上げ。
  特に「新規申込 × 過去解約者と酷似（高リスク）」は**契約直後に訪問挨拶**（初動の訪問版）。
- **決裁事項（小柳さん）**: 訪問に回す守れる金額のしきい値・リスク帯・**1日の訪問キャパ**
  （架電30件とは別枠）。訪問は重コストなので絞る。
- **接続**: `score`（過去解約者から学習）・`triggers.initial_contact`/`unpaid_trigger` → `triage`。

### B. 対話ログ（訪問の会話内容）
- **仕組み**: `contact_log` を拡張し、接触手段（架電/訪問）・**対話内容（話した論点）**・
  顧客の懸念・返し方・次アクション・所要時間を記録。既存の 対応内容/結果区分/顧客反応 に上乗せ。
- **PII（churn-pii-guard）**: 対話ログは機微情報。**private限定・審査後**。顧客名は使わずID管理。
- **接続**: `effect_learning`/`experiment`/`transitions` の入力に。

### C. 教育・対応レベルの蓄積（ナレッジループ）
- **仕組み**: 対話ログ × 結果（救えた/失った）を突き合わせ、「**この懸念にはこの返し方が効いた**」を
  `playbook` の会話版として蓄積。効いた対応を**トークスクリプト／教育カード**に。新人はこれで学ぶ。
- **対応レベル**: 測るのは**対応（アプローチ）の効き**であって**個人の成績ではない**
  （営業別スコアの人事評価転用は禁止・churn-retention-ops）。共有知として積む。
- **接続**: `playbook.segment_playbook` を「対話タイプ × 効いた対応」に拡張。

## 注意点（率直に・守り部/決裁で詰める）
1. **資格業務の線引き（CLAUDE.md ルール3）**: 訪問は募集人（営業）の保全なら可。教育コンテンツが
   不適切な販売トーク・保険業法/募集規制に触れないか＝**守り部の事前確認**。申請代行はしない。
2. **PII**: 対話ログ＝機微。private・審査後・ID管理。Issue #142 の枠組みで扱う。
3. **効果測定のバイアス**: 訪問は高リスクに偏る（無作為でない）＝救えた率の単純比較は生存者バイアス。
   **因果は段階導入（experiment.uplift）**で。単純比較は参考。
4. **教育の目的**: 効いた対応の共有。**個人の評価表にしない**。
5. **コスト**: 訪問キャパは架電と別枠で小さい。守れる金額×リスクが高い人に絞る（決裁）。

## 実装スライス（優先順・各TDD＋三名体制記録）
1. **訪問エスカレーション**（`recommend_action`に接触手段。しきい値=決裁）— 最小・すぐ。
2. **対話ログ拡張**（`contact_log`に接触手段/対話内容/懸念/次アクション）＋効果を対話タイプ別に。
3. **教育ナレッジ**（効いた対応のトークスクリプト化＝`playbook`会話版）。

## 三名体制（この設計方針）
- **スイシン**: 検知→訪問→対話ログ→学習→教育で、チームの対応レベルが自己増殖的に上がる。
- **ウタガイ（反対）**: 訪問はコスト重で乱発すると回らない／対話ログは主観的で効果測定が難しい／
  教育を個人評価に転用すると現場が萎縮する／資格業務・保険業法の線に触れやすい。
- **ベッカイ**: 訪問は「守れる金額×リスク」上位に絞り段階導入で因果検証。対話ログは選択式の
  タグ（懸念カテゴリ・返し方カテゴリ）中心にして主観を減らす。教育は対応（型）の共有に限定。
- **裁定（提案・小柳さん決裁事項）**: スライス1（訪問エスカレーション）から着手。閾値・訪問キャパ・
  資格業務の線は守り部確認＋小柳さん決裁の後に本番へ。合成データで先に仕組みを作る。
