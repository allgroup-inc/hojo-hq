# クローズドループ設計 — 今日の30件 ＋ 結果記録

目標: 契約後6ヶ月以内の解約 <3%。
狙い: **今日やる高リスクN件を確実にカバーし、保全の結果を記録して「測る・学ぶ」を回す**。
3%は、当てるだけでは動かない。**接触→結果→効果測定→学習**のループが回って初めて数字が動く（改善レビュー §6-D）。

## 全体像
```
要接触の統合 → 今日のN件(キャパ) → 保全担当が実行 → 結果をワンクリック記録
   → 接触ログに蓄積 → 効果測定(正直に) → 学習(効いた一手を更新) → 明日の重み付けへ
```

## 1. 今日の要接触（統合トリアージ）
複数の“きっかけ”を1本に束ねて、キャパ内で回す。
- **入力（きっかけ）**:
  - ② 支払い挙動ウォッチ（不着・遅延・連続不着）
  - ② 初回引落“前”の口座確認（未確認/いいえ）
  - 守れる金額順ランキング（リスク%×年間保険料）
  - 放置検知（高リスク×直近接触なし）
- **重複排除**: 同一契約が複数のきっかけで挙がっても1件に束ねる（きっかけは併記）。
- **優先度**: 不着 ＞ 連続不着 ＞ 遅延 ＞ 口座未確認×引落前 ＞ 高リスク。各バケット内は**守れる金額順**。
- **キャパ上限**: 「今日のN件」（現場キャパ＝約30件/日）。
- **取りこぼさない（resilient: no silent cap）**: 上限を超えた分は**翌日へ繰り越し（aging）**し、**落とした件数・最高“守れる金額”を明示**。黙って消さない。

## 2. 結果記録（ワンクリック・最小項目）
接触したら、その場で結果を記録。**記録が無いとループは閉じない**（＝効果測定も学習も回らない）。
- **項目（最小化・churn-pii-guard）**: 日付 / 顧客ID / 担当 / 手段（架電・来店・メール）/ 結果区分（つながった・不在・再架電予定）/ 対応内容（口座確認・減額提案・再説明・給付案内 等）/ 顧客反応（継続・検討中・解約意向）/ 次アクション。
- **持たない**: 自由記述に不要な個人情報を書かない。氏名は使わず顧客IDで扱う。
- **保存**: `private/` の接触ログへ追記（**状態の外部保存**＝履歴が監査ログ）。既存の接触履歴と同じ器に載せる。

## 3. クローズドループ（測る・学ぶ）
- **効果測定（正直に・churn-retention-ops）**: 保全接触あり/なしで、初回引落成功率・6ヶ月継続率を比較。**段階導入（先行/後発）で因果**を測る。**解約後接触は数えない（免疫時間除外）**。母数不足は「参考」。0/100%を断定しない。
- **学習**: 「駆動要因 × 対応内容 → その後の継続率」を集計し、**効いた一手を “最初の一手” に還元**（例: 負担感→減額提案、乗換懸念→対面サポート）。少件数は「参考」。営業担当別は**教育・型改善目的**（人事評価に使わない）。

## 4. resilient-agent-design 4層
| 層 | 中身 |
|---|---|
| Trigger | 毎日1回、要接触の統合リストを生成 |
| Workflow | 各きっかけ抽出→重複排除→優先度＋守れる金額で並べ→N件に絞る→繰り越し記録→提示 |
| Agent | なし（決定的） |
| Guardrail | **顧客連絡は人が実行（承認）**・**結果記録は必須**・PIIはprivate限定・キャパ上限・読取専用 |

## 5. カバレッジ監査（漏れをなくす＝3%の要）
- 今日: 誰が接触され、誰が繰り越し/未接触か。**未接触の高“守れる金額”を可視化**。
- 週次: 要接触に上がったのに一度も接触されていない契約はないか（取りこぼし＝解約の温床）。

## 6. 規律・関門
- **顧客連絡は人の判断で実行**（システムは提示まで）。締切アラートとは別系統。
- 実データ・接触ログの本番運用は **守り部審査(#142)＋小柳さん決裁の後**、統制環境（非公開hojo-churn）で。
- 合成では数字に意味を持たせない。断定表示をしない。

## 7. 合成での型づくり（次段）
現行のダッシュボード生成器に「要接触の統合＋今日のN件＋繰り越し表示」と「結果記録スキーマ（追記先）」を
足せば、クローズドループの入口までを合成データで実演できる（実PIIは扱わない）。実装は次段。
