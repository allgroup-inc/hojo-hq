# 早期解約 <3% に向けた 全部門レビューと“仕掛け”提案

目標: **契約日から6ヶ月以内の解約を 3% 未満**にする。
本システムの役割: 電話連絡・直接保全・その他対応の**きっかけを常に見つける装置**。
本書は、これまで作ったもの(scripts/churn・ダッシュボード・スナップショット等)を
各部門の視点で「構造→結果」まで点検し、ブラッシュアップ点と新しい仕掛けを洗い出したもの。

## 0. 大前提(3%をどう捉えるか)
- 3%を動かす主役は「当てるモデル」ではなく **気づく→手を打つ→測る→学ぶ の運用ループ**。モデルは“どこから手を打つか”の順序付け役。
- 狙うべきは3点を仕組みで担保すること: **①漏れなく気づく ②早く正しい一手 ③確実に測って学ぶ**。
- **最初にベースライン測定が必須**。現状の早期解約率(コホート別)が未計測。これが無いと3%が遠いか近いか、どの駆動要因で漏れているかが分からない。**まず現状値を出すことがスタート地点**。

## 1. データ基盤部(取込・品質・格納)
**構造→結果の確認**: column_map一致 / 成熟度判定(未成熟を学習に混ぜない) / private隔離 / 未紐付の明示。
**ブラッシュアップ**:
- **未紐付(customer_id欠損)を減らす** ＝ 全契約を可視化。3%狙いは“漏れゼロ”が要。未紐付は保全の網から落ちる。
- **月次スナップショット運用**(承認済 `snapshot.py`)で履歴を積む → 支払い挙動・接触の蓄積が半年後に効く。
- **スキーマ検証を取込の完了条件**に(件数・必須列・型)。「取れたつもり」を排除。

## 2. 分析・モデル部(リスク率・精度)
**構造→結果の確認**: 成熟実績のみ学習 / backtest(AUC・上位リフト・較正) / 表示%クランプ。
**ブラッシュアップ**:
- 合成AUCは弱い(0.5台)＝仕組み確認用。**本番は実データのAUCで是非判断**(品質ゲート)。
- 現状は単一スナップショット・要因独立の素朴モデル。本番データが貯まれば **交互作用・タイミング予測(生存分析)・較正** を検討。
- ただし **早期解約の最強シグナルは“支払い挙動”**。これは学習を待たず**ルールで拾える**(下記6-A/B)。モデル改良より先に、ここを厚くするのが3%への近道。

## 3. 保全運用部(現場で回す) ★ 3%の主戦場
**構造→結果の確認**: 守れる金額順 / 初回引落アラート / 最初の一手 / 放置検知 / キャパ30件/日。
**ブラッシュアップ**:
- **トリガーを“運用カレンダー”に接続**: 契約後3営業日(既存)/ 初回引落“前”/ 初回引落後“即”/ 2・3回目引落 / 応当月。節目ごとに、その契約を自動で「要接触」に上げる。
- **守れる金額 × キャパ**: 「今日やる30件」に、高額×高リスクが必ず入るトリアージ。取りこぼしを構造的に防ぐ。
- **最初の一手 → 具体トーク台本 ＋ ワンクリック結果記録**。記録がクローズドループ(効果測定・学習)の入口になる。

## 4. 監査 ＋ 守り部(独立・法務/PII)
**構造→結果の確認**: PIIガード / 営業スコア誤用防止 / 効果測定の正直さ / 守り部審査 #142 進行中。
**ブラッシュアップ**:
- 効果測定は **段階導入(先行/後発)で因果**を測る。免疫時間(解約後接触)を除外・母数不足は「参考」。
- 営業担当別は**教育・型改善限定**(人事評価に使わない)。
- 実データ・新項目・顧客接触は **守り部審査＋小柳さん決裁の関門**。合成では数字に意味を持たせない。

## 5. 統括(QCM/アカリ・KGI)
**ブラッシュアップ**:
- **“早期解約率<3%”のライブ・トラッカー(コホート別)を主KPI**に。月次コホートで「6ヶ月内解約」が何%かを追う。
- **漏れ分析**: どの駆動要因/担当/チャネル/地域で取りこぼしたか。次の一手の重み付けに還元。
- 定型運転(L3/L4)も止めない: 週次で無作為3件を三名体制で再点検、月末に前提破壊レビュー。

## 6. 新しい“仕掛け”(3%達成の装置) — 優先順位つき
| 優先 | 仕掛け | 効き方 |
|---|---|---|
| ★A | **初回引落“前”の口座確認トリガー** | 不着を“起こる前に”潰す。口座“普段使い”未確認の契約を初回引落前に自動で要接触へ。早期失効の最大要因への先回り |
| ★B | **支払い挙動ウォッチ(2・3回目も)** | 初回だけでなく毎月の遅延/不着を拾う。継続中の失効予兆を早期発見 |
| ★C | **トリガー・カレンダー** | 契約後の各節目で、その契約を自動で「要接触」に。気づきの取りこぼしをなくす |
| ★D | **守れる金額×キャパの“今日の30件”＋結果記録** | 高価値を必ずカバー＋記録でクローズドループ(測る・学ぶ)を起動 |
| E | **早期解約率コホート・トラッカー** | 3%への距離を可視化・漏れ分析。ベースライン＝スタート地点 |
| F | **理由別プレイブックの学習** | 効いた一手を学び、最初の一手に還元(減額提案・対面サポート等) |
| G | **未紐付ゼロ運動** | 全契約を可視化＝網から落ちる契約をなくす |
| H | **オンボーディングSLA検知** | 「契約後3営業日に接触」未実施を検知(放置検知の前段) |

## 7. 正直な注意(3%を語るときの規律)
- **<3%はモデルの精度目標ではなく“運用の成果目標”**。まずベースライン測定。モデルAUCが良くても、手を打たなければ数字は動かない。
- 効果を過大評価しない(免疫時間・母数不足で断定しない)。表示%は100/0を出さない。
- 新データ・顧客接触は守り部・決裁の関門を通す。実データ本番は非公開hojo-churn(統制環境)で審査後。

## 8. おすすめの最初の3手(3%へ最短)
1. **早期解約率コホート・トラッカー(E)** … 現状値=スタート地点を作る(これが無いと成否が測れない)。
2. **初回引落“前”確認トリガー＋支払い挙動ウォッチ(A+B)** … 最有効の“予防”。早期失効の最大要因を起こる前に潰す。
3. **守れる金額×キャパの今日の30件＋結果記録(D)** … クローズドループの起点。測って学ぶが回り始める。

> いずれも設計・合成データ検証はこのリポジトリで進められる。実データ投入は守り部審査(#142)＋小柳さん決裁の後。
