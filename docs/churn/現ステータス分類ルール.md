# 現ステータス分類ルール（徳元さん回答 2026-08-17 確定）

早期解約を測る・保全対象を選ぶための、**現ステータス18種の分類**と**解約日/開始日の定義**。
徳元さんのインライン回答に基づく確定版。判断を要する箇所は三名体制で記録し、小柳さん決裁事項として明示。

## 確定した定義
- **契約開始日 = 契約日**（保険料が発生する起点。保障開始は「受注日」だが、早期解約＝保険料・未収の事象
  なので契約日を起点に「6ヶ月以内」を数える）。
- **解約日 = 初回保険料着金日**。ただし**現ステータスが「成立済」の場合は無視**（着金日であって解約ではない）。
  ＝ 解約日専用列が無いため、徳元さんが解約者の解約日を初回保険料着金日欄に入れている運用。
- **クレジットカード払いは初回決済失敗＝不成立**（保全対象外）。**Ⅳ列の未収は口座振替が前提**。
  → 初回引落失敗の保全は **払込経路＝口座振替** に限定する。

### 分母・分子の定義（提案）
- **母集団（denominator）** = 上表で「継続」＋「早期解約」＋（対象外のうち成立後のもの）を除いた…ではなく、
  **引受以降に進み、かつ保全で防ぎ得る離脱の対象**＝「継続」＋「早期解約」。
- **早期解約率 = 早期解約 ÷（継続＋早期解約）**。母集団外（未成立）と対象外（死亡・CO・告知解除）は**分母から除外**。
- **is_early_churn = 1**: 早期解約分類 かつ （解約日−契約日 ≤ 6ヶ月）。
- **継続（is_resolved・生存）**: 成立済 かつ 契約日から6ヶ月経過（成熟）。

## 三名体制の記録（この分類は判断を含む＝規程に従い記録）
- **スイシン**: 保全で「防げる早期離脱」を減らすのが目的。死亡・クーリングオフ・告知義務違反解除は
  保全で防げないので**分母から除外**し、防げる離脱（自発解約・失効・未払消滅・初回引落失敗）だけを3%の対象にする。
- **ウタガイ（反対）**:
  - 死亡・COを除外すると**分母が小さくなり率が上振れ**して見える恐れ。除外の事実を必ず注記すべき。
  - 「不成立【引受後未入金】」は**初回保険料着金日が空**のことがあり、解約日が取れない＝6ヶ月判定ができない。
    日付欠損の扱いを決めないと母集団から漏れる。
  - クーリングオフを「対象外」にすると、**申込直後の品質問題（誤案内等）が保全KPIから消える**。
    見えなくしてよいのか。
- **ベッカイ**: 「早期解約率（保全対象）」と「全離脱率（参考）」の**2本立て**にすれば、除外の是非を後で議論できる。
  不成立【引受後未入金】の日付欠損は「契約日＝初回引落予定月の翌月末を想定解約日にする」等の代替日で救う。
- **裁定（提案・小柳さん決裁事項）**:
  1. 3%目標の対象＝「防げる早期解約」（死亡・CO・告知解除は除外）。ただし**除外件数を必ず併記**（上振れの明示）。
  2. クーリングオフ・告知解除の扱いは〔要決裁〕。初期は対象外＋件数併記で開始し、実データを見て再議。
  3. 不成立【引受後未入金】の解約日欠損は代替日（想定引落日）で救う。実装時にログを残す。

## column_map への反映
- `cancel_date` = **初回保険料着金日**（※成立済のときは解約日として使わない＝取込時に現ステータスで条件分岐）。
- `debit_result` は直接の列でなく **現ステータス（不成立【引受後未入金】＝不着）＋Ⅳ列（月別未収）から導出**。
- 初回引落失敗の保全は **払込経路＝口座振替** に限定。

→ この分類でよければ、schema に「現ステータス→継続/早期解約/対象外/母集団外の判定」「解約日の条件分岐」
「払込経路フィルタ」を **TDDで実装**する（合成データ・実処理は統制環境）。
