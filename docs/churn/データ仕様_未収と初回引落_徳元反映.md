## これが効く理由（モデル・運用への含意）
1. **現ステータス「引受OK」= 初回引落失敗** は、早期失効の**単独で最強の前兆**。実データで最初に狩るべき対象。
   我々の「不着」トリガー（`triggers.py`）にそのまま一致する。
2. **Ⅳ列の過去未収履歴**は強力な予測特徴量。**「未収回数」を新しい要因（factor）に追加**する価値が高い
   （繰り返し未収の顧客は解約リスクが高い）。
3. **「済」「●」は既に保全接触の記録**。徳元さんは**すでに手作業で保全している**＝効果測定（`effect_learning`／
   `experiment`）の母数が初日から存在する。過去の「済で救えたか」を測れる。
4. **理由で打ち手が分かれる**（`playbook` 直結）:
   - **★（口座不備）** → 口座確認・再設定（我々の「口座確認」トリガー）
   - **残高不足** → 入金案内・減額提案・コンビニ用紙（●）

## column_map への反映（要点）
- `debit_result` は「初回引落結果」列そのものではなく **現ステータス**から導く（引受OK→不着／成立済→成功）。
- **未収理由・接触状況（済/●）・未収履歴**は Ⅳ列に**複合**して入っている → 取込時に分解が必要
  （理由=残高不足/口座不備、接触=済の有無、アクション=●の有無、履歴=過去月の未収数）。
- 顧客名は使わず**ID管理**（前提・門前で強制）。
