# 業務定数 決裁ログ（早期解約リスク保全システム）

このシステムの挙動を決める「業務定数」の一覧と、その**決裁状況**を記録する。
コードの `scripts/churn/config.py` が唯一の実装源（single source of truth）。この表は
「なぜその値なのか」「誰がいつ決めたか」を人間向けに残すもの。

## 大原則
- **業務定数は小柳さん決裁事項**。テストを通すため・数字を良く見せるために勝手に変えない。
- 実データでの本番運用に入る前に、下表の「決裁待ち」を**ゼロ**にする（＝全定数が決裁済）。
- 値を変えたら、この表の「最終決裁」欄と `config.py` のコメントを同時に更新する。
- すべての決定に見直し期限（最長6ヶ月）。期限切れは自動で再議論（CLAUDE.md 三名体制運営規程）。

## 一覧

| 定数 | 現値 | 意味 / 効くところ | 決裁状況 | 備考・論点 |
|---|---|---|---|---|
| `AUC_MIN` | **0.65** | 日次パイプラインの品質ゲート。バックテストAUCがこれ未満なら publishせず安全停止 | 🟡 **決裁待ち** | 「当たらないモデルで現場を動かさない」下限。低すぎると外れた一覧で現場を動かす／高すぎると毎日停止。初期の実データAUCを見て確定 |
| `CAPACITY_PER_DAY` | **30** | 「今日の要接触」の1日あたり対応キャパ（件）。超過分は繰り越し（黙って切り捨てない） | 🟡 **決裁待ち** | 徳元さん等の実処理能力に合わせる。少なすぎると繰り越し滞留／多すぎると空振り |
| `PRE_DEBIT_LEAD_DAYS` | **40** | 引落予定日がこの日数以内＝「引落前」とみなし口座確認の対象にする先読み幅 | 🟡 **決裁待ち** | ≒翌月の初回引落まで先読み。短いと間に合わない／長いと早すぎて空振り |
| `FOLLOWUP_DAYS` | **14** | 高リスクでこの日数、接触が無ければ「要フォロー（放置）」とみなす | 🟡 **決裁待ち** | 放置検知の閾値。運用テンポに合わせる |
| `MIN_RELIABLE_N` | **20** | この母数未満は「参考値」と注記（断定しない） | 🟢 決裁済（既定） | 正確性最優先ルール由来。少件数で断定しないためのガード |
| `SMOOTHING_K` | **30** | 学習のスムージング強度。大きいほど少件数を全体平均へ強く引き寄せる | 🟢 決裁済（既定） | 過学習・偶然の偏りを抑える。実データ量が増えたら再調整候補 |
| `BAND_HIGH_MULT` | **2.0** | ベース解約率の何倍以上を「高リスク帯」とするか | 🟡 **決裁待ち** | 帯分けの境目。現場の動きやすさで調整 |
| `BAND_LOW_MULT` | **1.0** | ベース解約率の何倍未満を「低リスク帯」とするか | 🟡 **決裁待ち** | 同上 |
| `HIGH_CUTOFF_CEILING` | **0.9** | ベース率が高くても高リスク帯を取りこぼさない上限 | 🟢 決裁済（既定） | セーフティ。ベース率が高い母集団での帯圧縮を防ぐ |
| `EARLY_CHURN_MONTHS` | **6** | 「早期解約」の定義＝契約から何ヶ月以内の解約か。コホート成熟判定もこれ基準 | 🟢 **決裁済** | 事業定義（契約日から半年以内の解約を3%未満）。動かさない |
| `AMOUNT_EDGES` | **3000 / 10000 / 30000** | 金額ビンの境界（円） | 🟡 **決裁待ち** | 商品特性に応じて調整可 |
| `AGE_BANDS` | 〜10代/20代/…/60代〜 | 年代ビン | 🟢 決裁済（既定） | 一般的な区切り |

凡例: 🟢 決裁済 ／ 🟡 決裁待ち（本番前に要確定）

## 本番前チェック（この表の使い方）
1. 🟡 の各定数について、小柳さんに現値と論点を提示し、値を確定する。
2. 確定したら「決裁状況」を 🟢、備考に「YYYY-MM-DD 小柳さん決裁」を追記。
3. `config.py` の該当コメントも「決裁事項（決裁待ち）」→「決裁済（YYYY-MM-DD）」に更新。
4. 🟡 が全て 🟢 になったことを、守り部審査（Issue #142）の完了条件チェックリストに含める。
