# 契約テーブル連携メモ ― 証券番号がキー（軸 契約テーブル設計v0.1を受けて・2026-08-19）

軸が `docs/契約テーブル設計_v0.1案.md`（kakei-crm）を用意。保険会社の月次解約データと自社申込を繋ぐ
表の設計。❹保全CRMとしての受け止めと対応。

## 軸の要点（4つ）と❹の対応
| 軸の要点 | ❹の対応 |
|---|---|
| **証券番号が唯一の鍵**（氏名は表記ゆれで繋がらない） | **`policy_number` を schema に第一級で追加**（`column_map` に `証券番号` をマップ）。当面の分析キーは顧客IDだが、解約データ結合は証券番号で行う設計に寄せる。 |
| **申込日と成立日は別列**（申込≠成立・分母が変わる） | いまは `apply_date`(契約日=保険料起点) 中心。**申込日・成立日を別列で持つ**必要 → column_map に `apply_date`(申込) と `settle_date`(成立) を分けて確認（現データの列名を徳元さんに要確認）。 |
| **取り込むたび"紐づかなかった件数"を必ず記録**（「解約が少ない」と「捕捉できていない」を取り違えない） | 既に `preflight.n_unlinked`・`excluded_summary` で未紐付/除外を件数化。**保険会社データ結合時の"証券番号で紐づかなかった件数"を同様に必ず出す**（結合ジョブ実装時に追加）。 |
| **13ヶ月継続率は13ヶ月経たないと出ない**。過去契約に証券番号を遡れるかで開始時期が1年変わる | だから**「申込時に証券番号を控える」を今日から**（下記）。過去分に証券番号を埋められれば、13ヶ月分析を前倒しできる。 |

## 今日から始めること（軸の"1つだけ"の依頼）
- **保全部(❹)に口頭で「申込のとき証券番号を控えて」**と伝える（Excel・メモで可）。
  → `徳元さんへ_保全のはじめかた.md` に追記済み。控えていない期間は後から遡れないため**今日から**。

## ❹側でこれから合わせること（v1.0で確定）
1. `policy_number` を結合キーに（実装済＝読み取り。結合ジョブは保険会社月次データが来てから）。
2. **申込日／成立日を別列**で取り込む（現Excelの列名を徳元さんに確認）。
3. 保険会社データ結合時に**証券番号で紐づかなかった件数を必ず出力**（捕捉漏れの可視化）。
4. 早期解約の判定を、現ステータス由来（proxy）から**保険会社の月次解約データ（正）へ寄せる**（証券番号で結合）。
   ※現状の現ステータス分類は当面の proxy として維持。

※実データ処理は統制環境・#142審査後。分析キー・語彙・IDは軸の共通仕様に合わせる（迷ったら軸へ確認）。
