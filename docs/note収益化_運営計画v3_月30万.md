## 2. ❸への回答 — 「世界の実例研究」シリーズの編集方針(体験を偽らない)

小柳さんの指示「経験値や成功事例は、世界中にある事実を深くリサーチして総合したものを軸にする」を、
**信頼を毀損しない形**で商品化する。ここが本計画の背骨。

1. **名乗り方**: 「私が稼いだ話」ではなく**「AIが世界の公表事例を深掘りした研究報告」**として正直に名乗る。
   note・Xに氾濫する「スクショ+自称実績」型と真逆の、**全事実に出典URLつき**が差別化になる
2. **体験として語ってよいのはミカタ自身の運営実録のみ**(AI社員17人・週15分運用など=単発①の路線)。
   他者の事例はすべて「公表情報のリサーチ」として媒体名+URLを本文に明記する
3. **成功確率の提供の仕方**: 「誰でも成功する」とは書かない(禁止語検査で機械的に排除)。
   代わりに「複数事例に共通する型」+「失敗事例からの教訓」+「沖縄・地方の中小企業の実務への翻訳」の3点セットで、
   読者の再現性を高める構成に統一する
4. リサーチの正本は docs/note多ジャンル_世界事例リサーチ集.md に置き、記事はそこから引く
   (リサーチ→お題化→記事化が分離されているので、誤りの訂正が一箇所で済む)

## 3. ❶❷の実装 — 多ジャンル単発記事の自動下書きパイプライン(新規)

```
毎月1日 09:00 JST 成功事例ウォッチRoutine(既存)が世界事例をリサーチ
        ↓ 人間(またはAIセッション)が「お題」として登録
data/tanpatsu_topics.json(お題キュー: ジャンル・切り口・出典URL付きファクト)
        ↓
毎月8日・22日 09:35 JST  tanpatsu-draft.yml が起動
        ↓
scripts/generate_tanpatsu_draft.py がキュー先頭のお題から
posts/note/tanpatsu/NN_slug.md を生成(X告知文3パターン同梱)
        ↓
LINEでたかしくん・小柳さんへ「下書きできました」通知
        ↓
人間が一読(出典2件抜き取り確認)→ noteに貼り付け→有料設定→公開(1本約10分)
```

### 機械検査(note運用規程3-3準拠。スクリプトから外さない)
- お題のファクトに**出典URLが1つでも欠けたら生成拒否**(正確性最優先)
- 禁止語(必ず/絶対/誰でも/楽して/確実に稼)検査。落ちたらリトライ1回→なお落ちたら**生成失敗として止める**(緩和で埋めない)
- お題キューが空なら**自動でお休み通知**(質を落として量産しない)
- 記事フッターに「AI下書き+人間確認」「成果を保証しない」を機械的に付す

### ジャンル(「経営に効く実例研究」の棚に限定)
| ジャンル | 例 | 出典の性質 |
|---|---|---|
| AI・自動化の経営活用 | 少人数×AI運営の実例研究 | 海外メディア・公式発表 |
| SNS×コンテンツ販売 | X/ニュースレターで顧客を育てた実例 | プラットフォーム公式・調査 |
| ニッチメディア経営 | 業界特化ニュースレターの経済圏 | 公表数字・インタビュー記事 |
| 補助金×経営(本業シナジー) | 制度活用の構造・データ研究 | 自社DB+公的統計 |
| 地方×デジタル | 地方中小のDX実例 | 行政・公的機関の公表事例 |

**やらないジャンル(機械検査+編集方針で排除)**: 「あなたも稼げる」系の収益保証・投資・ギャンブル・
根拠の示せない自己啓発。ミカタの本業(補助金情報の信頼)を毀損する棚は作らない。

## 4. X運用(集客側)— 自動生成×人間投稿の役割分担は維持

- 週刊・単発・白書の全生成物に**X告知文を自動同梱**(実装済み+本計画で単発にも拡張)
- ヒロメ設計(規程4)の「学びポスト月8本」は、単発記事の無料部分・リサーチ集から切り出して**下書きを自動供給**
- **自動投稿はしない**: X APIの無料枠は投稿数制限があり、自動投稿ボット化はスパム判定・凍結リスクがある。
  投稿はナナコさん(代行: たかしくん)が1日1本まで。リプライは全返信方針(規程4)
- 伸びなかった場合のレバー: 告知文のABテスト(パターンA/B/Cの反応をKPI台帳に記録)→勝ち型に寄せる

## 5. 三名体制の議事(スイシン/ウタガイ/ベッカイ)

### スイシン(推進)
- 供給は完全自動化済みで限界費用ほぼゼロ。単発在庫は「積むほど検索面が広がる」ストック資産であり、
  月2本×12ヶ月で在庫26本(既存2本含む)=v2比13倍の売り場になる
- 世界事例リサーチをお題キュー化する仕組みで「ネタ切れ」が構造的に消える。毎月1日の成功事例ウォッチRoutine(既存)がそのまま補充源になる
- 「全事実に出典URL」は、自称実績型が主流のnote市場で明確な差別化。B2B(士業・金融機関)への信用形成にも直結する

### ウタガイ(懐疑・反対理由の記録)← 空欄不可
1. **目標3倍の根拠が集客側にない。** 供給を3倍にしても集客は1ミリも増えない(v2ウタガイ①の再来)。
   フォロワー4,500・月5万PVはv2前提の約3倍で、X運用は依然ナナコさん・たかしくんの手作業。
   人間の投稿が止まれば、自動化された在庫は「誰も来ない店の棚」になる
2. **ブランド希釈・毀損リスク。** 「沖縄×補助金の正確なメディア」が「稼ぐ系に見える多ジャンル記事」を出すと、
   本業の信頼(=LINE1,000社・士業提携)を毀損しかねない。読者は棚の区別をしてくれない
3. **リサーチ記事の正確性事故の面が増える。** 海外事例は一次検証が難しく、古い数字・誤訳・文脈落ちの引用ミスが起きやすい。
   締切・金額のようにDB照合できないため、既存の検証部の仕組みが効かない
4. **模倣が容易で価格維持が難しい。** 出典つきリサーチはAIがあれば誰でも作れる。1,600円の価格が持つかは未検証
5. **本業KPIとの工数競合。** 公開コピペが月4回→6回、X投稿が週2→毎日になる。人間ToDoが増えるほど、
   KGI(LINE1,000社)側の実行が痩せる恐れ
6. **「月30万」という目標額自体に検証可能な先例がない。** リサーチの結論(§0)のとおり、ゼロからnote単体で
   月30万級に到達した検証可能な事例は見つからなかった。相場データ(転換3%・解約月4%)で逆算すると、
   フォロワー4,500人・月5万PVの集客が崩れた瞬間に本計画の数字は絵に描いた餅になる

### ベッカイ(別解・前提を疑う)
- 「多ジャンル=何でも書く」ではなく**「実例研究」という1つの編集方針の下の棚違い**と再定義する(§3のジャンル表)。
  これでウタガイ2のブランド希釈は「棚の増設」に変わる。稼ぐ系の煽りタイトルは禁止語検査+公開前チェックで排除
- ウタガイ1への別解: 30万をnote単独で狙う前提を疑う。**note×X×B2B×Kindleの合算**で設計し(§1)、
  集客依存度が最も低いB2B(人的販路・嶺井さん人脈)を8社に増やして下支えにする
- ウタガイ3への別解: 「出典URLを本文に明記」を逆手に取り、**読者が自分で原文を確認できる**ことを品質保証にする。
  公開前チェックに「出典2件抜き取りで開く」を追加(検証部の抜き取り照合の思想を流用)
- ウタガイ4への別解: 価格ではなく**「沖縄・地方の実務への翻訳」**を防壁にする。事例の羅列は模倣できるが、
  自社DB・自社運営実録と接続した翻訳は模倣できない
- 定型化の罠(三名体制ルール5)対策: 自動下書きも週次無作為抽出の再点検対象に含める
