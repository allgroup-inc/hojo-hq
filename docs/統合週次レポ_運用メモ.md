# 統合週次レポ 運用メモ — 月曜LINE配信への組み込み方(ループ1)

対象: `scripts/weekly_report_integrated.py`(統合週次レポート初号機)
設計元: docs/達成確率を上げる設計_仕組みの接続_2026-07-31.md §1(計器盤ループ)
方針: **既存の `.github/workflows/fukugiiro-weekly-report.yml` に後から追記する**。workflowファイル自体は本ブランチでは変更しない(マージ競合回避 — 決裁キュー「PR4本のマージ判断」が先)。

## 1. いま出来ていること(このブランチ)

| もの | パス |

| 生成スクリプト(純Python・標準ライブラリのみ・`--self-test`付き) | scripts/weekly_report_integrated.py |

手動実行:

```bash
python3 scripts/weekly_report_integrated.py               # 生成
```

## 2. workflow への追記案(マージ後に fukugiiro-weekly-report.yml へ適用)

既存の毎週月曜 09:00 JST(cron `0 0 * * 1`)のジョブに**3か所だけ**足す。別workflowを新設しない理由: 同一cron・同一コミット処理を二重に持つと push 競合と二重コミットの温床になるため、1ジョブに相乗りする。

```yaml
# (a) push トリガーの paths に追加(スクリプト更新時に試運転が走るように)
on:
  push:
    paths:
      - "scripts/weekly_report_fukugiiro.py"
      - "scripts/weekly_report_integrated.py"      # ← 追加
      - ".github/workflows/fukugiiro-weekly-report.yml"

# (b) 既存「週次レポート生成(統括ユイさん)」ステップの直後に追加
#     順序が重要: もらいわすれ堂レポを先に生成 → その latest.md を統合レポが転記する
      - name: 統合週次レポート 自己テスト+生成(ループ1・計器盤)
        run: |
          python scripts/weekly_report_integrated.py --self-test
          python scripts/weekly_report_integrated.py

# (c) 既存「Commit report」ステップの git add に追加
          git add reports/fukugiiro reports/integrated   # ← reports/integrated を追加
```

補足:
- `--self-test` を生成の直前に必ず実行する(方程式4: evalなき自動化は必ず事故る)。自己テスト失敗時はジョブが落ち、壊れたレポートはコミットされない
- data/personal/stock_status.json はworkflowでは**書き換えない**(件数更新は人間かレビュー付きPRのみ)。金額系キーが混入した場合、スクリプトが読込を拒否してその節をスキップする(壊れたまま配信されない)

## 3. 月曜LINE配信(Power Automate)側の追記案

現行の月曜配信は「週次レポ自動生成+毎週月曜8:00 LINE配信」(棚卸し表)の型 — Power Automate が GitHub の raw URL から latest.md を取得して整形・配信する。統合レポの追加は**取得URLを1本足すだけ**:

1. 既存フロー(もらいわすれ堂 latest.md 取得)を複製、URL を
   `https://raw.githubusercontent.com/allgroup-inc/hojo-hq/main/reports/integrated/latest.md` に変更
2. 配信文はレポート全文を貼らず、**先頭の要約になる3点だけ**抜く(LINEは長文が読まれない):
   - §1 Grp信号のうち 🔴/⚠ の行
   - §3 決裁キュー(未チェック件数+最古の滞留日数)
   - §2 は合計契約件数が先週から動いたときのみ1行
3. 配信時刻は既存と同じ月曜 8:00 JST。workflow(09:00 JST生成)より**前**なので、配信されるのは「前週生成分」になる点に注意。ズレを無くすなら (a) workflow cron を `0 22 * * 0`(月曜07:00 JST)へ前倒しするか、(b) Power Automate 側を 10:00 に遅らせる。**推奨は (a)**(人間の朝の習慣を変えない)— これも上記マージ後の追記に含めてよい
4. 宛先は小柳さん(+たかしくん)の運用トーク。**顧客向けLINE公式アカウントには流さない**(内部計器盤であり、CV単一ルールの顧客導線とは無関係のまま保つ)

## 4. 運用ルール(週次)

- 件数が動いたら: data/personal/stock_status.json の `contracts` を更新(金額・顧客名は書かない)。ゲート合格(手売り3件等)で `gate` を「実線・検証済み」へ、撤退なら商品行ごと削除
- 決裁キューの並び順ルール(上から最速順)は統合レポの「最古項目」判定にも使われる — 日付が無い項目は先頭が最古扱いになるため、**起票時に日付(YYYY-MM-DD)を1つ入れる**と滞留日数が正しく出る
- エンライフ(board整合)・GLOW(接触消化率)は現状「確認先案内」のみ。台帳/監査結果がリポジトリに落ち始めたら自動集計へ昇格させる(ループ1の次の接続。ループ3の閾値上申と同時に設計)
