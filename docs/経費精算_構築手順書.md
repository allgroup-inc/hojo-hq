## この手順書の使い方(先に読んでください)

**一度に全部作らない構成にしてあります。** 4つの段に分かれていて、**どの段で止めても、そこまでの分は無駄になりません**。

| 段 | やること | 時間 | 費用 | ここで止めても残る価値 |
|---|---|---|---|---|
| **第0段** | AIが領収書を読めるか確かめる | 30分 | 無料 | 以降にお金を使うべきか判断できる |
| **第1段** | 一覧(箱)を作る | 1時間 | 無料 | 紙の回付が消え、精算が1画面に集まる |
| **第2段** | メール受付を自動にする(AIなし) | 2時間 | 無料 | 撮って送るだけで一覧に載る。金額は本人が入力 |
| **第3段** | AI読取を足す | 2時間 | 月額数千円 | 金額の入力も不要になる |

**順番を守ってください。** 特に第0段を飛ばして第3段の月額を払うと、読み取り精度が足りなかったときに払い損になります。

各段の終わりに「ここまでで動くこと」を書いてあります。そこが確認できてから次へ進んでください。

# 第0段: AIが領収書を読めるか確かめる(30分・無料)

**なぜ最初にやるのか**: 第3段で月額を払う価値があるかは、実際に読めるかどうかで決まります。日本の領収書は感熱紙のかすれ・手書き・レイアウトがばらばらで、読めるかは試すまで分かりません。これはお金も設定も要らずに確かめられます。

### やること

1. **領収書を20〜30枚集めて写真を撮る**
   - 手元にある実物で構いません。きれいなものだけでなく、**かすれた・手書き・しわのあるものも混ぜてください**(そこが本番で効きます)
   - 影にならない場所で、真上から

2. **読み取り精度を測る** — どちらか楽な方で

   **方法A(おすすめ・準備不要)**: 撮った写真をこのチャットに送ってください。こちらで1枚ずつ読み取り、`decide_status()` の判定にかけて成功率を出します。

   **方法B(ご自身で回す場合)**: パソコンで下記を実行します。`ANTHROPIC_API_KEY` の設定が必要です。
   ```bash
   python3 scripts/keihi_accuracy.py --images ~/受領した領収書のフォルダ --out ~/結果.json
   ```
   ※ 領収書と結果は個人情報です。**このリポジトリの中を指定するとスクリプトが止まります**(そういう作りにしてあります)

3. **結果を見る**

| 読取成功率 | 判断 |
|---|---|
| **80%以上** | 第3段まで進む価値あり。第1段へ |
| **60〜79%** | 第2段(AIなし)まで作り、AIは保留。撮影のコツを配れば上がる可能性あり |
| **60%未満** | AIは見送り。第1段・第2段だけで十分な効果が出る |

### ✅ ここまでで得られるもの
数字にもとづいて「月額を払う価値があるか」を判断できる状態。**まだ1円も使っていません。**

# 第1段: 一覧(箱)を作る(1時間・無料)

**ここで何が変わるか**: 自動化はまだありませんが、**紙を回覧して集める作業が消えます**。全員の精算が1つの画面に集まり、領収書の写真も一緒に残ります。

Microsoft 365 にサインインして、ブラウザで作業します。

## 1-1. SharePointサイトを作る(10分)

1. `https://allgroupokinawa.sharepoint.com` を開く
2. 左上の「**+ サイトの作成**」→「**チームサイト**」
3. サイト名: `経費精算` / プライバシー設定: **プライベート**(メンバーのみアクセス)
4. メンバーに経理担当を追加

## 1-2. 領収書を入れる場所を作る(5分)

1. 作ったサイトの左メニュー →「**ドキュメント**」
2. 「**+ 新規**」→「**フォルダー**」で `領収書原本` を作る
3. 右上の歯車 →「**ライブラリの設定**」→「**バージョン設定**」→ バージョン履歴を**有効のまま**にする
   - ⚠️ これは電子帳簿保存法で求められる「訂正・削除の履歴」になります。**無効にしないでください**

## 1-3. 一覧(リスト)を作る(30分)

1. 左メニュー →「**+ 新規**」→「**リスト**」→「**空白のリスト**」
2. 名前: `経費精算`
3. 下の表のとおり列を追加します(「+ 列の追加」から)

| 表示名 | 種類 | 設定 |
|---|---|---|
| 支払先 | 1行テキスト | ※既定の「タイトル」列の名前を変更でも可 |
| 申請者 | ユーザーまたはグループ | |
| 利用日 | 日付と時刻 | 時刻は表示しない |
| 金額(税込) | 通貨 | ¥ |
| 10%対象 | 通貨 | ¥ |
| 8%対象 | 通貨 | ¥ |
| 登録番号 | 1行テキスト | インボイス番号。空欄=免税事業者 |
| 目的 | 選択肢 | 移動 / 打合せ / 会食 / 備品 / その他 |
| 詳細 | 複数行テキスト | |
| どなたと | 複数行テキスト | 会食のときだけ使う |
| 領収書 | ハイパーリンク | |
| ステータス | 選択肢 | お預かり / 申請済み / 承認済み / 確定 / 要対応 / 差戻し |
| 読取確信度 | 数値 | 第3段で使う。今は空のままでよい |
| メールID | 1行テキスト | 第2段で使う。**非表示にしておく** |
| 受信日時 / 反映日時 / 申請日時 / 承認日時 / 確定日時 | 日付と時刻 | 試行の計測用。非表示でよい |

**「どなたと」を会食のときだけ出す設定**(交際費以外で余計な欄を見せないため):
リスト右上の歯車 →「リストの設定」→「フォーム」→「どなたと」列の条件式に貼り付け
```
=if([$Category]=='会食', 'true', 'false')
```

## 1-4. 自分の分だけ見えるようにする(5分)

⚠️ **ここは必ずやってください。** これをしないと、全員が他人の経費を見られます。

1. リスト右上の歯車 →「**リストの設定**」→「**詳細設定**」
2. 「アイテムレベルのアクセス許可」で:
   - 読み取りアクセス権: **ユーザーが作成したアイテムのみ**
   - 作成/編集アクセス権: **ユーザーが作成したアイテムのみ**
3. 経理担当と承認者は「サイトの所有者」に入れておけば全件見えます

## 1-5. 見やすくする(10分)

**3つのビュー(表示の切り替え)を作ります。**

1. **マイページ**(既定にする): フィルター「申請者 = [自分]」/ 並び順: 利用日の降順
   - 表示する列: 利用日・支払先・金額・目的・ステータス・領収書
2. **全件**(経理用): すべての列を表示
3. **要対応**(管理用): フィルター「ステータス = 要対応 または 差戻し」
   - ⚠️ **管理側が毎日見るのはこの1画面だけ**という設計です。ここが空なら何もしなくてよい日です

**ステータスに色を付ける**(ブランド配色): ステータス列の見出し →「列の設定」→「この列の書式設定」→「詳細モード」に貼り付け

**ここで一度止めて、数人で1〜2週間使ってみることを強くおすすめします。** 実際に使ってみて初めて分かる不便があります。

# 第2段: メール受付を自動にする(2時間・無料)

**ここで何が変わるか**: 社員は**写真を撮ってメールに添付して送るだけ**になります。一覧への行追加と原本保存が自動になります。金額はまだ本人が入力します(AIは第3段)。

## 2-1. 受付用のメールアドレスを作る(15分)

1. Microsoft 365 管理センター → 「チームとグループ」→「共有メールボックス」→「**共有メールボックスの追加**」
2. 名前: `経費精算受付` / アドレス: `keihi@...`
   - ⚠️ 現在の既定ドメインは `allgroupokinawa.onmicrosoft.com` です。社外にも見える名前にしたい場合は、先にカスタムドメイン(例: `@allgroup.co.jp`)を設定してください
3. メンバー: 小柳さん・経理担当
4. **自動応答は設定しない**(お礼メールはフローから送るため、二重に届いてしまいます)

## 2-2. フローを作る(1時間30分)

`https://make.powerautomate.com` を開きます。「**自動化したクラウドフロー**」→ 名前 `経費精算_受付`

> 💡 **所有者について**: 作ったあと「共有」から経理担当も所有者に追加してください。個人アカウント1つだけが所有者だと、その人が使えなくなった瞬間に止まります。

**手順(上から順に追加していきます)**

1. **トリガー**: 「**新しいメールが届いたとき(V3)**」
   - フォルダー: 受信トレイ / **共有メールボックスのアドレスを指定**
   - 添付ファイルあり: **はい** / 添付ファイルを含める: **はい**

2. **同じメールを二度処理しないようにする**
   - 「SharePoint - 複数の項目の取得」→ フィルター: `メールID eq '(トリガーのメッセージID)'`
   - 「条件」→ 取得結果が0件でなければ **何もせず終了**
   - ⚠️ これを入れないと、メールの再配送で同じ領収書が二重に登録されます

3. **添付ファイルごとに繰り返す**(Apply to each)
   - 画像(jpg/png)とPDF以外はスキップする条件を入れる

4. **原本を保存**: 「SharePoint - ファイルの作成」→ `領収書原本` フォルダーへ

5. **一覧に行を追加**: 「SharePoint - 項目の作成」
   - 申請者 = メールの送信者 / ステータス = `お預かり` / メールID = メッセージID / 受信日時・反映日時 = 現在時刻
   - 金額・支払先・利用日は**空のまま**(第2段では本人が入力します)

6. **お礼メールを返す**: 「メールの送信(V2)」— 共有メールボックスから送信
   - 文面は `docs/経費精算_文言集.md` の①をそのまま使う
   - ⚠️ **どんな場合でも必ず返します。** 無反応が一番不安にさせます

## 2-3. 動作を確かめる(15分)

- [ ] 自分の領収書を撮って `keihi@` に送る → 1〜2分で一覧に行が増え、お礼メールが届く
- [ ] **同じメールをもう一度転送する → 行が増えない**(二重登録の防止が効いているか)
- [ ] 添付なしのメールを送る → 何も起きない(エラー通知が飛んでこない)
- [ ] 他の社員のアカウントで開く → **自分の行しか見えない**
- [ ] スマホのブラウザで開いて、表示が崩れないか

### ✅ ここまでで動くこと
撮って送るだけで一覧に載り、原本も保存されます。本人は金額と目的を入力するだけ。**無料の範囲はここまでです。**

# 第3段: AI読取を足す(2時間・月額数千円)

⚠️ **第0段で読取成功率80%以上が確認できている場合のみ進めてください。**

**ここで何が変わるか**: 金額・日付・支払先の入力も不要になります。本人は目的を選ぶだけになります。

## 3-1. 前提の準備

- **Power Automate Premium ライセンス1本**(HTTPアクションを使うために必要)
- **Claude APIキー**(既にミカタで使用中のものと同じ発行元)
  - ⚠️ キーはフローの中に直接書かず、環境変数またはAzure Key Vaultから参照してください

## 3-2. フローに追加する(第2段の手順4と5の間に挟む)

**4.5 AIに読み取らせる**: 「**HTTP**」アクション
- POST `https://api.anthropic.com/v1/messages`
- ヘッダー: `x-api-key`(Key Vault参照)/ `anthropic-version: 2023-06-01`
- モデル: `claude-haiku-4-5-20251001`(1枚あたり数円。精度が足りなければ `claude-sonnet-5` に上げる)
- 本文に添える指示文は下記で表示して、**出てきた文章をそのまま貼ってください**
  ```bash
  python3 -c "import sys; sys.path.insert(0,'scripts'); import keihi_receipt; print(keihi_receipt.extraction_prompt())"
  ```
  ※ 手順書に書き写すと必ず古くなるので、正しい文面はコード側の1箇所だけに置いてあります
- **「設定」→「再試行ポリシー」→ 指数・回数3**(一時的な通信エラーのみ再試行)
  - 3回失敗したらステータス「要対応」にして次へ進む。**お礼メールは必ず送る**
  - 認証エラー(401/403)は再試行せず、管理者へすぐ通知

**5の変更(行を追加するとき)**: AIの読取結果で列を埋め、下記のとおりステータスを決めます。

| 条件 | ステータス |
|---|---|
| 確信度80以上 **かつ** 日付・支払先・金額が揃っていて形式も正しい | お預かり |
| それ以外 | **要対応**(理由を記録) |

形式が正しいかの判断基準(`scripts/keihi_receipt.py` の `decide_status()` と同じにしてください):
- 日付が `YYYY-MM-DD` 形式
- 金額が数値で0以上
- 登録番号が `T`+13桁(**記載なしは正常**=免税事業者)
- 10%対象+8%対象が金額を超えていない

**5.5 同じ領収書の二重申請を止める**: 「同じ申請者・同じ日付・同じ金額・同じ支払先」の行を検索し、見つかったら**両方を「要対応(重複の可能性)」**にして管理者へ通知します(二重精算を防ぐ内部統制)。

## 3-3. 動作を確かめる

第2段のチェックに加えて:
- [ ] きれいな領収書 → 2分以内に金額まで正しく入る
- [ ] **ピンボケの領収書 → 要対応に入る。ただし本人には通常どおりお礼が届く**(失敗を本人に見せない設計です)
- [ ] 同じ領収書を2通のメールで送る → 両方が「要対応(重複の可能性)」になり管理者に通知
- [ ] APIキーを一時的に無効にして送信 → 本人には通常のお礼、行は要対応、管理者に認証エラー通知

# 第4段(あとで): 承認と締めを自動にする

第3段まで動いて1か月試したあとに着手してください。

- **承認**: 「開始して承認を待機」→ 承認者は**申請者の上長1名**(2026-07-23 決裁)。承認=「承認済み」/ 拒否=「差戻し」+文言集④で本人へ通知
  - 💡 承認者は後から変えられるよう**変数にしておく**と、金額による2段階承認を足すときに条件を1つ足すだけで済みます
- **編集ロック**: 「確定日」が入った行は本人が編集できないようにする
- **定時フロー(週次・月曜8時)**
  - 要対応が48時間を超えていたら管理者へエスカレーション+本人へ文言集⑤で正直に状況連絡
  - **生存確認**: 直近7日の新規が0件なら「受信ゼロです。接続を確認してください」と管理者へ通知
    - ⚠️ これは接続が切れて**無言で止まる**のを防ぐためのものです。誤報が出てもよいので必ず入れてください
- **月末3営業日前**: まだ申請していない人にだけ文言集③のリマインド
- **月次**: 確定分を仕訳CSV(利用日・費目・金額・税区分・登録番号の有無)で経理へ

## 進めるときの原則(迷ったらここに戻る)

1. **社員の体験を止めない**: 裏で何が失敗しても、送った人には必ずお礼が返る
2. **失敗は管理側で引き取る**: 読み取れなかったことを本人に伝えて撮り直させない(最大1回まで)
3. **金額は必ず本人が目視確認**: AIの読み取りをそのまま申請させない
4. **紙はまだ捨てない**: 電子帳簿保存法の税理士確認が終わるまで、紙の原本は保管を続ける(docs/経費精算_電帳法規程ドラフト.md)

## 困ったときの連絡先

このチャットに状況を書いてください。手順書のとおりに動かない箇所は、手順書側を直します(次の人が同じところで詰まらないように)。
