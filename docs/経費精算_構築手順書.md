# 経費精算 構築手順書(Phase 1 MVP)

作成日: 2026-07-23 / 前提: docs/経費精算_試作設計.md v2 の決裁後、この手順書どおりに構築すれば MVP が完成する。

## STEP 1: 共有メールボックス(情シス依頼)

- Microsoft 365 管理センター → チーム/グループ → 共有メールボックス → 新規作成
- 名前: `経費精算受付` / アドレス: `keihi@<社内ドメイン>`
- メンバー: たかしくん・経理担当・フロー実行用アカウント
- 自動応答は**設定しない**(お礼返信はフローから送る。二重返信防止)

## STEP 2: SharePoint サイトとリスト

サイト: `経費精算`(チームサイト・組織内限定)

### 2-1. ドキュメントライブラリ「領収書原本」
- フォルダ構成: `YYYY/MM/`(フローが自動作成)
- ファイル名規則: `YYYYMMDD_送信者名_連番.jpg`(フローが命名)
- バージョン管理: 有効のまま(電帳法の訂正削除履歴として使う。無効化禁止)

### 2-2. リスト「経費精算」列定義

| 内部名 | 表示名 | 型 | 備考 |
|---|---|---|---|
| Title | 支払先 | 1行テキスト | Claude抽出 |
| Applicant | 申請者 | ユーザー | 送信者アドレスから解決 |
| UsedDate | 利用日 | 日付 | Claude抽出 |
| Amount | 金額(税込) | 通貨(¥) | Claude抽出・本人確認必須 |
| Tax10 / Tax8 | 10%対象 / 8%対象 | 通貨 | Claude抽出 |
| InvoiceNo | 登録番号 | 1行テキスト | T+13桁。空=免税事業者 |
| Category | 目的 | 選択 | 移動/打合せ/会食/備品/その他 |
| Detail | 詳細 | 複数行 | 本人補記(任意) |
| Companion | どなたと | 複数行 | 会食のみ必須(入力フォームの条件式で制御) |
| ReceiptLink | 領収書 | ハイパーリンク | 原本へのリンク |
| Status | ステータス | 選択 | お預かり/申請済み/承認済み/確定/要対応/差戻し |
| Confidence | 読取確信度 | 数値 | 0-100。80未満は要対応 |
| MailMessageId | メールID | 1行テキスト(非表示) | べき等性キー。同一IDは再処理しない |
| ReceivedAt / ListedAt / AppliedAt / ApprovedAt / FixedAt | 受信/反映/申請/承認/確定 日時 | 日付と時刻(非表示可) | 試行計測用(設計書§8)。フローが自動記入 |

- アイテムレベル権限: リスト設定 → 詳細設定 → 読取アクセス権「自分が作成したアイテム」・作成編集権「自分が作成したアイテム」(経理・承認者はサイト管理者権限で全件閲覧)
- フォーム制御: 「どなたと」欄は `=if([$Category]=='会食', 'true', 'false')` の条件式で会食のときだけ表示

### 2-3. ビュー
1. **マイページ**(既定): フィルター `申請者=[自分]`、並び=利用日降順。表示列: 利用日/支払先/金額/目的/ステータス/領収書
2. **全件**(経理用): 全列
3. **要対応**(管理者用・1画面運用の要): フィルター `ステータス=要対応 OR 差戻し OR (申請済み AND 更新から7日超)`

### 2-4. ビュー整形(ブランド準拠・カスタムアプリは作らない)
ステータス列の整形JSON(列の書式設定に貼り付け):

```json
{
  "$schema": "https://developer.microsoft.com/json-schemas/sp/v2/column-formatting.schema.json",
  "elmType": "div",
  "txtContent": "@currentField",
  "style": {
    "border-radius": "12px", "padding": "3px 12px", "text-align": "center",
    "font-family": "'Noto Sans JP', Meiryo, sans-serif", "font-weight": "600",
    "color": "=if(@currentField=='要対応'||@currentField=='差戻し','#FFFFFF','#FFFFFF')",
    "background-color": "=if(@currentField=='承認済み'||@currentField=='確定','#00335C', if(@currentField=='要対応'||@currentField=='差戻し','#F88800','#8FA5B8'))"
  }

```

- 承認済み/確定=ネイビー#00335C、要対応/差戻し=オレンジ#F88800、途中状態=薄ネイビー。金額列は右揃え・等幅(`"style": {"text-align":"right","font-variant-numeric":"tabular-nums"}`)

## STEP 3: Power Automate フロー(1本のみ)

名前: `経費精算_受付`(所有者はフロー実行用アカウント。個人アカウント所有禁止=退職・異動で止まるため)

1. **トリガー**: 「新しいメールが届いたとき(V3)」共有メールボックス keihi@ / 添付ファイルあり=はい
1.5 **べき等性チェック**: リストを MailMessageId で検索し、既存なら**何もせず終了**(再送・再配送で行を二重にしない)
2. **Apply to each**(添付ごと): 画像/PDF以外はスキップ
3. **原本保存**: 「SharePoint - ファイルの作成」→ 領収書原本/YYYY/MM/
4. **Claude API 呼び出し**: 「HTTP」アクション(プレミアム)。**リトライポリシー: 指数・回数3**(一時エラーのみ)。3回失敗→ステータス「要対応」で確定し次工程へ(お礼返信は必ず送る)。401/403(認証)は再試行せず管理者へ即通知
   - POST `https://api.anthropic.com/v1/messages`
   - ヘッダー: `x-api-key`(環境変数/Azure Key Vault参照。フロー定義に直書き禁止)・`anthropic-version: 2023-06-01`
   - モデル: `claude-haiku-4-5-20251001`(1枚数円。精度不足が実測されたら `claude-sonnet-5` に上げる)
   - プロンプト(image + text):
     ```
     この領収書画像から次をJSONのみerr無しで返す:
     {"date":"YYYY-MM-DD","vendor":"支払先名","total":数値,
      "tax10":数値,"tax8":数値,"invoice_no":"T+13桁 or null",
      "confidence":0-100の整数}
     読み取れない項目はnull。confidenceは全項目の確からしさ。
     手書き・かすれで不明瞭なら低く付ける。金額は推測しない。
     ```
5. **JSON解析** → **リストに行追加**: confidence≥80 → ステータス「お預かり」/ 80未満またはnull含む → 「要対応」。MailMessageId・受信/反映日時も記入
5.5 **重複領収書チェック**: 同一申請者×同一利用日×同一金額×同一支払先の既存行を検索。該当があれば**両方を「要対応(重複の可能性)」に変更**し管理者へ通知(二重精算の内部統制。設計書§7)
6. **お礼返信**: 「メールの送信(V2)」共有メールボックスから。文面は docs/経費精算_文言集.md の①(結果カード+マイページリンク)。**要対応でも同じお礼を返す**(失敗を本人に見せない)
7. **エラーハンドリング**: ステップ4-5の失敗時 → 「実行条件の構成」で失敗分岐 → リストに「要対応」行を作成+管理者へ通知。**社員への返信は必ず送る**

### 承認(Phase 1.5)
- 承認者設計(2026-07-23 小柳さん決裁): **申請者の上長1名**のシンプル型。金額閾値による2段階承認は試行1か月後に判断(フロー側は承認者を変数化しておき、閾値追加が条件分岐1つで済む形にする)
- 「開始して承認を待機」(承認の種類: 承認/拒否 - 最初に応答)→ 承認=ステータス「承認済み」/ 拒否=「差戻し」+文言集④で本人通知
- 承認済み・確定の行は Power Automate で編集ロック(列「確定日」記入後は本人編集不可の権限変更)

### 定時フロー(2本目・Phase 1.5)
- 週次月曜08:00: 要対応48時間超をチェック → 超過あれば管理者へエスカレーション+本人へ文言集⑤で正直に状況連絡
- 同フロー内: **生存確認** — 直近7日の新規行が0件なら管理者へ「受信ゼロ: フロー・接続の生存確認をしてください」通知(接続失効の無言停止対策。誤報でもよい、無言が最悪)
- 月末3営業日前: 未申請(お預かりのまま)の人にだけ文言集③のリマインド
- 月次: 確定分を仕訳CSV(利用日/費目/金額/税区分/登録番号有無)で経理へ

## STEP 4: 動作確認チェックリスト

- [ ] きれいな領収書 → 2分以内に一覧反映・お礼返信・金額一致
- [ ] ピンボケ領収書 → 要対応に入る・本人には通常のお礼が届く
- [ ] 添付なしメール → 何も起きない(エラー通知が管理者に来ない)
- [ ] 他人の行が見えない(アイテムレベル権限)
- [ ] 会食を選ぶと「どなたと」が現れ、それ以外では見えない
- [ ] 承認→本人に完了通知→行が編集ロック
- [ ] スマホのSharePointアプリ/ブラウザでマイページが崩れない
- [ ] 同一メールをもう一度送る → 行が増えない(べき等性)
- [ ] 同じ領収書を2通のメールで送る → 両方が「要対応(重複の可能性)」になり管理者に通知が来る
- [ ] APIキーを一時的に無効化して送信 → 本人には通常のお礼が届き、行は要対応・管理者に認証エラー通知
