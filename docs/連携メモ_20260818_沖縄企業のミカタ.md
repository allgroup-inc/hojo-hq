## 7. 他チームが知っておくべき制約・注意点

1. **hojo-hqは公開(PUBLIC)リポジトリ**。個人情報・営業数値・顧客接点情報を`docs/`に置かない。
   glow-ma関連の機密は **allgroup-inc/glow-docs-private** へ(2026-08-17 CLAUDE.md機密区分)
2. **並行セッションが多数ある**。コミット前に必ず `git pull --rebase origin main`。
   また `git add` を1ファイルにしても **commitはステージ全体を拾う**ため、他セッションの作業を
   巻き込まないよう `git status` を確認する(過去に180ファイル混入事故あり)
3. **監査・レビューは必ず`git fetch origin main`した最新版を対象に**(526コミット遅れたブランチで
   点検し前提が何度も覆った実例あり。CLAUDE.md技術構成に明記)
4. **GASは「新しいデプロイ」を作らない**。本番デプロイ(`AKfycbx6SYv…`)を選んで新バージョンを作る
5. **lin.eeの直貼り禁止**。SNS・紙・サイトすべて `/go/<チャネル>/` 経由(経路計測が壊れる)
6. **SNS実投稿は承認ゲート必須**(environment: sns-approval)。**LINE一斉配信は小柳さん承認のみ**で実行
7. **カモフラージュ設計**: ミカタの利用者に事業承継・M&Aのニーズを直接は聞かない。
   glow-ma側で「ミカタ経由の企業」を扱う際も、**本人が相談として自ら出してきた情報以外を
   前提にした接触はしない**(信頼設計の根幹)
8. **CV単一**(LINE登録のみ)。他CVの追加は小柳さん承認が必要
9. **正確性最優先**: 締切・金額・要件は原文URLと必ず照合。不明は「要確認」表示で断定しない。
   AI同士の一致は断定の十分条件ではない
10. `insurance-pdfs-local`ブランチ(他セッションの保険PDF)は**pushしない**
11. Chrome代行がブロックされるドメイン: manager.line.biz / script.google.com / docs.google.com /
    instagram.com 等。これらの管理画面操作は小柳さんの手作業になる
