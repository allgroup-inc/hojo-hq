## 🚨 重大懸念事項（本番稼働を絶対に避ける理由）

### A. 営業者個人情報の漏えい
**ファイル**: `enlife/scripts/chatgpt_analysis_enhancement.py` 行 48-51, 77-89  
**リスク度**: 🔴 **最高**  

**問題**:
```python
# 現在の実装
prompt = f"""
営業パーソン「{staff_name}」の個別改善プランを作成してください。

【本人のデータ】
- 成約率: {metrics.get('contract_rate', 0)*100:.1f}%
...
```

営業者の **実名** （前原 芳乃、奈須 章、下地 健太等 8名）がそのまま OpenAI のクラウド環境に送信される。

**影響**:
- 営業個人の成績データが外部クラウドで処理・ログされる
- OpenAI の データ保持ポリシーは30日削除だが、中間ログ・分析対象に残る可能性
- GDPR / 個人情報保護法に抵触する可能性

---

### B. 顧客情報の混在リスク
**ファイル**: `enlife/scripts/kachitalk_full_correlation_analysis.py` 行 128  
**リスク度**: 🔴 **最高**  

**問題**:
```python
'customer_name': row.get('顧客名') or row.get('customer_name', ''),
```

CSV読み込み時に顧客名が読み込まれており、分析オブジェクトに含まれている。ChatGPT送信時にこれが含まれていないか **確認が不十分**。

**確認が必要**:
- [ ] ChatGPT へ送信される `staff_summary` オブジェクトに顧客名が含まれていないか
- [ ] JSON出力ファイルにも顧客情報がないか
- [ ] 通話内容（transcript）が含まれていないか

---

### C. エラーハンドリングの不完全性
**ファイル**: `enlife/scripts/chatgpt_analysis_enhancement.py` 行 145-158  
**リスク度**: 🟠 **中～高**  

**問題**:
```python
except Exception as e:
    print(f"✗ ChatGPT連携エラー: {e}")
    return None
```

- リトライロジックなし → API一時エラーで即座に失敗
- レート制限(HTTP 429)への特別対応なし
- タイムアウト処理（30秒固定）が厳しすぎる可能性
- 部分的な送信成功と完全失敗を区別していない

**実運用での問題**:
- 月曜9時に自動実行してもAPI失敗で終了
- 人為的な再実行・確認が必要になる
- 再実行時に同じデータが二重送信される可能性

---

### D. 費用監視機能の欠如
**リスク度**: 🟠 **中**  

**問題**:
- OpenAI API呼び出し数の制限なし
- 月額費用の推定表示なし
- 異常な呼び出しパターン（1回の実行で過剰呼び出し等）の検出なし

**実運用での問題**:
- OpenAI API使用料が予期しない額に跳ね上がる可能性
- 追加料金の警告を受けるまで気づけない

---

### E. 二重実行・重複送信の防止なし
**ファイル**: `scripts/auto_kachitalk_analysis.sh` 全体  
**リスク度**: 🟠 **中**  

**問題**:
- 前回の実行時刻を記録・参照していない
- 同じCSVファイルで複数回実行された場合の判定なし
- スケジュール実行の履歴管理なし

**実運用での問題**:
- 月曜9時に自動実行 → エラーで失敗 → 手動で再実行 → 同じデータがChatGPTに二重送信される
- OpenAI API呼び出し数が2倍になる
- 分析結果が重複してサイトに登録される
