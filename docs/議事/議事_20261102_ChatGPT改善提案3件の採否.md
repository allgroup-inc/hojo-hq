# 議事 2026-11-02 — ChatGPT改善提案3件の採否(整理の仕組みの効率化)

参加: スイシン/ウタガイ/ベッカイ(トライアングル体制)・裁定=統括(アカリ) / 最終決裁=小柳さん(自動マージ可否のみ)

## なぜ(背景)

連携メモ(docs/連携メモ_20261102_ChatGPT連携_整理の仕組み効率化レビュー依頼.md)で、
これまで整理してきた仕組み(全体マップ・部品庫・Obsidian自動同期・koyanagi-compass・
月1棚卸し・WikiSkill)をChatGPTにレビューしてもらった。その改善提案3件の採否を決める。

## 前提: 事実確認の結果(1回目レビュー)

ChatGPTが指摘した3件の不整合を照合した結果、**すべて実在した**。

1. `docs/全体マップ.md`のヘッダー「最終更新: 2026-10-04」に対し、本文に2026-10-30の言及あり
   → **既にPR #556(未マージ)で2026-11-01へ修正済み**。マージ待ちで見えていただけ
2. `docs/部品庫.md`のヘッダー「最終更新: 2026-09-07」に対し、本文に2026-09-27の言及あり
   → **同じくPR #556で修正済み**
3. `docs/整理実行キット_手順と依頼文.md`の「宛先一覧」表で、C(月次)の貼り先が
   「❷❸❹・山梨版担当・家計側の5つ」のままだった。これは2026-09-21の自動送信化より前の
   古い記述の残骸で、すぐ上の「自動化の状況」表(❸以外は自動)と矛盾していた
   → **本議事と同じPRで修正**(どこにも反映されていなかった、唯一の新規発見)

1・2の原因は「**PR #416が2026-10-01の作成から1か月以上マージされず放置された**こと
(11/1に#556へ作り直して統合した)」の副作用であり、3は純粋な見落とし。ChatGPTの指摘は
いずれも的確だった。

## 論点: ChatGPTが提案した改善策(絞り込んだ3件)の採否

### スイシン(推進)
1. **PR承認待ちの滞留対策**: 経過日数を報告に含め、注意喚起する。mainと乖離した古いPRは
   取り込みを待たず作り直す(10月にPR #416→#556で実際に行った対応をルール化するだけ)
2. **事業登録台帳と月次Routineの差分検知**: 新しい事業・チャットが自動化の対象から
   漏れないよう機械的に照合する(❻が1か月漏れていた再発防止)
3. **記憶システム群(全体マップ・部品庫・WikiSkill)の鮮度・整合性チェック**: ヘッダーの
   日付と本文の矛盾を自動検出し、今回のような指摘を外部レビュー待ちにしない

いずれも、実際に今月起きた具体的な事故(PR放置・❻の漏れ・ヘッダー不整合)に対応しており、
机上の改善ではない。

### ウタガイ(懐疑) ※反対理由の記録
1. **PR滞留対策について**: 「経過日数を表示する」だけでは根本解決にならない。本当の問題は
   小柳さんの承認が追いつかないことで、通知や表示を増やしても読まれなければ意味がない。
   さらにChatGPT案にあった「競合がなければ機械的に最新化しておく」は、**レビュー対象を
   本人の知らないうちに書き換えることになり、「取り込んで」という一言承認の前提(見た内容が
   そのまま入る)を壊す**。これは安全側に倒すはずの仕組みを弱める方向の変更であり、
   小柳さんの決裁なしに実装してはいけない
2. **事業登録台帳について**: 新しい台帳を1つ作ると、それ自体が「もう1つの正本候補」になる。
   全体マップ・CLAUDE.mdのチャット一覧とズレるリスクを生み、**ChatGPT自身が指摘していた
   「知識の重複」と同じ構造の問題を、この提案自体が新たに作り出しかねない**。また台帳を
   作っても、記入を徹底する運用が無ければ同じ漏れが再発する
3. **鮮度・整合性の自動検査について**: 日本語の自由文書から「本文中の最新日付」を正規表現で
   機械的に抽出するのは誤検出が多い(過去の議事へのリンクの日付、見直し期限の未来日付を
   「最終更新」と誤認するおそれ)。**2026-09-25に正規表現の文字範囲ミスで検査が全文書を
   不合格にした事故(再発防止メモ)が実際にあり、軽々に新しい自動検査を足すと同じ事故を
   繰り返しかねない**

### ベッカイ(別解)
1. **PR滞留対策の別解**: そもそも「全体マップ・部品庫への追記のみ」のPRに、毎回人間の承認を
   必須にする必要があるか。索引文書の追記は三名体制ルール8の「可逆な技術作業・定型業務」に
   あたり、コード変更やCV変更とは性質が違う。「変更ファイルがdocs/全体マップ.mdと
   docs/部品庫.mdのみ・repo-scope検査合格」のときだけ自動マージを許す、という**対象を
   絞ったホワイトリスト方式**なら、承認待ちで腐ること自体を無くせる(**これは三名体制の
   ベッカイ案であり、ChatGPT自身の提案ではない**。ChatGPTは自動マージの即時導入には
   当初から慎重な立場だった)
2. **事業登録台帳の別解**: 新しい文書を増やさず、**既にある`docs/全体マップ.md`§1(チャット
   セッション一覧)の名前の一覧と、月次Routineの実際の宛先(`list_triggers`で確認できる
   持続セッション)を名前で突き合わせる**だけで十分。索引を"見る対象"から"検査対象"に
   使い方を広げる発想で、重複を増やさない。件数だけの比較は、1件の漏れと1件の余分
   (❺のような参照専用枠など)が相殺して見逃す恐れがあるため採らない
3. **鮮度・整合性チェックの別解**: 新しい検査スクリプトを作るのではなく、**月1棚卸しの
   チェックリストに「変更した文書のヘッダー最終更新日を、その日の日付に必ず更新する」
   という1行を加えるだけ**にする。これは今回のPR #416→#556の未マージ放置が主因であり、
   仕組みを足すより先に"マージを早める"方が効く

### 結論(統括アカリの裁定)

- **採否**: 3件とも**軽量版を採用**。重い自動化(ウタガイが懸念した部分)は見送る
  1. **PR滞留対策**: 「経過日数の報告」と「乖離時は作り直す」をRoutine手順に明記(採用)。
     「機械的な自動最新化(rebase)」は不採用(レビュー対象を無断で変える懸念を重く見た)。
     「docs限定の自動マージ」は**別議事として小柳さんへ上申**(運用ルールの変更にあたるため、
     本議事の裁定権限を超える)
  2. **事業登録台帳**: 新設は不採用(重複リスクを重く見た)。ベッカイ案(全体マップ§1と
     Routine宛先の**名前での**突合)を採用し、月1棚卸しの手順に追加
  3. **鮮度・整合性チェック**: 新しい自動検査スクリプトは不採用(過去の正規表現事故の
     再発防止を優先)。ベッカイ案(ヘッダー更新の徹底をチェックリスト化)を採用
- **ウタガイの懸念への対応**: 3件とも、ウタガイが挙げた「安全装置を弱める」「重複を増やす」
  「誤検出事故を繰り返す」のリスクを避ける形(軽量版・既存資産の活用・手順の明記)に倒した。
  重い自動化は実装しない
- **実施内容**: `docs/整理実行キット_手順と依頼文.md`§4に上記3つのチェック項目を追加し、
  §3の宛先一覧の古い記述(前提の③)も合わせて修正した(本議事と同じPR)
- **見直し期限**: 2027-05-02(6か月後。軽量版で十分だったか、PR #416→#556のような
  1か月規模の放置が再発していないかを見て再評価する)

## 追記(2026-11-02・ChatGPTの2回目レビューへの対応)

ChatGPTが1回目の裁定内容を独立レビューし、さらに4点を指摘した。実データで1件ずつ
確認した結果、すべて実在する問題だった(ChatGPTとの一致は断定の十分条件ではないという
社内方針どおり、鵜呑みにせず確認している)。

1. **月次送信先の表記ミス**: `docs/整理実行キット_手順と依頼文.md`の修正行で
   「❷❹」と誤記していた(正しくは「❶❷」)。`list_triggers`で実際のRoutine設定
   (4本の持続セッションの宛先=❶・❷・山梨・家計)を確認し訂正した。**自分で修正した
   はずの箇所に新しい誤記を作っていた**点は率直に認める。確認に使った内部識別子は
   公開リポジトリのため本議事には記載しない(2026-11-02 ChatGPTの指摘で判断。
   必要な照合記録は整理担当セッションの実行ログ側に残る)
2. **WikiSkillの正式形式との不一致**: 本議事に当初frontmatter・「## なぜ」見出しが
   無かった。`decision_memory.py --check`はexit 0で通ったが(フォントマターが無い議事は
   見出しからの推定読み取りにフォールバックするため)、直近(10月)の他セッションの議事は
   すべてfrontmatter付きで`docs/議事/`配下に作られており、本議事だけ旧形式(本店の
   hojo-triangle-reviewスキルのテンプレート)のままだった。本議事にfrontmatterを追加し、
   `docs/議事/`へ移動して揃える。**hojo-triangle-reviewスキルのテンプレート自体が
   WikiSkill導入後も更新されておらず、古いまま**という根本原因が残っている
   (スキル本体の更新はskill_validator等のパイプラインを通すべきであり、本議事の範囲外。
   決裁キューへ別途起票する)
3. **時系列の不正確な記述**: 上の「前提」節で「PR #556が1か月以上マージされず放置」と
   書いていたのは不正確だった(放置されたのはPR #416。#556は11/1作成で当時まだ1日)。
   本修正で「#416が1か月以上放置→11/1に#556へ作り直して統合」と書き分けた
4. **件数比較では登録漏れを検知しきれない**: ベッカイ案(事業登録台帳の別解)が
   「§1の行数とRoutine宛先数の突合」という件数ベースの表現だった。1件の漏れと1件の
   余分(❺のような参照専用枠)が相殺するリスクがあるため、**名前・IDでの突合**に改めた
   (本議事・整理実行キットとも修正済み)

また、私自身のユーザーへの口頭説明で「ChatGPTの提案のうち『自動マージ』案」と述べたのは
誤りで、正しくは本議事のベッカイ(三名体制側の別解)案である。ChatGPTは自動マージの
即時導入には慎重な立場を取っていた。上の「ベッカイ」節に訂正の注記を追加した。

**上記1・3・4は本議事ファイルの事実関係の訂正(採否・裁定は変更なし)。2は実装(形式の
是正)。この追記により決裁内容そのものが変わるものではないため、見直し期限は変更しない。**
