# 議事: 組版総仕上げ(PC行長・一覧の密度)2026-08-17

背景: 小柳さん指示「文字の列や段落の区切りを、スマホ/PCどちらでも美しく読みやすく」。
実機監査(390px/1280px・6ページ)で、①PCで本文段落が900px幅いっぱいに伸び全角50字超
(可読の目安35〜42字を超過)②準備シート一覧(176件)がモバイルでバッジ折れにより
縦約12,000pxの壁になっている、を確認。

## 論点: PCの本文行長を絞るか/一覧の密度をどう上げるか

### スイシン(推進)
- 行長は可読性の最重要因子。裸の段落(.wrap直下のp・p.note)にのみ max-width≒41em を
  掛ければ、モバイル(元々680px設計)と同じ読み味がPCでも再現される。fg-base.css 1箇所で
  全ジェネレーター配下に効く
- 一覧はリスト項目を flex 化し、バッジを縮小・折返し許容にすれば高さと視覚ノイズが減る

### ウタガイ(懐疑)  ← 空欄不可
- **反対理由1**: max-width を箱(.trust/.disclaimer/.card)の中まで掛けると、背景色の箱と
  文字幅がずれて左右非対称の不格好が生まれる。適用は「背景のない裸の段落」限定にすること
- **反対理由2**: 8/12の読み心地総点検はレイアウト系CSSの適用拡大でPerformance退行を
  起こした前科がある。今回の変更が max-width / flex のみ(文節分割系に非該当)であることを
  PRに明記し、なし崩しの適用拡大をしない
- **反対理由3**: 一覧の密度を上げすぎるとタップ目標が44px を切る。行の padding は
  タップ領域を守った上で詰めること

### ベッカイ(別解)
- 一覧の根本問題は176件を1ページに並べる情報設計で、組版でなく「市町村別・ライフ
  イベント別への振り分け」が本筋。ただし一覧ページはSEO受け皿として存置が決定済みで、
  振り分けリンクは既に上部にある。今回は組版の範囲(密度・バッジ)に留め、
  ページ分割は将来の別論点とする

### 結論(部門長の裁定)
- 採否: **採用**。①fg-base.css に PC(≥900px)での裸段落の行長上限(max-width:41em)を追加
  (箱の中は対象外=ウタガイ1)②準備シート一覧のリストを flex 化・バッジ縮小・
  タップ領域44px維持(ウタガイ3)③変更は max-width/flex/font-size のみで
  文節分割系CSSの適用拡大なし(ウタガイ2をPRに明記)④ページ分割は今回やらない(ベッカイ)
- 見直し期限: 2027-02-17(一覧のページ分割要否は件数250件超えたら再議論)
