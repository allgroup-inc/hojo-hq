# 議事: 事業分離の方針 第1弾(2026-10-29)

2026-10-29 小柳さん「推奨で進めてください」により、AI統合開発本部の推奨5点を採用。

## なぜ(背景)

AI統合開発本部の方針は「連携より先に分離」です。この方針に照らして hojo-hq を点検したところ、方針と食い違う点が7つ見つかりました(フクギイロ側の確認報告と、AI統合開発本部の独立した確認で一致)。そのうち、決裁が要る5点をここで決めます。

1. **計測の混在**: LINEへの中継ページ(`/go/`)24個がすべて、株式会社フクギイロの計測の箱(もらいわすれ堂、`G-TQMX3MPFSR`)に送っている。うち10個は株式会社GLOWのページ(`scripts/generate_go_pages.py`、`docs/議事_20260824_計測GA4切替.md` 42・55行目)
2. **憲法の共有規定**: CLAUDE.md が「資産(制度DB・パイプライン)は共有」「収集・検証・守り・SNS・デザイン・監査は既存部門が両事業を兼務」と定めている
3. **Obsidianの写し**: hojo-hq の文書が毎朝、非公開の保管庫へ全文で写されている(`docs/Obsidian連携ガイド.md`)
4. **山梨版の中継ページ**: 公開停止(2026-10-15)のあとも、`go/ymn-*` 6個が残してある(`scripts/stopped_sites.json` の keep、`scripts/deploy_moradou.py` の `GO_PREFIXES`)。残す理由は記録が見つからない
5. **決定事項への登録の時期**

## 前提

- 本リポジトリは公開。制度データベースはもともと公開情報
- 記憶(議事・失敗台帳)・鍵・計測の分離は、同じリポジトリの中では根本的に解決しにくい。専用リポジトリへの分離は、90日の計画で別に判断する
- 今回の決定は方針と記録まで。計測の切り替え・中継ページの削除は、それぞれ別のPRで行う

## 代替案

- 計測: a) 会社ごとに箱を分ける / b) 1つの箱のまま、経路で絞って読む / c) 何もしない
- 憲法: a) 共有規定を削除する / b) 共有してよいものを絞って書き直す / c) 何もしない
- Obsidian: a) 自動の写しを止める / b) 例外として続け、非公開リポジトリは写さない / c) 非公開リポジトリも写す
- 山梨版の中継ページ: a) 公開停止の範囲に含める / b) 残す

## 三名体制の議論

- **スイシン(推進)**: 計測は設定1か所が原因なので、直すのが安い。憲法は「共有してよいもの」を名指しする形に書き直せば、制度データベースの再利用を失わずに、記憶・鍵・計測の混在だけを止められる。Obsidianの写しは公開文書だけを写しており、決裁者が読むための片方向の写しなので、止めると判断の材料を失う。
- **ウタガイ(懐疑・反対理由。必須)**:
  1. 計測を分けると、ミカタの経路ごとの数が切り替え日で途切れる。週次レポの前週比が一時的に意味を失い、「急に減った」と誤解されるおそれがある
  2. もらいわすれ堂の「LINE登録の目安」が減る。正しくなるのだが、KGIの現在地を見る人には後退に見える
  3. 憲法を書き直しても、実際の記憶の読み込み(`scripts/memory_bootstrap.py`)は事業で絞っていない。文言だけ先に変えると「分かれている」と誤解される
  4. 山梨版の中継ページを消すと、外で配った紙やLINEのメニューにURLが載っていた場合、押した人が行き止まりになる。リポジトリの中には印刷物の記録が無いが、外にあるかは分からない
  5. Obsidianの写しを例外にすると、「自動同期は禁止」の方針に最初の穴が開く。次に例外を足すときの前例になる
- **ベッカイ(別解・前提を疑う)**: 計測を分けるより先に、リポジトリごと分ければ、計測・鍵・記憶がまとめて分かれる。ただし大がかりで、動いている作業を止める。第1弾は「設定で分けられるもの」に絞り、リポジトリの分離は90日の計画で判断するのが現実的。

## 裁定

1. **計測**: 案a(会社ごとに箱を分ける)を採用。GLOWの中継ページ10個はGLOWの箱(`G-TW6M6WFB9T`)へ、フクギイロの14個は今の箱に残す。**変更の前に影響を見積もる**: `docs/計測の会社別分離_提案_2026-10-29.md`。実装は提案の承認後に別PR。ウタガイ①②には、切り替え日を週次レポに明記すること、切り替え前にミカタ分の過去30日の件数を数えて水増しの大きさを記録すること、で答える
2. **憲法**: 案b(絞って書き直す)を採用。共有してよいのは「公開情報の制度データベース(読み取りのみ)と、承認済みの汎用の仕組み」に限る。記憶(議事・失敗台帳・作業記録)・鍵・計測・顧客との接点は事業ごとに分ける。部門の兼務は「役割の定義を共有する」ことに限り、記憶と鍵は共有しない。ウタガイ③には、CLAUDE.md の文言に「記憶の読み込みの事業別化は未実装」と明記することで答える
3. **Obsidian**: 案b(例外として続ける)を採用。条件は、写すのは公開リポジトリの文書だけ、片方向、非公開リポジトリは写さない、の3つ。ウタガイ⑤には、例外をこの1件に限り、追加には新しい議事を要する、と決めることで答える
4. **山梨版の中継ページ**: 案a(公開停止の範囲に含める)を採用。ただしウタガイ④のため、削除の前に1つだけ確認する: **外で配った紙・LINEのメニュー・Instagramのプロフィールに `go/ymn-` のURLが載っているか**(所有者に確認)。載っていなければ削除する。載っていれば、削除の代わりに「公開を停止しました」の案内ページへ置き換える。作業は Pages 側(`scripts/stopped_sites.json`)と moradou.jp 側(`scripts/deploy_moradou.py`)の両方が要るため、別PRで行う。公開しないまま更新だけ再開することは、全国展開の判断まで行わない
5. **登録の時期**: この議事をもって登録する(本ファイル)

## 見直し条件

- 計測の切り替えが終わった時(数字の途切れが説明できているか)
- 記憶の読み込みを事業で絞る仕組みができた時(憲法の「未実装」の注記を外す)
- リポジトリの分離を判断する時(90日の計画)
