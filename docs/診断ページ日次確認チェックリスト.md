# 診断ページ日次確認チェックリスト

## 目的
もらいわすれ堂の診断ページ（site/fukugiiro/shindan/）が常に利用可能な状態を維持するための **多層的な信頼性確保システム**の一部。

自動ワークフロー(`.github/workflows/daily-sync-branches.yml`)が1日2回(06:00 UTC / 12:00 UTC)実行され、ブランチの同期と生成ファイルの検証を行いますが、人による目視確認により さらなる信頼性を担保します。

背景：2026-10-30、ブランチが main から3コミット遅れ、診断ページが「データ読み込み失敗」エラーを表示。その後2週間で4件の外部からの指摘を受けました。

## 実施要件

- **実施日**: 平日（月〜金）毎日
- **実施者**: SNS部・LINE部より1名ずつの2名体制（土日祝は不実施）
- **実施時刻**: 営業開始時（朝9:00 JST）に1度、午後（14:00 JST）に1度
- **所要時間**: 約2分/1回
- **記録**: `docs/診断ページ日次確認記録_YYYYMM.md` に逐一記入

## 確認手順

### Step 1: 本番ページへのアクセス確認

```
https://moradou.jp/shindan/
```

または

```
https://allgroup-inc.github.io/moradou/shindan/
```

にアクセスし、次を確認：

- [ ] ページが読み込まれる（404や500エラーが出ない）
- [ ] 「3分で調べる」という見出しが表示される
- [ ] 診断フォームが表示される（入力欄が見える）
- [ ] エラーメッセージ「データの読み込みに失敗しました」が表示されていない

### Step 2: 診断機能の動作確認

次の最小限の入力で診断を実行：

- 業種: 「農業」を選択
- その他の項目: デフォルト状態のまま

[ ] 「診断する」ボタンをクリック
[ ] 結果ページに遷移する（loading状態が止まり、結果が表示される）
[ ] 「制度が見つかりました」という表示か、「対象制度がみつかりません」という表示のどちらかが出る
[ ] エラーメッセージが表示されない

### Step 3: GitHub上のブランチ状態確認

```bash
# terminal で実行
cd /path/to/hojo-hq
git fetch origin
git log --oneline -1  # 自ブランチの最新コミット
git log --oneline -1 origin/main  # main の最新コミット
```

[ ] 自ブランチの最新コミットと main のコミットが同じか、最大1コミット差
[ ] （差があれば、毎朝6時の同期ワークフローが次に走るまで待つ）

### Step 4: ワークフロー実行状態確認

https://github.com/allgroup-inc/hojo-hq/actions?query=workflow%3A"Daily+Sync+Feature+Branches+with+Main"

[ ] 最新の実行が「✅ Success」（緑）になっている
[ ] 前回実行から24時間以上経過していない
[ ] （失敗（❌ Failed）の場合は、直ちに Slack 通知が発火しており、同時に小柳さんへ報告）

## 記録方法

`docs/診断ページ日次確認記録_YYYYMM.md` に以下の形式で記入：

```markdown
## 2026-10-30 朝 (9:00 JST)
- 実施者: ナナコさん
- 本番ページ読込: ✅
- 診断動作: ✅ （農業で診断 → 5件の制度を表示）
- ブランチ状態: ✅ （main と同期済み）
- ワークフロー: ✅ （6時実行 Success）
- 判定: **正常**

## 2026-10-30 午後 (14:00 JST)
- 実施者: ツナグさん
- 本番ページ読込: ✅
- 診断動作: ✅ （飲食業で診断 → 対象制度なし）
- ブランチ状態: ✅
- ワークフロー: ✅
- 判定: **正常**
```

### 判定基準

- **正常**: Step 1〜4 がすべてチェック（✅）できた場合
- **注意**: Step 1 は OK だが Step 2〜4 のいずれかに不備がある場合 → 直ちに小柳さんへ報告
- **障害**: Step 1 でエラーが出た、またはページが開かない場合 → 直ちに Slack 通知 + 小柳さん・技術チームへ報告

## Slack通知が来た場合の対応

ワークフロー失敗の Slack 通知が届いたら：

1. 直ちに本番ページへアクセスし、実際にエラーが出ているか確認
2. GitHub Actions の失敗ログを確認
   - 生成ファイルが欠ける（site/fukugiiro/shindan/ など）
   - ブランチの sync 失敗（マージコンフリクト等）
3. ブランチが main から乖離していないか確認（`git log` で確認）
4. **チーム全体へ Slack で報告し、技術チームに修復を依頼**

## 見直し周期

本チェックリストの運用は 2026-12-30 時点で再評価。その時点で：

- ワークフロー失敗の頻度が 0 件 → チェックを月1回の抜き打ちに変更検討
- ワークフロー失敗が 1 件以上 → チェック継続、原因対策の議事を開く
