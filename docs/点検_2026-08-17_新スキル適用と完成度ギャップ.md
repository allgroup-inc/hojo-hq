# A. 目標達成確率への影響が大きい順(改善点)

## A-0 【最大】このプロジェクトがKGIにもKPIにも紐づいていない

**対象** → 本チャットの全成果物(後確認SMSシステム・UIプロトタイプ)
**使うべきスキル** → hojo-triangle-review(ベッカイ役)/ CLAUDE.md のKGI再確認
**何が不十分か** →

憲法のKGIは「沖縄経営者・企業のLINE登録 1,000社」、真のKPIは「出口への相談・面談転換 月10件以上」。
**後確認SMSシステムは、このどちらにも1件も寄与しません。**
しかも Q2-1(本体システムの正体)が未回答のため、**そもそもどの事業のものかすら特定できていない**状態で
設計・UI実装まで進みました。ミカタ/フクギイロ/GLOW/保険/催事のどれなのかが不明のまま3日分の成果物があります。

これは「悪い仕事」ではありません。業務効率化として筋は通っています。しかし
**憲法の判断順4番目「Grp完全達成 > 個人収益」に照らすと、KGIに寄与しない作業に工数を割いている**という
事実は記録に残すべきです。

**どう作り直すか** →
1. Q2-1の回答をもって、この案件を**どの事業のKPIに紐づけるか**を明記する(例: 保険=出口3の営業支援、催事=ログ解析の入口)
2. 紐づけ先が決まらないなら、**KGI直結の作業を優先する**判断を小柳さんに仰ぐ(決裁キューへ)
3. 紐づいた場合、削減できる工数(電話件数×分)を数字で置き、効果測定できる形にする

> ウタガイの言い分: 「業務が楽になる」は正しいが、**楽になった時間がLINE登録1,000社に向かう保証はない**。
> 削減した時間の行き先まで書いて初めて、この案件はKGIに接続される。

## A-1 スラッシュコマンド38個が1つも配備されていない(再実行しても入らない)

**対象** → `.claude/commands/`(不在)/ `scripts/update-skills.sh`
**使うべきスキル/コマンド** → 全38コマンド(/brief /critique /ghost /devil /scout 等)が使えない状態
**何が不十分か** →

`update-skills.sh` は `.claude/skills` **だけ**を同期しており、`.claude/commands` は同期対象外でした。
つまり「古いから再実行すれば入る」のではなく、**スクリプトの設計上、永遠に入らない**構造でした。
`/ghost`(humanizer)`/devil`(反対役)`/critique` が使えないことは、対外文面の質と意思決定の質に直結します。

**やったこと(本セッションで修正済み)** →
- `update-skills.sh` を拡張し、本店の `.claude/commands/` を全リポジトリへ配布する処理を追加
- 本店側に実体が無い場合は `!! MISSING at 本店` を出力(黙ってskipしない)

**残タスク(小柳さん or 別チャット)** → **38コマンドの実体を hojo-hq の `.claude/commands/` に置く**。
実体がどのリポジトリ・どのチャットで作られたかが分からないため、こちらでは復元できません。置けば全repoに自動配布されます。

# D. 組織編成の点検

## D-1 本チャットの体制: **体制化していない**

`.claude/agents/` には21体(統括アカリ・収集シュシュ・検証ケンショウ・守りマモリ・SNSヒロメ・LINEツナグ・
提携ムスブ・note ツヅル・監査タダス・ニドナシ機構3名ほか)が定義されていますが、
**本チャットは1人称で進めており、これらのエージェントに担当を分けていません。**

依頼文の指示に従い、この事実を記録として残します。規模的には妥当な判断でしたが、**D-2の問題を生みました。**

## D-2 三名体制は機能したが、**監査の目が独立していなかった**

| 観点 | 結果 |
|---|---|
| ウタガイの反対理由の記録 | ✅ 記録あり。後確認SMSの議事で6点(返信受信・本人性・法的有効性・未返信の山・PII・文字数制限)、再議で6点 |
| 全会一致の連続(視点の同化) | ✅ 検知なし。1回目は「保留・上申」、2回目は「条件付き採用」と結論が割れており、健全 |
| リポジトリ全体の議事 | ✅ 直近の議事にもウタガイ記録あり(20260731=10箇所、20260730=7箇所)。20260812は1箇所と薄い |
| **独立監査** | ❌ **機能していない** |

**問題の核心** → 三名体制は「議論の質」は守りましたが、**裁定したあと、その裁定が守られているかを見る役がいませんでした。**
スイシン/ウタガイ/ベッカイはいずれも議論の当事者で、部門長は裁定者。**裁定後の遵守を監視する役は3役の外**です。
憲法にはタダスさん(独立監査)とミハリさん(再発監視)がいるのに、**本チャットでは呼ばれませんでした。**
その結果がFK-003です。

**どう作り直すか(規模に見合う形)** → 21体を呼び出す運用は本チャットの規模に対して過剰です。代わりに**仕組みで担保**しました。

- CLAUDE.md 絶対ルール6 = 着手条件つき裁定は、条件充足の記録なしに実装へ進めない(**文章ではなくルール化**)
- 成果物側に仕掛品ヘッダ(**ファイルを開けば分かる**)
- 失敗台帳FK-003 = ニドナシ機構の既存フローに乗せた(**監視とクローズ判定は機構が持つ**)

resilient-agent-design の「守らせたいルールは、文章ではなく権限・コード・環境で守る」に沿い、
**人を増やすのではなく、次に同じ穴に落ちない置き場所を作る**方向で解決しています。
