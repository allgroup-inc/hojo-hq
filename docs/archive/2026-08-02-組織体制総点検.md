# 2026-08-02: 組織体制・やり切り計画 総点検

指示: 小柳さん「組織体制とやり切り計画を、改めて総点検してほしい」(9ステップ指定)
対象: 沖縄企業のミカタ(KGI: LINE登録1,000社/公開から12ヶ月)

## 1. 体制の見直し(トライアングル体制)

`hojo-triangle-review` スキルに準拠。事実確認は `.claude/agents/*.md`(全17ペルソナ)、
CLAUDE.md、`docs/引き継ぎ台帳.md`、`.github/workflows/`、`scripts/weekly_report*.py` を
実際に読んだ上での議事。

## 論点: 現行体制(統括+収集/検証/守り/SNS/LINE/提携の6部門+独立監査+ニドナシ機構)は、KGI(1,000社/12ヶ月)に対して十分か

### スイシン(推進)
- 収集→検証→守り→集客(SNS+提携)→転換(LINE)→監査という機能分解は網羅的。ムスブさん(既存基盤300+紹介200=500社)とヒロメさん(SNS300+検索200=500社)の担当目標は、CLAUDE.mdのチャネル別内訳表と完全に一致しており、目標分解に矛盾がない
- 士業紹介の法務線引き(`mamori.md`の資格業務区分、`musubu.md`の「紹介料規制に触れる設計は守り部の事前確認必須」)は既に明文化済みで、外部調査で確認した社会保険労務士法23条の2の規制実態とも整合する方向性
- 独立監査(タダスさん)+ニドナシ機構(記録・真因・監視の3人)という二重の外部チェック機構は、外部調査で見たAIG社の「知識・助言・批評」三層構造や、Gartnerが指摘する「均一なガバナンスはAIエージェント組織を失敗させる」への対策として機能しうる設計

### ウタガイ(懐疑) ← 必須
- **【重大】事業の「真のKPI」が組織のどこにも一元管理されていない。** `docs/引き継ぎ台帳.md` は「真のKPI: 面談・相談件数 月10件」と明記するが、この数字はCLAUDE.mdの公式KPI表になく、アカリさんの週次レポート自動化にも組み込まれていない。しかも `tsunagu.md`(LINE部)には独自に「相談転換(承継・融資・士業): 5件/月以上」という**別の数字**が存在し、社内文書間で真のKPIの値そのものが割れている
- **【重大】統括アカリさんの週次レポートが実装として存在しない。** `akari.md` は「累計登録数・チャネル別内訳・ファネル・GLOW接続数・ボトルネック」を週次で扱うと定義するが、実際に動いている `weekly-report.yml`/`weekly_report.py` はサイト訪問・LINE友だち数・IG/FBの表面的な数字をLINEに直送するだけで、**repoに残らない**。姉妹事業フクギイロ(ユイさん)は `reports/fukugiiro/*.md` に自動保存され次のセッションでも参照できるのに、企業のミカタ側は毎週消える。これは統括の職務遂行に必要なデータ基盤が欠けている状態
- **出口(士業紹介・GLOW接続・保険クロス)を「実行」する部門が組織図上に存在しない。** 提携部・LINE部は登録を増やすところまでで、登録後に実際へ橋渡しする運用フロー(誰が・いつ・どうやって)が一切文書化されていない。フクギイロ側には出口実行専任の「アキナイさん(法人部)」がいるのに、企業のミカタ側にはこの機能が誰の担当か不明
- 外部調査(Boston大学/BCG論文)が指摘する通り、「3役が割れたら上申」という現行のエスカレーション条件は主観的判断に依存しており、感覚的なエスカレーションは差し戻しを増やすが品質向上に繋がらないというリスクがある
- 現状、実際のLINE登録の累計数がこのレビュー時点でもリポジトリのどこにも記録されておらず、3ヶ月100社のマイルストーン(公開日から起算)に対して今どの位置にいるか、外部からは確認できない

### ベッカイ(別解)
- 出口実行部門の不在は、新部門を新設するのではなく、資産共有しているフクギイロ側「アキナイさん」の役割を両事業共通化する方が組織を複雑にせず筋が良いのではないか
- アカリさんとユイさんの週次レポートの実装レベル差は、意図的な設計差ではなく単に実装時期の差(フクギイロが後発で洗練された)である可能性が高い。だとすれば新しい仕組みを作るより「フクギイロの実装をそのまま横展開する」のが最短
- 「面談・相談」は最終的に人間(たかしくん・嶺井さん)の営業活動であり、無理に自動計測に乗せず人間の月次報告に委ねるという考え方もありうる。ただし「測らないものは改善できない」という原則に反するため、この別解は不採用とする

### 結論(裁定)
- **採否: 体制の骨格(8部門+独立監査+ニドナシ機構)は維持。ただし3点を必須の強化事項として採用する**
  1. アカリさんの週次レポートをフクギイロ方式に統一し、`reports/hojo-mikata/` へ自動保存する(**本日実装済み** — 下記3節参照)。「真のKPI(面談・相談件数)」と「GLOW接続数」を将来的な自動集計項目として明記する
  2. 出口実行(登録→士業紹介/GLOW接続/保険クロスのハンドオフ)の運用フローを文書化する。新部門は作らず、既存の提携部(ムスブさん)の業務範囲拡張として対応する(ベッカイの指摘を採用し新設は見送り)
  3. エスカレーション条件を数値化する(下記「2. ルールの明文化」参照)
- 理由: ウタガイの指摘はいずれも実際のドキュメント・コードの不整合として裏付けられており看過できない。一方、新部門の新設(ベッカイの一部提案)は組織を複雑化させるだけで、既存部門の業務範囲拡張で十分対応可能
- **見直し期限: 2026-11-02(3ヶ月マイルストーン100社の判定と同時に再点検)**

## 2. ルールの明文化

### 2-1. 真のKPIの一元化(2026-08-02 小柳さん決裁・確定)
- 事業の唯一の真のKPIは **「出口(士業送客・GLOW接続・保険クロス)への相談・面談転換 月10件以上」**(CLAUDE.mdに明文化済み)
- **合算方式で確定**: LINE部(`tsunagu.md`)5件/月+提携部(`musubu.md`)5件/月=事業全体で月10件。両ペルソナファイルに反映済み
- 週次報告項目にそれぞれ「相談転換件数」を追加済み(ムスブさんは新設、ツナグさんは既存項目のまま)。アカリさんの週次レポート(`reports/hojo-mikata/`)で両者を合算し、月10件の進捗として追跡する運用に移行する(T4の自動集計実装が前提。手動集計は当面アカリさんが週次で行う)

### 2-2. 週次レポートの標準化
- アカリさんの週次レポートは、フクギイロと同じ基準で `reports/hojo-mikata/<週>_weekly.md` + `latest.md` にコミットする(実装済み)
- 未接続・取得不可の項目は「未接続/取得不可」と明記し、静かに欠損させない(既存の `hikari-report-thresholds` 相当の慣例を踏襲)

### 2-3. エスカレーション条件(数値ルール化・主観判断からの脱却)
以下のいずれかに該当した場合、**部門長は自動的に**アカリさん経由で小柳さんへ上申する(「迷ったら」ではなく機械的トリガー):
- 週次登録ペースが目標(20社/週)を**2週連続**で下回った場合
- 3ヶ月マイルストーン(100社)を判定日時点で**20%以上**下回った場合
- 3役(スイシン/ウタガイ/ベッカイ)の意見が割れ、部門長が採否を確信できない場合(既存ルール)
- 監査(タダスさん)またはニドナシ機構が「重大」指摘を出した場合
- 士業・金融機関との提携条件が、守り部確認前に外部合意されそうになった場合(即時ブロック)

### 2-4. 承認フロー(自動化と人間承認の境界)
外部調査(automation boundary概念)を踏まえ、行動種別ごとに3段階を明文化する:
| 行動種別 | 区分 | 備考 |
|---|---|---|
| 制度データの収集・構造化・「要確認」フラグ付与 | 自動実行可 | 検証部の照合を経ることが条件 |
| 検証済みデータの公開・SNS投稿・LINE定型配信(週1まとめ等) | 自動実行可 | 誇大表現禁止等の既存ルール内 |
| ドキュメント整備・CI/レポート機能追加などのコミット・PR作成 | 計画範囲内なら実行可、影響大なら一言報告 | 本タスクの6節に準拠 |
| 新規収集ソースの追加 | 守り部の事前承認必須 | 既存ルール |
| 士業・商工会・金融機関との提携条件確定、報酬体系の決定 | 小柳さん決裁必須 | 既存ルール+社労士法等の法務リスクのため特に厳格 |
| 既存顧客データ(保険・催事名簿)の目的外利用 | 小柳さん決裁必須 | 既存ルール |
| LINE配信頻度の増加、CVの追加、掲載方針変更 | 小柳さん決裁必須 | 既存ルール(CLAUDE.md絶対ルール4) |
| 本番Secrets操作・外部への金銭を伴う合意・法的効力のある文書送付 | 小柳さん決裁必須(実行前承認) | 外部調査で確認した金融業界標準に準拠 |

### 2-5. 品質基準
- 検証部: 締切・金額の誤表示0件、検証済み率100%(既存)
- 監査: 月次でランダム10件抽出し原文突合、誤り率を報告(既存)
- **追加**: 監査ログ(3役議事・裁定根拠・ウタガイの反対理由)は改ざん耐性のある形で最低6ヶ月保持する(外部調査のガバナンス実務を踏まえ追加)

## 8. 深いリサーチ(一次情報ベース)

外部調査エージェント2名(並行実行)による調査結果の要旨。全文は担当者間の議事録として別途保存可能。

### 8-1. 同業・類似モデルの成功事例
- **補助金ポータル/士業ポータル**(GNE×Wiz、月間利用者約100万人): 企業向け完全無料+士業側課金の二面市場型。ミカタの出口①と同型で国内実証済み
- **税理士ドットコム**(東証プライム上場・弁護士ドットコム運営): 依頼企業は無料、専門家側が成功報酬(解約時返金保証つき)を負担する設計。適法性を上場企業が担保している実例
- **社労士紹介ビジネスの違法性**(社会保険労務士法23条の2): 非社労士が社労士から成果報酬型の紹介料を得る行為は規制対象。士業送客は「専門家側課金の成果報酬」または「広告掲載の定額料」に限定すべき
- **横浜市LINE公式アカウント**(友だち数47万人・人口比12%): 実用機能(通報等)が「使い続ける理由」となりブロック率を抑制。ミカタも締切アラートだけでなく継続利用価値の追加が有効
- **商工会議所×商工中金モデル**: 紹介料でなく相互送客・共催セミナー型が主流。規制リスクを最小化しながら提携部の施策と整合

### 8-2. AIマルチエージェント組織運営のベストプラクティス
- Anthropic自身の知見: 読み取り中心の並列調査は複数エージェント向き、書き込み・意思決定は単一責任者に権限集約すべき(Cognition社も同様の主張)。現行の「部門長が裁定者」という設計は、この原則と整合
