# 守り部審査チェックリスト — 実データ投入の関門

作成日: 2026-07-26 / 起案: Claude(churn-pii-guard 準拠)
審査者: 守り部 マモルさん(法務全般)＋ コジンさん(個人情報)＋ 監査 テキホウさん(適法性・独立)
決裁: 小柳さん / 対象: 早期解約リスク保全システム(`scripts/churn/`)への**本物の顧客個人情報の投入**

## 使い方
- これは**実データを1件でも投入する前**に全項目を確認する関門。**未確認・不可の項目が1つでも残る間は、実データを入れない**(合成データでの検証・デモは継続可)。
- 各項目に 可 / 不可 / 該当なし と、確認者・根拠を記録する。不可があれば対応策と期限を書き、再審査する。
- 迷う項目・重い判断は、必要に応じて外部の個人情報・保険実務の専門家に確認する。AI・エージェントは判定者にならない。

---

## A. 法的根拠・利用目的・同意(個人情報保護法)
- [ ] このデータ利用(早期解約リスクの予測・保全)が、**取得時の利用目的の範囲内**か。範囲外なら目的変更・通知/同意の要否を確認。
- [ ] 顧客の**プロファイリング**(リスク%の付与)について、利用目的として説明できるか。差別的・不利益な取り扱いにならないか(監督指針・テキホウさん)。
- [ ] 第三者提供に当たる連携(別システム・士業送客等)がある場合、同意・委託・共同利用の整理ができているか。

## B. 資格業務・保険業の線引き
- [ ] 本システムの用途が、保険募集・申請代行など**資格・業法に抵触**しないか(CLAUDE.md 絶対ルール3)。
- [ ] 営業マン別スコアが**人事評価・不当な取り扱い**に誤用されない運用になっているか(コウヘイさん/churn-retention-ops)。

## C. 公開と機密の分離(churn-pii-guard)
- [ ] 顧客データ処理を、公開リポジトリ/公開サイトと**物理的に分離**したか(別紙:分離アーキテクチャ案)。
- [ ] 保全システムのコードが公開リポジトリに残る場合でも、実データ・モデル・出力が公開配下(private以外)に出ない運用が担保されているか。
- [ ] 誤コミット検知(`private/` gitignore・レビュー・自動チェック)が効いているか。

## D. アクセス制御(最小権限)
- [ ] 顧客データ・カルテ・営業マン別スコアを**誰が閲覧・操作してよいか**が定義され、最小権限で付与されているか(カルテ共有範囲=決裁事項)。
- [ ] 認証(個人アカウント・多要素)があるか。共有アカウント・全開の共有ドライブになっていないか。

## E. 暗号化
- [ ] 保存時(ディスク・保管先)の暗号化があるか。
- [ ] 通信時(エクスポート・転送)の暗号化があるか。

## F. 保管・保持期限・削除
- [ ] 顧客データ・生成物(カルテ/一覧/モデル)の**保管場所**が定義され、ネット非露出か。
- [ ] **保持期限**と、期限後の**確実な削除**手順があるか。不要データを溜め込まない(最小化)。

## G. ログ・監査証跡
- [ ] 誰がいつ顧客データ・カルテにアクセス/生成したかの**ログ**が残るか。
- [ ] 監査(テキホウさん)が独立に点検できる証跡があるか。

## H. 委託先・連携先管理
- [ ] 別システム(入力・エクスポート元)・クラウド・保管先の**委託契約・SLA・安全管理措置**が確認できているか。
- [ ] 別システムからのエクスポート経路が安全か(手渡し・暗号化・アクセス制御)。

## I. データ最小化・匿名化
- [ ] 分析に**不要な個人情報を持ち込んでいない**か(氏名不使用・年代ビン化・ID運用=実装済み)。
- [ ] 出力(カルテ等)に必要以上の個人情報を載せていないか。

## J. インシデント対応
- [ ] 漏えい・誤公開が起きた場合の**初動手順・報告ルート・当局/本人への対応**が用意されているか。
- [ ] 誤って公開リポジトリにPIIをコミットした場合の緊急対応(取り消し・履歴削除・影響評価)が定義されているか。

## K. 端末・物理
- [ ] 実行端末が管理された社内端末か(私物・無管理端末で扱っていないか)。
- [ ] 端末の暗号化・画面ロック・持ち出し管理があるか。

---

## 総合判定
- [ ] A〜K すべて **可**(または該当なし)であることを、マモルさん・コジンさん・テキホウさんが確認した。
- [ ] 上記を踏まえ、**小柳さんが実データ投入を決裁**した。

**→ すべて満たすまで、本物の顧客個人情報は投入しない。** 合成データでの検証・デモ・モックアップは継続してよい。

> 見直し期限: 最長6ヶ月、または環境・法令・連携先に変更があった時点で再審査(三名体制運営規程に準拠)。
