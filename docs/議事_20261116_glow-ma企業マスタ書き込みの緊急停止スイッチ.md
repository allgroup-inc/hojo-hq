# 議事: glow-ma 企業マスタの書き込みの緊急停止スイッチ(2026-11-16)

CLAUDE.md 三名体制ルール8 の「小柳さん決裁が要る事項(体制=誰が再開できるか)」と「本番のルールの変更(書き込みを止める・再開する手順)」に当たるため、議事を残す。
小柳さんの承認は、コード調査・設計・合成データの試験・新しい Draft PR の作成まで(2026-11-16)。**マージ・本番反映・本番設定の変更は別の承認を待つ**ため status は `deferred`。

## なぜ(背景)

- 2026-11-16 の最終チェックで、「障害時に、本番データにも設定にも触れずに、人の判断で企業マスタの書き込みを止める方法が無い」ことが分かった。PR #612(書き込みの安全化)は、失敗したときに自分で止まるが、人が先回りして止める手段は持たない。
- それまでの代わりの案は「企業マスタの空いた行に、企業IDを空にしたままメモを1セル書く」だったが、台帳のセルを使う止め方は採らない(小柳さん指示)。
- 止めたいのは、たとえば次のとき: 企業マスタの件数や中身がおかしいと気づいた/バックアップから人が貼り戻している間/原因の分からない失敗が続いていて、次の朝の書き込みを待ちたくないとき。

## 前提

- 小柳さんの要件(2026-11-16): ①企業マスタへの書き込みを停止できる ②読み取り・バックアップは可能な限り継続 ③停止中は自動再試行・自動再開しない ④停止・再開の操作履歴を残す ⑤再開には代表者の明示承認が必要 ⑥停止状態を稼働状況に表示 ⑦本番データのセルを使った停止方法は採用しない。
- 企業マスタを一括で書き直す処理は、`writeCompanyRecords_`(`glow-ma/src/ImportRunner.gs`)を通る6つ(スコアの再計算・お断りの反映・インポート・事前選定・過去記録の取り込み・試験データの片付け)。11/11 の欠落(失敗台帳 FK-010)は、この一括の書き直しで起きた。
- このほかに、担当者の記録に伴って1社の数セルだけを書く処理が、3つのファイルに11か所ある(管理画面の記録・メモ、LINE の録音の確定・新しい会社の登録、発送のフォロー日)。
- この PR は #612 の上に積む(#612 の「止めた例外に付ける印」と「日次メンテナンスの手順の区分」を使う)。#612・#617 は変更しない。
- 本リポジトリは公開のため、議事・試験に実在の会社・人のアドレスを書かない。

## 代替案

- A(採用): 停止の状態をスクリプトプロパティに置き、台帳のメニューから止める・再開する。`writeCompanyRecords_` の最初で確かめる。
- B: 台帳に「設定」のセルを作り、そこに「停止」と書く。誰でも見える・直せるが、セルを使う止め方は採らない(要件⑦)。誤って消すと、黙って再開する。
- C: 日次メンテナンスのトリガーを消す。自己修復が6時間以内に戻すため止めたままにできず、バックアップまで止まる。取り込みは止まらない。
- D: PR #612 を取り消す。止まるのではなく、古い書き方(全部消してから書く)に戻るだけ。

## 三名体制の議論

- **スイシン(推進)**: 止める場所を1か所(一括の書き直しの入口)にすれば、6つの処理を確実に止められ、試験で機械的に確かめられる。止めるのは気づいた人がすぐできる(台帳を編集できる人なら誰でも・確認と理由つき)、再開は代表者だけ(台帳の持ち主のアカウント+「再開」の入力+承認の記録)にすれば、「急いで止める」と「慎重に戻す」を両立できる。停止中も、バックアップ・ダッシュボード・今日の連絡先・アラートは動くので、営業は止まらない。
- **ウタガイ(懐疑・反対理由。必須)**:
  - 止めたまま忘れると、お断り(連絡不要)の反映が止まり続ける。断った会社が、連絡先の一覧に戻る。一番避けたい事故を、安全のための仕組みが起こしうる。今日の連絡先は「7日以内に連絡した会社」を外すので数日は守られるが、1週間を超えると守りが切れる。
  - 「企業マスタへの書き込みを停止できる」という要件に対して、止まるのは一括の書き直しだけ。担当者の記録に伴う1社ずつの更新(11か所)は止まらない。「止めたのに企業マスタが変わった」と受け取られるおそれがある。
  - 止める操作を誰でもできるようにすると、誤操作や思い込みで止まる。止まった朝は、スコアもランクも古いまま営業が動く。
  - 再開を「台帳の持ち主のアカウント」に限ると、代表者が動けない日は再開できない。代理を置くなら、仕組みを変える必要がある。
  - 止める・再開するには、PC で台帳のメニューを開く必要がある。スマートフォンの台帳アプリにはメニューが出ない。外出先では止められない。
  - 操作の履歴を台帳の設定(スクリプトプロパティ)に置くと、残せるのは直近の十数件。古い分は、通知メールと実行記録(30日)にしか残らない。
  - 合成データの試験だけで、本番の Apps Script の画面(確認・入力欄)では動かしていない。
- **ベッカイ(別解・前提を疑う)**: 人が止めるスイッチより先に、「書き込みが途中で失敗したら、人が確かめるまで次の書き込みをしない」自動の歯止めのほうが、事故の型には合うのではないか。今回は人の判断で止める手段を先に作り、自動の歯止めは、止まりすぎ(一時的な失敗のたびに人の再開が要る)との兼ね合いを見て別に決める。また、止める手段を増やすより、毎日全社を書き直すこと自体をやめる(変わった行だけを書く)ほうが、止める必要そのものを減らす。

## 裁定

- 採否: 案Aを採用(設計・合成データの試験・Draft PR まで)。マージ・本番反映・本番での操作は、小柳さんの別の承認を待つ。
- 設計:
  1. **止まるもの**: 企業マスタを一括で書き直す6つの処理。`writeCompanyRecords_` の最初で停止を確かめ、停止中は企業マスタを読まず・書かずに止める。インポート・事前選定・フェーズA試験は、バックアップのタブや試験データを作る前に止める。過去記録の取り込みは試さず、貼られた行をそのまま残す。
  2. **続くもの**: 台帳のバックアップ、読むだけの処理(ダッシュボード・今日の連絡先・世界の架け橋の週次KPI・アラート)、担当者の記録に伴う1社ずつの更新。
  3. **止める**: 台帳のメニュー「GLOW台帳 → 企業マスタの書き込みを止める(緊急停止)」。台帳を編集できる人なら誰でも。確認(はい/いいえ)と理由の入力が要る。メニューを開けないときは、Apps Script エディタから止める関数を実行できる。
  4. **再開**: メニュー「企業マスタの書き込みを再開する(代表者のみ)」。台帳の持ち主のアカウントだけ。「再開」と入力し、承認の記録(誰がいつ何を確かめて承認したか)を書く。どれかが欠けたら停止のまま。持ち主以外が再開しようとしたことも履歴に残す。
  5. **自動では再開しない**: 期限なし。停止の記録を消すのは再開の操作の1か所だけ(試験で確かめる)。自己修復・反映(コードの入れ替え)では変わらない。
  6. **止まる側に倒す**: 停止の記録が壊れている・設定を読めないときは、停止中として扱う。
  7. **見えるようにする**: 稼働状況タブに「企業マスタの書き込み停止スイッチ: 停止中/稼働中」。日次メンテナンスの結果は「停止中」(失敗とはしない)。止めた・再開したときは、台帳の持ち主へお知らせ(担当者が止めても代表者に届く)。停止中は毎朝1通、停止からの日数つきでお知らせ。台帳を開くと右下に表示。
  8. **履歴**: 止めた・再開した・再開を断った記録(日時・操作した人・理由/承認の記録)を、直近12件まで台帳の設定に保持。メニュー「状態・履歴を見る」で確認できる。全件は、お知らせのメールと実行記録に残る。
- ウタガイの反映:
  - 止めたまま忘れる: 毎朝のお知らせに、停止からの日数と「お断りの反映も止まっている」ことを必ず書く。運用の決まりとして、**停止は原則7日以内**とし、超えそうなときは小柳さんへ上申する(今日の連絡先の守りが7日で切れるため)。
  - 1社ずつの更新は止まらない: この議事・PR・停止の確認画面に「止まるもの・続くもの」を明記する。1社ずつの更新まで止めるかは、営業の記録が止まる影響と合わせて、小柳さんが別に決める(今回の範囲外)。
  - 誤操作: 確認と理由を必須にし、止めたら必ず代表者へお知らせが届く。止めすぎの害(スコアが古い)は、止めないことの害(欠落)より小さいと判断する。
  - 代表者が動けない日・スマートフォン: 代理の再開者と、PC を開けないときの止め方は、運用の決めごととして未決。本番で使う前に小柳さんが決める。
  - 本番の画面で未確認: 本番反映の後、企業マスタを書かない時間帯に、止める→状態を見る→再開する、を1回通して確かめる(本番設定の変更に当たるため、承認の後)。
- ベッカイの反映: 「途中で失敗したら自動で停止に入る」歯止めと、変わった行だけを書く方式は、次の改善候補として残す。

## 見直し条件

- 見直し期限: 2027-05-11(失敗台帳 FK-010・PR #612 の議事に合わせる)。
- 停止が7日を超えた・止めたまま忘れた・誤って止めた、が1回でも起きたら、止められる人の範囲と毎朝のお知らせの出し方を再議論する。
- 1社ずつの更新で企業マスタが壊れる事故(または、その恐れ)が出たら、止める範囲を広げることを再議論する。
