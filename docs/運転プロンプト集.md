# 自分管理計画の運転プロンプト集(コピペ用・2026-08-07)

## ① 週次運転(毎週月曜・決裁バッチの直前に貼る)
```
週次運転をお願いします。docs/決裁キュー.md と docs/運用規程_やり切り実行計画_2026-08.md を正として:
1. git fetchで全ブランチ・PR・mainの最新を確認し、前週からの完了・新規を差分で報告
2. 決裁キューを実態に合わせて更新(完了消し込み・新規追加・順位見直し)し、私が「採用/不採用/保留+一言」で返すだけの決裁リストを提示
3. 統合週次レポ(reports/integrated/latest.md)と早期警報閾値を突合し、🔴があれば原因と一手を提示
4. data/personal/stock_status.json のゲート状態を確認し、手売りゲートの進捗(契約件数)と今週の「売る時間」の使い先を1つ推奨
5. 更新はコミット・プッシュまで実施
```

## ② 改善サイクル(月末・成果を上げたい時に貼る)
```
改善サイクルをお願いします。三名体制(hojo-triangle-review)で、ウタガイの反対理由を必ず記録して:
1. 今月の実績(ゲート判定・解約・失敗台帳_商談版・週次レポ)を読み、計画と実績の乖離が最大の1点を特定
2. その1点について、生の声(last30days/customer-research)で今の市場の声を再取得し、商品・価格・文面のどれを直すべきか三名体制で議論
3. 修正案を「私が採否だけ返せる形」で上申(修正はドラフト作成まで進めてよい)
4. 前提破壊レビュー: 全会一致が続いている領域・見直し期限切れの決定を洗い出して再議論に載せる
5. 成果物はコミット・プッシュし、docs/決裁キュー.md に決裁事項を追記
```

## ③ 新チャット立ち上げ(新しい作業を任せる時に最初に貼る)
```
このリポジトリの憲法と運用に従って作業してください:
- CLAUDE.md(絶対ルール・トーン)/ docs/運用規程_やり切り実行計画_2026-08.md(判断基準: 正確性>法務>CV単一>Grp達成>速度、出荷ゲート: accuracy-check→deadline-alert→humanizer)
- 意思決定は hojo-triangle-review(ウタガイ反対必須)、無人自動化は resilient-agent-design 準拠
- 私の決裁が要るものは docs/決裁キュー.md に1行追加(チャット内で完結させない)
- 完了したら状態ファイル/ドキュメントに記録を残す(「やったのに記録がない」を作らない)
その上で、次のタスクをお願いします: 【ここにタスク】
```

## 使い方のコツ
- ①は毎週同じ文面でよい(差分は機械が拾う)。②は月1回か、数字が動かない時に
- 返事は常に「採用/不採用/保留+一言」の3択でよい設計にしてある
- どのプロンプトも「更によくする提案があれば末尾に1つだけ付けて」と足すと、改善が毎回1個ずつ積み上がる
