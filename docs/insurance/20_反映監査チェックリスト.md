# 反映監査チェックリスト

> 反映(データ入力)の正確性を保つための手順。**断定しない・要確認で止める・原文=元セルで照合**。

## 前提:なぜ監査が必要か
`※反映のやり方`の運用は**手作業の値貼り付け**中心:
- 反映の〆= 毎日の稼働終わり〜翌日9時。
- 委託/QS/共同募集シートの個人簡易データを**値貼り付け**して保存。
- 共有の定例ALL委託で `【実数値】A3縦` を値貼り付け。
- `【チーム進捗】A3縦` の**経過日数だけは手打ち(値貼り付け厳禁)**。

→ 参照ズレ・貼り付け範囲ミス・手打ち漏れが**構造的に**起きやすい。

## 毎日の反映後チェック(人手・5分)
- [ ] **① 負値が無いか** — 実数値系(実稼働時間・発信数・件数・ANP・想定単価等)に負値が無いか。※現差異・進捗は負でも正常。
- [ ] **② 空欄が無いか** — 予算・実績の主要セルが空欄でないか。
- [ ] **③ 経過日数が正しいか** — 手打ちの経過日数(土曜祝祭日込み)が当日と一致するか。値貼り付けされていないか。
- [ ] **④ 月版のズレが無いか** — 前月版と当月版で指標の並び・列定義がズレていないか。

## スクリプトで機械チェック
```
python scripts/insurance/audit_reflection.py <board.xlsx> --out <非追跡ディレクトリ>/audit_<月>.md
```
- 出力先は**スクラッチパッド等の非追跡ディレクトリ**(生データ・実データレポートはコミットしない/設計書§5)。
- 出力「要確認リスト」の**各行=元セル**。必ず board を開いて原文を確認する。
- 検知種別: `negative`(実数値系の負値)/ `blank`(空欄)。ロールアップ照合は `check_rollup()`。

### 読み方の例(2026-07 board 実行結果)
- ★ALL委託【島袋管轄】の目標列(H列: H38/H44/H46/H48–H51)に負値 → **要確認**。値貼り付け時の参照ズレの疑い。
- QCM(徳元管轄)想定単価 I65 = −8.58 → **要確認**。
- ※いずれも断定せず、該当管轄へ原文確認を依頼する。

## エスカレーション
```
要確認を検知
  → 該当管轄の責任者へ原文確認を依頼
    → 直らない/原因不明 → 数値監査役(独立)へ
      → 方針判断が要る → 小柳さん(最終決裁)
```
断定的な指摘はしない。「この値は要確認です(元セル: ○○)」の形で伝える。
