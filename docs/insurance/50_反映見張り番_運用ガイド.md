# 反映 見張り番 運用ガイド(allgrp_watchdog)

毎日の **定例KPI(9部門)→【ALLGRPデータ】(マスター)** 反映を、間違い・破損しないよう**常時監視**し、必要なら**修正**する仕組み。

## なぜローカル実行か
監視対象はOneDrive上のExcel。クラウドのAI環境から直接は触れないため、**ファイルがある場所(OneDrive同期先のPC)でPython実行**する。既存の `weekly_pipeline.py` と同じ動かし方。

## 何をするか
1. `定例_収集` の9部門の定例を、**中身の管轄／ファイル名で自動同定**(定例_ALL委託 等)。
2. 各部門: **定例チーム合計 = マスター実績** を日付を揃えて突合。
   - ✅ 整合 / 🟡 一部要目視(1〜2ブロックだけ不一致=日付揃えの誤差の可能性・目視) / ⛔ 反映異常(全滅=別データ誤反映などの重大) / — 未検出
3. マスターの**負値・空欄**を部門別符号ルールで検知(QCMの意図的マイナス等は除外)。
4. 結果を**当日レポート**＋**history.csv**(推移)に記録。
5. `fix` 実行時のみ: **⛔反映異常**の部門を、**バックアップを取ってから**実績を定例KPIで反映修正(🟡は誤修正回避のため自動修正しない)。

## 準備(1回だけ)
1. PCに Python(既存の weekly_pipeline.py が動く環境でOK)と openpyxl。
2. `scripts/insurance/` 一式(rollup_check.py / audit_reflection.py / audit_all.py / reflect_teikei_to_board.py / allgrp_watchdog.py)を同じフォルダに置く。
3. 設定ファイル `watchdog_config.json` を作る(パスは各自の環境に):
```json
{
  "kpi_dir":  "C:\\Users\\xxx\\OneDrive\\...\\定例_収集",
  "master":   "C:\\Users\\xxx\\OneDrive\\...\\定例_集計\\【ALLGRPデータ】.xlsx",
  "work_dir": "C:\\Users\\xxx\\OneDrive\\...\\監視ログ"
}
```

## 使い方
```
python allgrp_watchdog.py check --config watchdog_config.json   # 監視のみ(既定)
python allgrp_watchdog.py fix   --config watchdog_config.json   # バックアップ後に反映異常を修正
```
- 出力: `work_dir/reports/watchdog_YYYY-MM-DD_HHMM.md`、`work_dir/history.csv`、(fix時)`work_dir/backups/`。
- 終了コード: 重大異常(⛔・負値)があれば 1、無ければ 0(スケジューラでの検知に使える)。

## 毎朝の自動実行(Windows タスクスケジューラ)
1. タスクスケジューラ →「基本タスクの作成」→ 毎日 **9:05**(反映直後)。
2. 操作: プログラム=`python`、引数=`allgrp_watchdog.py check --config watchdog_config.json`、開始=スクリプトのフォルダ。
3. まずは **check(監視のみ)** で運用開始。⛔が出た日に中身を確認 → 問題なければ `fix` を手動 or タスクで実行。
4. `history.csv` を時々見れば、どの部門でいつ反映が崩れたかが残る。

## 安全設計
- **fix は必ずバックアップを先に取る**(work_dir/backups)。元に戻せる。
- **目標(予算)列・経過必要数は触らない**(マスター【ALLGRPデータ】由来。実績だけを定例KPIで適正化)。
- **データが無いブロックは触らない**(催事の未使用⑤⑥等を誤ってゼロにしない)。
- 🟡(一部要目視)は自動修正の対象外(日付揃えの誤差の誤修正を避ける)。

## 補足・今後
- マスターのシートは `【ALLGRP】A3縦` を前提。実ファイル(【ALLGRPデータ】)の構造が違えば `board_dept_actuals` の列判定を合わせる。
- 目標(予算)列の負値など**目標側の破損**は検知するが自動修正しない(正しい目標はマスター運用側で入れる)。
