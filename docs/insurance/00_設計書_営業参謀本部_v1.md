## 0. 目的とスコープ

### 目的
- ALLGROUP の**保険対面代理店**事業について、営業数値を**個人 → チーム(管轄) → 全体(ALLGRP)** の3階層で正確に把握する。
- **反映(データ入力)の正確性**を継続的に検証し、誤りを早期に検知する。
- 目標(予算件数・予算ANP 等)の達成に向け、ボトルネックを特定して**単一のネクストアクション**を提示する戦略家集団(参謀本部)を編成する。

### 対象範囲
- **地域**: 沖縄本島 + 札幌市。
- **9管轄 × 責任者**(2026-07 board 準拠):

  | 管轄 | 責任者 | 部門の性質 |
  |---|---|---|
  | ★DS嘉手納 | 下地 | 沖縄本島アポへ訪問→保険契約 |
  | ★DS特殊リスト | 長澤(兼任) | ラジオ問い合わせ・通販ユーザーへアポ |
  | ★DS催事 | 仲宗根 | 催事場「家計の見直しやさん」→訪問アポ |
  | ★DS豊見城 | 金城 | 沖縄電話帳リスト架電→アポ |
  | ★DS札幌 | 泉谷 | 札幌電話帳リスト架電→アポ |
  | ★ALL委託 | 島袋 | ALL委託まとめ |
  | CRM | 呉屋 | (要確認: 顧客基盤系) |

  ※ CRM/QCM/LTV の正式名称・役割は未確定(§7)。board上は「呉屋/徳元/上地管轄」として管轄扱い。

### スコープ外(現時点)
- 個々の営業手法の指導内容そのもの(参謀は数値と打ち手の設計に集中)。

## 1. 把握した数値モデル(現状の理解)

### 1.1 ファイル構成(2026-07-25 時点で受領した実データ)
- **ALLGRP定例board**(全体ロールアップ): `【ALLGRP】A3縦` 単一シート。6月版・7月版の2種。
- **管轄別KPIファイル**(複数): 各ファイルが以下4〜8シートを持つ共通テンプレート。
  - `管轄` — 対象管轄の定義。
  - `【チーム進捗】A3縦` — チーム/管轄単位の進捗(経過日数は手打ち更新)。
  - `【実数値】A3縦` — **個人単位・日次**の実数値(1日〜31日の実稼働時間等、~1,250行)。
  - `【確認】A4横` — 確認用。
  - 一部ファイルに `委託 / QS / 共同募集`(募集区分別KPI)、`※反映のやり方`(運用手順)。
- 6月版は `202606` 等の月次スナップショット。

### 1.2 3階層のロールアップ
```
個人(【実数値】日次)  →  管轄/チーム(【チーム進捗】)  →  全体(【ALLGRP】board)
```

### 1.3 営業ファネル(KPIの縦軸)
実稼働時間 → 発信数・配布数 → キャッチ数・着座数 → アポ・前確OK・保全数 → 訪問・後確OK数・保全完了数 → 申込数・開通数・戻入金額 →(予算件数 / 予算ANP / 想定単価 / 返送率 / 戻入)。
- 保険特有指標: **ANP**(年換算新契約保険料)、**保全**、**戻入(戻入率・戻入金額)**、**想定単価**。
- 変換率系: 稼動予→減率、時間→発信数、キャッチ数(率)、アポ・パーミ・リーズ化率、訪問数・P説・前確率、申込・後確OK・戻入率。

### 1.4 進捗の見方(各指標に4列)
`実績` / `経過必要数`(稼動日数・経過日数・残日数で按分した「今あるべき数」)/ `現差異`(実績−経過必要数)/ `進捗`(達成率)。
- board冒頭に **稼動日数・経過日数・残日数** があり、月中の按分基準になる。

### 1.5 責任者現能力図(❷)= 5能力軸
管轄長を5軸で採点し S/A/B ランク付け。**この5軸が参謀本部の役割設計の骨格**になる。

| 能力軸 | 意味(現状理解) | 対応ファネル領域 |
|---|---|---|
| 稼動管理 | 実稼働時間・稼動減率の管理 | 実稼働時間 |
| 無生産性管理 | 無駄・離脱・非生産時間の削減 | 発信〜着座の歩留まり |
| ゼロイチ管理 | 新規の立ち上げ(発信→キャッチ→アポ) | ゼロイチ(新規獲得) |
| 営業管理 | 訪問→申込→ANP・単価 | 中核営業 |
| 物件管理 | 保全・返送・戻入の管理 | 契約後の維持・返し |

## 2. 反映(データ入力)の正確性 — 監査アプローチ

### 2.1 なぜ監査が必要か
`※反映のやり方`シートより、運用は**手作業の値貼り付け**中心:
- 反映の〆= 毎日の稼働終わり〜翌9時。
- 各シート(委託/QS/共同募集)の個人簡易データを**値貼り付け**して保存。
- 共有の定例ALL委託で `【実数値】A3縦` を値貼り付け。
- `【チーム進捗】A3縦` の**経過日数だけは必ず手打ち・値貼り付け厳禁**。

→ 参照ズレ・貼り付け範囲ミス・手打ち漏れが構造的に起きやすい。

### 2.2 既に検知した要確認事項(v1時点)
7月ALLGRP board の **★ALL委託【島袋管轄】列に負の値**を確認:

| セル | 指標(目標側) | 値 | 異常の理由 |
|---|---|---|---|
| H38 | 時間→発信数 | −8.55 | 発信数が負はあり得ない |
| H46 | 実稼働時間 | −283 | 稼働時間が負 |
| H48 | キャッチ数・着座 | −2,827 | 件数が負 |

- **断定しない**。値貼り付け時の参照ズレの典型症状として「要確認」で扱い、原因は個人→管轄→ALLGRPの照合で特定する。

### 2.3 監査の方法(実装で作る)
1. **異常値検知**: 負値・ゼロ割・極端な外れ値・空欄を機械検出。
2. **ロールアップ照合**: 個人【実数値】の合計 = 管轄【チーム進捗】= ALLGRP board の対応セル、が一致するか突合。
3. **月間整合**: 6月版と7月版で定義列・並びのズレがないか。
4. **手打ち項目の確認**: 経過日数など「値貼り付け厳禁」項目が数式のまま/妥当かをチェック。
5. 検知結果は**要確認リスト**として出力(原文=元セルの座標付き)。断定表記はしない。

## 3. チーム設計 — 営業参謀本部

### 3.1 原則
- 既存repoの**三名体制(スイシン/ウタガイ/ベッカイ)**と**独立監査(ニドナシ機構)**思想を踏襲。
- すべての打ち手提案は3役で議論し、**ウタガイ(懐疑・反対必須)の反対理由が記録されない議事は無効**。
- 参謀は**提案まで**。予算・人事・方針の**最終決裁は小柳さん**。
- 3階層(個人・チーム・全体)すべてを対象に数値を追う。

### 3.2 構成

| 役 | 担当領域 | 主担当KPI | 根拠 |
|---|---|---|---|
| **統括参謀** | 全体最適・ボトルネック特定・単一ネクストアクション・週次/日次レポ | 予算件数/予算ANP 全体 | アカリ/達成くん思想 |
| 稼動参謀 | 稼動量の最大化 | 実稼働時間・稼動減率 | 稼動管理軸 |
| ゼロイチ参謀 | 新規の立ち上げ | 発信→キャッチ→アポ、リーズ化率 | ゼロイチ管理軸 |
| 生産性参謀 | 無駄・離脱の削減 | 着座率・歩留まり | 無生産性管理軸 |
| 営業参謀 | 中核営業の転換 | 訪問→申込→ANP・想定単価 | 営業管理軸 |
| 物件参謀 | 契約後の維持 | 保全・返送率・戻入 | 物件管理軸 |
| **数値監査役(独立)** | 反映の機械照合・異常検知。指揮系統外・報告は小柳さん直 | §2 の監査全般 | ニドナシ機構思想 |

- 各参謀は**個人・チーム・全体**の3視点で担当KPIを見る。
- 監査役は統括参謀の指揮下に入らない(独立性の担保)。

### 3.3 意思決定フロー
```
参謀(3役で議論・ウタガイ反対理由必須)
  → 統括参謀が結論+採否理由を明記(統括は裁定者、当事者にならない)
    → 割れたまま確信不可なら たかしくん経由で小柳さんへ上申
      → 最終決裁: 小柳さん
```

## 5. データ運用・プライバシー(守り)

- 【実数値】には**個人名**(営業担当者)が含まれる=個人データ。取り扱いは業務目的の範囲内に限定。
- 生データ(受領したxlsx)は**リポジトリにコミットしない**。設計・集計ロジック・匿名化した様式のみをコミット対象とする(要 §7 確認)。
- 監査スクリプトはローカルのxlsxを読む前提。生データの外部送信はしない。
