# 議事 2026-10-31 BlueBeanのパスワード更新メニューと管理画面の認証設定

- 起案: ❶システム関係全般(本セッション)
- 決裁: 小柳さん(2026-10-31「管理画面のログイン設定の点検・BlueBeanのパスワード変更…自動で対応して完了させてください」)
- 区分: ②本番設定(認証情報の扱い方の変更)
- 実装: PR #554(デプロイ設定の読み取り点検)、#555(パスワード更新メニュー・説明の訂正)

## 背景
- 福田さんのメールに、BlueBeanのログイン情報(連携に使うアカウントと同じもの)が書かれて届いていた。念のため、パスワードを変えたい。
- これまでのパスワードの入れ替え方: 台帳の持ち主(小柳さん)が Apps Script エディタのスクリプト プロパティを開き、`BLUEBEAN_PASSWORD` を書き換える。この方法だと、パスワードを変えた人(福田さん)から小柳さんへ、新しいパスワードを渡す必要がある。
- 決裁キュー15: 家計のポっのレビュー(2026-08-17)で、「GAS Web App の実行ユーザーが『自分』だと、個人Gmail運用では持ち主以外がログインできない」問題が見つかった。glow-ma の管理画面にも同じ問題がないか、未確認のままだった。

## 論点1: BlueBeanのパスワードをどう入れ替えるか

### スイシン(推進)
- 台帳のメニュー「GLOW台帳 > BlueBeanのパスワードを更新する」を足す。BlueBeanでパスワードを変えた本人が、その場で入力する。パスワードを人に渡さずに済む。
- 入力した直後にBlueBeanへ接続して確かめる。つながらなければ元のパスワードに戻す。パスワードそのものはログに出さない。

### ウタガイ(懐疑)
- **入力欄は伏せ字にならない(Apps Script の入力画面の制約)。** 周りから画面が見える。
  → 入力は本人が1回だけ行い、画面は閉じれば残らない。メールやチャットで送るより漏れる範囲が狭い。
- **台帳を編集できる人なら誰でも書き換えられる。**
  → 台帳を編集できる人は、もともと Apps Script のスクリプト プロパティも書き換えられる。新たに権限が広がるわけではない。編集者は3名(小柳さん・福田さん・嶺井さん)。
- **BlueBeanが一時的に落ちていると、正しいパスワードでも「つながらない」として元に戻る。**
  → 画面で「もう一度お試しください」と案内する。戻した記録はログに残る(ステータスのみ。パスワードは残さない)。
- **パスワードを変えてからメニューで入れるまでの間は、通話の取り込みが失敗する。**
  → 失敗しても取得済みの時点は進まないため、入れた後に続きから取り込まれる。

### ベッカイ(別解)
- 連携専用のBlueBeanアカウントを発行してもらい、人の管理者アカウントと分ける案。根本的にはこちらがよい(パスワード変更の影響を受けない)。BlueBean(ソフツー)への確認が要るため、今回は見送り、見直し時に再検討する(glow-ma/README.md の「現時点の制約」にも記載あり)。

### 結論(裁定)
- 採否: 採用(`glow-ma/src/CtiRunner.gs` の `updateBlueBeanPassword`、メニューは `ShareRunner.gs`)。福田さんへ手順を案内した(10/31)。

## 論点2: 管理画面の認証設定(決裁キュー15)

### スイシン(推進)
- 本番のデプロイ設定を、Apps Script API で読み取って確かめる(`scripts/glow_ma_exec_health.py` の `report_web_deployments`。URL・デプロイID・スクリプトIDは出さない)。
- 結果(2026-10-31):
  - 管理画面用のデプロイ(版3・31・56)は、実行ユーザー「アクセスしているユーザー」、アクセス「Googleアカウントを持つ全員」。同じ問題は無い。
  - トラッキング用(版55)は「自分」/「全員(匿名)」で、設計どおり。
- 決裁キュー15をクローズする。

### ウタガイ(懐疑)
- **`appsscript.json` の `webapp` は「自分」のまま。** 管理画面のデプロイを新しい版へ更新すると、実行ユーザーが「自分」に戻り、持ち主以外が入れなくなる。
  → glow-ma/README.md に注意を書いた。点検ログの「Web公開(デプロイ)の設定」で毎回確かめられる。
- **管理画面は9/4の版のまま動いており、その後のコードの変更が反映されていない。**
  → 管理画面で困りごとの報告は出ていない。更新するときは、上の注意を守って行う(今回は更新しない)。
- **AdminRunner.gs の冒頭の手順に「実行ユーザー: 自分」と書かれていた。** 次に設定する人が誤る。
  → コメントを訂正した。

### ベッカイ(別解)
- 管理画面とトラッキングを別の Apps Script プロジェクトに分け、マニフェストの設定がぶつからないようにする案。作業が大きく、今は困っていないため見送る。

### 結論(裁定)
- 採否: 採用(確認・記録・説明の訂正のみ。本番の設定は変えていない)。決裁キュー15をクローズした(docs/決裁キュー.md)。
- 見直し期限: 2027-04-30
