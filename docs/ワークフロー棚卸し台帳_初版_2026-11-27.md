## main にファイルが無い登録(13本)

GitHub の一覧にだけ残っている登録。main にファイルが無いので、定時では動かない。手動・push で動くのは、そのファイルを含むブランチがある場合だけ(今回、取得済みのブランチにはファイルが見つからなかった。全ブランチの確認は次版)。
GitHub 側で登録を消す操作は無く、実害は無いため、**対応は不要**と判断する。

## 自動で更新する項目と、人が決める項目

| 自動で取る(次版で連続失敗の見張りに相乗りして更新。定期処理は増やさない) | 人が決める |
|---|---|
| ファイルの有無・名前・起動条件・定時の設定 | 本当に必要な機能か |
| GitHub 上の有効・停止 | 対象の事業・重要度 |
| 最終実行日時・最終成功日時・連続/断続の失敗 | 維持・統合・廃止の判断 |
| | 停止を許せる期間・責任者・事業分離後の移し先 |

## この初版で分かったこと(要点)

- 監視・点検のうち「認証・期限管理」は1本だけで、APIキー・トークンの期限を見るものが無い。
- 実行は成功でも目的が達成されていないもの: 結果マガのX投稿(定時の遅れで毎回見送り)。原文照合の断続的な失敗は、PR #656 で対処(2026-11-27 統合)。
- note・結果マガ・Xの15本は、事業を続けるかの判断が保留のため、この台帳でも「判断待ち」とする。
