**期間**: 2026-09-25 〜 2026-10-01  
**目的**: 7〜8月の古い検証記録(80件)を最新情報で再検証

## Phase 2 実行計画

### 1. 実行期間と負荷
- **期間**: 2026-09-25（水） 〜 2026-10-01（火）= 7日
- **ペース**: VERIFY_SAMPLE_SIZE=20 で 20件/日
- **総処理**: 80件を5〜7日で完了
- **実施方法**: GitHub Actions workflow_dispatch 手動トリガー

### 2. 実行コマンド (毎日実行)
```bash
# GitHub Actions UI から以下を実行:
# Actions > verify-sources > Run workflow
# Inputs:
#   sample_size: 20
```

または CLI の場合:
```bash
gh workflow run .github/workflows/verify-sources.yml \
  -f sample_size=20 \
  -r main
```

### 3. ワークフロー動作

verify-sources.yml の更新内容:
- `workflow_dispatch` に `sample_size` 入力パラメータを追加
- デフォルト: 5 (通常時)
- Phase 2: 20 (集中検証期間)

実行時の環境変数:
```yaml
VERIFY_SAMPLE_SIZE: ${{ github.event.inputs.sample_size || '5' }}
```

### 4. 出力と確認

各実行後:
- `data/kpi/verify_history.json` に日付ごとの検証結果を記録
- NG件数 = 0 が理想的
- NG件数 > 0 の場合: GitHub Issue が自動起票される

## 発見時のエスカレーション

**NG件数 > 0 の場合**:

1. GitHub Issue が自動起票される (label: verify-sources)
2. `投稿実績台帳.md` の「既知の問題・追跡対象」セクションに追記
3. 出版側(SNS部/もらいわすれ堂)へ修正要否を報告
4. 修正が必要な場合:
   - `fetch_fukugiiro.py` または掲載データを修正
   - 翌日の再実行で確認
5. 修正不要な場合:
   - Issue に `human_verdict: false_positive` を記入
   - 自動クローズ

## 成功定義
