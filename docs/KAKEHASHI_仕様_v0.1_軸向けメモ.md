## § 1. 顧客ID体系（KM- root）

### 発行者・管理者: 軸

#### 顧客ID構成
```
KM-YYMMDDHHHH
├─ KM: Kakei Management 識別子
├─ YYMMDD: 登録日（年月日）
└─ HHHH: ハッシュ下4桁（重複排除）
```

#### 例
```
KM-261015A1B2  （2026年10月15日登録・ハッシュ A1B2）
KM-261016X9Z4  （2026年10月16日登録・ハッシュ X9Z4）
```

### 発行ルール（軸が守る）
1. **enLife 個人のみ**: 契約済み・見込み・リード全て含む。法人・事業主は除外
2. **GLOW分離**: M&A候補企業・営業先候補は別体系（別ファイル・非公開リポジトリで管理）
3. **一意性保証**: 同一個人の重複登録を防ぐ（名前・電話・生年月日で照合）
4. **非PII出力**: 軸が各チャットに提供する「新規リスト」には KM- id のみ（氏名・電話は含めない）

### 中央台帳（KM-root）の構成

| 項目 | 用途 | 保有者 | 暗号化 | 保持期限 |
|---|---|---|---|---|
| KM- id | 顧客識別 | 軸 | いいえ | 7年（税法） |
| 氏名 | カルテ・通知 | 軸 | ✅ at-rest | 7年 |
| 電話 | 架電・SMS | 軸 | ✅ at-rest | 7年 |
| メール | 通知 | 軸 | ✅ at-rest | 7年 |
| enLife 契約ID | 契約確認 | 軸 | いいえ | 契約期間 |
| GLOW フラグ | 出口制御 | 軸 | いいえ | 案件期間 |
| 登録日時 | 監査 | 軸 | いいえ | 7年 |
| 最終更新日時 | 監査 | 軸 | いいえ | 7年 |

## § 2. 新規リスト（❶→軸→❢）の仕様

### 軸の役割
1. ❶から受け取った CSV/JSON を **schema.py でバリデーション**
2. **重複排除** : 既存 KM- root と照合して、新規のみ抽出
3. **KM- id 付与** : 新規顧客に新規 KM- id を発行
4. **DNC チェック**: DNC マスタと突合、DNC は除外リストへ
5. **❢へ配信**: 新規リスト＋DNC を ❢の reserve_call API へ送信

### スキーマ（docs/スキーマ_新規顧客リスト.py）
```python
{
  "new_customers": [
    {
      "customer_id": "KM-261015A1B2",    # 軸が付与
      "name_masked": "〇〇子",           # 非PII返却（マスク）
      "phone_masked": "090-xxxx-9999",   # 非PII返却（パーシャルマスク）
      "source": "診断ページ",             # 流入元
      "entry_date": "2026-10-15",        # 登録日
      "condition": "enLife見込み"        # ラベル
    }
  ]
}
```

### ❶からの入力（raw 状態）
```python
{
  "customers": [
    {
      "name": "山田太郎",              # 軸が受け取る時点では PII
      "phone": "090-1234-5678",
      "email": "yamada@example.com",
      "entry_date": "2026-10-15",
      "source": "診断ページ",
      "notes": "家計見直し希望"
    }
  ]
}
```

### バリデーション ロジック（軸）
```
1. 必須フィールド確認：name, phone, entry_date
2. 電話形式チェック：090/080/070 で始まる11桁
3. メール形式チェック：@を含む文字列
4. 重複確認：既存 KM-root と name/phone で照合
5. エラー扱い：不正形式は ❶へ差戻し（修正要求）
6. 成功時：新規として KM- id を新規採番
```

## § 3. DNC マスタ（軸管理）

### 軸の責任
1. **複数ソース統合**: 法務・営業・ユーザー申告・法令リスト
2. **3分類管理**:
   - ①電話拒否：個別ユーザー申告（「電話しないで」）
   - ②商法対象外：法人、事業主、未成年など
   - ③マークリスト：保留中、放置中、無応答繰返し
3. **❢への毎日配信**: 新規ターゲット配信時に同時配信
4. **更新ログ記録**: いつ誰が何を追加したかは監査対象

### スキーマ（docs/スキーマ_DNC_3分類.py）
```python
{
  "dnc_entries": [
    {
      "phone": "090-9999-9999",
      "category": 1,                  # 1=電話拒否, 2=商法対象外, 3=マークリスト
      "reason": "本人申告：電話しないで",
      "added_by": "ユーザーチャット",
      "added_date": "2026-09-10",
      "valid_until": "2027-09-10"     # 自動期限切れ（❢が再確認）
    }
  ]
}
```

### DNC の除外ロジック（❢が実装）
```
1. 新規リストの各 phone を DNC と突合
2. マッチした場合：
   - category 1 → 絶対除外（架電禁止）
   - category 2 → 除外（法令・事業主）
   - category 3 → 軸に相談（一時保留 or 再トライ）
3. 除外リストを軸へ報告（「XX件除外」という形式）
4. 軸が除外ログを記録（監査用）
```

## § 4. スコアリング（見込み度帯）

### 軸の役割
1. **見込み度スコア計算**: enLife 契約確度・営業マン見込み度・経過日数などから スコア 0-100 を計算
2. **見込み度帯に分類**: スコア→帯への変換（例: 80-100=高、50-79=中、0-49=低）
3. **❤への配信**: 営業管理画面で見込み度帯を表示

### スコア計算の基本式（軸が定義）
```
score = (
  enLife_契約確度 × 0.4 +           # 保険契約の有無・契約額
  営業マン_見込み度 × 0.3 +          # 営業マンの営業活動・面談回数
  経過日数_正規化 × 0.2 +            # 登録からの経過日数（長い→新鮮度↓）
  訪問_実績 × 0.1                    # 訪問の有無・実績
)
```

### 見込み度帯の定義（軸が定義・小柳さん決裁）
```
帯の種類 | スコア範囲 | 意味 | 営業マン行動
---------|-----------|------|----------
高（A帯） | 80-100 | 成約直前 | 集中営業・契約急ぎ
中（B帯） | 50-79 | 見込み中 | 定期接触・情報提供
低（C帯） | 20-49 | 検討中 | 月1回接触
冷（D帯） | 0-19 | リード | 季節接触・アラート待ち
```

⚠️ **警告**: 帯の定義は業務パラメータ。テストを通すために勝手に変更してはいけない。変更は三名体制で議事化し小柳さん決裁

## § 5. 統一コールログ 10 列

### 軸の責任
1. **スキーマ設計・管理**: 10 列の定義・バリデーション
2. **ログ集約**: ❢（新規架電）、❣（保全架電）からの ログを受け取る
3. **Log Analytics 送信**: Azure Monitor へ自動送信
4. **❤へのビュー提供**: 営業マン向け UI で参照可能にする

### 10 列の詳細（docs/統一コールログ_10列_仕様.md）

| # | 列名 | 型 | 例 | 説明 |
|---|---|---|---|---|
| 1 | call_id | string | call-20261015-A1B2 | 軸が採番（一意） |
| 2 | customer_id | string | KM-261015A1B2 | 顧客 ID |
| 3 | call_type | enum | "new" / "retention" / "sms" | 架電種別 |
| 4 | start_time | datetime | 2026-10-15T14:30:00+09:00 | 架電開始時刻 |
| 5 | duration | integer | 180 | 通話時間（秒） |
| 6 | outcome | enum | "success" / "failure" / "dnc" / "voicemail" | 結果 |
| 7 | operator | string | "営業マン太郎" | 架電者名 |
| 8 | notes | text | "了承・月内訪問予定" | メモ・営業マン見込み度 |
| 9 | next_action | string | "訪問予約 2026-10-22" | 次のアクション |
| 10 | recorded_at | datetime | 2026-10-15T14:35:00+09:00 | 記録日時（軸が自動記入） |

### 非 PII 原則
- 氏名・電話・住所・メール は 記録しない
- customer_id だけで顧客特定
- notes は営業情報のみ（個人特定情報含むな）

### エラーハンドリング
```
① 不正形式: スキーマバリデーション失敗
  → ❢❣ へ 「XX件エラー」報告
  → Log Analytics へは "ERROR" ステータスで記録
  
② 重複： call_id 重複検出
  → エラーハンドリング（リトライ or スキップ）

③ タイムアウト: Log Analytics 送信失敗
  → ローカルキュー保持＋再試行
  → 24時間以上失敗は監査アラート
```
