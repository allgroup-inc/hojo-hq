### 全国の制度と県の案内の違い(確認すること)

- 児童扶養手当は国の制度(制度ID `fk-kuni-`・発行元 こども家庭庁)。県のページは「県の案内」で、額や手続き(市町村の窓口)は全国共通だが、県・市町村の連絡先や県独自の補足が載る
- 出典を県のページにする場合も、制度ID と発行元(こども家庭庁)は変えない。`notes` の「出典: こども家庭庁ウェブサイト」は発行元から自動で作られるため、県のページを出典にするなら表記が合わなくなる点を検証部が決める(こども家庭庁のページに戻す案もある)
- `fk-ken-` の2制度は県の事業なので、県のページが出典になる

## 出典URLを直したときの影響(合成データで確認: `tests/test_fetch_publish.py`)

| 直し方 | 収集・公開への影響 |
|---|---|
| 児童扶養手当の出典を、取得できるページに直す | 新しく載る制度として戻る。公開用データの更新は止まらず、「必須制度の欠け」は解消し、`diagnosis-data-hold` の Issue は次の停止検知で閉じる(LINE で知らせていた場合だけ解消を知らせる) |
| 確認を省いている2制度の出典を、正しいページに直す | 到達性の確認を省いたままなら、収集・公開の判定は変わらない。市町村別ページ・申請準備シート(`site/fukugiiro/kit/…`・`life/…`)の出典リンクが次の収集で新しいURLになる |
| 2制度の `assume_reachable` を外す | 新しいURLが取れれば変化なし。**取れなければ「前回公開していた制度の取得失敗」として公開用データの更新が止まる**(前回の公開データが表示され続ける)。外すのは、収集で取れることを確かめてから |
| SNS 投稿 | 投稿の出典はシードとは別に記録している(`data/kpi/ig_posts.json`)ので、シードの出典を直しても過去の投稿の記録は変わらない。今週のネタ選び(`scripts/generate_ig_neta.py`)は収集データ `data/fukugiiro/seido.json` から、使用済みの制度ID・出典URLを除いて選ぶ。児童扶養手当は使用済み(`used_ids`)に入っているので、戻っても再び候補にはならない。今週のネタ(`data/fukugiiro/ig_neta.json`)に3制度は入っていないため、出典を直しても `selfcheck_moradou.py` の「出典が seido.json にありません」には当たらない(ネタに入っている制度の出典を直すときは、ネタ側も合わせて直す) |

## 追加した検査

- `scripts/fetch_fukugiiro.py` の `shared_dead_sources()`: 到達性の確認を省いているシードのうち、**別のシードが同じURLで 404/410** を受けたものを `publish_status.json` の `source_dead_shared` に記録し、収集ログに警告を出す。一時的な障害(503 など)では出さない。公開の判定・掲載内容は変えない
- 今回の収集で動いていれば、`fk-ken-hitorioya-sodan` が記録される(合成データのテストで確認)。`fk-ken-kouto-shokugyo-kunren` は URL が別なので、この検査では見つからない

## 直すために必要なこと

1. 原文を読めるようにする: セッションの環境設定で `www.pref.okinawa.lg.jp`・`www.cfa.go.jp` への接続を許可する(Network access の Allowed domains)、または検証部が直接確かめる
2. 3制度それぞれについて、ページ本文・対象者・支給内容・更新日・URL が有効なことを確かめ、確かめられた制度だけ出典を直す(別の PR)
3. 2制度の `assume_reachable` を外すかどうかは、新しいURLが収集で取れることを確かめてから決める
