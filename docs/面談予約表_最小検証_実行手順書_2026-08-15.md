## 1. この検証で確かめること(1つだけ)

> **LINE登録者に予約導線を出したら、実際に面談予約が入るか。**

YES/NOだけを見ます。UIの出来・指名制の是非・顔写真の効果は今回測りません(混ぜると何が効いたか分からなくなる)。

### 測る数字(4つ)

| 数字 | どこで取るか |
|---|---|
| 予約リンクのクリック数 | Plausible(`/go/yoyaku/` の計測イベント) |
| 予約完了数 | 予約ツールの管理画面 |
| 実施数(当日実際に会えた数) | 手で数える |
| 出口接続数(士業・GLOW・保険へ繋がった数) | 手で数える ← **真のKPI** |

### 判定(1週間後)

- **続ける**: 予約2件以上 かつ 実施1件以上 → 導線を残し、内製(glow-ma Phase 19相当)を再検討
- **やめる**: クリックがほぼ0 → 予約表の問題ではない。「相談したい人がいない」か「リッチメニューが見られていない」のどちらかなので、装置ではなくLINE配信の文面側に戻る
- **保留**: クリックはあるが予約0 → 予約ページで止まっている。項目数・所要時間の表示・日程の少なさを疑う

※ 1週間・数件の母数です。**これは統計ではなく「入口が詰まっているかの確認」**です。数字で断定はしません。

## 3. 手順

### 小柳さんの作業(約30分・1回だけ)

1. ツールのアカウント作成 → **Googleカレンダーと連携**
2. 枠の設定

   - 受付曜日・時間帯: 平日の実際に空けられる時間だけ
   - 締切: 前日◯時まで(当日予約は事故のもと)
   - 1日の上限: ◯件
3. **予約ページで聞く項目を最小にする** — 会社名 / お名前 / 連絡先1つ / 相談したいこと。これ以上増やさない(項目が増えるほど予約は減り、預かる個人情報も増える)

5. LINEリッチメニューの1枠を「面談を予約する」に差し替え(画像文言はこちらで用意します)

## 5. 止める条件(フェイルクローズ)

無人で動く導線なので、**壊れたときに止まる**ようにしておきます(resilient-agent-design)。

- **カレンダー連携が切れたら予約受付を止める。**古い空き枠を出して二重予約するくらいなら「現在調整中です」の方が被害が小さい
- **週1回、自分のスマホで最後まで予約を通す**(枠が出るか・完了メールが届くか)。目視確認を挟まない自動導線は必ず腐ります
- **予約が入ったのに通知が来ない事故が1件でも起きたら、原因が分かるまで導線を下ろす**。面談前に信頼を壊すのが最悪の結果
