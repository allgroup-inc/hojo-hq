## 真因分析: FK-003(フカボリさん)

【失敗ID】FK-003

**なぜ×5**

1. なぜ当時の判断を検証できないのか → 設計書に「裁定」しか残っておらず、ウタガイが何に反対したのかが読めないから
2. なぜ裁定しか残っていないのか → 議事本体を「本セッションの会話記録を参照」と書いて、gitの外に置いたから
3. なぜ会話の中に置いたのか → 議事の保存先が、憲法にもスキルにも一言も書かれておらず、書き手の裁量だったから
4. なぜ書かれていなかったのか → 2026-08-06までは偶然「別ファイル(`*-triangle-review.md`)で作る」運用が続き、問題が表面化しなかったから(暗黙知のまま regulation されなかった)
5. なぜ暗黙知のままだったのか → **保存漏れを検知する仕組みが無く、規程が破られても誰にも分からなかったから**

**真因(仕組みの穴として一文で)**
三名体制の議事に保存先の規定と検査が存在せず、議事が揮発しても検知されない構造だった。

**当初仮説の否定**
点検の初期には「議事が重いから急ぐと省略された」と仮説を立てたが、事実は違った。**議事は実施されている**(設計書が裁定1〜4を引用している)。消えたのは議事の保存先である。したがって対策を「フォーマットの軽量化」だけに置いていたら、真因を外していた。軽量版は補助的な対策として残す。

**対策(形態)**
- **テスト化**: `scripts/check_triangle_review.py`。「議事」の近傍に「会話記録/本セッションの記録/チャット履歴」がある書き方を検出する。既知10本は `KNOWN_GAPS` に台帳IDつきで固定し、**新規に増えた分だけ落とす**ラチェット方式。CI は `docs-governance`(specs配下の変更で起動)
- **ルール化**: hojo-triangle-review / glow-ma-triangle-review の両スキルに「議事の保存先(A ペアファイル / B パス参照 / C 設計書に直接)」と「軽量版=3役×各1行でも有効」を明記
- 遡っての議事作成は**行わない**。実装後に書くウタガイは結論を知ったうえでの後付けであり、規程の趣旨(実装前に止める)を果たさないまま記録だけが整う。該当10本には事実を1行追記して残した

**横展開: 同じ穴(gitの外に状態を置く)の走査結果**
- `docs/決裁キュー.md` が16日間未更新だった件も同根。決裁の現況が人の記憶と会話の側にあり、ファイルが追随していなかった → 2026-08-17に注意書きを追加済み。恒久対策は未着手(**残課題**)
- `context-limit-handoff` スキルが扱う領域そのもの。CLAUDE.mdのスキル運用表に「会話がコンテキスト上限に近い → context-limit-handoff」として明記済み
- **配布の穴(残課題)**: hojo-triangle-review / glow-ma-triangle-review は repo固有スキル扱いで `scripts/update-skills.sh` の `ALLGROUP_SKILL_NAMES` に入っていない。他repoで同型の議事揮発が起きても、この対策は届かない。ALLGROUP共通化するかは要判断

**実装担当部門**: 実装済み(検査スクリプト・CI・スキル改訂)。監視は ミハリさん。
**クローズ条件**: CI稼働のうえ `KNOWN_GAPS` が1行も増えないまま6ヶ月(2027-02-17判定)。
