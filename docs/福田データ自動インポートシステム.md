# 福田データ自動インポートシステム

> **自動化完了日**: 2026-10-06  
> **対応内容**: Excel品質チェック → Google Drive → Google Sheets → Apps Script インポート の完全自動化パイプライン

## 概要

福田さんが毎月送付する過去100件の企業データ（Excel）を、自動で品質チェック・Google Sheetsにセット・Apps Script実行するシステムです。

### 自動化フロー

```
福田さん
   ↓
(メール添付Excelファイル)
   ↓
GitHub Actions
   ├─ detect_fukuda_email.py: Gmailから最新メールを検出
   ├─ download_fukuda_attachment.py: Google Driveから Excelダウンロード
   ├─ validate_fukuda_data.py: 品質チェック（形式・重複検出）
   ├─ upload_to_staging_sheet.py: Google Sheets「福田_履歴インポート」にセット
   ├─ trigger_gas_import.py: Apps Script importFukudaHistoricalData() を実行
   └─ wait_import_completion.py: インポート完了を待機
   ↓
Apps Script (HistoricalDataImporter.gs)
   ├─ バリデーション
   ├─ 重複検出
   ├─ 企業マスタ追加
   ├─ 対応履歴ログ記録
   └─ 結果レポート出力（「福田_インポート結果」タブ）
   ↓
メール通知（成功/失敗）
```

## セットアップ手順

### 1. 事前準備（1回だけ）

#### 1a. Google Cloud設定
- Google Cloud Consoleで「Google Sheets API」「Gmail API」「Google Drive API」を有効化
- サービスアカウント認証情報（JSON）を作成

#### 1b. GitHub Secrets設定
以下を `Settings → Secrets and variables → Actions` に登録：

| Secret名 | 説明 | 取得方法 |
|---|---|---|
| `GOOGLE_SHEETS_CREDENTIALS` | サービスアカウント JSON | Google Cloud Console |
| `GLOW_SHEET_ID` | GLOW企業リレーション台帳 スプレッドシートID | スプレッドシート URL の `/spreadsheets/d/...` 部分 |
| `GAS_DEPLOYMENT_ID` | Apps Script デプロイID | Apps Script「デプロイ」タブ |

#### 1c. Google Sheets側の準備
1. 「福田_履歴インポート」タブを作成（1行目: ヘッダー行）
2. 「福田_インポート結果」タブは自動作成される

#### 1d. Apps Script側の準備
```javascript
// Apps Script エディタで実行
setupImportTrigger();
```
これで毎日午前2時に自動実行されるようになります。

### 2. 初回テスト

```bash
# ローカルでバリデーション実行
python glow-ma/scripts/validate_fukuda_data.py <福田から받けたExcelファイル>
```

### 3. 本番運用開始

福田さんから「企業マスタデータ*.xlsx」メールを受け取ると：
1. 毎日午前1時(JST)に自動検出・ダウンロード
2. 品質チェック実行
3. 自動アップロード＋インポート実行
4. メール通知

## バリデーション内容

### 必須フィールド
- **企業名**: 空でない文字列
- **電話番号**: 有効な電話番号形式（10〜11桁）

### オプションフィールド（チェック対象）
- **手紙送付日**: 有効な日付形式（YYYY-MM-DD / YYYY/MM/DD）
- **架電日**: 有効な日付形式
- **所在地、代表者名、業種、規模、代表者年齢、備考**: 型チェック

### 警告チェック
- **時系列チェック**: 手紙送付日 > 架電日 の場合、警告
- **重複検出**: 既存台帳との電話番号重複
- **フォーマット**: 電話番号の正規化

## エラー対応

### Q: 「企業名が空」でスキップされた行が多い
**A**: Excelファイルの1行目がヘッダーになっているか確認してください。データは2行目以降に記載してください。

### Q: 「電話番号が無効」と判定された
**A**: 以下の形式で入力してください：
- `098-XXXX-XXXX`（沖縄）
- `090-XXXX-XXXX`（携帯）
- `09012345678`（ハイフンなし）

有効な形式: 10〜11桁の数値

### Q: 自動インポートが実行されない
**A**: 以下を確認：
1. 福田さんのメールが `from:glowfukuda@gmail.com` で送られているか
2. メール件名に「企業マスタ」または「過去100件」が含まれているか
3. Excelファイルが添付されているか

### Q: バリデーション結果を確認したい
**A**: GitHub Actions のワークフロー実行ログ、または以下パスのレポートを確認：
```
docs/logs/fukuda-import/result_YYYYMMDD_HHMMSS.json
```

## インポート後の確認

インポート完了後：

1. **Google Sheet** → 「福田_インポート結果」タブ
   - インポート件数、重複数、架電・手紙記録数が記録される

2. **メール通知**
   - `takeshi.koyanagi9@gmail.com` に成功/失敗メールが送信される

3. **企業マスタの更新状況**
   - ダッシュボード → 「流入ルート別」集計を確認
   - 新規追加企業が「②手紙DM」として計上される

## トラブルシューティング

### パイプライン全体が失敗する場合

1. **GitHub Actions ログを確認**
   ```
   リポジトリ → Actions → 最新ワークフロー実行 → ログ
   ```

2. **よくあるエラー**
   | エラー | 原因 | 対応 |
   |---|---|---|
   | `PERMISSION_DENIED` | サービスアカウント権限不足 | Google Cloud IAM設定を確認 |
   | `File not found` | 添付ファイルが見つからない | メールに Excelファイルが添付されているか確認 |
   | `Invalid date format` | 日付形式が異なる | YYYY-MM-DD または YYYY/MM/DD に統一 |
   | `Duplicate phone number` | 既に登録済み企業 | 正常（警告レベル） |

### Apps Script 側のエラー

Apps Script エディタで「実行」ログ（Cmd+Enter）を確認：

```
Logger.log("✓ インポート完了！");  // 成功時
Logger.log("✗ エラーが発生しました: " + e.toString());  // エラー時
```
