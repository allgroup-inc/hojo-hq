# 2026-08-07: 真のKPI(相談転換 月10件)のログ分析設計(log-analysis-playbook活用)

新しく使えるようになった`log-analysis-playbook`スキルの§D(他システムへの連動手順)を、
真のKPI(月10件・LINE部5+提携部5、`docs/2026-08-02-組織体制総点検.md`で確定)の
トラッキングに適用した設計。

## 1) 概念の対応表(§D-1準拠)

`docs/議事_20260804_相談転換の設計.md`で既に確定している相談転換フローに当てはめる。

| 汎用概念 | CC事業(あいおい生命)での実体 | hojo-hqでは何か |
|---|---|---|
| 活動イベント | 架電1回(メモ1行) | LINEで「相談」と一言送信(GASボット一次受付) |
| 接触(キャッチ) | 通電・本人会話 | 小柳さんが台帳を確認し返信 |
| 合意(中間成果) | アポ(面談了承) | 嶺井さんへ接続 |
| 履行→最終成果 | 訪問→申込 | 訪問・面談の実施(=**真のKPIのカウント対象**) |
| 断り/離脱 | NG・着信拒否 | 相談モード6時間以内に本人から返信なし/ブロック |
| 個人の帰属 | 架電者名 | 対応者(小柳さん一次対応/嶺井さん接続後) |
| 品質メモ指標 | 候補日・予算等の記載率 | 台帳P列(相談本文)の具体度(業種・相談テーマの記載有無) |
| 打ち切り閾値 | 6回ルール | 相談モードの継続転送は6時間(既存仕様・実測前提で見直し) |

企業台帳の**経路列が`line-consult`の行**が、この分析の一次データになる
(`docs/議事_20260804_相談転換の設計.md`で既に定義済み)。

## 2) ツールの役割対応(§D-2準拠)

| プレイブックの役割 | hojo-hqでの実体 |
|---|---|
| validate_input(関門) | 台帳の経路列が`line-consult`で正しく記録されているかを検証 |
| ingest(正規化・匿名化抽出) | 台帳から`line-consult`行を抽出し、個人情報を除いた集計用データに変換 |
| operator_analysis+scorecard(個人) | 対応者別(小柳さん・嶺井さん)の返信速度・接続率・訪問成立率 |
| customer_analysis(顧客属性) | 業種・地域・相談テーマ(承継/融資/士業)別の傾向分析 |
| transition/recall(遷移・再訪) | 相談受付→接続→訪問、の各段階の遷移率(どこで離脱しているか) |
| guard_audit(守り・台帳) | 台帳は既に非公開スプレッドシート。個人情報の利用目的同意(mamori.md既存ルール)の遵守確認 |
| cost_analysis(無駄の金額化) | 今回は対象外(3ヶ月目以降の検討候補) |
| build_dashboard(経営版/従業員版) | アカリさんの週次レポート(`reports/hojo-mikata/`)への統合。
  LINE部(tsunagu.md)5件+提携部(musubu.md)5件の合算値として表示 |

## 3) 安全の型(§D-3準拠・削らず踏襲)

- 相談本文(台帳P列)は個人情報を含むため、この分析はGit管理下のリポジトリでは行わない。
  台帳(Google Sheets)側で完結させ、リポジトリには**集計後の件数のみ**を持ち込む
- 出力の匿名化: 週次レポート(アカリさん向け)には対応者別の件数・遷移率のみを載せ、
  相談者の個人情報・企業名は載せない
- 誇張禁止: 「相談◯件」は実数+分母(相談受付総数のうち何件が訪問まで到達したか)で示す

## 4) 立ち上げの順番(§D-4準拠)

- **初月**: 関門(経路`line-consult`の記録が正しく機能しているか確認)→ 取込 →
  ファネル(相談受付→接続→訪問の3段階カウント)→ 対応者別一覧(小柳さん/嶺井さん)
- **2ヶ月目**: 前月比 + 対応時のFAQ的な教育資料の蓄積 + 守りの台帳(個人情報の扱い再確認)
- **3ヶ月目**: 相談モード6時間ルールの妥当性検証(実測の累積カーブから)・
  相談トリガー文言のA/Bテスト等

## 前提: 企業台帳へのAPIアクセスが必要(小柳さんの人間側ToDoと連動)

この分析を実際に自動化するには、企業台帳(Google Sheets)への読み取りアクセス手段が
必要(`docs/2026-08-02-組織体制総点検.md`5節の人間側ToDo②「企業台帳へのAPIアクセス
手段を用意する」と同一の前提)。サービスアカウント発行、または当面は手動集計(小柳さん・
アカリさんが週次で経路`line-consult`行を目視カウント)のいずれかで開始できる設計にした。
