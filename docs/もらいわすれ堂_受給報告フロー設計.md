# もらいわすれ堂 受給報告フロー設計(v1・2026-09-19)

## 目的
LINE登録者が「制度から給付金をもらった」という実績を報告 → データ化 → ❷ KGI「受給報告1,000件」へ

## ユーザーストーリー
```
1. 診断サイトで「児童手当が対象かも」と判定
2. LINEで「詳しく知りたい」を選択
3. LINE公式から「申請手続きガイド」受信
4. 4ヶ月後「児童手当をもらいました！」報告
5. データが台帳へ → 支援実績・効果測定に
```

## LINE運用原稿 §D 実装内容(A1後に必須)

### §D-1. あいさつ文のコール to アクション
```
「給付金をもらえました」「申請が通りました」
↓ リッチメニュー「受給を報告する」で受け付け開始
```

### §D-2. リッチメニュー レイアウト
```
┌─────────────────────────────┐
│ もらいわすれ堂              │
├─────────────────────────────┤
│ [🎁 受給を報告] [❓ 制度検索] │
│ [📋 診断を再度] [ℹ️ よくある質問] │
└─────────────────────────────┘
```

### §D-3. 「受給を報告する」フロー

**ステップ1**: ユーザーが「受給を報告する」タップ
↓
**ステップ2**: フォーム表示
```
【給付金をもらいましたね】

1. 制度の名前を選ぶ(リスト: 児童手当・就学援助・奨学給付金...)
2. もらった時期: 〇年〇月
3. おおよその金額: 
   □ 5千円未満 / □ 5〜10万円 / □ 10〜50万円 / □ 50万円以上
4. (オプション)コメント: 「手続きがスムーズでした」など

[報告する]
```

↓
**ステップ3**: 送信完了
```
「報告ありがとうございました🎉
このデータは、沖縄の制度改善に役立ちます。」
```

## 計測・分析

### KPI: ❷ 受給報告数
- 目標: 1,000件/12ヶ月(約83件/月)
- 早期目標: 3ヶ月で100件

### セカンダリ指標
- 平均額(amount_estimated): 制度ごとの効果額を可視化
- 報告→LINE登録率: 「もらった人がLINEに留まるか」の指標
- 最多制度ランキング: 実際に効果があった制度トップ5

## LINE Insight API との連動

A2実装完了後、LINE Insight にて:
- 「受給報告」メッセージの到達率
- クリック率・離脱率
- ユーザーセグメント分析

## 注意・ルール(守り部チェック項目)

| 項目 | ルール |
|---|---|
| 断定禁止 | 「必ずもらえます」と言わない。「報告ありがとう」まで |
| 個人情報 | 報告内容をPIIとして非公開リポジトリ(allgroup-inc/kakei-crm等)に保管 |
| 資格業務 | 申請代行はしない。「報告してくれてありがとう」のみ |
| 統計公開 | 制度別・月別の集計は公開OK(個人特定不可) |
