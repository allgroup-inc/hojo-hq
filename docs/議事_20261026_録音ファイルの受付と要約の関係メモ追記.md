# 議事 2026-10-26 録音ファイルの受付と要約の関係メモへの追記

- 起案: ❶システム関係全般(本セッション)
- 決裁: 小柳さん(2026-10-26「録音も進めるのと。システムの訪問した企業の見込み内のメモ欄にもログの内容を要約して記載できる様にして下さい」)
- 区分: ②不可逆な変更(外部送信: 録音をGeminiへ送る範囲の拡大・ドライブフォルダの共有)
- 依頼元: 福田さん(2026-10-26)。LINEボイスメッセージには次の問題があるため、録音アプリ(PCM録音)のWAV/AACで記録したい。
  - 最大30分
  - スリープで停止する
  - 送信後にデータが消える

## 背景
- LINE音声記録は確認ボタンを経て対応履歴ログと関係メモに残せるが、福田さんの面談(長時間)はLINEボイスの制約で記録できていなかった(送信後にエラー・データ消失の報告あり)。
- その結果、訪問・面談の内容が台帳に残らず、対応履歴は全体で8件にとどまっている。

## 論点: 面談の録音ファイルを、LINE音声と同じ流れで台帳に記録するか

### スイシン(推進)
- ドライブの「GLOW音声ログ受付」フォルダに入れるだけで、LINE音声と同じ流れに乗せる。
  - 流れ: 文字起こし・要約 → LINEで確認ボタン → 対応履歴ログ → 企業の関係メモへ要約を追記。
  - 関係メモへの追記は既存の仕組み(lineVoiceLogContent.buildProspectUpdates)。確定時に「【日付 種別(LINE音声)】要約 ▶次: …」を先頭に積む。
- 大きなファイル(1時間のWAVは数百MB)は、ドライブから分割して読み、Geminiのファイル置き場へ分割アップロードする。
  - 1回の実行(6分)で終わらなければ続きは次の実行へ回す。
- 長い面談の要約は、要点ごとに最大8行にまとめる(短いメモは従来どおり2〜3文)。

### ウタガイ(懐疑)
- **面談をまるごと録音したものは、短い口頭メモより機微な情報(財務・後継者・家族の事情)が多い。**
  外部AI(Gemini)へ送る量が増える。
  → 送る先は既存のLINE音声と同じGemini APIで、新しい送り先は増やさない。録音そのものはドライブに残り、台帳には要約だけを書く。相手に録音の同意を取る運用は福田さん側で徹底する(面談冒頭で一言)。
- **ドライブのフォルダを共有すると、権限の管理が増える。**
  → 共有するのは「スタッフ」タブで有効な人だけにする(自己点検で追加のみ。外す操作は人が行う)。
- **誤った会社に記録される恐れ。**
  → LINE音声と同じく、確定前に必ずLINEで会社・内容の確認ボタンを押してもらう。ファイル名の会社名はヒントにとどめ、音声と食い違えば音声を優先する。
- **処理が長時間止まる・二重に処理される恐れ。**
  → 受け付けたファイルは名前に「受付済_」を付け、処理状況タブにもIDを残して二重受付を防ぐ。同じ担当者は1件ずつ処理する。

### ベッカイ(別解)
- LINEのファイル送信で受ける案もある。ただし、Apps Script の通信上限(50MB)を超える長時間のWAVは扱えないため、ドライブ経由を主とした。LINEで送られたファイルも引き続き受け付ける(14MBを超えるものはGeminiのファイル置き場へ送ってから処理し、LINE側の上限50MBまで扱える)。担当者向けの案内は docs/glow-ma_訪問ログの記録方法_担当者向け.md 。
- 文字起こしを外部の専用サービスにする案もある。新しい外部送信先が増えるため、今回は採らない。

### 結論(裁定)
- 採否: 採用(ウタガイの対策を実装に入れた。テスト7件: tests/glow_ma_voice_file_intake.test.mjs)
- 見直し期限: 2027-04-26(録音の件数・誤記録の有無・Gemini費用を見て再評価)

## 追記 2026-10-27: 残高補充後の再開で、大きな録音が取り消された件
- 起きたこと(16:20〜16:23):
  - 福田さんの188MBの録音は、分割アップロードの途中(128MB)で「続きは次の実行で」と順番待ちへ戻った。
  - ところが放置検知が受信時刻(10/26)から数えたため、その録音を「操作がなかった」として取り消した。
  - 別の1件は、前の実行がサーバーエラーで途中終了した後に続きから送ろうとして、送信位置のずれ(wrong offset)でエラーになった。
- 対策:
  - 順番待ち(受信済み)は放置検知の対象から外した(再試行は最大10回で打ち切られる)。
  - 処理中のまま15分進まない行は、取り消さずに順番待ちへ戻す(回数は再試行と同じく数える)。
  - 続きから送る前に、Gemini側が受け取った量を問い合わせ、そこから再開する。ずれは一時的な障害として扱う。
  - 取り消し・エラーになった該当行は、1回だけ順番待ちへ戻す(文字起こしまで進んだ行には触れない)。

## 追記 2026-10-28: 要約は済んだが、確認ボタンが押されないまま取り消された件
- 10/27 夕方、待機から戻った録音は要約まで進み、福田さんのLINEに確認ボタンが届いた。ただ、2時間押されなかったため、放置検知で取り消された(18:23・19:07)。
- 待機から戻った録音が同時に流れ、確認ボタンが複数並ぶ状態にもなっていた。
- 対策:
  - 担当者ごとに確認待ちは1件ずつにする。前の確認が終わるまで、次の録音は順番待ちのまま置いておく。
  - 取り消された該当行は1回だけ順番待ちへ戻し、要約し直して確認ボタンを送り直す。
- 2時間で取り消す決まりそのものは変えていない。長くするかどうかは、福田さんの使い方を見て小柳さんに相談する。
