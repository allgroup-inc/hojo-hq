## 📊 レポート内容と見方

### 1. **架電（昨日/週間/月間）**

**定義**: インタラクションログの「種別」= 「電話」の件数

| 指標 | 対象期間 | 用途 |
|------|---------|------|
| 架電（昨日） | 前日1日 | 昨日の活動量確認 |
| 架電（週間） | 過去7日 | 週間ペースの把握 |
| 架電（月間） | 月初〜当日 | 月間目標進捗 |

**ランク別内訳**（A/B/C/D）:  
企業マスタの「ランク」列から自動判定。ランクが設定されていない企業は D と集計。

**前週比・前月比**: 前週同期間・前月同期間との件数差を表示。  
→ 「+5」なら前週より5件多い、「-3」なら3件少ない

---

### 2. **訪問・面談（昨日/週間/月間）**

**定義**: インタラクションログの「種別」= 「面談実施」の件数

注: スキーマでは「訪問」と「面談」は区別されず、全て「面談実施」として記録されます。

**前週比・前月比**: 架電と同じ考え方。

---

### 3. **成約（月間）**

**定義**: インタラクションログの「種別」= 「成約」の件数

| 計算式 | 説明 |
|-------|------|
| 成約率 = 成約件数 ÷ 訪問・面談件数 × 100 | 訪問・面談からの成約転換率 |

---

### 4. **手紙発送（昨日/週間/月間）**

**定義**: 企業マスタの「最終手紙送付日」= 対象日の企業数

DM（初回・ナーチャリング）やレター発送の実績。

---

### 5. **QRスキャン（昨日/週間/月間）**

**定義**: LINE 公式アカウントからのスキャン数（新規追加ユーザー数）

**現在**: 実装予定中（プレースホルダー = 常に 0）  
→ LINE API 仕様確定後に実装予定

---

### 6. **ランク分布**

全企業のランク別構成（A・B・C・D）を集計。  
例: A: 15社, B: 42社, C: 87社, D: 156社

営業リソース配分の目安。

## ⚠️ トラブルシューティング

### レポートメールが届かない

**症状**: 10:00 に受信されない

**対応手順**:
1. スプレッドシート「日次レポート」を開き、本日の行が記録されているか確認
   - 記録あり → メール配信エラー（次項参照）
   - 記録なし → スクリプト実行エラー（3項参照）

2. **メール配信エラーの確認**
   - Apps Script エディタ → 実行ログ を開く
   - 「エラー通知メール」が 10:05 に takeshi.koyanagi9@gmail.com に送信されているはず
   - エラーメッセージを確認して、以下の対応を試みる

   | エラーメッセージ | 原因 | 対応 |
   |---|---|---|
   | `MailApp.sendEmail() failed` | メール配信権限なし | Apps Script エディタで再認証（Ctrl+Enter で実行） |
   | `Sheet not found: 日次レポート` | シート名変更 | シート名を「日次レポート」に戻す |
   | `Company Master not found` | マスタシート削除 | 企業マスタを復元 |

3. **スクリプト実行エラーの確認**
   - Apps Script エディタ → 実行ログ を開く
   - 10:00 周辺のエラーを探す
   - よくあるエラー:

   | エラー | 原因 | 対応 |
   |---|---|---|
   | `Cannot read property "日付" of undefined` | インタラクションログの列名が変更 | schema.js と整合確認 |
   | `getRankDistribution is not defined` | コード同期失敗 | `git pull` して最新コード取得 |

---

### メール受信後に訂正が必要な場合

**対象**: データ不正（例: 架電件数 0 のはずが 5 件）

**対応**:
1. スプレッドシート「日次レポート」を開く
2. 該当行を手動で修正
3. 翌日以降のレポートで正確性を確認
4. 根本原因調査（フィールド名ズレ、スキーマ変更等）

---

### ランク別架電が全て 0

**原因**: 企業マスタの「ランク」列が未設定 or 企業ID が一致していない

**確認方法**:
1. スプレッドシート「企業マスタ」を開く
2. 「企業ID」列と「ランク」列を確認
   - ランク列が空白 → ランク設定が必要
   - 企業ID が NULL → インタラクションログの企業ID と型が一致しているか確認（数値 vs 文字列）

## ❓ よくある質問

**Q: 昨日のレポートをもう一度実行したい場合は?**

A: Apps Script エディタから手動実行できます。

```javascript
// Apps Script エディタの実行ボタンを使用（関数選択 → 実行）
sendDailyReport();
```

対象日を変更したい場合は、コード内の `getYesterday()` を修正するか、別途実装が必要です。

---

**Q: メールを別のアドレスにも送信したい場合は?**

A: 現在は小柳さんのメールアドレスのみに固定。  
複数配信が必要な場合は、アーキテクチャ検討と決裁が必要です。  
→ CLAUDE.md の「絶対ルール5」（最終決裁は小柳さん）に準拠

---

**Q: スプレッドシート「日次レポート」の行数制限は?**

A: Google Sheets の制限: 1シート最大 1000万行。  
実運用で達するまでには 10年以上かかる見込み（1日1行なら 1年で365行）。
