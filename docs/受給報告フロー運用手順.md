# 受給報告フロー 運用手順(❷ 北極星: 受給できた報告 1,000件)

もらいわすれ堂の北極星は「制度を知らせた → 実際に受け取れた」の積み上げ(受給報告)。
この手順は、LINEに届いた自己申告を、正確性を崩さず・個人情報を持たずに、サイトのカウンターへ反映するための定型運用。
関連: `scripts/add_jukyu_report.py`(追加ツール)/ `scripts/generate_jukyu_counter.py`(検証・集計)/ `data/fukugiiro/jukyu_reports.json`(台帳)/ `docs/フクギイロ_計測レポート設計.md`。

## 全体の流れ(すでに配線済みの部分)
```
利用者(サイト or LINE)
  └「LINEで受給を報告する(匿名・無料)」= /go/fg-jukyu/ → LINE公式アカウント   ← 配線済み
       └ 利用者は「制度名・おおよその金額・市町村」だけ送る(氏名/口座/住所は聞かない)
            └ 検証部(ケンショウ)が seido.json / 公式制度と突合
                 └ python scripts/add_jukyu_report.py で台帳に追加(検証器が守る)
                      └ カウンター自動更新(0件なら準備中のまま/計上があれば公開中へ)   ← サイト表示済み
```

## LINEで利用者に尋ねること(humanizerトーン・PIIは尋ねない)
- 「どの制度でしたか?(例: 児童手当、出産育児一時金 など)」
- 「だいたいいくら受け取れましたか?(おおよそで大丈夫です)」
- 「お住まいの市町村は?(那覇市 など。番地は不要)」
- 尋ねない: 氏名・住所の番地・電話・口座・生年月日・メール(台帳の禁止フィールド)。
- ひとこと添える: 「お名前や口座番号はうかがいません。次の県民のもらい忘れを防ぐために、匿名で集計します。」

## 検証部の判定(status の付け方)
| 状況 | status | verified |
|---|---|---|
| 制度・金額を公式と突合できた | 計上 | true(+ verified-at) |
| 突合中・情報不足 | 保留 | 付けない |
| 制度対象外・重複・いたずら等 | 対象外 | 付けない |
- **計上は必ず verified=true**(未検証の金額は絶対に積み上げない=絶対ルール1「正確性最優先」)。
- 金額は利用者の自己申告(概算可)。断定はしない。

## 追加コマンド(検証後に実行)
```bash
python scripts/add_jukyu_report.py \
  --seido-id fk-kuni-shussan-ichijikin --seido-name "出産育児一時金" \
  --area 那覇市 --amount-type 一時金 --amount-yen 500000 \
  --status 計上 --verified --verified-at 2026-08-10
# 突合できていない場合は --status 保留(--verified を付けない)
# 内容だけ確認: 末尾に --dry-run
```
- ツールが自動で行うこと: ID採番(jr-YYYYMMDD-NN)/ 必須・語彙・日付・金額の検証 / PII値の気配を検知して中止 / seido_id の実在チェック / summary・phase の再計算。
- 検証に通らなければ台帳には**一切書き込まない**。

## 公開前ゲート(CI)
- `python scripts/generate_jukyu_counter.py --check`(検証のみ)
- `python scripts/generate_jukyu_counter.py --self-test`(検証器そのものの eval)
- 変更は feature ブランチ → PR → マージ(mainのCIと競合しないよう pull --rebase)。

## いま人間(小柳さん)がやると開くもの
1. **LINE §D の設定**(あいさつ文→リッチメニュー「中下: 受給を報告する」→テスト配信→運用GO)。原稿は `docs/フクギイロ_LINE運用原稿.md §D`。これで /go/fg-jukyu/ の先が「報告を受け取れる導線」になる。
2. (任意)報告を LINE で受けたあと台帳へ入れる担当(検証部の実務担当)を1人置く。上のコマンド1行で完結。

## 注意(やってはいけない)
- 未検証の金額を「計上」にしない。カウンターを実績より大きく見せない(0件なら準備中のまま正直に出す)。
- 個人が特定される情報を台帳・リポジトリに残さない。
- 受給の可否・金額を断定しない(最終判断は各窓口)。
