## ブロッカー1: 新しい担当者を登録する手段が存在しない

### 症状

嶺井さんが音声を送っても「担当者が特定できませんでした」で止まり、**先に進む方法がありません。**

### 原因

LINE User IDを取得する唯一の仕組み（スクリプトプロパティ `LAST_LINE_USER_ID`）が、
コミット `433fee372`（2026-08-22）で削除されています。コミットメッセージのとおり
「小柳さん・福田さんでの実機確認が完了しているため」削除されたものですが、
**以後に担当者を追加する経路まで一緒に消えていました。**

READMEは現在も「実行ログからLINEユーザーIDを確認し…」と書いていますが、
`handleAudioMessage_` は担当者未特定の時点で `return` しており、
`Logger.log` も `appendVoiceLogRow_`（LINEユーザーID列への書き込み）も通りません。
**実行ログにIDは1行も出ていません。**

### 入れた修正

未登録者への返信に、その人自身のLINE User IDを併記します。実行ログにも出します。

```
担当者が特定できませんでした。管理者に「スタッフ」タブへの登録を依頼してください。

----------
このメッセージをそのまま管理者に転送してください。
LINE User ID: U0123456789abcdef0123456789abcdef
```

実行ログを掘る運用に戻すより、本人に転送してもらうほうが速く確実です。
返すのは本人自身のIDのみで、他人の情報は含みません。
引数なしで呼べば従来どおりの文面を返すため、後方互換です。

## ブロッカー2: 「対応相手」の未判別警告が一度も出ていない

### 症状

`b77e425f9` で「判別できない場合は推測で決めつけず『不明』と出力させる」修正が入りましたが、
**その意図は実装に届いていません。** 未判別の訪問はすべて、警告なしで
「経理・総務等の窓口担当」として確定・保存されています。

### 原因

`processOneVoiceLog_` が、シート保存と確認メッセージ生成の**前**に
`normalizeRespondentType()` を通しています（L485）。

```
Gemini: "不明"
  → L485 normalizeRespondentType("不明") → "経理・総務等の窓口担当"
  → L513 buildFinalConfirmPrompt(..., "経理・総務等の窓口担当", ...)
  → isRespondentUncertain("経理・総務等の窓口担当") === false
  → 警告は付かない
```

`buildFinalConfirmPrompt` 内の警告分岐（L218-221）は**到達不能なコードでした。**
Nodeで実行して確認済みです。

### なぜ実害があるか

`calculateReactionScore` の `decisionMakerBonus`（+15点）は
`row["対応相手"] === "オーナー社長本人"` の完全一致のみで加点します。
未判別のまま「窓口担当」で保存されると、**社長に会えている会社に15点が付きません。**
ランクB=40点／A=70点の境目を15点が動かすため、最重要の会社が埋もれます。

### 入れた修正

1. `processOneVoiceLog_` で正規化せず、生の値のまま持ち回す
   → 警告が正しく出るようになる
2. 未判別のとき、内容メモの先頭に `【対応相手 要確認】` を付ける
   → 台帳を「要確認」で検索するだけで訂正対象を拾える

**列は増やしていません。** 対応履歴ログの「対応相手」列は
`buildInteractionLogRow` が従来どおり正規化するため、
入力規則（`RESPONDENT_TYPES` の3値）に必ず収まります。
既存データ・ダッシュボード集計への影響はありません。

音声ログ処理状況タブの「対応相手候補」列には「不明」が入るようになりますが、
同タブには入力規則が掛かっていないことを `SheetSetup.gs` で確認済みです。
