# 議事: カチトーク催事版(他社向けトークレベル管理)の設計方針(2026-09-10)

**発端**: 小柳さん指示「カチトークの仕組を他企業の仕組にあわせて作りたい」(2026-09-10・本チャット)。
ヒアリングの結果、対象は**特定の1社(催事場で保険アポ・インターネット・リユース・携帯などを案内する会社)**で、
目的は**スタッフの案内トークのレベルを管理し、レベルを上げること**。採点対象は**本番の接客の録音**。

※ 本リポジトリは公開のため、相手企業の社名・個別条件はここに書かない(機密区分ルール)。
※ 既存の商品設計「催事ログ解析v1」(docs/商品設計_催事ログ解析_v1.md)と同じ商品群に属する案件。
  同v1の開始条件(セキュリティ関門5点)はそのまま本件にも適用する。

## 論点: カチトークを他社催事向けにどう作るか(作り方3案)

- 案A: 今のカチトーク(本社ログシステム)に「会社」「商材」の区分を足して相乗り
- 案B: カチトークの仕組みを複製し、その会社専用の環境(LINE公式アカウント・保存場所・台帳)を別に立てる
- 案C: 催事特化の軽量版を一から新規開発

### スイシン(推進)
- カチトークは「録音→文字起こし→PIIマスク→採点→台帳→結果回収」まで実証済み。複製(案B)なら実績ある流れをそのまま使え、催事向けの差分(商材別採点基準・スタッフ別レベル表)だけ作ればよい
- 催事ログ解析v1が「未実証」のままだった弱点を、この1社への導入がそのまま実証(ゲート0相当)として埋める。商品化の柱(値札3つの催事ログ)に直結する
- 人手入力は「録音を送る」「結果ボタンを押す」の2つだけ。カチトークの教訓「自動で埋まらない項目は現場は埋めない」を踏襲できる

### ウタガイ(懐疑)← 空欄不可
- **本番接客の録音にはお客様の声が入る**。告知(掲示+一言)と催事会場側の許可なしに録れば、相手企業ごと信用を失う。守り部審査+外部専門家確認(商品設計v1 §3)の**前に実データを1件でも流したら終わり**
- **採点・レベルは販売員個人の評価に直結する情報**。「育成目的に限る」を契約に明記しないと、人事評価への流用でスタッフの反発・紛争リスクを相手企業に持ち込む
- **催事場は騒音・短時間接客**で、文字起こしと採点の精度が本社商談より確実に落ちる。精度が低いまま採点すると、誤った低評価がスタッフを傷つけ、仕組みごと不信を買う。**試験期間の合格条件に「精度の人手確認」を入れるべき**
- 相手企業には録音送信の習慣がない(カチトークは録音習慣が既にある営業に乗せたから成功した)。**「録ってもらえない」が最大の失敗パターン**。録音率を月次で測り、低ければ設計を見直す仕組みが要る
- 案Aは論外に近い: 他社のお客様の声と自社商談データの同居は、漏えい時に説明不能

### ベッカイ(別解)
- 全接客を録るのではなく、**「1日の代表数件だけ録る」から始める**案。負荷・データ量・同意リスクが下がり、レベル判定には十分な標本が取れる
- お客様の声を録らず、**スタッフ側の声だけ拾う録り方(ピンマイク等)**を技術検証する価値はある。同意問題が大幅に軽くなる
- AI採点をいきなり正とせず、**最初の1か月は人(教育担当)が録音を聞いて採点し、AI採点は突き合わせの補助**とする案。精度検証と採点基準の納得感づくりを兼ねられる

### 結論(裁定)
- 採否: **案B採用(小柳さん決裁 2026-09-10・本チャット)**。データ完全分離を最優先とする
- 条件(ウタガイ・ベッカイの反映):
  1. 守り部審査+外部専門家確認+NDA/覚書(商品設計v1 §3の関門)を通るまで**実データ解禁しない**(合成・ロープレ音声での検証は可)
  2. 契約書に**「採点・レベルは育成目的に限る」**を明記
  3. 試験運用は**「1日の代表数件」方式**+**人手採点との突き合わせ**から始め、精度確認を合格条件にする
  4. **録音率(録るべき接客のうち実際に録れた割合)を月次で測る**。5割を切ったら設計を見直す(カチトークの「言い忘れ率」ルールの流用)
- 理由: 他社のお客様の声という最高感度のデータを扱う以上「物理的に別」が最も安全で説明しやすく、かつ実証済み資産を最大限流用できるため。ウタガイの懸念はすべて開始条件・運用ルールとして組み込んだ
