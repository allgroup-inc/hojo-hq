# みらいひらけ堂 試写と検査の自動化(2026-09-21)

トップの世界観フィルム(夜→朝・5シーン)は、写真の境目やアニメーションを**人が目で見て**確かめていた。
その手作業をコマンド1つと GitHub Actions に置き換えた。

## 何が自動になったか
| 手作業だったこと | 自動化後 |
|---|---|
| CSS・JS・写真を1ファイルに埋め込んで試写用HTMLを作る | `scripts/miraihirake/build_preview.py` |
| ブラウザで開き、境目・コメント・ロゴのアニメーションを目視 | `scripts/miraihirake/check_film.js`(Playwright)が撮影して機械判定 |
| 「境目に硬い線が出ていないか」 | 境目付近の行ごとの明るさの飛びを測り、上限(既定10)を超えたらNG |
| 「アニメーションが動いているか」 | 全シーンに `.in` が付き、虹3本が描き切られ、朝日が出たかを確認 |
| 変更のたびに上を繰り返す | `.github/workflows/miraihirake-film-check.yml` が push/PR ごとに実行し、成果物として残す |

## 使い方
- 手元: `bash scripts/miraihirake/preview.sh` → `dist/miraihirake/preview.html` を開く。撮影画像は `dist/miraihirake/shots/`、判定は `report.json`
- GitHub: `site/miraihirake/` を変更して push すると Actions「miraihirake-film-check」が動く。Actions の実行ページ下部の成果物 `miraihirake-preview-<sha>` を落とすと同じものが入っている
- Claude に「最新の試写を見せて」と言えば、`preview.html` をそのままアーティファクトとして公開する(公開判定前は GitHub Pages で配信しないため、この経路が正)

## 境目を消す作り(もらいわすれ堂と同じ発想+一歩先)
1. 背景は段差のない1枚のグラデーション(`.mfilm`)
2. 各写真は上下30vhずつ隣のシーンへはみ出し、上下端を透明に溶かす(`.photoback` のマスク 42/58%)
3. 後のシーンほど上に重なるので、次の写真の透明な上端から前の写真の下端が透けて、**前の写真が消えながら次の写真が現れる**(オーバーラップ)
4. 実写のシーンでは影絵の丘・集落の灯りを消す(硬い直線が境目に見えるため)

## 見直し期限
2027-03-21(6ヶ月)。上限値10は実測から置いた数字: 現行の作りは3か所とも 2〜3点、わざと硬い境目を作った版(丘を戻す・写真のはみ出しと溶かしを無効化)は 15〜26点(2026-09-21・スマホ幅420px)。誤検知・見逃しが出たら `--seam-max` で調整し、この文書に実測を追記する。
