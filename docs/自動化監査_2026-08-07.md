対象: GitHub Actions cron群(update-subsidies/fukugiiro-fetch/週次・月次レポ/監査/healthcheck/e2e/lighthouse/verify-sources/social-post/note系)+ Claude Routines(進捗ループ/拡充ループ/成功事例ウォッチ)。
スキル `resilient-agent-design` のチェックリストに沿って点検。**今回の修正1件は即実装済み**、残りは提案として記録。

## 総評
基本設計は既に型どおり(コード主体のWorkflow+要所だけAI判断+self-test+失敗時Issue/LINE通知)。
致命度の高い欠陥は1つだけ見つかり、**修正済み**。

## ✅ 今回修正したもの(1件・致命度高)

**push起動ワークフローのブランチ無制限**
- 症状: fetch等5本が「どのブランチへのpushでも起動→そのブランチへbotがコミットバック」する設計だった。作業ブランチにbot再生成が混入し、マージ競合を繰り返す実害が本セッションでも複数回発生(7/25のPR#6監視ループ・8/7のmain統合競合)。
- 対応: `fukugiiro-fetch / fukugiiro-audit / fukugiiro-weekly-report / mikata-audit / weekly-report` の push トリガーに `branches: [main]` を追加。fetchの`git push`先を`origin main`に明示。スケジュール実行(main上)は従来どおり。
- 該当原則: ④べき等性(意図しない対象への副作用防止)・⑥権限最小(書き込み先の限定)。

| 4 | 副作用のべき等性 | ⚠️→✅ | ブランチ無制限push(上記)を修正。LINE配信系はschedule+dispatch限定で重複配信リスク低。**残提案**: weekly-reportのLINE実弾配信に「同日送信済みならスキップ」のidempotency_key(data/に送信記録)を追加すると再実行に強くなる |

| 7 | Hook・最低限ログ | ✅ | 実行ログ=Actions、状態遷移=Gitコミット履歴、失敗通知=Issue+LINE。stop-hookで署名チェックも稼働 |
| 8 | 文章ルールのコード化 | ✅ | 禁止語=validate/check_lpで強制、締切表現=スキル+検証器、PII=非コミット運用。「文章だけで守っている」ものは検出されず |
