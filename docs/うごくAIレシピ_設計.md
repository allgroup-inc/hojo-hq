## コンセプト

**「うごくAIレシピ」— 公開前に機械で実際に動かした、実行ログ付きのAI仕事レシピ**

- 売り物は「情報」ではなく「動く成果物」: コピペで使えるプロンプト+手順+実際の実行ログ
- 差別化の核: 全レシピを公開前にCI(GitHub Actions)上でClaude APIに実行させ、**生の実行ログを紙面に載せる**。
  手作業のプロンプト販売者には構造的に真似しづらい
- 誠実性: 載せるのは実際に動かした結果だけ。体験談の捏造はしない(絶対ルール1の汎用適用)
- 検証環境の明記(「検証はClaude(claude-opus-5)で実施」)を**バリデーションで機械強制**。欠落したら生成失敗扱い

| Guardrail | バリデーション不合格=フェイル(捏造フォールバックなし・お題は持ち越し)/ BANNED_WORDS / 必須文言 / API最大2呼び出し/回 / 公開は人間ゲート |

### 7原則の適用

1. **判断だけAIへ**: キュー管理・日付・べき等性・検証判定・組版・通知はコード。レシピの中身と実行だけAI
2. **完了条件はシステム判定**: 必須セクション有無/検証文言/実行ログ非空/文字数上限/BANNED_WORDSをコードで判定
3. **状態は外部保存**: data/airecipe_topics.json(status: pending → drafted(日付付き))+ data/airecipe_kpi.json(実売台帳)。Gitコミットが監査ログ
4. **べき等性**: 記事ファイル名=お題ID固定(posts/airecipe/NN_slug.md)。同日再実行は同ファイル上書き。お題statusはコミット成功と同時に更新
5. **リトライ上限**: git push リトライ3回。API失敗はワークフロー失敗→LINE通知(無限リトライなし)
6. **最小権限**: contents:write のみ。note公開・価格変更・X投稿は人間
7. **監視**: 失敗時LINE通知+下書き完成通知に未公開在庫本数を同梱(4本以上で警告=静かな空回りの検知)。
   通知は専用LINE(AIRECIPE_LINE_*)のみ。他事業LINEには流さない(2026-08-09 小柳さん指示・docs/うごくAIレシピ_LINE開設キット.md)

## タイトル公式(2026-08-09 バズ要素リサーチより追加)

世の中で「クリックされる・売れる」タイトルに共通する要素(2026年のnote攻略記事・約30件の売れ筋分析の傾向):

1. **数字のギャップ**: 「30分→1分」のようなビフォーアフターの具体数字。曖昧な「すごい方法」はクリックされない
2. **悩みの言語化**: 読者が「今まさにそれで困っている」と感じる一文(問いかけ型)
3. **条件の軽さ**: 「貼るだけ」「コピペするだけ」= 行動コストの低さを見せる
4. **常識破り**: 「議事録は会議後に書くものではなくなった」のような前提をひっくり返す型
5. **ベネフィット明示**: 読後に何が変わるかがタイトルだけで分かる

これを機械化した内容:
- 本題タイトル = **【作業の悩み】×【数字のギャップ】×【条件の軽さ】** の公式で生成(数字はお題のuse_caseにある実数のみ・捏造禁止)
- 加えて**タイトル別案2つ**(悩み言語化の問いかけ型/常識破り型)を毎回自動生成し、記事冒頭の削除ブロックに同梱。公開時に人間がしっくり来るものを選べる
- 煽り(緊急性の偽装・成果断定)は採用しない: 禁止語検査と免責で機械的に排除(信頼が売りの媒体のため)
- 公開後どのタイトル型が売れたかは data/airecipe_kpi.json の実売記録で振り返る(タイトル型の勝ちパターン学習)
