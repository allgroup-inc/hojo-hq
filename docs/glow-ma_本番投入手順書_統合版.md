# GLOW企業リレーション台帳 — 本番投入 実行手順書(Phase 1〜16 統合版)

**対象**: 実際のGoogleスプレッドシート・Apps Scriptエディタを操作できる人(たかしくん、または権限を持つ人)
**位置づけ**: `glow-ma/README.md`はPhase別の設計・使い方リファレンス。こちらは「今この状態のコードを、
実際に動くシステムにするには何をどの順で実行すればよいか」だけを1本にまとめた実行用チェックリスト。
コード側(このリポジトリのmainブランチ)は既にPhase 1〜16まで実装・テスト済み。ここから先はすべて
Googleスプレッドシート・Apps Scriptエディタ上での人間の作業になる。

実データを一切扱わない項目(A・D・E)はどのタイミングで進めても安全。実データに触れる項目
(B・F・G)は、末尾の「本番投入前チェックリスト」を満たしてから着手すること。

---

## A. 初回セットアップ(GASプロジェクトがまだ存在しない場合)

1. `npm install -g @google/clasp`(未導入の場合)
2. `clasp login` でGoogleアカウント認証
3. 新規スプレッドシートを作成し、「拡張機能」→「Apps Script」からスタンドアロンスクリプトを
   作成する(この作成方法だとスプレッドシートに自動で紐付く)
4. `glow-ma/.clasp.json.example` を `glow-ma/.clasp.json` としてコピーし、`scriptId` を
   実際のスクリプトIDに書き換える(**このファイルはコミットしない**)
5. `cd glow-ma && clasp push` でコードを反映する
6. Apps Scriptエディタで **`ensureLedgerTabs`** を実行する

   → これ1回で、企業マスタ・対応履歴ログ・紹介パートナーマスタ・設定・レター下書き・
   ダッシュボード・ダッシュボード履歴・スタッフ・パートナー対応履歴ログ・紹介実績ログの
   10タブが、Phase 1〜16で追加された全列(発送日・関係メモ・窓口担当者名・携帯番号・
   後継者状況 等)込みで一度に作成される。個々のPhaseごとに何度も実行し直す必要はない。

新規セットアップの場合はここでB章は不要。C章(Script Properties)以降へ進む。

## B. 既存スプレッドシートをPhase 16まで追従させる場合(既に運用中のケース)

1. `cd glow-ma && clasp push` で最新コードを反映する
2. Apps Scriptエディタで **`ensureLedgerTabs`** を再実行する

   → `ensureTab_`(`glow-ma/src/SheetSetup.gs`)は各タブの**1行目(見出し行)だけ**を
   現在の`schema.js`の定義で上書きする実装のため、**2行目以降の既存データには触れない**。
   途中のPhaseから止まっていても、1回の実行で最新(発送日列を含む)まで追いつく。
   逆に言えば、実行するたびに見出し行は必ず上書きされるので、見出しセルを手動で
   書き換えている場合はその変更は失われる(データ行には影響しない)。
3. 下記C・Dのうち、まだ設定・実行していないものだけを行う(重複実行しても安全)

## C. Script Properties(スクリプト プロパティ)一覧

Apps Scriptエディタの「プロジェクトの設定」→「スクリプト プロパティ」で設定する。
**値をコードに直接書かないこと。**

| キー | 用途 | 値の取得元 | 導入Phase |
|---|---|---|---|
| `SLACK_WEBHOOK_URL` | 掘り起こしアラート(日次・Incoming Webhook) | Slackで対象チャンネル用Webhookを発行 | 3 |
| `ANTHROPIC_API_KEY` | レター下書き生成(Claude API呼び出し) | Anthropicのアカウント | 4 |
| `TRACKING_BASE_URL` | レターURLアクセスの反応計測 | 下記Eでデプロイする Web App のURL | 4 |
| `TRACKING_REDIRECT_URL` | 反応計測後の遷移先ページ | 案内したいページのURL(例: 沖縄企業のミカタのトップページ) | 4 |
| `SLACK_BOT_TOKEN` | 対面連携のSlack DM送信(`xoxb-`で始まる) | 下記Fで作成するSlack Appから発行 | 15 |

`TRACKING_BASE_URL`/`TRACKING_REDIRECT_URL`・`SLACK_BOT_TOKEN`は、それぞれE・Fの機能を
使わないなら未設定のままでよい(未設定時はその機能だけが動かない設計で、他機能には影響しない)。

## D. インストール型onEditトリガー一覧

Apps Scriptエディタの関数選択で以下を**それぞれ一度だけ**手動実行する(初回実行時は
権限承認ダイアログが出るので許可する)。どちらも冪等(同名の既存トリガーを削除してから
登録し直す実装)なので、何度実行し直しても安全。

| 関数名 | 役割 | 導入Phase |
|---|---|---|
| `installInteractionLogEditTrigger` | 対応履歴ログへの反応イベント入力を検知し、即時アラート(Speed to Lead)をSlackへ送る | 3 |
| `installLetterDraftEditTrigger` | 「レター下書き」タブの発送日入力を検知し、次回アクション予定日の自動セット・対応履歴ログへの自動記録を行う | 16 |

さらに、時間主導トリガーを1件、Apps Scriptエディタの「トリガー」画面から**手動で登録**する:

- `runDailyAlerts` を毎日1回の時間主導トリガーとして登録する
- 登録時、トリガー編集メニューの「失敗通知の設定」を**必ず「毎回通知を受け取る」に設定する**
  (Slack自体が長時間ダウンした場合など、コードのリトライだけでは検知できない障害を
  人間が気づけるようにするため。Phase 14)

## E. Web Appデプロイ(レターURLアクセスの反応計測。使う場合のみ)

1. Apps Scriptエディタ「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」
2. 実行ユーザー: **自分**(「アクセスしているユーザー」にすると、手紙を受け取った
   企業側の担当者がGoogleアカウントなしでアクセスできなくなるため誤り)
3. アクセスできるユーザー: **全員**
4. デプロイ後に発行されるURLを、C章の`TRACKING_BASE_URL`に設定する
5. C章の`TRACKING_REDIRECT_URL`(案内したい実際のページ)も設定する

## F. Slack App作成(対面連携のSlack DM送信。使う場合のみ)

1. https://api.slack.com/apps で新しいSlack Appを作成する
2. 「OAuth & Permissions」→「Bot Token Scopes」に **`chat:write`のみ** を追加する
   (原則「権限は最小限から」。それ以外のスコープは付与しない)
3. ワークスペースにインストールし、発行されたBot User OAuth Tokenを、C章の
   `SLACK_BOT_TOKEN`に設定する(**このトークンは絶対に外部へ持ち出さない**。
   `SLACK_WEBHOOK_URL`とは別物で、こちらは個人へのDM送信権限を持つため取り扱いに一段注意)
4. 「スタッフ」タブに、連携対象にしたい社員の「氏名」「Slack User ID」を入力し、
   「有効」列にチェックを入れる
   (Slack User IDの調べ方: Slackで対象社員のプロフィールを開き「その他」→
   「メンバーIDをコピー」。`U`から始まる文字列で、メールアドレスではない)

## G. データ投入・初期集計(実データを扱う。本番投入前チェックリストを満たしてから)

1. **7000件リストのインポート**(初回のみ): スプレッドシートに「インポート待ち」タブを作り
   元データを貼り付け → `glow-ma/src/ImportRunner.gs`の`IMPORT_COLUMN_MAP`を実際の見出しに
   合わせて書き換え → `clasp push` → `importCompaniesFromStaging`を実行
2. **スコア・ランクの再計算**: `recalculateAllScores`を実行(企業マスタの初期スコア・
   反応スコア・総合スコア・ランクが更新される)
3. **ダッシュボード集計**: `updateDashboard`を実行(「ダッシュボード」タブと
   「ダッシュボード履歴」タブが更新される)

以降の運用(掘り起こしアラート・レター下書き生成・発送日記録・CSV出力・対面連携)は、
`glow-ma/README.md`の各Phaseセクションの「使い方」を参照。

- [ ] 未一致が1件以上あった場合、「事前選定_未一致」タブに会社名一覧が自動で追記されていることを確認する

      (事前選定スコアが0の企業は、加算前と同じ初期スコアになっていることも確認する)
- [ ] 見出しが異なる2つ目以降のファイルを取り込む場合、`PRE_SCREENING_COLUMN_MAP`を書き換えてから
      再実行することを確認する
