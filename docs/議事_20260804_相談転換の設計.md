# 議事 2026-08-04 — 相談転換の設計(お客様が「相談したい」と思う状態をどう作るか)

参加: スイシン/ウタガイ/ベッカイ(トライアングル体制)・裁定=LINE部長 / 最終決裁=小柳さん

## 論点: サイト訪問者・LINE登録者が「相談したい」と思う状態をどう作るか

### スイシン(推進)
- 「相談」という言葉を軽くする(LINEに「相談」と一言でOKの導線・無料/売り込みなしの明記)
- 相談の「瞬間」を捉える(締切アラート受信時=間に合うか不安 / 診断結果で書類の大変さを見た時)。既存配信の文面に一行足すだけで効く
- 「相談したらどうなるか」を見せる(3ステップ図解: LINEで一言→担当が返信→必要なら嶺井が直接・訪問)

### ウタガイ(懐疑) ※反対理由の記録
- **受け皿が先**: 誰が対応するか未確定のまま相談を集めると、返信遅延で信頼をむしろ毀損する。集客より対応体制の決定が先
- 「無料でチェックします」系の表現は申請代行(士業法・絶対ルール③)に近づく。守り部基準の文言に限定すること
- ハードルを下げすぎると冷やかしが増え、真のKPI(面談転換)の質が下がる懸念
- 事例掲載は本人許諾と正確性照合が必須(今回は見送り)

### ベッカイ(別解)
- 「相談したい気持ちを作る」のではなく「相談が必要だと本人が自覚する装置」(申請前チェックリスト)を配る案
- 新規より既存300社基盤への逆流(顔見知り経由)の方が相談転換率は高い(配布キットが入口)

### 結論(部門長の裁定)
- **採否: 段階採用**。①アラート・診断結果への相談トリガー文言 → ②LINEボットの相談一次受付 → ③相談の流れ図解 → ④チェックリスト型は②③の反応を見てから
- **理由**: 新規開発ほぼゼロで既存導線に「相談への橋」を足すだけで試せる。ウタガイの「受け皿が先」は小柳さんへ上申した
- **見直し期限**: 2026-11-04

## 小柳さん決裁(2026-08-04)
> 「まずは③(技術部が一次対応)で。その後自分が確認してシステムに連携して嶺井さんへつないで訪問、って感じ」

**確定フロー**: ボット一次受付(自動返信) → 小柳さんのLINEへ即時通知 → 台帳に記録(経路line-consult) → 小柳さんが確認・返信 → 必要案件は嶺井さんへ接続 → 訪問・面談(=真のKPIカウント)
