# 診断動線 ゼロベース再設計(単一スクロール・入口一本化)
作成: 2026-07-27 / 決裁: 小柳さん(2026-07-27 承認) / 起案: 技術部
関連: [引き継ぎ台帳](引き継ぎ台帳.md) / スキル準拠: brainstorming(設計ゲート)・hojo-triangle-review・hojo-accuracy-check・hojo-deadline-alert・go-link-discipline

## 目的
利用者が上から下へスクロールするだけで、迷わず・打ちやすく・分かりやすく ❶〜❼ を進める。
企業情報の入力箇所を「1つ」に統一し、LINEとサイトの二重入力による混乱をなくす。

## ❶〜❼ の目標フロー
1. **❶** 4つを選ぶ(市町村/業種/従業員数/経営テーマ)。「10年後」は任意
2. **❷** 1件だけ全表示+残りぼかし+**合計の可能性(最大金額の合算)を隠す**
3. **❸** それを見るためにLINE登録(無料・10秒・1ボタン)
4. **❹** 登録して戻ると ❷ が全解禁(端末記憶=localStorage・実装済み)
5. **❺** 企業情報を入れてLINEで送りたくなる導線(限りなく打ちやすく)
6. **❻** 企業とつながり情報が蓄積(裏側=GAS台帳・基準❺着工後)
7. **❼** 専門家誘導/連携が始まり、その中でM&A予備群に分かれていく

## 三名体制レビューの裁定(要点)
- **論点1(入力箇所の一本化)**: 採用=「サイト内の1フォーム」に統一。
  **PIIはサイトに保存せず、記入内容をLINEメッセージにセットして送るだけ**を厳守(法務ライン)。
  「LINEを開いて自分で打つ」重複導線は撤去。
  ※ベッカイ案「会社情報はLINEトーク内で会話収集」は登録率向上の有力案だが、
  LINE自動応答設計に関わるため **LINE部+小柳さん決裁事項として次段に保留**。
- **論点2(❷の隠す/見せる)**: 採用=1件+残りぼかし+合計金額を隠す。
  合計は「**公募上限額の単純合算・参考値・受給を保証しない・中小向けレンジ(上限1億円以下)に限定**」表記を厳守(`hojo-accuracy-check`)。
- **論点3(gBizID)**: 採用=メイン動線から外し、結果最下部の折りたたみ+制度カードのバッジに集約。
  冒頭・スクロール途中には置かない。gBizIDは❶〜❼を進めるゲートではない(必要なのは申請直前・約140/147件のみ)。

## 実装方針(競合最小化)
- `site/index.html` は複数チャットが同時編集中のため、**全面書き換えは禁止**。差分を当て込む。
- 既存実装で流用: localStorage解除(❹)、会社情報フォーム→LINE送信(❺)、総額ポテンシャル(❷)、gBizID折りたたみ(❼)。
- 本改修のスコープ:
  1. 企業情報の入口を1つに(重複導線があれば撤去/統合)
  2. ❷で合計金額をロック対象に含める(解禁前は隠す)
  3. gBizIDがメイン動線に露出していれば最下部へ
  4. スクロールで迷わない導線(選択→自動で次へ/結果へ戻る動線)の点検

## 受け入れ基準
- 企業情報の入力箇所がサイト上に**1つだけ**(LINE直打ちの重複導線なし)
- PIIがサイト側に保存・送信されない(LINEメッセージへのセットのみ)
- 未登録時: 合計金額と残り制度が隠れている / 登録後: 全解禁
- gBizIDはメイン動線に出ない(最下部折りたたみ+カードバッジのみ)
- E2E(診断→結果→LINE導線)がグリーン
- Lighthouse 4項目95以上を維持
