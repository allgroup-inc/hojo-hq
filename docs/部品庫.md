# 部品庫 — 作ってきた仕組みを「小分けに取り出す」ためのカタログ

最終更新: 2026-10-01(月1棚卸し) / 管理: 統括(アカリ) / 見直し期限: 2027-03-07

**目的**: 今まで作った仕組み・考え方・コードを、次の開発や類似システムの
販売(売り切り・手離れ)のときに、探さずすぐ取り出せるようにする。
新しい仕組みが1つ完成したら、この表に1行足す(全体マップと同じ運用)。

**実績**: この方式の第1号は山梨版。沖縄の部品を組み合わせて第1段階を
1チャットで公開まで持っていけた(docs/連携メモ_20260903_山梨版への沖縄資産引き継ぎ.md)。

## D. 類似システムを作って売る(手離れさせる)ときの手順

1. **部品を選ぶ**: この表から必要な行だけ選ぶ(全部渡さない)
2. **機密を抜く**: 顧客データ・APIキー・営業数値・固有名を除去。
   `check_repo_scope.py`の検査を流用して機械チェック
3. **固有名の置換はassert方式**: 山梨版ビルダーと同じく「置換されたことを機械が確認」する形にする(手作業の置換漏れが一番の事故源)
4. **運用の型もセットで渡す**: コードだけ渡すと手離れしない。B(運用の型)とC(スキル)を含めて「AIごと引き継げる」形にすると保守依頼が減る
5. **地雷リストを添付**: 山梨連携メモ§3の形式で「先に踏んだ失敗」を渡す
6. **販売条件・価格は小柳さん決裁**(絶対ルール5)。外部提供前に守り部審査
