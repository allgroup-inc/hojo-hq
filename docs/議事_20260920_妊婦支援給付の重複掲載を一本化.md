# 議事: 妊婦のための支援給付の重複掲載を一本化する(2026-09-20)

**種別**: 不可逆な変更(データ削除)= 憲法ルール8②により議事必須
**起案**: 出典URL棚卸し中に、同一URL `cfa.go.jp/policies/shussan-kosodate` を共有する2件を検知
**決裁**: 小柳さん(2026-09-20「一本化してください」)

## 論点: `fk-kuni-ninpu-shien` を削除し `fk-kuni-shussan-ouen` へ一本化するか

### 対象

| id | name | 定義元 | 内容 |
|---|---|---|---|
| `fk-kuni-ninpu-shien`(削除) | 妊婦のための支援給付・伴走型相談支援 | `fetch_fukugiiro.py` L113 | amount_note が「要確認」のみで**中身が無い** |
| `fk-kuni-shussan-ouen`(存続) | 出産・子育て応援給付金(**妊婦のための支援給付・伴走型相談支援**) | `fetch_fukugiiro_extra.py` | 計10万円相当(妊娠時5万+出産時5万)・併給注意あり |

### スイシン(推進)

- 同一制度が診断結果に2件並び、利用者を混乱させている。掲載制度数も1件過大に数えられる
- 存続側は削除側の**上位集合**: life_events は `['妊娠・出産','子育て']` ⊇ `['妊娠・出産']`、
  how_to_apply は「母子保健・**子育て支援**担当」⊇「母子保健担当」、併給注意(combine)も存続側のみ
- 存続側の名称が削除側の名称を**括弧で内包**しているため、検索・診断の受け皿は失われない
- 受給報告台帳(`jukyu_reports.json`)からの参照は **0件**。データ損失なし

### ウタガイ(懐疑)

- **存続側の名称が古い可能性がある。** 「妊婦のための支援給付」は子ども・子育て支援法上の
  新しい給付名で、「出産・子育て応援給付金」は先行事業の呼称。新名称で検索する利用者から見て
  「出産・子育て応援給付金」が主名称なのは実態と逆行しうる
- 生成物45ファイル(市町村ページ・準備シート・sitemap)に参照があり、再生成が必要。
  **山梨版(`build_yamanashi.py`)は `data/fukugiiro/seido.json` から生成されるため波及する**
- 削除側の `deadline_type: 常時` という情報は失われる(存続側は「要確認」)。
  安全側には倒れるが、情報量としては後退
- 一度消すと、後から「やはり別制度だった」と分かった場合の復旧は手間

### ベッカイ(別解)

- 削除せず、**存続側の名称を実態に合わせて改める**案:
  「妊婦のための支援給付(旧: 出産・子育て応援給付金)」とし、削除側を統合する
- あるいは両方残し、削除側を「総合案内」として位置づけ直す案。ただし現状の削除側は
  中身が空でありこの役割を果たせていない
- そもそも重複が生まれた原因は、**コアシード(`fetch_fukugiiro.py`)と追加シード
  (`fetch_fukugiiro_extra.py`)を別々に育てており、ID重複ではなく「同一制度の別ID」を
  機械検査していない**こと。個別対処より、同一 source_url の重複を検知する仕組みが本筋

### 結論(部門長の裁定)

- **採否: 採用**(`fk-kuni-ninpu-shien` を削除し `fk-kuni-shussan-ouen` へ一本化)
- **理由**:
  - ウタガイの「名称が古い」懸念は重要だが、存続側の名称が**両方の呼称を含んでいる**ため、
    どちらで検索しても到達できる。名称の最適化は掲載方針の判断として別途行う(下記申し送り)
  - 受給報告0件・存続側が上位集合であり、実害のある損失がない
  - 山梨版への波及は、**向こうにも同じ重複が存在するため是正**であり、副作用ではない
  - ベッカイの「検査の仕組み化」は正しい。個別対処と併せて同一 source_url の検知を
    週次レポの品質欄で見えるようにする(今回は記録のみ・次の着手対象)
- **申し送り(小柳さん判断)**: 存続側の名称を「妊婦のための支援給付(旧: 出産・子育て応援給付金)」へ
  改めるかは掲載方針の判断。制度の正式名称の変遷を確認したうえで決めたい
- **見直し期限: 2027-03-20**(6ヶ月)

## 実施中に判明した別件(未対応・要判断)

### A. 高等学校等就学支援金・高校生等奨学給付金がサイトから欠落している

`fetch_fukugiiro.py` のシードには両方とも存在するのに、`data/fukugiiro/seido.json` に
**1件も出力されていない**(名称・別IDでの代替も無し)。

収集処理は `reachable()` が HTTP 200 を返さないシードを「URL到達不可」として
**黙って落とす**設計になっている。文部科学省のページがbotを弾いていれば、
制度ごとサイトから消える。13件の市町村サイトと同じ「bot遮断」が原因の可能性が高いが、
市町村側は `assume_reachable=True` で救済されているのに対し、この2件には付いていない。

高校授業料の支援は「もらい忘れ」が起きやすい代表的な制度であり、欠落の影響は大きい。
**対処案**: 市町村と同じ手順(WebSearchで公式URLを確認 → `assume_reachable=True` を付与)。
ただし出典URLの確認が要るため、AI側では未実施。

### B. 山梨版が沖縄版と同期していない

`site/yamanashi` は `build_yamanashi.py` が `data/fukugiiro/seido.json` から生成するが、
**このスクリプトはどのCIワークフローからも実行されていない**。そのため沖縄版の更新が
自動では反映されず、今回削除した `fk-kuni-ninpu-shien` も山梨版に31ファイル分残っている。

今回いったん再生成を試みたが、**上記Aの2制度まで山梨版から消える**ことが分かったため取り消した
(山梨版は古いデータのおかげで、たまたま正しい2制度を表示できている状態)。
Aを解消してから山梨版を再生成するのが正しい順序。

**対処案**: Aを先に直し、そのうえで `build_yamanashi.py` を週次ワークフローに組み込む。
