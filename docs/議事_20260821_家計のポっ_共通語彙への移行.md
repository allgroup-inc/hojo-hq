# 議事: 家計のポっ(❷)のステータスを共通語彙へ移行する — 三名体制

日付: 2026-08-21 / 発端: 軸から配られた共通認識(1つのアプリ・5つの入口)
適用スキル: hojo-triangle-review / resilient-agent-design
関連: `docs/連携メモ_20260821_家計のポっ_共通認識への回答.md`

## 前提

共通認識の約束【4】「ステータスの言葉を言い換えない」に対し、家計のポっの7種が不一致。
`allgroup-inc/kakei-crm` は本セッションから読めない(3回試行、ツール承認が下りない)ため、
**共通認識の本文に明記された語彙を正として**移行する。

## 論点: `予定 / 確定 / 再調整中` の3値を、共通語彙の2値にどう畳むか

共通語彙で ❷ が持てるのは **`アポ確定` / `スケジュール調整中`** の2つだけ。
現行は3値あり、しかも**「その時間の枠を押さえているか」が3値で違う**。

| 現行 | 意味 | 枠を押さえるか(現行の実装) |
|---|---|---|
| 予定 | 日時は入っているが未確定(仮押さえ) | **押さえる** |
| 確定 | 日時確定 | **押さえる** |
| 再調整中 | 日時が崩れて組み直し中 | 押さえない(空き扱い) |

単純に「予定・再調整中 → スケジュール調整中」と畳むと、**押さえる/押さえないが同じ語に同居**し、
空き枠の計算ができなくなる。ここが機械的に決められない箇所。

### スイシン(推進)

- 共通語彙に合わせること自体は必須。約束【4】は「後で変えられてしまう」のを防ぐための決まりで、
  例外を1つ作ると他システムも例外を作る
- **`アポ確定` だけが枠を押さえる**とすれば、2値のまま矛盾なく畳める
- 共通認識では ❷ の初期表示は「今日調整すべきアポ、**埋まっていない訪問枠**」。
  確定していない枠を「空き」として出すほうが、この初期表示の意味が通る

### ウタガイ(懐疑)

- **運用が変わる。**いまは仮予定でも枠が埋まるため、同じ時間に別のアポを入れると警告が出る。
  「アポ確定だけが枠を押さえる」に変えると、**仮予定の時間に別アポが入っても警告が出なくなる**。
  ダブルブッキングが増える方向の変更で、これは現場の事故に直結する
- 家計のポっは**まだ1度も稼働していない**。実運用で「仮予定」がどれくらい使われるか誰も知らない。
  使われ方が分からない段階で判定ロジックを変えるのは、根拠のない賭けになる
- `追客中` の新設も同じ懸念。共通語彙にあるからという理由だけで状態を増やすと、
  現場は「訪問済と追客中の使い分け」を覚えることになり、約束の「入力は仕事の副産物」に反する

### ベッカイ(別解・前提を疑う)

- そもそも**枠の占有をステータスで判定していること自体が筋が悪い**。
  「その時間に人が動けないか」は日時と所要分が決めることで、ステータスの役目ではない
- 別解: **占有判定を「日時が入っているか」に移す**。ステータスは共通語彙の2値に素直に畳み、
  再調整中だったものは**日時を空にする**。日時が無いレコードは枠を押さえない
- こうすれば、共通語彙を守りつつ現行の挙動(仮予定は押さえる/再調整中は押さえない)が保たれる
- `追客中` は今回入れない選択もある。「14日さわられていない検討客の浮上」は
  **最終更新日時**があれば `訪問済` のままでも実現でき、状態を増やさずに済む

## 結論(裁定)

**ベッカイ案を採用する。**

1. ステータスは共通語彙に素直に畳む
   - `予定` → **スケジュール調整中**
   - `確定` → **アポ確定**
   - `再調整中` → **スケジュール調整中**(移行時に日時を空にする)
   - `実施済` → **訪問済**
   - `申込み` → **申込**
   - `キャンセル(顧客都合)` / `キャンセル(自社都合)` → **差し戻し**(理由は新設の「差し戻し理由」列へ)
2. **枠の占有判定を、ステータスから「日時が入っているか」へ移す**
   - 日時があるレコードは枠を押さえる(仮予定でもダブルブッキング警告が出る=現行の挙動を維持)
   - 日時が無いレコードは押さえない(再調整中だったものが該当)
   - ウタガイの「事故に直結する変更」を回避しつつ、共通語彙を守れる
3. **`追客中` は今回入れない**
   - ウタガイ・ベッカイの指摘を採用。「14日さわられていない検討客」は最終更新日時で出せる
   - 稼働していない段階で現場に覚えることを増やさない。必要性が実運用で見えたら再検討
4. `対象外`(架電禁止)は**家計のポっに持たせない**
   - 持ち場を越えて効く必要があるため、顧客台帳(kakei-crm)側が正しい置き場所

理由: 約束【4】を守りながら、ウタガイが挙げた「ダブルブッキングが増える」という実害を避けられるのは
ベッカイ案だけであるため。また稼働前で移行データが存在しないため、**いま変えるのが最も安全**。

- 見直し期限: **2027-02-21**(6ヶ月)。実運用で仮予定の使われ方が見えた時点で再点検

## 軸への確認事項(事後でも構いません)

- `再調整中` を「スケジュール調整中 + 日時なし」で表現する扱いで問題ないか
- `追客中` を ❷ 側に持たせない判断で問題ないか(❸を別システムにするなら、そちらが持つべき状態)
- `対象外` を顧客台帳側に置く判断で問題ないか
