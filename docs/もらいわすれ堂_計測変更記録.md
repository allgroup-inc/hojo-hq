# もらいわすれ堂 計測変更記録

計測の数え方や画面の版が変わった日を、ここに1行ずつ残す。週次レポートの数字を前後で比べるときは、まずこの表を見る。
(2026-11-09 新設。診断改善と申請支援の改善を、画面の版の印で切り分けるため)

## 画面の版の印

| 印 | 何の版か | 値 |
|---|---|---|
| top_v | トップページ(site/fukugiiro/index.html) | 1=2026-11 の画面 |
| ui_v | 診断(site/fukugiiro/shindan/) | 1=2026-11 の画面 |
| support_v | 申請準備シート・受給報告・訂正ページ | 1=2026-11 の画面 |

- 各ページが `window.FG_VERSIONS` に自分の版を持ち、共通の計測部品(site/fukugiiro/assets/fg-analytics.js)がすべての計測に添える
- トップを通った人は、同じタブの間 top_v を他のページの計測にも添える
- GA4 の画面・Data API で版ごとに分けて見るには、カスタムディメンションの登録が要る(GA4 の設定変更=事前承認の対象。登録より前の値は分けて見られない)

## 変更の記録

| 反映日 | 段階 | 変えたこと | 見た目 | 版 |
|---|---|---|---|---|
| (統合時に記入) | 第1段階・計測だけ | 版の印を全計測に添える / 診断の結果の「公式ページで確認する」を result_official_click で数える / 診断の完了に resumed(保存した答えを開き直したか)を付ける / 申請準備シートの5ステップの2つ目で jukyu_step_soudan、4つ目で jukyu_step_shinsei を同じ端末・同じ制度で1回だけ数える / 週次レポートに「公式ページへ・相談・申請」の行を足す | 変えない | top_v=1・ui_v=1・support_v=1 |

## 数え方の注意

- ② 最初の質問に答えた数は、既存の shindan_step_q2(市町村を選んで次へ進んだ)で数えている
- 保存した答えを開き直した人は途中の質問を通らないため、shindan_complete の resumed=true は段の数と分けて見る
- 相談できた・申請できたは本人の申告(押し忘れ・付け間違いがある)。受給報告の代わりにしない
- 第1段階の反映後、約2週間は見た目を変えずに基準値を取る。画面の変更(ui_v=2 など)は別の承認で行い、同じ週に重ねない
