# IG配信プロセス - 運用ガイド

**目的**: 毎週月曜に遥さん(Haruka)へ Instagram 投稿ネタ5案をメール送信する際、検証ゲートを通して品質を保証する。

**運用開始**: 2026-09-28(小柳さん決裁)

---

## 全体フロー

```
毎週月曜 02:00 UTC (11:00 JST)
  ↓
send-ig-neta-haruka.yml (GitHub Actions ワークフロー)
  ↓
scripts/send_ig_neta_to_haruka.py 実行
  ├─ 1. ig_neta.json を読み込む
  ├─ 2. 検証ゲート:
  │   ├─ 全案が seido.json の verified=True か
  │   └─ 全案が常時制度か (deadline_type がないか)
  ├─ 3. 失敗時: 送信スキップ + このチャットに報告
  └─ 4. 成功時:
      ├─ 各案の source_url をメール本文に含める
      ├─ LINE返信要求なし
      ├─ docs/IG配信チェックリスト_YYYYMMDD.md を作成
      └─ 遥さんへメール送信
```

## 検証ルール

### ① 全案が verified=True であること

**確認場所**: `data/fukugiiro/seido.json` の各制度

```json
{
  "id": "fk-kuni-shugaku-shien",
  "title": "高等教育の修学支援新制度",
  "verified": true,
  "verified_date": "2026-09-25",
  ...
}
```

- `verified=false` または未設定の場合 → **送信NG**
- 理由: 元の制度データが公式ページと照合されていない

### ② 全案が常時制度であること

**確認場所**: `data/fukugiiro/seido.json` の `deadline_type` フィールド

- `deadline_type` フィールド **存在しない** → 常時制度 → **OK**
- `deadline_type: "特定日"` など → 期限ありの制度 → **NG**

**理由**: 
- SNS投稿ルール(CLAUDE.md)では、常時制度のみ無制限投稿可
- 期限ありの制度は、SNS=残り30日以上のみ、LINE=7〜29日のみという3層ルールに従う必要がある
- IG配信は「今週のネタ」というカジュアルな流れなので、常時制度のみに限定

## トラブルシューティング

### 送信に失敗した場合

**ワークフローログを確認**:
1. GitHub Actions の `send-ig-neta-haruka` を開く
2. 最新の run を見て失敗理由を確認

**一般的な失敗原因**:

| エラー | 原因 | 対応 |
|--------|------|------|
| `verified=True` ではない | 元の制度が公式ページと照合されていない | `data/fukugiiro/seido.json` で制度を照合してから再実行 |
| `deadline_type` が存在 | 期限ありの制度が混ざっている | ig_neta.json から除外して再実行 |
| SMTP_HOST など環境変数未設定 | GitHub Secrets が未設定 | リポジトリ設定で SMTP_* Secrets を追加 |
| メール送信失敗(SMTP接続) | ネットワーク/認証エラー | Secrets の設定値を確認(特にパスワード) |

### 手動実行

**スケジュール以外に送信したい場合**:
```bash
gh workflow run send-ig-neta-haruka.yml
```
