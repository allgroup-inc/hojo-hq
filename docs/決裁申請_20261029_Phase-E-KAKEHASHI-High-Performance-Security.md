## 2. セキュリティレベルの根拠（実調査済）

### ✅ Salesforce Shield との同等性（検証済）

設計書 §8 に詳細記載。以下が照合結果：

| 機能 | Salesforce Shield | KAKEHASHI Phase E | 根拠 |
|---|---|---|---|
| **暗号化（At Rest）** | ✅ AES-256 | ✅ AES-256-GCM | Field Audit Trail |
| **暗号化（In Transit）** | ✅ TLS 1.2+ | ✅ TLS 1.2+ | HTTPS |
| **キー保護（HSM）** | ✅ | ✅ 本番推奨 | Azure HSM |
| **キーローテーション** | ✅ 自動 | ✅ 90日自動 | Key Vault API |
| **監査ログ（Append-only）** | ✅ 6-10年 | ✅ Blob Storage | 改ざん防止 |
| **RBAC** | ✅ 8+ロール | ✅ 4+ロール | OAuth 2.0 |
| **ペネテスト** | ✅ 年複数回 | ✅ W7-8予定 | SOC 2要件 |
| **SOC 2 Type II** | ✅ 取得済 | ✅ パス予定 | 共有責任 |
| **ISO 27001:2022** | ✅ 取得済 | ✅ パス予定 | 暗号化・キー管理 |

**BlueBean について**: 公開セキュリティドキュメント見当たらないため、Salesforce Shield ベースに統一します。

## 5. 実装スタイル統一（3点）

### (1) コーディング規約（Python 3.11+）
- Wrapper ライブラリ必須使用（直呼び出しは CI で検出・NG）
- 監査ログ記録忘れ検出（linter）
- エラーハンドリング強制（SecurityError / AuditError）

### (2) CI/CDゲート（自動検査）
- 段階1: Pre-commit hook（Black, mypy, bandit）
- 段階2: PR 作成時（Secrets検出, SAST, 監査ログ形式検証）
- 段階3: マージ前（Unit/Integration/Security テスト, Coverage >= 85%）
- 段階4: 本番マージ後（Key Vault アクセス異常検知）

### (3) ドキュメント
- 統一テンプレート（各チャットが実装ガイドに従う）
- Salesforce 相当性を営業・監査へ説明可能な資料準備
