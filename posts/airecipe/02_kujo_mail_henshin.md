# 怒りメールを貼るだけ、1時間悩む返信が3分に

お怒りのメールを開いた瞬間、手が止まる。謝りすぎれば責任の話がこじれ、言い訳すれば火に油。そのまま1時間、下書きと削除を往復——という時間を減らすためのレシピです。事実・謝罪・対応の3つを機械的に切り分け、送る前に人が確認できる返信下書きを3分で用意します。

## このレシピでできること

- 確認済みの事実と未確認の事実を分けて整理できます
- 謝る対象と保留する論点を切り分けられます
- そのまま推敲できる返信下書きが手に入ります

## 実行ログ(抜粋・原文ママ)

サンプル入力(架空の例です):

> 先週注文した商品がまだ届きません。発送完了メールは3日前に来ています。明日の催事で使う予定だったので間に合わないと困ります。どうなっているのか今日中に説明してください。場合によってはキャンセルも考えます。

これを本記事のレシピに渡した、実際の出力がこちらです。

```
【1. 相手の主張の整理】
- 先週注文した商品が、現時点でまだ手元に届いていない。
- 発送完了メールは3日前に受信しており、その後の状況が分からない。
- 明日の催事で使用する予定で、間に合わないと支障が出る。
- 本日中に状況の説明を求めている。
- 状況次第ではキャンセルも検討している。

【2. 事実の切り分け】

| メール本文から確認できること | こちら側で調べないと分からないこと |
|---|---|
| 注文が先週行われたこと | 注文番号・注文日・商品名・数量 |
| 3日前に発送完了メールが送信されていること | 実際の出荷日と配送業者・追跡番号 |
| 本日時点で商品が未着であること | 現在の配送ステータス（輸送中／保管中／滞留等） |
| 明日の催事で使用予定であること | 明日中の配送が物理的に可能かどうか |
| 本日中の説明とキャンセル検討の意向 | 催事の開催時刻・お届け先住所の指定条件 |
| — | キャンセル可否の判断に必要な出荷段階の情報 |

【3. 謝罪の切り分け】
- すぐ謝る点：商品が届かずご不安な状態が続いていること／催事を控えたお忙しい時期にお手数をおかけしていること／状況をご説明できていない現状。
- 未確認のため保留する点：遅延が発生した原因、配送上の問題の所在、明日への間に合いの可否、キャンセルや今後の取り扱いの結論。

【4. 返信下書き】

件名：【本日中にご連絡】ご注文商品の配送状況を確認しております（注文番号：［　］）

［お客様のお名前］様

このたびは、ご注文の商品がお手元に届かず、ご不安な思いをおかけしております。明日の催事を控えたお忙しい時期に、ご負担をおかけしておりますこと、心よりお詫び申し上げます。

現在、配送業者への照会を含め、［注文番号：　］の配送状況を確認しております。発送完了のご案内後の輸送状況につきましては、確認が取れ次第、正確な内容をお伝えいたします。

ご指定いただきました本日中のご説明につきまして、本日［　時　分］までに、現在の配送状況と明日の催事に向けて取り得る対応
(以下略)
```

## レシピ全文(コピペ用)

```
あなたは、顧客対応の文面を整えるカスタマーサポート担当の相談相手です。目的は、お怒りのメールに対して「火に油を注がない構造」の返信下書きを作ることです。

以下の手順で考えてください。
1. 受け取ったメールから、相手が困っている事実・相手の要望・締め切りや期日を抜き出す。
2. 事実を「メール本文から確認できること」と「こちら側で調べないと分からないこと」に分ける。
3. 謝罪の対象を切り分ける。ご不便やご心配をおかけした点はすぐ謝り、原因や責任の所在が未確認の点は謝罪ではなく「確認します」と扱う。
4. 相手の期日に対して、いつまでに何を返すかを明示する一文を作る。

出力は次の形式にしてください。
【1. 相手の主張の整理】箇条書き3〜5行
【2. 事実の切り分け】確認できること／要確認のこと の2列で箇条書き
【3. 謝罪の切り分け】すぐ謝る点／未確認のため保留する点
【4. 返信下書き】件名と本文。300〜450字程度、敬体。
【5. 送信前チェック】社内で確認すべき点を3つ

制約:
- 事実が入力にない場合は創作せず、下書き内は［　］の空欄にして担当者が埋める形にする。
- 原因や責任を断定しない。補償・返金・値引きの約束は書かない。
- 相手の感情を否定しない。反論・言い訳・「〜のはずです」という推測表現は使わない。
- 期日の指定があれば、その期日に触れる一文を入れる。

それでは、以下の入力を処理してください。
```

## 手順

1. プロンプト全文をAIチャットにコピペする
2. その下にお怒りメールの本文をそのまま貼って送信する
3. 【2】【3】の切り分けを読み、事実認識のズレがないか確かめる
4. ［　］の空欄を社内で調べた事実で埋める
5. 【5】のチェック項目を上長や関係部署に確認してから送る

## 自分用にアレンジする

- 自社の署名や定型のお詫び表現があれば、プロンプト末尾に「文末はこの形式で」と貼り付けて統一できます。
- 電話で折り返す運用なら、出力形式に「電話でのお詫びトーク台本」を追加すると口頭対応にも使えます。
- 強い口調が続く相手には「本文は250字以内で簡潔に」と条件を足すと、論点が増えにくくなります。

## うまく動かないとき

下書きが謝りすぎたり言い訳っぽくなるときは、「原因は未確認という前提で書き直して」と一言添えて再生成してください。事実が創作されている場合は、その行を指摘して「入力にない情報は［　］にして」と伝えます。長すぎるときは字数を指定し、堅すぎるときは「取引先向け／個人のお客様向け」と相手を明示すると調子が合いやすくなります。
