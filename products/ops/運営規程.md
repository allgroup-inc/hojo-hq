# 収益プロダクト事業 運営規程(憲法への差分)

作成日: 2026-08-02 / 見直し期限: 2027-02-02(最長6ヶ月)
位置づけ: **CLAUDE.md憲法と docs/三名体制運営規程.md を親規程とする差分**。
本規程と親規程が矛盾した場合は親規程が勝つ。
目的: 達成の保証ではなく、**品質の再現とリスクの早期検知**(議事録・論点3の裁定)。

## 1. 承認レベル(自律度)

| レベル | 内容 | 例 |
|---|---|---|
| L4(自動実行) | リポジトリ内で完結し、対外に出ない作業 | テンプレのバグ修正・テスト・FAQ/ドキュメント追記・記事/文面のドラフト生成・台帳更新 |
| L3(実行後報告) | 対外に出るが定型で可逆な作業 | 既存商品ページの誤字修正、決裁済み価格の範囲内での文言調整、コミット/PR/マージ(計画範囲内) |
| L2(三名短評つき事前承認) | 対外に出る新規物 | 新しい記事の公開、商品説明の大幅変更、期間限定の値引き(定価の20%以内・14日以内) |
| L1(小柳さん決裁・都度) | 金額・提携・方針 | 新商品の発売、定価の変更、新販路の追加、B2B契約、返金ポリシー変更、月2件を超える代行受注 |

※L3の「実行後報告」は次回の週報にまとめて記載すればよい。

## 2. 出荷品質ゲート(商品・記事を世に出す前の必須チェック)

商品(テンプレ/ZIP)は以下**全部**を満たすまで販売開始しない:

1. オフラインテストモードでの通し実行が成功している
2. 実環境テスト(GitHub Actions+実APIキー)が**1回以上**成功している ← 人間作業
3. LICENSE.md・README・FAQが同梱されている
4. 「要確認」設計(不明値を断定しない)が壊れていない
5. 販売文言に景表法・薬機法上のNG表現(「必ず」「絶対」「日本一」等)がない
6. 補助金関連商品は士業法の線引き文言(申請代行はしない)が明記されている
7. 対外文面は humanizer スキルを通している

記事・SNS告知は 5・7 のみ必須(数値実績を書く場合は実データと照合すること)。

## 3. 販売・価格の規律

- 定価変更・新商品はすべてL1(小柳さん決裁)。エージェントは提案まで
- 成果報酬型(受給額・売上の%)の価格設計は**一切しない**(憲法・資格業務線引きと同根)
- 実績数字(売上・部数)を対外に出すときは、プラットフォーム管理画面の実数のみ。
  推測値・盛った数字は出さない(未確定は「集計中」と書く)
- 代行メニューは**月2件を上限**に受注。超過は翌月納期を明示するか、お断りする

## 4. ミカタ/フクギイロとの分離(混同防止)

- 本事業の販路(note/X/ココナラ等)はミカタのアカウント・LINE・サイトと**共有しない**
- ミカタのLINE登録者・サイト訪問者に本事業の商品を売り込まない(CV単一ルールの保護)
- 「沖縄企業のミカタ」「もらいわすれ堂」のブランド名・実データを本事業の販促に使う場合はL1決裁
- 制度データの扱いは hojo-accuracy-check に完全準拠(原文照合・要確認・出典必須)

## 5. エスカレーション条件(即時に人間へ上げる)

| 事象 | 行動 |
|---|---|
| 返金要求・クレーム | 24時間以内に小柳さんへ報告。一次返信はササエル雛形で即応、判断は人間 |
| 法的疑義(権利侵害の指摘・士業法・景表法) | 該当物の販売/公開を**即時停止**してから報告(事後48時間以内に三名レビュー) |
| 購入者データ・個人情報の漏えい疑い | 即時停止・即時報告(親規程の緊急停止系) |
| 販売プラットフォームからの警告 | 当該出品を非公開にしてから報告 |
| 売上ゼロが8週連続 | ピボット判定を三名体制で実施(自動で議題化) |

## 6. 週次サイクル(駆動の最小単位)

毎週月曜のRoutineで: ①KPI・台帳更新 ②成功事例ウォッチ(検索3件以上・使える発見は台帳へ)
③記事/改善ドラフト生成 ④小柳ToDoの催促(2週停滞は週報先頭で警告)。
このRoutineが止まっていたら、それ自体をニドナシ機構の失敗台帳に記録する。

## 7. 失敗の扱い

インシデント(誤情報の販売・返金・警告等)は隠さず、48時間以内に docs/失敗台帳.md へ
記録(ニドナシ機構様式・人を責めない)。対策は「気をつける」を禁止し、
テスト化/ゲート化/設計変更/ルール化のいずれかで返す。
