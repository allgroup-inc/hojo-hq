# 収益プロダクト事業(products/) チーム編成

作成日: 2026-08-02 / 親文書: products/ops/議事録_体制総点検_20260802.md
原則: エージェントは「役割名」ではなく**週次Routine+タスク台帳で駆動される実行単位**。
組織図を増やすことより、ループが回り続けることを優先する(議事録・論点2の裁定)。

## KGI / KPI

- **KGI: 12ヶ月で月30万円(手取り)** — テンプレ販売+セットアップ代行+B2B導入支援
- **90日間の正KPIは「検証階段」**(金額ではなく検証の到達度で測る):

| 階段 | 内容 | 期限目安 |
|---|---|---|
| 1 | 販路3つ開設(note/Brain/ココナラ) | 〜2週間 |
| 2 | 初販売(どの商品でも1件) | 〜30日 |
| 3 | 累計10販売 | 〜60日 |
| 4 | 代行 初受注 | 〜75日 |
| 5 | 商品別の勝敗判定(継続/改良/撤去) | 90日レビュー |

- ミカタのnote収益化計画(月10万)とは**導線・ブランド・KPIを完全分離**。
  小柳さん閲覧用の合算は `products/ops/ポートフォリオ台帳.md` のみ

## 組織図

```
小柳さん(最終決裁・人間側実行者)
└─ 本セッション(実行環境。統括は置かない)
   ├─ ツクルさん(プロダクト部)…新設 .claude/agents/tsukuru.md
   ├─ ウリテさん(販売部)………新設 .claude/agents/urite.md
   ├─ ササエルさん(顧客部)……新設 .claude/agents/sasaeru.md
   └─ 兼務(既存組織から管轄拡張)
      ├─ マモリ(守り部: ライセンス・景表法/薬機法表現・士業法線引き)
      ├─ タダス(独立監査: 販売文言と実装の乖離チェック)
      └─ ニドナシ機構(失敗台帳: 本事業のインシデントも48時間以内記録)
```

## 職掌の要点

| 部門 | 主担当 | 週次Routineでやること |
|---|---|---|
| プロダクト部(ツクル) | 商品の開発・テスト・FAQ更新・購入者不具合の修正 | 不具合報告の処理、テンプレ改善、実地テスト結果の反映 |
| 販売部(ウリテ) | note記事・出品文言・価格運用・KPI集計 | 記事ドラフト生成、販売数の台帳更新、成功事例ウォッチの反映 |
| 顧客部(ササエル) | 購入者サポート・代行納品・返金一次対応 | 問い合わせ対応文面の用意、代行案件の進行管理(**月2件上限**) |

## 駆動系(体制を絵に終わらせない仕組み)

1. **週次Routine**(毎週月曜 08:00 JST・本セッションに着火): KPI点検 → 台帳更新 →
   成功事例ウォッチ → 記事/改善のドラフト生成 → 人間ToDoの催促
2. **タスク台帳**(products/ops/タスク台帳.md): 全タスクに担当・状態・期限。
   Routineが毎回読み書きする唯一の進行管理簿
3. **小柳ToDo**(products/ops/小柳ToDo.md): 人間にしかできないことだけを分離。
   2週連続で動きがない項目はRoutineが「最重要ボトルネック」として週報の先頭に出す

## 90日レビュー(2026-11-02)

検証階段の到達状況で継続/ピボットを三名体制で判定。
販路開設が未完なら、体制・商品の議論はせず「人間ToDoが進まなかった理由」だけを議題にする。
