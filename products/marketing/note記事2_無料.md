# 【note無料記事 下書き2本目】

タイトル案: **AIに「数字」を書かせてはいけない — 週次経営レポートを自動化して分かったこと**

---

毎週月曜の朝、私の手元には先週の売上レポートが自動で届きます。集計表と、AIが書いた「良かった点・注意点・来週やること」つきで。

作るのにかかった時間は半日。運用コストは月100円未満。

ただ、この仕組みを作る過程で、**AI活用の一番大事な原則**にぶつかったので、今日はその話を書きます。

## 最初の失敗: AIに集計させた

最初のバージョンは単純でした。売上CSVを丸ごとClaudeに渡して「先週のレポートを書いて」と頼む。

出てきたレポートは、一見完璧でした。文章は流暢で、前週比のパーセンテージまで書いてある。

でも検算したら、**数字が微妙に違う**。

嘘をつこうとしているわけではなく、大量の行を目視で足し算しているようなものなので、ズレるんです。人間と同じです。そして怖いのは、**間違った数字も完璧に自信満々な文章で書いてくる**こと。

## 解決: 「計算は機械、文章はAI」に分業する

作り直したバージョンはこうです。

1. **集計はPythonが実行**(前週比・カテゴリ別・件数——すべて普通のプログラムで計算。1円もズレない)
2. **集計済みの数字だけをAIに渡す**
3. AIの仕事は「この数字を見て、所見と提案を書く」ことだけ
4. プロンプトで「渡した数字以外を書くな。要因は断定するな」と縛る

この構造にしてから、数字のミスはゼロです。そしてAIの所見は正直かなり優秀で、「保険カテゴリの件数は横ばいだが単価が下がっている。単価の高い商品の提案数を確認しては」みたいな、ちゃんと使える指摘をしてきます。

## 原則: AIには「AIにしかできないこと」だけをさせる

| 仕事 | 誰がやるべきか |
|---|---|
| 計算・集計 | プログラム(絶対に間違えないから) |
| 形式チェック | プログラム(ルールが明確だから) |
| 要約・所見・提案 | AI(ここが人間の代替になる部分) |
| 最終判断 | 人間 |

「全部AIにやらせる」は事故のもとで、「AIを組み込んだ仕組みを作る」のが正解——というのが、いくつか自動化を作ってきた今の結論です。
